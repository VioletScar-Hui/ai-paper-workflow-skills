# 后训练推理数据入门综述：五大直觉陷阱与验证合约分类法

📄 **原文 PDF**：[[RAW/38 - A Primer in Post-Training Reasoning Data - What We Know About How It Works.pdf]]

## PM 速判
> 一句话：150+篇论文综述揭示五大反直觉教训——最重要：对Agent训练，清洗掉失败/重试的"干净成功轨迹"反而是最差数据，因为失败分支包含信用归因所需的高价值训练信号。

## 双层费曼 🗣️
> **给CEO**：训练AI推理能力时，直觉上"喂正确答案、删掉错误过程"的做法正好适得其反。这篇综述告诉我们：推理训练数据的好坏不是看"干净程度"，而是看"验证可靠性"——数学题有标准答案最好办；写代码可以跑测试；但医疗诊断或法律文书，连"对错"都没法自动判定，这才是真正的瓶颈。对于能自主操作工具的AI Agent，那些失败、重试、绕弯路的"脏轨迹"反而是最宝贵的训练素材，因为它们教会模型"什么不该做"。
> **给工程师**：综述以验证合约（verification contract）为核心维度重构推理数据分类——程序化验证（数学/代码的确定性答案检查）、环境验证（工具调用/代码执行的运行时反馈）、判断-需要验证（开放域任务需人工或LLM-as-Judge）。监督粒度上区分结果标签（outcome label，回答是否解决）和步骤标签（step label，哪些推理步骤是有效的）。对RLVR和Agent训练，完整episode中的失败分支、状态差分、工具误用与恢复序列是信用归因（credit assignment）的核心信号源，清洗掉这些等于自毁训练数据。

## 问题域定位 🎯
- **回应的根本约束**：后训练推理数据的质量评估缺乏统一框架——研究者各自用"长度""难度""规模"等直觉指标决策，但这些直觉系统性地错误。综述回应的是"如何系统性地判断一段推理数据是否值得用于训练"这一根本问题。
- **之前卡在哪**：数据工程社区在五个维度上反复使用错误启发式——长CoT等于好推理、困难数据等于好数据、更多数据等于更好覆盖、干净成功轨迹等于最佳训练数据、自我对弈等于去除人工筛选。每个直觉都有反例，但缺乏系统性的纠正框架。
- **开启/关闭的路线**：开启：以验证合约而非数据来源作为数据分类的主维度，将讨论从"数据长什么样"转向"数据能否被可靠验证"；Agent轨迹数据必须保留失败分支的标准化共识。关闭：单纯用数据量、轨迹长度、题目难度来评估推理数据质量的粗糙做法被系统性证伪。

五大直觉陷阱对照表：
```
+--+---------------------------+--------------------------------------------------+
|# | 常见直觉（错误）            | 正确理解（150+论文证据）                              |
+--+---------------------------+--------------------------------------------------+
|1 | 长CoT = 好推理             | 长轨迹可能是合理化、复制教师风格、隐藏真实推理原因；       |
|  |                           | 需要有效性(validity)和接地性(grounding)双重验证          |
+--+---------------------------+--------------------------------------------------+
|2 | 困难数据 = 好数据           | 难度是三元关系: 基座模型 x 题目 x 采样协议；               |
|  |                           | 对模型A不可达的题对模型B可能是最佳练习；需报告pass-rate band|
+--+---------------------------+--------------------------------------------------+
|3 | 更多数据 = 更好覆盖         | 覆盖是配方(来源混合/过滤/教师/生成器)而非计数；             |
|  |                           | 规模和数据泄露可以共存；需报告血统风险和去污染状态           |
+--+---------------------------+--------------------------------------------------+
|4 | 干净成功轨迹 = 最佳训练数据  | 对Agent训练，清洗失败/重试/恢复/状态差分 = 删掉信用归因的    |
|  |                           | 最高价值信号；Agent数据应是完整可重放episode，非清洗路径     |
+--+---------------------------+--------------------------------------------------+
|5 | 自我对弈 = 去掉了人工筛选    | 自我对弈把筛选工作转移到锚点(答案/解释器/验证器/多数投票)，   |
|  |                           | 并未消除；需报告锚点类型、选择规则、验证器与故障模式          |
+--+---------------------------+--------------------------------------------------+
```

监督粒度双维度：
```
        结果标签 (Outcome Label)           步骤标签 (Step Label)
        ─────────────────────              ────────────────────
回答:   "这题答对了吗？"                   "推理的哪一步是有效的？"
信号:   准确率 (accuracy)                  可教性 (teachability)
局限:   知道学生会不会，不知道哪不会         知道具体哪步卡住了
成本:   低（答案匹配即可）                  高（需标注每步推理质量）
适用:   程序化验证类型                      环境验证 / 判断-需要验证类型
```

## 设计决策解剖 ⚖️
| 决策点 | 选择 | 被放弃方案 | 为什么 | 何时失效 |
|--------|------|-----------|--------|---------|
| 分类主维度：为何以验证合约而非数据来源分类 | 以"能否被可靠验证"做一级分类（程序化/环境/判断-需要） | 按数据来源分类（人工标注/模型生成/规则合成） | 数据来源不决定数据质量——同一来源可产出好数据和坏数据；验证合约直接决定训练信号的可信度，这才是质量的根本约束 | 当多种验证类型混合时（如数学题需要代码执行验证），分类边界模糊；此时需按主导验证方式归类 |
| 监督粒度：为何区分结果标签和步骤标签 | 两层粒度并行——结果标签判对错，步骤标签定位有效推理 | 只用结果标签（正确/错误二元标注） | 结果标签告诉你"学生会不会做"，步骤标签告诉你"学生哪里卡住了"；后者是RLVR中信用归因的关键输入，PRM训练依赖步骤级信号 | 程序化验证中步骤标签收益有限（答案对=步骤大概率对）；当标注成本极度受限时，优先结果标签是合理退路 |
| 轨迹清洗：为何坚持保留失败分支而非仅成功轨迹 | Agent训练数据保留完整episode（含失败/重试/回溯/状态差分） | 清洗轨迹、只保留最终成功的干净路径 | 失败分支包含工具误用模式、恢复策略探索、信用归因信号——RL的核心是"从错误中学习"，删掉错误等于删掉学习素材；多篇独立研究验证此结论 | 当失败分支是随机噪声（非策略性探索）时，保留无益；当episode过长导致上下文窗口溢出时，需选择性截断而非全保留 |

## 成本与量级 💰
综述本身无直接实验成本，但验证合约分类法直接映射到数据获取成本梯度：

| 验证合约类型 | 单条数据获取成本 | 验证成本 | 规模化瓶颈 |
|-------------|----------------|---------|-----------|
| 程序化验证（数学/代码） | 极低（模型采样即可，答案自动校验） | 近似为零（单元测试/答案匹配全自动） | GPU算力是唯一瓶颈 |
| 环境验证（Agent工具使用） | 中高（需搭建沙箱/模拟环境，单条轨迹可能需几十轮工具调用） | 中等（环境返回成功/失败信号，但需解析） | 环境搭建与维护成本非线性增长 |
| 判断-需要验证（医疗/法律） | 极高（需领域专家标注，每条数据可能需要数小时专家时间） | 极高（人工标注或LLM-as-Judge，后者仍需人工抽检校准） | 专家供给是硬约束，LLM-as-Judge的可靠性上限限制了自动化程度 |

估算梯度：以程序化验证为基准（1x），环境验证约为10-50x（环境+算力），判断-需要验证约为100-1000x（专家人力）。这解释了为何数学/代码推理能力进步最快——验证合约的自动化程度直接决定了数据飞轮的转速。

## 证据审计 🔬
- **综述类文章的特殊审计**：综述的证据强度不来自一手实验，而来自多独立研究的结论收敛度。五大陷阱中，"干净轨迹是最差Agent数据"获最强收敛——多篇独立Agent训练研究在不同环境中验证了保留失败分支的完整episode优于清洗后成功轨迹。方法论上无发表偏差矫正是主要局限。
- **最强证据**：Agent轨迹保留失败分支的结论由多研究独立验证——包括SWE-bench、WebArena、AgentBench等多个环境下的实验，方向一致。困难度是三元关系（基座模型 x 题目 x 采样协议）的结论在GSM8K、MATH、HumanEval上跨模型复现，稳健性高。
- **最可疑泛化及原因**："长CoT不等于好推理"的方向正确但边界模糊——适当长度的CoT在特定任务（如多步数学推理）中确实有益。综述呈现为"长度无关"可能过度简化：应该是"长度不是充分条件，但必要长度的缺乏会损害推理"。另外，五大陷阱的适用领域不同，综述扁平化呈现忽略了领域特异性。
- **审稿补充关注点**：(1) 综述未做系统性元分析（meta-analysis），结论的统计显著性缺失；(2) 验证合约分类的完备性——是否存在无法归入三类的推理数据类型？(3) 结论对多模态推理数据的可迁移性未讨论。
- **最小复现设计**：选取一个开源Agent benchmark（如SWE-bench Lite），对同一基座模型使用两种数据配方训练——A组只用成功轨迹，B组保留含失败分支的完整episode——对比pass@1。预期B组显著优于A组，复现第四直觉陷阱的核心结论。预算约$500 GPU算力。

## 可复用点
- **何时采用**：(1) 设计Agent训练数据采集管线时，直接将"保留完整episode（含失败/重试/状态差分）"写入数据规范；(2) 评估外部推理数据集时，以验证合约类型为第一筛查维度——优先采购程序化验证类数据；(3) 内部数据标注SOP中加入步骤级标签，尤其对判断-需要验证类型的任务。
- **何时规避**：(1) 当任务有明确唯一正确答案且步骤空间小（如简单分类），过度保留探索分支会导致噪声；(2) 预算极度受限时，判断-需要验证类任务的步骤级标注ROI可能为负——先做好结果标签。
- **供应商拷问清单**：(1) "这个数据集的困难度是针对哪个基座模型、用什么采样协议测量的？pass-rate band是多少？"——如果答不上来，困难度标签没有参考价值。(2) "数据集中有哪些类型的验证合约？程序化验证占多少？判断-需要验证占多少？后者的人工校验比例是多少？"——判断-需要验证无校验的数据集应大幅折价。(3) "这个Agent训练数据集是否保留了失败/重试/回溯的完整轨迹？如果清洗过，清洗标准是什么？"——如果清洗掉了失败分支，Agent训练价值至少打对折。

## 动手练习 💻
**练习目标**：用拒绝采样构造推理数据——采样8个解答只保留答案正确的

**代码**（30-80行可运行Python，逐行中文注释）：

```python
"""拒绝采样构造推理训练数据：采样8个解答，仅保留答案正确的。
验证合约类型：程序化验证（答案匹配）。
讨论：如果验证器只能判最终答案对错而无法判中间步骤，有什么风险？"""
import random
import math

# ===== 1. 生成数学题（两位数加减法）=====
def generate_problems(n: int = 20) -> list[tuple[str, int]]:
    """生成n道两位数加减法题，返回(题目文本, 正确答案)列表"""
    problems = []
    for _ in range(n):
        a, b = random.randint(10, 99), random.randint(10, 99)
        op = random.choice(['+', '-'])
        expr = f"{a} {op} {b}"
        answer = a + b if op == '+' else a - b
        problems.append((expr, answer))
    return problems

# ===== 2. 模拟模型采样：对每题生成8个解答 =====
def sample_answer(true_answer: int, temperature: float = 0.8) -> tuple[int, bool]:
    """模拟temperature控制下的模型输出。
    高temperature: 更多错误（方差大）；低temperature: 更准确（方差小）。
    返回(模型答案, 是否正确)"""
    # 以正确答案为均值，temperature控制噪声标准差
    noise_std = temperature * 15  # temperature越大，偏差越大
    error = int(random.gauss(0, noise_std))
    model_answer = true_answer + error
    # 整数约束：答案在合理范围内
    model_answer = max(-999, min(999, model_answer))
    is_correct = (model_answer == true_answer)
    return model_answer, is_correct

# ===== 3. 拒绝采样：只保留答案正确的解答 =====
def rejection_sample(problems, temperature=0.8, samples_per=8):
    """对每题采样samples_per个解答，只保留正确答案的作为训练数据"""
    accepted, all_samples = [], []
    for expr, true_ans in problems:
        correct_samples_for_this_problem = 0
        for _ in range(samples_per):
            model_ans, is_correct = sample_answer(true_ans, temperature)
            all_samples.append((expr, model_ans, true_ans, is_correct))
            if is_correct:
                accepted.append((expr, model_ans, true_ans))
                correct_samples_for_this_problem += 1
    return accepted, all_samples

# ===== 4. 实验主流程 =====
random.seed(42)
problems = generate_problems(20)

# 低temperature采样（模型较准）
accepted_low, all_low = rejection_sample(problems, temperature=0.3)
# 高temperature采样（模型较发散）
accepted_high, all_high = rejection_sample(problems, temperature=0.8)

# ===== 5. 统计与输出 =====
def report(label, accepted, all_data):
    acc_rate = len(accepted) / len(all_data) * 100
    all_correct = sum(1 for _, _, _, ok in all_data if ok)
    all_acc = all_correct / len(all_data) * 100
    # 拒绝采样后正确率应为100%（定义如此）
    after_acc = sum(1 for _, ans, true in accepted if ans == true) / max(len(accepted), 1) * 100
    print(f"=== {label} (temperature) ===")
    print(f"  全量数据正确率: {all_acc:.1f}% ({all_correct}/{len(all_data)})")
    print(f"  拒绝采样接受率: {acc_rate:.1f}% ({len(accepted)}/{len(all_data)})")
    print(f"  拒绝采样后正确率: {after_acc:.1f}%")
    print()

report("低temperature (0.3)", accepted_low, all_low)
report("高temperature (0.8)", accepted_high, all_high)
```

## 自测三层 🎓
- **L1 复述**：五大直觉陷阱分别是什么？对Agent训练最关键的是哪一条？→ 答案：(1)长CoT不等于好推理、(2)困难数据不等于好数据、(3)更多数据不等于更好覆盖、(4)干净成功轨迹不等于最佳训练数据、(5)自我对弈不等于去除人工筛选。最关键的是第四条——对Agent训练，保留失败/重试/回溯的完整episode远比清洗后的成功轨迹有价值。
- **L2 解释**：为什么验证合约应该作为推理数据分类的主维度，而不是数据来源？用具体例子说明。→ 答案：数据来源（人工标注/模型生成/规则合成）不决定数据质量——同一来源可以产出好数据和坏数据。例如，模型生成的数学题解答中，正确答案的那部分（程序化验证可确认）是高质量数据，而模型生成的医疗诊断建议（无专家校验）即使来源相同也质量不可靠。验证合约直接决定了训练信号的可信度上限：能自动验证的数据可以大规模飞轮迭代，无法自动验证的数据的质量受限于人工校验带宽。
- **L3 应用**：你正在设计一个内部代码Agent的训练数据管线。代码可以在沙箱中执行，执行结果（通过/失败/报错）可以自动获取。你应该如何设计数据采集策略？什么应该保留、什么应该丢弃？→ 答案：应保留完整的编码episode——包括：初始任务描述、模型生成的每次代码提交（含语法错误版本、逻辑错误的失败版本、最终正确版本）、每次执行的沙箱输出（编译错误、测试失败、运行时错误、最终通过）、工具调用序列（文件读取、搜索、文档查询）、时间戳。不应丢弃任何失败分支——失败的代码提交和对应的错误输出是信用归因的关键信号，RL算法需要这些来学习"什么操作导致什么后果"。唯一可以丢弃的是超出上下文窗口的冗余中间状态（如连续重复的相同错误且无新信息的情况），但需记录截断点。
