# The Shift to Agentic AI: Evidence from Codex

📄 **原文 PDF**：[[RAW/109 - The Shift to Agentic AI - Evidence from Codex.pdf]]

## PM 速判
> **OpenAI 用 Codex 的实际使用数据证明了 Agentic AI 的"工作委托"转型——用户不再是"问 AI 问题"，而是"把工作交给 AI 做"。** OpenAI 内部研究员产出 token 数 6 个月增长了 50 倍，法务人员增长了 13 倍。OpenAI 内部 99.8% 的 AI token 使用已切换至 Agentic 委托模式。这是有史以来最有说服力的 AI 生产力实证研究，所有 AI PM 必读。

## 双层费曼
> **给CEO**：你的员工使用 AI 的方式正在发生质变。以前是"ChatGPT，帮我想想这个问题怎么解"（咨询模式），现在是"Codex，帮我做完这个项目"（委托模式）。OpenAI 自己的员工已经 99.8% 切换到委托模式——研究员每人每月产出的内容量 6 个月翻了 50 倍。这不是 AI 更强了，而是人把整套工作交给了 AI。未来 18-24 个月，你的公司也会是这个状态。现在该想想：你的团队准备好"管理 AI 干活"而不是"自己干活"了吗？
>
> **给工程师**：这篇不是模型论文，而是对 Codex 平台 H1 2026 全量使用数据的实证分析。核心发现：(1) 委托 vs 对话 token 比在三个用户群中呈现明显梯度（OpenAI 员工 99.8% vs 企业 63.3% vs 个人 16.5%），说明委托模式是"被教会"而非"自发的"；(2) 任务复杂度快速上移——提交"需 8+ 小时人工完成"任务的用户比例增长 10x；(3) 26.6% 用户使用可复用 Skills；(4) 理论框架定义了"委托经济学"：价值 = 任务规模 x 执行质量 x 人工监督效率，新瓶颈是人工监督而非 AI 能力。

## 问题域定位
- **根本约束**：AI 生产力提升的瓶颈从"AI 不够强"迁移到"人类不会/不愿把工作委托给 AI"。这本质上是工作流程设计和信任问题，不是技术能力问题
- **之前卡点**：学界对 AI 生产力的讨论停留在实验室对照实验（受控任务、短期观察），缺乏真实生产环境中大规模、长期的使用数据。Brynjolfsson et al. (2019) 提出"组织互补性"但缺乏 Agentic 时代的实证
- **本文开启的路线**：用平台全量使用数据（而非实验设计）量化委托转型——"token 切换比例"成为可追踪的转型度量。为后续 Agentic 产品设计提供数据驱动框架
- **本文暗示的未来**：OpenAI 内部今天的使用模式 = 企业市场 18-24 个月后的使用模式。组织核心竞争力从"做"转向"监督 AI 做 + 设计可委托任务"

| 分析维度 | 本研究的做法 | 替代方案 | 为什么这样做 | 局限 |
|---------|-------------|---------|-------------|------|
| 数据来源 | Codex 平台全量使用数据（H1 2026） | 实验室对照实验 / 自我报告调查 | 实验室实验无法捕捉真实生产环境中的长期行为变化；调查数据受回忆偏差和社会期望偏差影响 | 数据来自 OpenAI 自身平台，存在选择偏差（Codex 用户本身是早期采用者），且无法观察非 OpenAI 平台的 Agentic 使用 |

| 产出度量 | 月产出 token 数 | 代码行数 / 文档字数 / 完成项目数 | Token 数是 AI 时代的"产出单位"，可直接从平台采集 | Token 产出与价值产出之间的关系未经验证——50x token 可能只是 5x 实际价值 |

## 证据审计

### 实验公平性
- 非实验设计（观察性研究），无随机对照。用户群差异（OpenAI 员工 vs 企业）可能是选择效应：OpenAI 员工本身更懂如何用好 AI
- 数据仅来自 Codex 平台，存在平台选择偏差——无法观测到"放弃 Codex 改用其他工具"的用户

### 最强证据（数字 + 条件）
- **OpenAI 内部 99.8% token 切换**：在"最懂 AI 的人群"中，委托已完全取缔对话——这个数字是"终局状态"的最强信号。条件：OpenAI 员工使用 Codex 有内部培训和支持，外部企业可能需要更长时间
- **研究员 50x 产出增长**：即使假设 80% 的 token 是低质量 AI 生成，仍有 10x 的净增长——任何合理的折扣后仍是惊人的生产力提升。条件：研究员的核心工作（论文/代码）本身适合并行化和委托
- **法务 13x 增长**：证明委托模式不止适用于开发者——非技术知识工作同样受益
- **26.6% Skills 使用率 + 10x 8h+任务增长**：两者结合说明用户不仅在多用 AI，而且在"重新设计工作流"

### 最可疑数字及原因
- **50x token 增长 ≠ 50x 价值增长**：这是论文本身最大的局限，也是最容易被媒体消费的数字。token 中的实际有效信息密度未知。一个研究员生成 50x token 可能只是做了 50 倍量的"草稿级输出"
- **选择偏差**：Codex 用户本身是早期采用者，现有数据无法区分"Agentic AI 提升了生产力"和"高生产力的人更早采用 Agentic AI"（双向因果）
- **OpenAI 员工数据的代表性**：OpenAI 员工的工作内容（AI 研究、模型评估）本身就是最适合 AI 辅助的领域——他们的 50x 增长可能无法推广到制造业、医疗等行业

### 审稿补充
- 需要按行业/职能的分解数据（目前只给了研究员和法务两个职位）
- 需要"任务成功率"而不仅仅是 token 产出——委托给 AI 的任务有多少是"一次性成功"的？失败后的返工成本被忽略了
- 个人用户的 Codex 采用增长曲线值得单独分析（16.5% → ？）——非技术用户的 Agentic 采用是最难但规模最大的市场

### 最小复现实验
在一个 50 人的工程团队中，随机分配一半使用 Codex（委托模式），一半继续使用 ChatGPT（咨询模式），跟踪 4 周的 PR merge 数量、代码 review 轮次、以及开发者自评的"感觉完成了多少工作"。这是本篇论文缺失的因果推断。

## 可复用点

### 何时采用本文框架
- 设计 Agentic 产品时，用"Codex/ChatGPT token 比"作为委托深度的北极星指标
- 向客户展示 Agentic AI 的 ROI 时，引用 50x/13x 作为"上限参考"（强调这是最懂 AI 的人群的数据）
- 产品路线图规划时，用"OpenAI 内部 18-24 个月领先"框架预判市场演进阶段

### 何时谨慎引用
- 向传统行业（制造/医疗/政府）推广时——OpenAI 员工的 50x 在这些领域几乎不可能复现
- 需要"净生产力"数字而非"token 产出"数字时——本文没有控制 token 质量
- 短期 ROI 论证——本文的时间跨度是 6 个月，转型效果可能在 6-12 个月后才显现

### 供应商拷问清单
1. "你的 Agentic 产品的用户中，Codix/ChatGPT token 比是多少？"→ 如果他们没有追踪这个指标，说明产品思维还在咨询模式

## 动手练习

```python
"""
练习：实现"可委托性评分器"（Delegability Scorer）
评估一个任务是否适合委托给 AI
基于两个维度：可重复性 × 可验证性
"""
import numpy as np

class DelegabilityScorer:
    """
    可委托性 = 可重复性 × 可验证性
    - 可重复性：任务是否可以分解为标准化步骤、输入输出是否明确、是否可并行
    - 可验证性：输出是否有客观标准可自动检查、失败模式是否可检测
    每维 0.0-1.0，乘积为最终可委托性评分
    """

    def __init__(self):
        # 可重复性评估的维度与权重
        self.repeatability_dims = {
            "步骤可标准化": 0.35,   # 任务能否分解为固定流程
            "输入输出明确": 0.30,   # 输入格式和期望输出是否清晰定义
            "可并行执行":   0.20,   # 多个子任务能否同时进行
            "领域通用性":   0.15,   # 是否需要高度专业化的领域知识
        }
        # 可验证性评估的维度与权重
        self.verifiability_dims = {
            "客观对错存在": 0.30,   # 是否有客观正确的答案
            "可自动化测试": 0.30,   # 能否用测试用例/脚本自动验证
            "失败可检测":   0.25,   # 错误输出是否容易被发现
            "质量可量化":   0.15,   # 输出质量能否用数值指标衡量
        }

    def score_repeatability(self, ratings: dict) -> float:
        """计算可重复性加权分"""
        score = 0.0
        for dim, weight in self.repeatability_dims.items():
            score += weight * ratings.get(dim, 0.0)
        return min(1.0, max(0.0, score))

    def score_verifiability(self, ratings: dict) -> float:
        """计算可验证性加权分"""
        score = 0.0
        for dim, weight in self.verifiability_dims.items():
            score += weight * ratings.get(dim, 0.0)
        return min(1.0, max(0.0, score))

    def evaluate(self, task_name: str, repeat_ratings: dict, verify_ratings: dict):
        """综合评估一个任务的可委托性"""
        r = self.score_repeatability(repeat_ratings)
        v = self.score_verifiability(verify_ratings)
        delegability = r * v

        # 分级建议
        if delegability >= 0.7:
            advice = "强烈推荐委托 —— 这是 Agentic AI 的杀手场景"
        elif delegability >= 0.4:
            advice = "可以委托但需人工审核 —— 建议人机协作模式"
        elif delegability >= 0.15:
            advice = "部分委托 —— 只委托高可验证性子任务"
        else:
            advice = "不建议委托 —— 人工完成为佳"

        return {
            "task": task_name,
            "repeatability": round(r, 3),
            "verifiability": round(v, 3),
            "delegability": round(delegability, 3),
            "advice": advice
        }

# ===== 评估几个典型任务 =====
scorer = DelegabilityScorer()

tasks = [
    ("代码实现（有测试用例）", {
        "步骤可标准化": 0.9, "输入输出明确": 0.9,
        "可并行执行": 0.7, "领域通用性": 0.8
    }, {
        "客观对错存在": 1.0, "可自动化测试": 1.0,
        "失败可检测": 0.9, "质量可量化": 0.8
    }),
    ("法律合同起草", {
        "步骤可标准化": 0.6, "输入输出明确": 0.5,
        "可并行执行": 0.4, "领域通用性": 0.2
    }, {
        "客观对错存在": 0.3, "可自动化测试": 0.1,
        "失败可检测": 0.5, "质量可量化": 0.2
    }),
    ("创意文案撰写", {
        "步骤可标准化": 0.3, "输入输出明确": 0.4,
        "可并行执行": 0.6, "领域通用性": 0.7
    }, {
        "客观对错存在": 0.1, "可自动化测试": 0.0,
        "失败可检测": 0.3, "质量可量化": 0.2
    }),
    ("数据分析报告", {
        "步骤可标准化": 0.8, "输入输出明确": 0.7,
        "可并行执行": 0.6, "领域通用性": 0.6
    }, {
        "客观对错存在": 0.6, "可自动化测试": 0.5,
        "失败可检测": 0.7, "质量可量化": 0.7
    }),
]

print("=" * 70)
print(f"{'任务':<20s} {'可重复性':>6s} {'可验证性':>6s} {'可委托性':>6s}  建议")
print("-" * 70)
for name, rr, vr in tasks:
    result = scorer.evaluate(name, rr, vr)
    print(f"{result['task']:<20s} {result['repeatability']:>6.3f} "
          f"{result['verifiability']:>6.3f} {result['delegability']:>6.3f}  "
          f"{result['advice']}")

# 关键洞察：代码实现的可委托性最高（0.8+），
# 这解释了为什么"软件开发"是 Agentic AI 的第一个大规模应用场景
# —— Codex 论文的数据在这里得到了理论支撑
```

**L3 应用**：你是一家 200 人 SaaS 公司的 CTO，正在引入 Agentic AI。你的工程团队已在使用 Copilot（代码补全），但还没有委托模式。设计一个 3 个月的转型计划：第一个月做什么（选什么任务先委托）？如何度量成功？你预计会遇到什么阻力？参考本文的数据，你如何向 CEO 论证这个投资？
