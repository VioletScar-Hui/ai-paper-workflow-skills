# Agentic 编程与专业知识的持续回报

📄 **原文 PDF**：[[RAW/113 - Agentic coding and persistent returns to expertise.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：40 万次 Claude Code 使用数据揭示了 Agentic 时代的核心分工——人决定"做什么"（70% 规划决策），AI 决定"怎么做"（80% 执行决策）；更重要的是，**领域专业知识**比编程技能更重要：非程序员在领域内的成功率与软件工程师相当。

```
实际 Claude Code 会话中的决策分配：

用户（人）：  ██████████████░░░░░░  70% 规划决策
              "做什么/构建什么"

Claude（AI）：░░░░░░░░░░████████████  80% 执行决策
              "怎么做/用什么方法"

→ 这不是临时分工，而是一种稳定的人机协作范式
```

---

## 最反直觉的发现：领域专业知识 > 编程技能

```
对比：
  有编程经验的用户（软件工程师）   成功率：X
  无编程经验但有领域知识的用户   成功率：≈X

→ 只要对"要解决什么问题"有深刻理解，
  AI 就能帮你实现，无论你会不会写代码
```

**具体机制**：
- 领域专家带来更清晰的问题定义 → AI 执行更高效
- 专家带来的领域知识越多，每条指令能让 Claude 完成的工作越多
- 专家用户遇到 trouble 时，恢复速率也更高

## 九种工作模式分布

| 模式 | 比例 | 说明 |
|------|------|------|
| 修复现有代码 | 26% | Debug、修 bug |
| 新建功能 | 25% | 从零开始构建 |
| 运行/部署软件 | 17% | 部署、配置、监控 |
| 规划/探索 | 14% | 理解现有系统、规划变更 |
| 数据分析 | ~9% | 数据处理 |
| 测试/编排 | 5% | 测试代码、编排 Agent |
| 非代码输出（文档等）| ~4% | PPT、报告 |

**趋势**：Debug 比例 7 个月减少了近一半 → AI 变强，人类需要处理的低级 Bug 越来越少。

## 核心结论（带时间锚）

1. **"人规划、AI 执行"是 Agentic 时代的稳定分工** 📅 2026.H1
   70% 规划由人做、80% 执行由 AI 做——这不是过渡状态，而是可能持续很长时间的均衡分工模式。

2. **AI 时代最值钱的技能是"知道要解决什么问题"** 📅 2026.H1
   领域专业知识（懂业务、懂问题）比编程技能更能放大 AI 效果——这意味着"会提问题的专家"比"会写代码的工程师"更具 AI 时代竞争优势。

3. **非程序员已可以和程序员一样有效地使用编程 Agent** 📅 2026.H1
   在领域内，成功率与软件工程师相当——编程不再是软件创建的瓶颈技能。

4. **7 个月任务价值增长 25%：AI 在做越来越重要的工作** 📅 2026.H1
   不只是任务量增加，每个任务的商业价值也在增长——AI Agent 在经济中承担的责任权重在提升。

## 论文精读卡片

**一句话**：40 万次 Claude Code 会话数据揭示稳定的人机分工——人做 70% 规划决策、AI 做 80% 执行决策，且无编程背景的领域专家成功率与软件工程师相当，7 个月内任务估算价值增长约 25%。

**问题**：Agentic 编程工具（如 Claude Code）实际如何被使用？谁用得最好？人与 AI 之间如何分工？领域专业知识和编程技能哪个更重要？

**核心方法**：
- 分析约 40 万次 Claude Code 会话（2025.10-2026.04），对每个决策点标注"由用户做出"vs."由 Claude 做出"
- 将任务类型分为 9 类（修复代码/新建功能/运行部署/规划探索/数据分析/测试编排/非代码输出等）
- 对比有/无编程背景用户但有领域知识用户的成功率，评估"专业知识回报"

**关键图/公式**：人机分工图——`用户：70% 规划决策（做什么）；Claude：80% 执行决策（怎么做）`。7 个月内 Debug 任务比例减少约一半，任务价值增长约 25%。

**实验设置**：
- 规模/数据：约 40 万次 Claude Code 会话，时间跨度 2025.10-2026.04（7个月）
- 对比：软件工程师 vs. 无编程背景领域专家的成功率；9 类任务分布随时间变化；任务价值随时间变化

**最强证据**：非程序员（有领域知识）成功率与软件工程师相当——这是"AI 时代领域专业知识取代编程技能"最直接的实证；Debug 比例 7 个月减少近一半，证明 AI 在持续吸收低级任务。

**最弱证据**："成功率"的定义未明确说明（可能是用户自报告或基于会话结束信号），存在主观偏差；25% 价值增长通过与自由职业市场价格对比估算，方法论有争议空间。

**可复用点**："人规划/AI执行"分工框架——产品应优化用户表达"做什么"的界面（任务规划层），而非帮用户做更多"怎么做"（执行层）；这是 Agentic 产品设计的核心方向。
