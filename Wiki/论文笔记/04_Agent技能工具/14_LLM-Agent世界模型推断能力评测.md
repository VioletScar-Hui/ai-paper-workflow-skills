# LLM Agent 能推断隐藏世界模型吗？

📄 **原文 PDF**：[[RAW/14 - Can LLM Agents Infer World Models Evidence from Agentic Automata Learning.pdf]]

## PM 速判（2 分钟）

> **这篇论文给 PM 的一句话**：用"发现隐藏自动机"测试 LLM Agent 的交互式推断能力——结果是当隐藏状态超过 6 个时大多数模型成功率<50%，超过 9 个时无模型超过 25%；与经典算法（L*、TTT）相比，LLM Agent 不仅更慢，还更不可靠。

| 项目 | 评估 |
|------|------|
| **测试任务** | 通过查询发现隐藏确定性有限自动机（DFA）|
| **最强模型** | Gemini 3.1 Pro（在小 DFA 上表现最好） |
| **关键发现** | DFA 状态数=9 时，所有 LLM 成功率<25% |
| **对比基线** | 经典算法（L*、TTT）在相同预算内几乎 100% 成功 |
| **失败模式** | 查询规划/证据整合/假设构建的重复性失败 |
| **成熟度** | 🔬 能力评测研究，指向 Agent 推理局限 |

---

## 核心结论（带时间锚）

1. **LLM Agent 的交互式世界模型推断能力随复杂度急剧下降** 📅 2026
   这不是"不擅长"，而是"接近随机"——9状态DFA对当前最强模型来说几乎无解。

2. **推理模型（thinking）显著强于非推理模型，但仍远落后于经典算法** 📅 2026
   关键失败：查询规划（不能有效探索）+ 证据整合（不能利用历史对话）+ 假设构建（不能形成一致假设）。

## 论文精读卡片

**一句话**：Hebrew University+Google Research 用"发现隐藏确定性有限自动机"任务测试 LLM Agent 的交互式推断能力，发现隐藏状态超过 9 个时所有 LLM 成功率低于 25%，而经典算法（L*、TTT）在相同预算内接近 100% 成功——揭示了 LLM Agent 在系统性探索推理上的根本性缺陷。

**问题**：LLM Agent 需要通过交互来推断环境的隐藏规律（如 API 行为、系统逻辑、黑盒流程），但这种"交互式世界模型推断"能力从未被严格测试。已有的 Agent Benchmark 通常有已知解，而真实环境中 Agent 需要从零发现规则。

**核心方法**：
- 隐藏 DFA 发现任务：给 Agent 一个黑盒自动机，只能提交字符串并观察接受/拒绝，目标是完整推断所有转移规则
- 可控复杂度：通过调节 DFA 状态数（3-15 个）系统性测试不同复杂度下的能力衰减曲线
- 与经典算法对比：L*（主动学习算法）和 TTT（时间高效 Tester）在相同查询预算下的对比基线

**关键图/公式**：能力衰减曲线：DFA 状态数 = 6 时多数模型成功率跌破 50%，状态数 = 9 时所有 LLM 成功率低于 25%，而 L*/TTT 在相同预算内接近 100%——这不是性能差距，是数量级差距，揭示了当前 LLM 的根本架构局限（无法维护跨轮次的一致性假设状态）。

**实验设置**：
- 规模/数据：DFA 状态数从 3 到 15 系统性变化；评测 Gemini 3.1 Pro（最强，小 DFA 表现最好）及多个主流 LLM
- 对比：经典主动学习算法 L* 和 TTT，在相同查询预算内对比

**最强证据**：L*/TTT 在相同预算内接近 100% 成功 vs LLM 在 9 状态 DFA 上低于 25%。这是与形式化正确方法的直接对比，不存在任何数据偏差或评测协议问题，且数量级差距无法用"模型能力还不够强"解释——失败模式（查询规划/证据整合/假设构建）指向了 LLM 的架构性局限。

**最弱证据**：隐藏 DFA 是高度受控的抽象任务，与真实 Agent 面对的"模糊复杂系统"差距较大；论文没有测试通过提供 scratchpad 或结构化记忆能否部分弥补能力差距；仅用成功率衡量，没有分析 LLM 在失败案例中接近正确答案的程度。

**可复用点**：复杂性阈值原则（隐藏状态数 > 6 = LLM Agent 不可靠）可以直接指导产品设计：任何需要 Agent 通过交互推断复杂隐藏逻辑的场景，当系统状态数超过 6 时，应设计人工辅助或分步简化，而不是依赖 LLM 自主推断。

**我能拿它做什么**：
- 在 Agent 产品设计中，避免要求 Agent 通过交互"自主发现"超过 6 个状态的隐藏系统规律

- 在评估 Agent 系统时，用 DFA 发现任务作为"逻辑推断复杂度"的基准测试
