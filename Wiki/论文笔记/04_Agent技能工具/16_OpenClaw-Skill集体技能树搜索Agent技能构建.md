## 核心机制

```
问题：当前 Agent 技能构建的三个局限
  ① 技能碎片化 — 只捕获孤立子任务的局部过程，没有整体结构
  ② 多样性不足 — 单模型生成导致同质化技能，偏向同一推理风格
  ③ 迁移性差 — 一个模型合成的技能在其他骨干 LLM 上表现明显下降

CSTS 的解法：
  1. 复杂任务分解 → 子任务列表
  2. CSN-Gen（集体技能节点生成）：
     - N 个不同模型各自生成每个子任务的候选技能
     - 汇总 → 多样化技能池（消除单模型偏见）
  3. CSN-Assess（集体技能节点评估）：
     - 集体质量评分：多模型独立评估，聚合得分
     - 集体迁移性评分：模型 A 合成的技能是否对模型 B/C/D 也有效？
     - 只保留高质量 + 高迁移性的技能节点
  4. 迭代构建 → "技能树"（每层=子任务，每节点=一个技能）

训练流程：
  技能树 → 生成技能增强训练数据 → SFT 基础训练
  + CSRL：每个子任务同时提供多个候选技能 → 采样轨迹 → GRPO 更新
  → 模型可以自适应选最合适的技能，而非固定在单一技能
```

---

## 核心结论（带时间锚）

1. **集体评估（多模型打分）消除单模型偏见，提升技能泛化** 📅 2026
   迁移性评分机制明确要求：技能不只在生成它的模型上有效，而要在多个骨干 LLM 上有效——这是让技能库真正可复用的关键。

2. **CSRL（多技能 RL）防止模型陷入单一技能局部最优** 📅 2026
   传统 RL 条件化在单一技能上 → 解法空间狭窄；CSRL 同时提供多个相关技能 → 扩大探索空间 → 模型学习适配最优技能。

## 论文精读卡片

**一句话**：CSTS（集体技能树搜索）用多个异构 LLM 共同生成和评估技能节点，引入迁移性评分（跨模型验证）消除单模型偏见，在 OpenClaw 复杂 Agent 基准上比单模型技能方案显著更优，CSRL 进一步通过多技能候选扩大 RL 探索空间。

**问题**：Agent 技能库的三大缺陷：单模型生成导致技能同质化（多样性不足）、技能只捕获局部子任务（结构碎片化）、一个模型合成的技能迁移到其他 LLM 时性能大幅下降（泛化差）。

**核心方法**：
- CSN-Gen：N 个异构模型各自为每个子任务生成候选技能，汇总形成多样化技能池
- CSN-Assess：多模型独立评分聚合质量分 + 交叉验证迁移性分（技能 A 对模型 B/C 是否有效），只保留高质量且高迁移性节点构建技能树
- CSRL：将技能树作为 RL 条件，每步同时提供多个候选技能，用 GRPO 更新策略，避免单技能条件化导致的局部最优

**关键图/公式**：技能树结构图——纵向是任务分解层次，每节点存储通过集体评估和迁移性过滤的技能；核心洞察是"通过迁移性评分，技能不再属于某一模型，而是成为可复用的跨模型资产"。

**实验设置**：
- 规模/数据：OpenClaw 复杂 Agent 任务基准（工具使用/多步推理/动态交互），以及 QwenClawBench（真实用户分布）
- 对比：单模型技能构建方案、无技能的基础 RL 训练

**最强证据**：迁移性评分机制的有效性——技能在非生成模型上验证后，在 OpenClaw 基准上的跨模型泛化显著提升；集体评估消除了单模型偏见，体现在技能多样性指标上。

**最弱证据**：OpenClaw 是定制基准，与 WebArena / GAIA 等通用 Agent 基准的关联未充分验证；CSRL 多技能候选在计算成本上的代价（需要多次采样）未与性能增益做详细的效率分析。

**可复用点**：构建 Agent 技能库时，应对每个技能增加"跨模型验证步骤"——用至少 2-3 个不同底座 LLM 测试技能是否有效，只有在多模型上通过的技能才进入生产技能库，避免单一模型偏见导致的技能库锁定。
