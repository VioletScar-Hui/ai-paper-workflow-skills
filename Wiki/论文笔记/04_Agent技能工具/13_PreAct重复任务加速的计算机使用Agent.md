# PreAct：重复任务越做越快的计算机使用 Agent

📄 **原文 PDF**：[[RAW/13 - PreAct - Computer-Using Agents that Get Faster on Repeated Tasks.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：计算机使用 Agent（点击/输入）每次都从头推理太贵——PreAct 第一次成功后将操作编译为状态机程序，再次触发时**直接回放（0 个 LLM 调用）**，速度快 **8.5-13×**；只有当屏幕状态不符合预期时才退回 LLM。

| 项目 | 评估 |
|------|------|
| **核心机制** | 成功首次 → 编译状态机 → 后续回放（无 LLM） |
| **速度提升** | 8.5-13× 实际运行时间（移动/桌面/Web 三平台） |
| **准确率提升** | 1.75-2.6 个任务/基准（冷→热转换） |
| **关键设计** | 存入前验证门（Verify-before-Store Gate）防止错误程序积累 |
| **成熟度** | 🔧 开源，PineAI，可集成到现有 CUA 框架 |

## 核心机制

```
标准 CUA（计算机使用 Agent）：
  每次：读屏幕 → LLM 推理 → 点击/输入 → 读屏幕 → ...
  重复任务：每次都完整付出 LLM 成本
  
PreAct 的改进：
  首次成功时：
    编译轨迹 → 状态机程序
    每个状态 = 屏幕检查条件
    每个转移 = 实际动作
    
  后续调用时：
    状态机回放：在每一步先验证屏幕状态，确认无误再执行动作
    ✓ 屏幕匹配 → 直接执行（无 LLM）
    ✗ 屏幕不匹配 → 退回完整 CUA，继续后更新状态机
    
  存入前验证门：
    新编译的程序在干净环境中重跑
    独立评估器确认任务完成 → 才存入语料库
    防止"走完所有步骤但任务未完成"的程序进入库
```

## 关键数据

| 平台 | 回放速度 | 成功率提升 |
|------|---------|----------|
| AndroidWorld | 8.5× | +1.75 任务 |
| OSWorld（桌面） | — | +2.6 任务 |
| WebArena（Web） | 13× | 与最强基线持平 |

**验证门的价值**：
- 有验证门：冷→热转换一致提升
- 无验证门：错误程序积累 → 热性能比冷更差

---

## 核心结论（带时间锚）

1. **验证前存储（Verify-before-Store）是程序缓存系统的必要条件** 📅 2026
   "成功走完所有步骤"≠"任务完成"——没有验证门，错误程序会污染缓存，越用越差。

2. **重复任务的 LLM 成本接近零是可实现的** 📅 2026
   企业场景（每天重复数百次同类操作）中，PreAct 类方案可以将长尾重复任务的 LLM 成本压缩 90%+。

3. **检索方式不重要；验证方式很重要** 📅 2026
   LLM 选择器 vs 嵌入检索器（100% vs 75.6% 检索准确率）对最终结果几乎无影响——真正重要的是程序本身是否经过验证。

## 论文精读卡片

**一句话**：Pine AI 的 PreAct 首次证明计算机使用 Agent 在首次成功后可将操作编译为状态机程序并完全零 LLM 调用回放，实现 8.5-13x 速度提升；关键创新是存入前验证门——没有验证门时错误程序积累导致热性能反而比冷更差。

**问题**：计算机使用 Agent（GUI 点击/输入）每次都从头 LLM 推理，成本高且延迟大；但直接缓存执行轨迹会积累错误程序（"执行完所有步骤"≠"任务完成"），导致缓存随时间变坏而非变好。

**核心方法**：
- 轨迹→状态机编译：首次成功后，将执行轨迹编译为状态机程序（每状态 = 屏幕检查条件，每转移 = 实际动作），屏幕状态匹配则直接执行无需 LLM
- 存入前验证门（Verify-before-Store Gate）：新编译程序在干净环境中重跑，独立评估器确认任务完成后才存入语料库
- 退化机制：屏幕状态不匹配时退回完整 CUA，继续执行后更新状态机，实现持续进化

**关键图/公式**：有/无验证门的对比是全文最强证据：无验证门时热性能比冷性能更差（错误程序污染缓存）；有验证门时冷→热转换一致提升。这直接证明验证门是程序缓存系统的必要条件，而非优化项。

**实验设置**：
- 规模/数据：AndroidWorld（移动端）、OSWorld（桌面端）、WebArena（Web 端）三平台；8.5-13x 实际运行时间提升；冷→热转换 +1.75 到 +2.6 个任务
- 对比：Muscle-Mem（记录回放系统基线）、LLM 选择器 vs 嵌入检索器（检索方式对比）

**最强证据**：三平台跨域验证（移动/桌面/Web）均显示 8.5-13x 速度提升，且准确率同步提升；检索方式（LLM 选择器 100% vs 嵌入检索器 75.6% 检索准确率）对最终结果几乎无影响，证明验证质量而非检索精度是关键——这是反直觉的重要结论。

**最弱证据**：实验场景以重复性任务为主（相同/相似的 GUI 操作），对需要大量上下文变化的长尾任务效果未测；状态机程序随 UI 版本更新的失效率未量化；编译成本（+162-217% of solve time）在高频场景下是否值得的分析基于单次任务成本，未给出不同重复频率的 ROI 曲线。

**可复用点**：程序缓存的 Verify-before-Store 原则可推广到所有 Agent 代码生成场景：任何"生成程序然后缓存"的系统，必须在缓存前用独立评估器验证程序是否真正完成任务，不能依赖"执行完成"作为代理指标。
