# Autodata：合成数据智能体 — 弱强差距驱动的数据质量飞轮

📄 **原文 PDF**：[[RAW/03 - Autodata - An Agentic Data Scientist to Create High-Quality Synthetic Data.pdf]]

## PM 速判
> 一句话：Meta FAIR用多Agent迭代循环自动生成训练数据，弱-强模型Gap从0.019提升到0.314（+16.5倍），同等RL训练下4B模型成绩提升26%（0.500→0.632）。

## 双层费曼
> **给CEO**：训练AI需要高质量题目，就像学生需要好习题。以前靠人出题，又慢又贵。Autodata让AI自己出题、自己验证——出的题刚好卡在"强AI会做、弱AI不会"的难度边界上，这种题训练效果最好。结果是：用AI出的题训练，弱AI成绩提升26%，而成本全在推理算力上，不需要人工标注。
>
> **给工程师**：Autodata通过Challenger（出题Agent）+ 弱/强Solver（目标模型和验证模型）+ Judge（评判Agent）+ Orchestrator（主编排器）四角色闭环，用弱-强模型得分差（Gap）作为数据质量筛选信号。只有强模型正确、弱模型错误的样本才被接受，确保每条数据都在弱模型的能力边界上——这比绝对分数更能衡量数据的"训练价值"。平均每题需6.59轮迭代才能生成一个被接受样本，80%的拒绝原因是题目太简单（弱模型也能做对）。

## 问题域定位
- **回应什么根本约束**：合成数据的核心瓶颈不是"生成数据"，而是"生成有效难度的数据"。传统Self-Instruct和无辅助的CoT生成，弱模型得分0.677、强模型得分0.696，Gap仅0.019——两个模型几乎一样，意味着这些数据对训练没有区分度。垂直领域（法律/医学/科研）标注数据稀缺，但更稀缺的是精准校准难度的数据。
- **之前卡在哪**：缺乏自动化的难度校准机制。人工出题可以控制难度但不可扩展；LLM直接生成题目无法感知目标模型的真实能力边界；用绝对分数筛选（如只保留强模型得分>0.8的题）会把大量"弱模型也会"的简单题也收进来。
- **开启/关闭了哪条路线**：开启了"推理算力换数据质量"的路线——推理时多投入Agent循环，直接换来更高训练价值的数据。关闭了"单纯堆数据量"的路线——实验证明Agentic数据的训练效果远超同等数量的CoT数据，说明数据质量比数量更重要。同时也暗示：未来训练数据的生产可能从"人工标注+清洗"转向"Agent闭环自举"，人工角色从生产者变为审核者。

## 核心机制（ASCII图必备）
```
                    ┌──────────────────────────────────────────────────────────┐
                    │                    Orchestrator（主编排器）                  │
                    │  分析失败原因 → 更新策略 → 决定重试/接受                      │
                    └──────┬───────────────────────────────────┬───────────────┘
                           │  发送指令 + 历史反馈                │  接受/拒绝 + 改进建议
                           ▼                                   ▲
                    ┌──────────────┐                    ┌──────────────┐
                    │  Challenger  │                    │    Judge     │
                    │  （出题Agent） │                    │  （评判Agent） │
                    │              │                    │              │
                    │ 输出：       │                    │ 检查：       │
                    │ [Context,    │                    │ - 答案正确性  │
                    │  Question,   │                    │ - 弱强Gap    │
                    │  Ref Answer, │                    │ - Rubric匹配  │
                    │  Rubric]     │                    │              │
                    └──────┬───────┘                    └──────▲───────┘
                           │                                   │
                           │  同一道题                           │ Gap = Strong_score
                           ▼                                   │   — Weak_score
              ┌────────────────────────────┐                    │
              │         Solver 层          │                    │
              │  ┌──────────────────────┐  │                    │
              │  │  Weak Solver         │  │  多次采样            │
              │  │  （目标训练模型）      │──┼────────────────────┤
              │  │  如 Qwen3.5-4B       │  │  降低方差            │
              │  └──────────────────────┘  │                    │
              │  ┌──────────────────────┐  │                    │
              │  │  Strong Solver       │──┼────────────────────┘
              │  │  （验证模型）          │  │
              │  │  如 Qwen3.5-397B     │  │
              │  └──────────────────────┘  │
              └────────────────────────────┘

   筛选逻辑：
   ┌─────────────────────────────────────────────────────────────┐
   │  强模型对 ✓  弱模型对 ✓  →  Gap≈0  →  REJECT（太简单）      │
   │  强模型对 ✓  弱模型错 ✗  →  Gap大  →  ACCEPT（黄金数据）    │
   │  强模型错 ✗  弱模型错 ✗  →  题无效  →  REJECT + 反馈修正    │
   │  强模型错 ✗  弱模型对 ✓  →  异常    →  REJECT（标注问题）    │
   └─────────────────────────────────────────────────────────────┘

   统计：平均 6.59 轮 / 被接受样本  |  80%拒因太简单  |  13%强模型也不会
```

## 设计决策解剖
| 决策点 | 选择 | 被放弃方案 | 为什么 | 何时失效 |
|--------|------|-----------|--------|---------|
| 数据筛选标准 | 弱-强Gap（差值） | 绝对分数阈值（如强模型分>0.8） | 绝对分数无法区分"两个模型都会"和"只有强模型会"。Gap天然反映数据对弱模型的训练价值——Gap越大，弱模型的学习空间越大 | 当弱模型已很强（如弱模型也是70B+级别），Gap天然小，此时可能需要引入更弱的模型或改用技能分类覆盖度作为筛选标准 |
| Agent架构 | 多Agent（Challenger+Judge+Orchestrator分离） | 单模型自检（同一LLM既出题又评分） | 单模型自检有确认偏差——出题模型倾向于给自己打高分或无法发现自己的盲区。角色分离让每个Agent只需专注一个子任务，Judge可以客观评判Challenger的产出 | 当模型能力足够强（如未来的GPT-5级别），单模型可能具备充分的自我批判能力；或者当延迟/成本约束极严格，无法承受多轮多模型调用 |
| 失败样本处理 | 保留失败反馈→回传Challenger修正 | 直接丢弃失败样本 | 失败样本包含难度校准信号——"太简单"和"无效"两类失败的反馈能教会Challenger如何避开无价值区域。保留反馈让Challenger形成学习闭环，6.59轮中大部分是修正过程 | 当Challenger本身已达到天花板（无论怎么反馈都无法改进），保留反馈的边际收益归零；或者当任务领域太窄，失败模式高度重复，反馈无法带来多样性 |
| 弱模型选取 | 用目标训练模型本身 | 用一个独立的小模型作为弱求解器 | 目标模型作答直接反映其真实能力边界，Gap信号与训练目标完全对齐。用独立小模型无法保证筛选出的数据对目标模型同样有效 | 当目标模型尚不存在（如预训练前数据筛选），只能用已有模型替代，此时Gap信号是近似的，需事后验证迁移效果 |

## 成本与量级
- **单样本生成成本**：平均6.59轮 × 每轮4次模型调用（Challenger + Weak Solver × N次采样 + Strong Solver × M次采样 + Judge），以CS研究任务为例，弱模型4B推理成本低，强模型397B单次推理约为主成本项。论文未公开精确token/美元数字，但可估算：生成1000条Agentic数据约需4B推理约26000次 + 397B推理约26000次（按4次采样/轮计），强模型推理成本占大头。
- **训练成本**：4B模型RL训练与常规微调相当，数据量从数千到数万条级别。训练本身不额外增加成本。
- **最小可行配置**：弱模型=目标微调模型（如Qwen2.5-7B），强模型=同家族最大模型或GPT-4o API（仅作验证不训练），Challenger/Judge可共用强模型。单任务生成200-500条数据，预期5-8轮/条。两卡H100可跑通全流程（4B推理+7B推理，强模型用API）。
- **性价比拐点**：当人工标注成本 > 强模型推理成本 × 6.59轮 × 样本量时，Agentic方案经济上占优。对于垂直领域（法律/医学），单条人工标注成本可达$5-50，Agentic方案生成同等质量数据的推理成本约为$0.5-2/条（估算），优势明显。

## 证据审计
- **实验公平性**：对比公平——CoT Self-Instruct和Agentic方法使用相同的弱/强模型对（Qwen3.5-4B/397B）和相同的RL训练流程。但CoT方法的"题目生成"没有迭代优化环节，Agentic方法多投入了推理算力——这恰是论文要论证的tradeoff。训练评测在同一Agentic测试集上进行，测试集由Agentic方法生成，可能对Agentic训练有利（但论文也报告了CoT数据训练后在Agentic测试集的结果0.500，作为参照）。
- **最强证据**：同等RL训练量下，Agentic数据训练的4B模型在Agentic测试集得分0.632 vs CoT数据训练的0.500（+26.4%，p值<0.01）。且弱-强Gap从0.019→0.314（16.5倍），两个指标交叉印证：Gap大说明数据质量高，端到端训练提升说明数据训练价值高。
- **最可疑数字**：6.59轮/样本是平均值，论文未报告分布（中位数、方差）。如果分布右偏（少量极端困难题需要20+轮），实际工程中的P99延迟可能远超均值。另外，弱/强模型对仅测试了4B/397B，未做消融（如4B/8B、4B/70B、8B/397B），无法判断Gap对模型对选择的敏感性。
- **审稿补充问题**：(1)如果弱模型被Agentic数据训练后变强，重新跑Autodata流程，Gap是否仍然显著？即数据飞轮能否持续多轮？(2)不同领域（CS/法律/数学）的Gap-训练收益曲线是否形状一致？是否存在最优Gap区间？(3)Challenger和Judge用不同模型（如Claude出题、GPT评判）的跨模型鲁棒性如何？
- **最小复现设计**（2个本地模型）：
  1. 弱模型=Qwen2.5-7B-Instruct（vLLM部署，单卡）
  2. 强模型=Qwen2.5-72B-Instruct（或用GPT-4o API替代）
  3. 选一个中文垂直领域（如中国法律条文问答），准备10篇grounding文档
  4. Challenger/Judge复用强模型，Orchestrator用固定规则（Gap<0.15→要求更难，强模型分<0.7→要求更准确）
  5. 目标生成100条数据，预期500-800轮API调用，成本约$20-50
  6. 用生成数据微调7B模型，与原版对比法律问答准确率

## 可复用点
- **何时采用**：(1)垂直领域微调且缺乏人工标注预算；(2)目标模型已有基础能力但需要针对性拔高（Gap筛选天然适配"补短板"场景）；(3)有可用的强验证模型（开源大模型或商业API），推理预算充足；(4)任务有客观或半客观的评判标准（Rubric/答案匹配/代码执行）。
- **何时规避**：(1)目标模型能力极弱（如随机水平），此时几乎所有题Gap都大，筛选失效；(2)任务纯主观（如创意写作），Judge无法可靠评估；(3)成本极度敏感且数据量要求巨大（百万级）；(4)已有大量高质量人工标注数据，Agentic数据的边际收益递减。
- **供应商拷问清单**：
  1. "你们的弱-强模型对是怎么选的？Gap阈值是多少？这个阈值和最终训练收益的关系你们验证过吗？"
  2. "平均6.59轮/样本——你们的P99延迟和单样本成本是多少？如果目标生成10万条，总时间/成本预估？"
  3. "当目标模型经过Agentic数据训练后能力提升，原来的Challenger参数和Gap阈值是否需要重新校准？你们有飞轮的后续轮次数据吗？"

## 动手练习
**练习目标**：实现弱-强差距筛选器——生成题目让两个模型作答，筛选强对弱错的题

**代码**（逐行中文注释）：
```python
import numpy as np

# ========== 0. 设定随机种子 ==========
np.random.seed(42)

# ========== 1. 模拟题目生成 ==========
# 假设我们有1000道候选题目，每道题有两个属性：
#   difficulty ∈ [0, 1]：题目难度（1=极难）
#   quality ∈ [0, 1]：题目质量（1=完美无歧义）
N = 1000
difficulty = np.random.beta(2, 5, N)      # 偏简单的难度分布（大多数题偏容易）
quality = np.random.beta(8, 2, N)         # 大多数题质量尚可

# ========== 2. 模拟弱模型和强模型作答 ==========
# 弱模型准确率：高质量简单题也未必全对，难题基本全错
weak_base = 0.45  # 基础准确率
# 弱模型对每道题正确的概率 = base * quality * (1 - difficulty * 0.9)
weak_prob = weak_base * quality * (1 - difficulty * 0.9)
weak_prob = np.clip(weak_prob, 0.05, 0.95)
weak_correct = np.random.binomial(1, weak_prob)  # 1=对, 0=错

# 强模型准确率：高质量题几乎全对，低质量难题可能错
strong_base = 0.85  # 基础准确率
# 强模型正确的概率 = base + quality增益 - difficulty惩罚
strong_prob = strong_base + 0.1 * quality - 0.3 * difficulty
strong_prob = np.clip(strong_prob, 0.1, 0.99)
strong_correct = np.random.binomial(1, strong_prob)

# ========== 3. 计算原始Gap ==========
original_weak_acc = weak_correct.mean()
original_strong_acc = strong_correct.mean()
original_gap = original_strong_acc - original_weak_acc
print(f"=== 筛选前 ===")
print(f"弱模型准确率: {original_weak_acc:.4f} ({int(original_weak_acc*N)}/{N})")
print(f"强模型准确率: {original_strong_acc:.4f} ({int(original_strong_acc*N)}/{N})")
print(f"弱-强 Gap:     {original_gap:.4f}")

# ========== 4. 弱强差距筛选 ==========
# 规则：只保留"强对 AND 弱错"的题目（黄金数据）
gold_mask = (strong_correct == 1) & (weak_correct == 0)
# 额外筛掉极低质量的题（强模型也大概率错的）
low_quality_mask = strong_prob < 0.3
# 最终接受 = 黄金数据 AND NOT 低质量
accepted = gold_mask & (~low_quality_mask)

# 分类统计
n_gold = gold_mask.sum()
n_accepted = accepted.sum()
n_too_easy = (strong_correct == 1) & (weak_correct == 1)  # 两个都会
n_invalid = (strong_correct == 0) & (weak_correct == 0)   # 两个都不会
n_anomaly = (strong_correct == 0) & (weak_correct == 1)   # 强错弱对（异常）

print(f"\n=== 筛选结果 ===")
print(f"黄金数据（强对弱错）: {n_gold} ({n_gold/N*100:.1f}%)")
print(f"最终接受（去低质量后）: {n_accepted} ({n_accepted/N*100:.1f}%)")
print(f"拒绝-太简单（都会）: {n_too_easy.sum()} ({n_too_easy.sum()/N*100:.1f}%)")
print(f"拒绝-无效（都不会）: {n_invalid.sum()} ({n_invalid.sum()/N*100:.1f}%)")
print(f"拒绝-异常（强错弱对）: {n_anomaly.sum()} ({n_anomaly.sum()/N*100:.1f}%)")

# ========== 5. 筛选后统计 ==========
accepted_weak_acc = weak_correct[accepted].mean() if n_accepted > 0 else 0
accepted_strong_acc = strong_correct[accepted].mean() if n_accepted > 0 else 0
accepted_gap = accepted_strong_acc - accepted_weak_acc

print(f"\n=== 筛选后（仅被接受样本） ===")
print(f"弱模型准确率: {accepted_weak_acc:.4f}")
print(f"强模型准确率: {accepted_strong_acc:.4f}")
print(f"弱-强 Gap:     {accepted_gap:.4f}")
print(f"Gap提升倍数:   {accepted_gap / original_gap:.1f}x" if original_gap > 0 else "Gap提升: N/A（原始Gap为0）")

# ========== 6. 核心理念输出 ==========
print(f"\n=== 关键洞察 ===")
print(f"筛选前 Gap={original_gap:.3f}——弱强模型几乎无差别，数据无训练价值")
print(f"筛选后 Gap={accepted_gap:.3f}——被接受的数据恰好卡在弱模型能力边界")
print(f"这就是Autodata的核心思想：不用绝对分数，用相对差距筛选训练数据")
```

**期望输出**：筛选前Gap约0.05-0.15，筛选后Gap接近1.0（因为只保留了强对弱错的样本）。这直观展示了"弱-强Gap筛选"的效果：从一堆大部分无区分度的数据中，精准挑出有训练价值的子集。

## 自测三层
**L1 复述**：
- Q: Autodata的四个Agent角色分别是什么？各自负责什么？
- A: Challenger（出题，输出Context+Question+Rubric）、Weak Solver（目标训练模型作答）、Strong Solver（验证模型作答）、Judge（评估答案+计算Gap+给出接受/拒绝/改进建议）、Orchestrator（分析失败原因，更新Challenger策略，决定重试或接受）。平均6.59轮生成一个被接受样本。
- Q: 被拒绝的样本中，最主要的原因是什么？占比多少？
- A: 80%因为"太简单"——弱模型也能做对，Gap≈0，对训练无价值。13%因为强模型也不会，题目无效。剩余为标注异常等其他原因。

**L2 解释**：
- Q: 为什么弱-强Gap比绝对分数更适合作为合成数据的质量指标？
- A: 绝对分数（如"强模型得分>0.8"）筛选的是"强模型能做的题"，但无法区分弱模型是否也能做。如果弱模型准确率也是0.8，那这批数据对训练毫无增量。Gap直接衡量"弱模型的学习空间"——只有强模型会做而弱模型不会的题，才包含弱模型尚未掌握的知识或推理模式。Gap本质上是数据对目标模型的"信息增量"的代理指标。
- Q: 元优化（外循环）优化的是什么？与内循环的区别是什么？
- A: 内循环优化的是训练数据质量（通过Agentic迭代提升Gap），最终训练出更好的弱模型。外循环优化的是Agent本身（Challenger/Judge/Orchestrator）——用RL让数据生成Agent变得更擅长出题和评判，从而让下一轮内循环产生更高质量的数据。两者形成双飞轮：更好的Agent→更好的数据→更好的模型→反过来可以当更强的Judge→更好的Agent。

**L3 应用**：
- Q: 你的团队要微调一个客服意图识别模型（7B），标注数据只有500条。设计一个基于Autodata思路的数据扩充方案。
- A: (1)强模型选GPT-4o或内部72B模型作为验证器；(2)Challenger用强模型+500条已有标注作为grounding context，生成候选意图识别样本（用户query+正确意图+干扰项）；(3)弱模型=当前7B模型，分别作答；(4)Judge用规则+LLM混合评判（意图分类有正确答案，可直接比对）；(5)筛选强对弱错的样本，目标500→2000条；(6)混合原始500条+Agentic1500条微调；(7)关键：用业务指标（意图识别准确率、转人工率）而非仅用测试集分数衡量收益。
