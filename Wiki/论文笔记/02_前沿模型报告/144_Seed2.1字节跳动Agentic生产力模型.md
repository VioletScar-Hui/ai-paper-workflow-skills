# Seed2.1：字节跳动 Agentic 生产力旗舰模型

📄 **原文 PDF**：[[RAW/144 - Seed2.1 Model Card - Agentic Intelligence for Productivity.pdf]]

## PM 速判（30秒）
> 字节跳动 Seed 团队发布的旗舰生产力模型，有 Turbo（高效）和 Pro（强推理）两个变体，核心差异化是 **Agentic 能力**——将规划、工具调用、代码执行、GUI 操控、多模态感知统一在单一 policy 下。在 SWE-bench、AIME、MCP-Atlas 等关键基准上达到或超越 GPT-5.5 和 Claude 4.7 Opus。PM 须知：这是 ByteDance 的豆包/Trae 等产品的技术底座，在工具使用和计算机操控类任务上尤其突出（MCP-Atlas 83.8 最高分），但 Model Card 形式导致部分数字复现有难度。

## 双层费曼 🗣️
> **给 CEO 的一句话**：字节跳动最新的大模型，不仅在写代码和做数学题上顶级，更擅长"串联使用各种工具完成任务"——比如让它自己规划、写代码、测试、部署一条龙。在真实开发者的匿名盲测中，程序员更喜欢 Seed2.1 的代码质量而不是 Claude Opus 4.6。这是一款可以当"数字员工"用的模型。
>
> **给工程师的一段话**：Seed2.1 有两个变体——Turbo（高吞吐、高效）和 Pro（强推理、复杂 Agent 任务）。核心方法论是以"产品可用性"而非"基准分数"为驱动：Coding 能力通过 Claude Code / Trae 等产品的大规模 dogfooding 迭代优化（Turbo 在 178 项对比中 56.2% win rate 胜过 GLM 5.1；Pro 在 230 项对比中 59.1% win rate 胜过 Opus 4.6）。Agent 能力覆盖六个维度：General Agent（Agent Startup Bench 68.8 最佳）、Daily Life（MCP-Atlas 83.8 最佳）、Multimodal Agent（Claw-Eval Pass^3 领先）、Computer-Use Agent（OSWorld 78.2；Generalist CUA 设置比纯 GUI 模式成功率 +6.2pp 且步骤 -18.7%）、Production Coding（SWE-bench 等）、Long-context（128K+ 原生支持）。特别值得一提的是 Generalist CUA 模式——模型同时具备 GUI 操控 + Bash 命令 + 代码执行能力，比纯 GUI 代理成功率更高、步骤更少。

## 问题域定位 🎯
- **根本约束**：真实企业生产力需要模型完成**多步复杂任务**（代码编写→调试→执行→反馈循环），而非仅单次问答。单一能力（如纯推理或纯代码）不足以支撑真实产品级 Agent。
- **之前的方案卡在哪**：多数模型要么专注于单轮能力（MMLU、HumanEval）要么在 Agent 评测上覆盖浅（仅 tool use 或仅代码）。没有统一度量标准来衡量"真实产品中的端到端生产力"。评测也滞后于产品——模型强不等于产品好用。
- **开启/关闭的技术路线**：开启了"产品驱动模型开发"的范式——用 dogfooding 和真实用户反馈而非纯 benchmark 驱动迭代。同时证明了 Generalist CUA（GUI+CLI+代码混合）比纯 GUI 或纯 CLI 代理更优，为下一代 Agent 架构指明方向。

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 产品驱动开发 | 以 Claude Code / Trae 内部的 dogfooding 和众包评估为主要迭代信号 | 纯 benchmark 驱动（仅关注 SWE-bench/AIME 分数） | Benchmark 与真实用户满意度脱节。Seed2.1 在 Claude Code 上赢 Opus 4.6 的 59.1% win rate 比任何 benchmark 数字都更直接反映产品价值 | 众包评估样本偏差（仅 Coding Plan 用户）；benchmark 分数仍是选型时的硬指标 |
| 两个变体策略 | Turbo（高效）和 Pro（强推理） | 单一模型或按场景细分多个模型 | Turbo 满足产品场景（豆包、Trae 等需要低延迟高吞吐），Pro 满足复杂 Agent 任务；两者共享基础训练但后训练分开优化 | 两个模型的维护成本 ×2；Turbo 在某些复杂 Agent 场景能力不足，用户可能在同一个产品中需要动态切换 |
| Generalist CUA | 统一 policy：GUI + CLI + 代码执行同时可用 | 纯 GUI agent 或纯 CLI agent | 实验证明 Generalist 设置下成功率 +6.2pp、步骤 -18.7%。一条命令替换一串脆弱的 GUI 点击 | GUI 沙箱的安全风险扩大（CLI 可以执行任意命令）；混合策略的调试和 log 追踪更复杂 |

## 成本与量级 💰
- **训练成本量级**：未公开。从 Seed 2.0 到 Seed2.1 推测需数万 GPU·天（H100），包含大规模预训练、Agentic SFT 数据构造、代码执行反馈 RLHF。
- **推理成本 vs 基线**：未公开具体数字。Turbo 变体明确为高吞吐优化，Pro 变体对标 GPT-5.5 级别成本。在相同 API 定价下（通过火山引擎），Seed 模型的定价与竞品相比有竞争力。
- **我的产品要用**：最小可行配置——通过火山引擎 API 调用 Seed2.1-Turbo 用于通用 Agent 场景（成本优先），Seed2.1-Pro 用于复杂多步任务（质量优先）。对延迟敏感的实时场景推荐 Turbo。

## 证据审计 🔬
- **实验设计公平吗？** 总体优秀。Model Card 形式透明地列出了所有 benchmark 分数、对比模型、设置细节。每个 benchmark 都标注了来源论文。同行众包评估采用匿名盲测。但缺陷是部分 Seed 自建 benchmark（xDailyBench、SeedClawBench）的外部可比性有限，且部分 state-of-the-art 结果来自 "Seed-developed benchmark"。
- **最强证据**：Generalist CUA 对比实验（GUI-only vs Generalist）设计干净，同一模型两种配置，结果一致（两个变体都显示 Generalist 更优）。MCP-Atlas 83.8 最高分来自公开 benchmark，具可比性。Trae 盲测 48.5% win rate vs Opus 4.7（近持平）令人信服。
- **最可疑的数字**：Workspace Bench 的 "100-task OpenClaw setting" 对比——Seed2.1 Turbo 54.7 接近 Claude 4.7 Opus 55.1，但 Claude Code 几乎专精于软件工程而 Seed2.1 是一个多面手模型，此处可能有 prompt/harness tuning 差异。此外 "Self-evolving model development" 的表述多于数据支撑。
- **最小复现实验**：在 MCP-Atlas 公开子集上调用 Seed2.1 API vs Claude API，比较 Pass@1 分数。代理指标：任务完成率。预算：约 100 美元 API 费用（50 个任务，每个任务平均 20 轮交互）。

## 可复用点（PM 决策）
- **何时采用**：需要 Agent 能力强的模型作为产品底座（特别是工具调用和代码执行密集型场景）；在字节跳动生态内开发（豆包、火山引擎集成度高）；需要平衡多维度能力（编程+数学+Agent+多模态）的通用模型。
- **何时规避**：对安全合规敏感且不能使用字节跳动 API 的场景；需要完全开源可控（Seed2.1 未开源，仅可通过 API 调用）；小团队场景下 Turbovs Pro 的选择增加了决策成本。

## 动手练习 💻（15-45分钟）
练习目标：调用 API 对比 Seed2.1 风格模型在编程 task 上的 plan-then-code 表现（模拟 Agent 的 decomposition → coding → verification 流程）。如果 API 不可用，用 mock 模拟，重点是结构而非真实 API 调用。

```python
import json
import time
from typing import List, Dict, Optional
from dataclasses import dataclass
import random

# ============================================================
# 模拟 Seed2.1 风格的 plan-then-code 编程 Agent
# 对比两种策略：
#   Strategy A: 一步到位（直接生成代码，不分解）
#   Strategy B: plan-then-code（先分解再逐子任务实现）
# ============================================================

@dataclass
class ProgrammingTask:
    """编程任务定义"""
    description: str
    language: str = "python"
    complexity: str = "medium"  # easy, medium, hard
    
    def to_prompt(self) -> str:
        return f"用 {self.language} 实现：{self.description}"

class MockModelAPI:
    """模拟大模型 API 调用。
    
    在真实场景中替换为 Seed2.1 API / Claude API 调用。
    模拟假设：
    - 简单任务两种策略成功率接近
    - 复杂任务 plan-then-code 更好
    """
    
    def __init__(self, model_name: str = "mock-seed2.1"):
        self.model_name = model_name
        self.call_count = 0
        self.total_tokens = 0
    
    def call(self, system_prompt: str, user_prompt: str,
             max_tokens: int = 1024) -> Dict:
        """模拟 LLM 调用"""
        self.call_count += 1
        self.total_tokens += len(system_prompt + user_prompt) // 4 + max_tokens
        
        time.sleep(0.02)  # 模拟网络延迟
        
        # 模拟成功/失败逻辑
        task_complexity = "hard" if "hard" in user_prompt.lower() else "medium"
        has_decomposition = "步骤" in system_prompt or "step" in system_prompt.lower()
        
        if task_complexity == "hard":
            success = random.random() < (0.7 if has_decomposition else 0.4)
        else:
            success = random.random() < (0.9 if has_decomposition else 0.8)
        
        if success:
            return {
                "status": "success",
                "code": f"# {self.model_name} 生成代码\n"
                        f"# 复杂任务完成: {has_decomposition}\n"
                        f"def solution():\n    pass\n",
                "completion_tokens": 256,
            }
        else:
            return {
                "status": "failed",
                "error": "Generated code has bug",
                "code": "",
                "completion_tokens": 128,
            }

def strategy_direct(task: ProgrammingTask, model: MockModelAPI) -> Dict:
    """Strategy A：一步到位，直接生成"""
    print(f"\n  [策略A] 直接生成代码...")
    
    system = "你是一个资深程序员。根据用户需求直接生成可运行代码。"
    result = model.call(system, task.to_prompt(), max_tokens=2048)
    
    return {
        "strategy": "direct",
        "task": task.description[:30],
        "success": result["status"] == "success",
        "calls": model.call_count,
        "tokens": model.total_tokens,
        **({"error": result["error"]} if result["status"] == "failed" else {}),
    }

def strategy_plan_then_code(task: ProgrammingTask, model: MockModelAPI) -> Dict:
    """Strategy B：Seed2.1 风格的 plan-then-code
    
    流程：
    1. Task Decomposition（分解为子任务）
    2. Code Generation（逐子任务生成代码）
    3. Code Review & Fix（自检修复）
    """
    print(f"\n  [策略B] Plan-then-Code（Seed2.1 风格）...")
    
    start_calls = model.call_count
    start_tokens = model.total_tokens
    
    # Step 1: 任务分解
    print("    → Step 1: 任务分解")
    decompose_prompt = "请将以下编程任务分解为具体的实现步骤（每个步骤一个函数）:\n\n"
    plan_result = model.call(
        "你是软件架构师。将任务分解为不超过 5 个步骤，每步一个明确交付物。",
        decompose_prompt + task.to_prompt(),
        max_tokens=1024,
    )
    
    if plan_result["status"] != "success":
        return {
            "strategy": "plan_then_code",
            "task": task.description[:30],
            "success": False,
            "failed_at": "decomposition",
            "calls": model.call_count - start_calls,
            "tokens": model.total_tokens - start_tokens,
        }
    
    # 模拟分解出 3-4 个子任务
    num_subtasks = random.randint(3, 4)
    print(f"    → 分解为 {num_subtasks} 个子任务")
    
    # Step 2: 逐子任务实现
    for i in range(num_subtasks):
        print(f"    → Step 2.{i+1}: 实现子任务 {i+1}/{num_subtasks}")
        code_result = model.call(
            f"实现第 {i+1}/{num_subtasks} 步。确保代码完整可运行。", 
            f"子任务 {i+1}: 实现步骤 {i+1} 的代码",
            max_tokens=2048,
        )
        if code_result["status"] != "success":
            return {
                "strategy": "plan_then_code",
                "task": task.description[:30],
                "success": False,
                "failed_at": f"subtask_{i+1}",
                "calls": model.call_count - start_calls,
                "tokens": model.total_tokens - start_tokens,
            }
    
    # Step 3: 代码审查（Seed2.1 设计要点：自检修复）
    print(f"    → Step 3: 代码审查和集成")
    review_result = model.call(
        "审查上述代码是否有问题。检查：边界条件、类型安全、性能。",
        "整合所有子任务代码并审查",
        max_tokens=1024,
    )
    
    return {
        "strategy": "plan_then_code",
        "task": task.description[:30],
        "success": review_result["status"] == "success",
        "subtasks": num_subtasks,
        "calls": model.call_count - start_calls,
        "tokens": model.total_tokens - start_tokens,
        "review_passed": review_result["status"] == "success",
    }

def run_comparison(tasks: List[ProgrammingTask], trials: int = 5):
    """对比两种策略在多个任务上的表现"""
    
    models = {
        "Strategy-A (Direct)": MockModelAPI("direct"),
        "Strategy-B (Plan-Code)": MockModelAPI("plan-code"),
    }
    
    results = {name: [] for name in models}
    
    for task in tasks:
        print(f"\n{'='*50}")
        print(f"任务: {task.description} [{task.complexity}]")
        
        for _ in range(trials):
            # Strategy A
            model_a = MockModelAPI("direct")
            r1 = strategy_direct(task, model_a)
            results["Strategy-A (Direct)"].append(r1)
            
            # Strategy B
            model_b = MockModelAPI("plan-code")
            r2 = strategy_plan_then_code(task, model_b)
            results["Strategy-B (Plan-Code)"].append(r2)
    
    # 汇总
    print(f"\n{'='*50}")
    print(f"对比结果（每个任务 {trials} 次）")
    print(f"{'='*50}")
    
    for name, res_list in results.items():
        successes = sum(1 for r in res_list if r["success"])
        total_calls = sum(r.get("calls", 0) for r in res_list)
        total_tokens = sum(r.get("tokens", 0) for r in res_list)
        print(f"\n{name}:")
        print(f"  成功率: {successes}/{len(res_list)} ({100*successes/len(res_list):.0f}%)")
        print(f"  平均调用: {total_calls/len(res_list):.1f}")
        print(f"  平均 token: {total_tokens/len(res_list):.0f}")
    
    # 结论
    a_success = sum(1 for r in results["Strategy-A (Direct)"] if r["success"])
    b_success = sum(1 for r in results["Strategy-B (Plan-Code)"] if r["success"])
    total = len(results["Strategy-A (Direct)"])
    print(f"\n{'→'*25}")
    if b_success > a_success:
        print(f"Plan-then-Code 策略总体更好（{b_success}/{total} vs {a_success}/{total}）")
    else:
        print(f"两种策略差异不明显（数据集可调整复杂度以拉开差距）")
    print(f"提示：将 task.complexity 改为 'hard' 可更显著体现分解策略优势")

# ============================================================
# 运行对比实验
# ============================================================
if __name__ == "__main__":
    tasks = [
        ProgrammingTask("实现一个 LRU Cache（支持 get/put，O(1) 访问）", complexity="medium"),
        ProgrammingTask("实现一个简易的数据库查询引擎：支持 SELECT/FROM/WHERE/JOIN 的解析和执行", complexity="hard"),
    ]
    run_comparison(tasks, trials=5)
```

**逐行注释说明**：
- `ProgrammingTask`：任务定义，支持不同复杂度
- `MockModelAPI`：模拟 API 调用，用随机成功/失败模拟不同策略的效果差异
- `strategy_direct`：一步到位生成，不分解
- `strategy_plan_then_code`：三步走（分解→编码→审查），模拟 Seed2.1 的 plan-then-code 风格
- `run_comparison`：对比实验引擎，多次执行并汇总成功率、调用次数、token 消耗
