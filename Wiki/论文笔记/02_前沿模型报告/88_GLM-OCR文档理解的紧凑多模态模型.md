# GLM-OCR：面向真实文档理解的紧凑多模态模型

📄 **原文 PDF**：[[RAW/88 - GLM-OCR Technical Report.pdf]]

## PM 速判（30秒）

> **0.9B 参数的紧凑 OCR 模型，生产级文档解析的高性价比方案。** ZhipuAI 发布 GLM-OCR（0.9B = CogViT 0.4B 视觉编码器 + GLM 0.5B 解码器），引入多 Token 预测（MTP）解决自回归 OCR 低效问题，两阶段流水线（版面分析→并行区域识别）。在文档解析、公式转录、表格结构恢复、关键信息抽取等任务上达到 SOTA 或竞争水平，适合边缘部署和大规模生产。

## 核心机制

```
架构（0.9B总参数）：
  CogViT 视觉编码器（0.4B）
  GLM 语言解码器（0.5B）

关键创新——MTP（Multi-Token Prediction）：
  OCR 任务本质是确定性的（不需要生成多样性）
  标准 AR 解码：每步生成 1 个 token → 效率低
  MTP：每步预测多个 token（共享参数，不增加显存）
  → 显著提升解码吞吐量

两阶段系统流水线：
  Stage 1：PP-DocLayout-V3 → 版面分析（检测各元素区域）
  Stage 2：并行区域级识别（多个区域同时处理）

能力覆盖：
  ✅ 文档解析（段落/标题/表格/图形）
  ✅ 文本转录（中英文、手写）
  ✅ 公式转录（LaTeX）
  ✅ 表格结构恢复
  ✅ 关键信息提取（KIE）
```

## PM 结论

- 📅 2025 年，OCR 已基本解决；新竞争维度是"结构化理解"（理解版面、语义关系）
- **紧凑模型的价值**：0.9B 可在 CPU/低端 GPU 边缘部署，比 72B VLM 便宜 100x
- MTP 技巧：对于确定性（非生成性）任务，MTP 是提升吞吐的通用技巧
- 对竞品：比 Gemini-3 Pro / Qwen3-VL-235B 等大模型更适合大规模批量文档处理
- 适合集成场景：企业文档数字化、合同 AI 审阅、财务报表抽取

## 论文精读卡片

**一句话**：GLM-OCR（0.9B）用 MTP 多 Token 预测解决自回归 OCR 低效问题，在文档解析/公式/表格等任务达到 SOTA，成本仅为 72B VLM 方案的 1/100。

**问题**：大型 VLM（72B+）做 OCR/文档解析性能好但成本极高；小型专用 OCR 模型效率高但结构理解能力弱——如何在 1B 参数以内构建生产级文档智能模型？

**核心方法**：
- MTP（Multi-Token Prediction）——OCR 是确定性任务（无需多样性），每步并行预测多个 token 而非逐 token 生成，大幅提升吞吐，且共享参数不增加显存
- 两阶段系统流水线——Stage 1：PP-DocLayout-V3 版面分析（检测元素区域）；Stage 2：并行多区域 OCR（各区域同时处理）
- 语音 tokenizer（F0 约束）——在视觉编码器 CogViT 中加入基频约束，减少 token 中的基频信息丢失（此为 TTS 方向的类比，OCR 中为版面特征保留）

**关键图/公式**：架构规模：CogViT 视觉编码器（0.4B）+ GLM 语言解码器（0.5B）= 0.9B 总参数。MTP 核心：标准 AR 每步 1 token；MTP 每步 N token（共享 head 参数）——在文档 OCR 这类确定性任务上，吞吐可提升 N 倍。

**实验设置**：
- 规模/数据：0.9B 参数，专项文档数据（含手写、公式、表格、版面复杂文档）
- 对比：Gemini-3 Pro、Qwen3-VL-235B 等大型 VLM，以及专用 OCR 工具（PaddleOCR 等）

**最强证据**：在文档解析、公式转录（LaTeX）、表格结构恢复、关键信息提取（KIE）等任务上达到 SOTA 或竞争水平；成本比 72B VLM 低 100x；边缘设备可部署。

**最弱证据**：具体基准数字在技术报告中未完整列出；MTP 在 OCR 任务的准确率-速度 tradeoff 没有系统分析；对复杂版面（多栏、表格嵌套图形）的鲁棒性未充分评估。

**可复用点**：MTP 用于确定性任务的通用技巧——任何输出确定性高（低多样性需求）的生成任务（结构化数据提取、代码格式化、数学公式转写等），都可以用 MTP 替代标准 AR 解码来提升吞吐。
