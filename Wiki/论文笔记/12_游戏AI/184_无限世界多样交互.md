> arXiv:2607.07534 (cs.CV)，2026-07-08。开源：github.com/robbyant/lingbot-world-v2；权重在 HuggingFace robbyant/lingbot-world-v2；主模型 14B + 轻量 1.3B（单卡可跑）。

## PM 速判（30秒）

> 蚂蚁 Robbyant 团队的开源交互式世界模型二代：宣称做到**无限时长**（1 小时连续生成无可见衰减）+ **720p@60fps 实时**交互 + 战斗/射箭/施法/开枪等丰富动作 + 文本驱动改天换地，并首次把"coding agent 的 harness 哲学"搬进世界模型——VLM 当 Director（大脑，提事件提案）、视频生成器当 Pilot（小脑，渲染物理动态）。PM 必须知道两点：(1) "可玩的生成式游戏世界"的产品形态正在从 demo 走向可部署开源栈；(2) 本文**全篇没有一张量化指标表**，所有对比都是定性图——采购/立项时要求补量化证据。

## 双层费曼 🗣️

> **给 CEO 的一句话**：这是一个"永不落幕的 AI 游戏引擎"——你给一张图，它实时生成一个可以走、可以打、可以施法、可以随口下雪的世界，连续跑一小时画面不崩，而且开源可自部署；它还给世界配了个 AI 导演，玩家不动它也能自己往下演。

> **给工程师的一段话**：底座是 14B 因果 DiT 视频模型，逐 chunk 自回归生成，动作输入 = 相机位姿（Plücker 射线嵌入 + AdaLN 注入）+ chunk 级文本 prompt（下三角 cross-attention 掩码防未来信息泄漏）。预训练核心 trick 是 **MoBA 掩码**（Mixture of Bidirectional and Autoregressive）：在 teacher-forcing 因果掩码右下角拼一个双向全注意力块——纯 teacher forcing 会让模型越来越依赖干净上下文而不学预测，导致长程画质退化，双向块起正则作用。训练目标是条件 flow matching。后训练两步蒸馏：consistency distillation 把多步去噪压成少步，再用 **DMD（分布匹配蒸馏）在长自回滚（self-rollout）轨迹上**做——关键是让学生在"自己生成的状态分布"上优化而非 teacher-forced 干净状态，直接对抗曝光偏差与漂移。部署侧：动态 KV cache 调度（按控制信号保留最有信息量的历史）、异步 latent 生成/VAE 解码流水线、TensorRT 时空 refiner（上采样+插帧）。Harness 层：VLM Director 读场景→因果推理→出"事件提案"，DiT Pilot 落地成物理一致的视频；交互两模式——A 直接语义交互（VLM 动态出事件卡），B SAM 跟踪辅助的对象级交互（跨 chunk 跟踪目标、hold-to-switch）。

## 问题域定位 🎯

- **根本约束（两个）**：① 长程稳定性——自回归视频逐帧自馈，误差复利，此前系统几秒到几分钟就纹理糊化、几何扭曲；② 高保真下的交互性——实时响应 + 高分辨率算力冲突，以往靠牺牲分辨率/流畅度/控制粒度换交互，用户只能"在死景里挪相机"。
- **之前的方案卡在哪里**：Genie 3 / HappyOyster 闭源且时长按分钟计；开源系（Matrix-Game 3.0、LingBot-World 1.0、HY-World 1.5 等）要么域窄（只有游戏画面）、要么动态度低、要么非实时。误差累积问题在纯 teacher forcing 训练范式下是结构性的——训练分布（干净上下文）与推理分布（自生成上下文）错配。
- **它开启的路线**：① "训练时就在自回滚分布上做分布匹配"成为反漂移正统做法；② 世界模型 + Agent harness 的合体——生成模型只是"引擎"，Director/Pilot 双 agent 才让它变成"会自己演的世界"；③ 开源 14B/1.3B 双规格降低了交互世界模型的准入门槛。
- **它关闭不了的问题（作者自认）**：外观持久 ≠ 身份持久——离开上下文窗口的区域再回访是"重新生成"不是"回忆"，真正的长期记忆仍开放。

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 自注意力掩码 | MoBA：teacher forcing + 拼接双向全注意力块 | 纯 teacher forcing / 纯双向 | 纯 TF 下上下文越长模型越"抄上下文不学预测"，画质退化；双向块当正则并保留基座画质 | 双向块依赖全局 prompt，推理时纯自回归——训练/推理仍有残余错配；上下文超出 KV 预算时正则效果无从谈起 |
| 抗漂移蒸馏 | DMD 施加在长 self-rollout 轨迹上 | 只在 teacher-forced 干净状态上蒸馏 | 学生部署时活在自己的预测分布里，必须在该分布上纠偏（曝光偏差的正面解） | 学生上限被 teacher 封顶：teacher 自身的物理错误（穿模等）会被完整继承；rollout 训练成本随长度线性涨 |
| 语义层/物理层分工 | Director(VLM)=大脑出事件提案，Pilot(DiT)=小脑渲染动态 | 端到端单模型既推理又生成 | 视频模型天生缺因果/常识推理，VLM 天生不会渲染物理；各干各的 | VLM 提案超出生成器动作分布时渲染崩坏；实时循环里 VLM 推理延迟成为交互瓶颈；两层世界观不一致时出"导演说 A 演员演 B" |
| 上下文管理 | 动态 KV cache 调度（按控制信号选留历史） | 固定长度上下文 | 提速 + 抑制陈旧内容干扰 | 被逐出的历史=被遗忘的世界——这正是"回访区域被重新生成"的直接原因，用效率换掉了记忆 |
| 文本条件粒度 | chunk 级局部 caption + 全局 caption 双轨（多轨事件级标注） | 单条全局视频 caption | 推理时指令随时间变化，只用全局 caption 会造成训练-推理错配 | 标注管线复杂度高（多轨事件、动作上下文对齐）；chunk 边界模糊的连续事件仍会切碎 |
| 模型规格 | 14B 主模型 + 1.3B 蒸馏小模型 | 只出大模型 | 1.3B 单卡可部署，铺开社区生态 | 1.3B 的画质/交互保真度论文未单独量化——小模型体验可能显著缩水而无数据可查 |

## 成本与量级 💰

- **数据引擎三阶段（Sec.2，重工程所在）**：① 采集——自采第一人称视频（真实手物交互）+ 游戏/Unreal 合成数据（几何准确、动作信号时间对齐，跳/打/驾驶/飞行等控制信号在野生视频里采不到）+ 网络视频（长尾覆盖）；② 画像——TransNet V2 镜头切分 → 技术评分（画质/亮度/OCR 文字占比/运动统计/编码稳定性）粗筛 → VLM 语义画像（质量属性 + 视角/活动/交互模式标签，用于配比与路由）；③ 多维标注——全局 caption + chunk 级局部 caption 双轨；事件级标注按"主体可见性/运动状态/交互状态/环境动态/静态场景"五条轨道**独立**打标（避免无关变化被并进一句描述），有控制信号时用其做边界线索，最后清洗掉"剧透未来/臆测"的表述。
- **训练成本**：未披露（数据规模、GPU 时数全部缺失）。标注管线本身是重工程（人月量级起步）。
- **推理成本**：实时 720p@60fps 依赖"多 GPU 混合并行 + 异步 VAE 解码 + TensorRT refiner"——**具体几张什么卡未披露**，这是评估部署成本的最大盲区。1.3B 变体单 GPU 可跑，但质量数据缺失。
- **工程复杂度**：四层栈（模型/推理优化/harness/UI）+ SAM 跟踪 + VLM 服务，是"模型+系统+产品"的全栈工程，估计 10 人年量级团队投入（作者名单核心贡献者 19 人分四个方向）。
- **我的产品最小可行配置**：拿 1.3B 开源权重 + 单卡起 demo 验证交互范式；Director 用现成 VLM API；不自训，先验证"事件提案→视频落地"的产品闭环是否成立。

- **实验设计公平吗**：**全文没有任何量化指标**——无 FVD/PSNR/用户研究/动作跟随准确率，Fig 11/12 是定性帧对比（可挑选），Table 1 是作者自评的维度勾选表（且维度选取明显利己：开源、时长、动态度）。与闭源 Genie 3/HappyOyster 的对比无法复核。
- **最强证据**：1 小时不间断单次会话（Fig 10，20 个场景，59分20秒处仍结构连贯）。作为存在性证明（"结构性稳定而非片段侥幸"）是有力的，前提是承认其单次、自选性质。
- **最可疑的数字**："1 小时无可见衰减"。60 分钟里切了 **20 个场景**（平均约 3 分钟一切）——每次 prompt 切换场景都可能"软重置"误差累积，单场景连续生成的真实漂移上限被场景切换掩盖了。要证"无限"，该展示的是**同一场景**不切换的 60 分钟。
- **内部矛盾（术语翻转）**：摘要/引言说 pilot agent 负责"规划并执行角色行为"、director agent 负责"合成新环境元素"（两者都像 VLM 侧的双 agent）；到 4.2 节却变成 Director=VLM 大脑、Pilot=视频生成器小脑。同一对术语在同一篇论文里指代不同架构层，说明 harness 部分成文仓促。
- **如果我是审稿人，会要求补充**：(1) 量化长程漂移曲线（按时间窗的 FVD/CLIP 一致性 vs 基线）；(2) 单场景不切换的长时测试；(3) 回访一致性实验（走出去再走回来，场景还是不是原样——他们自己承认会被重新生成）；(4) 实时系统的硬件清单与端到端延迟分解；(5) MoBA、self-rollout DMD 的消融数字；(6) 1.3B vs 14B 的质量差距量化。

## 可复用点（PM 决策）

- **何时采用**：① 需要"可交互视频世界"的产品原型（UGC 游戏、虚拟陪伴场景、影视预演）——开源 + 单卡小模型让 PoC 成本极低；② Director-Pilot 双层架构可平移到任何"语义规划 + 底层执行"的生成产品（语义层用 VLM 出提案、执行层用专用模型落地）；③ "在 self-rollout 分布上做蒸馏"是所有自回归生成产品对抗质量漂移的通用配方。

## 动手练习 💻（约 30 分钟）

练习目标：用 1D 玩具自回归模型直观理解"曝光偏差→误差复利"以及为什么"在 self-rollout 分布上训练"能抗漂移（对应本文 DMD-on-rollout 的核心思想）。

```python
import numpy as np

rng = np.random.default_rng(0)                       # 固定随机种子

# ── 玩具世界: 真实动态是 x_{t+1} = 0.95*x_t + sin(x_t), 模型学一个线性近似 ──
def true_step(x):
    return 0.95 * x + 0.1 * np.sin(3 * x)            # 真实世界转移(带非线性)

def gen_data(n=2000):
    xs = rng.uniform(-2, 2, n)                       # 采样干净状态(teacher forcing 分布)
    return xs, np.array([true_step(x) for x in xs])  # (当前状态, 下一状态) 配对

# ── 模型: 一次多项式拟合 y = a*x + b, 模拟"容量不足必然有残差"的生成器 ──
def fit(xs, ys, w=None):
    W = np.ones_like(xs) if w is None else w         # 可选样本权重
    A = np.vstack([xs * W, W]).T                     # 加权最小二乘设计矩阵
    a, b = np.linalg.lstsq(A, ys * W, rcond=None)[0]
    return a, b

def rollout(a, b, x0, steps=60):
    xs = [x0]                                        # 自回滚: 模型吃自己的输出
    for _ in range(steps):
        xs.append(a * xs[-1] + b)                    # 预测值回灌 → 误差逐步复利
    return np.array(xs)

# ── 方案1: 纯 teacher forcing —— 只在干净状态分布上拟合 ──
xs, ys = gen_data()
a1, b1 = fit(xs, ys)

# ── 方案2: self-rollout 再训练 —— 把模型自己滚出来的状态也加入训练分布 ──
#    (对应论文: DMD 施加在长自回滚轨迹上, 学生在自己的错误分布上被纠偏)
roll_states = np.concatenate([rollout(a1, b1, x0, 40) for x0 in rng.uniform(-2, 2, 50)])
roll_states = roll_states[np.abs(roll_states) < 10]  # 丢掉已经发散的点
xs2 = np.concatenate([xs, roll_states])              # 训练分布 = 干净数据 + 自滚状态
ys2 = np.array([true_step(x) for x in xs2])          # 自滚状态也用"真实动态"当监督(类比真分布score)
a2, b2 = fit(xs2, ys2)

# ── 对比两种训练法在长 rollout 下的漂移 ──
x0 = 1.0
truth = [x0]
for _ in range(60):
    truth.append(true_step(truth[-1]))               # 真实轨迹
r1, r2 = rollout(a1, b1, x0), rollout(a2, b2, x0)
err1 = np.abs(r1 - np.array(truth))                  # teacher forcing 版逐步误差
err2 = np.abs(r2 - np.array(truth))                  # self-rollout 版逐步误差
for t in [10, 30, 60]:
    print(f"step {t:2d} | 纯TF误差={err1[t]:.3f} | self-rollout训练误差={err2[t]:.3f}")
# 预期: 两者第10步差不多, 到第60步纯TF误差显著更大 —— 误差复利被训练分布覆盖所抑制
```

预期收获：亲手看到"训练时没见过自己的错误状态"如何让长 rollout 崩掉，以及把自滚状态纳入训练分布后漂移曲线被压平——这正是本文后训练阶段的第一性原理。

> [!question]- L1 复述：说出四大升级（无限时长/720p@60fps 实时/多样动作/agentic harness）；MoBA 掩码的两个组成块及各自作用；后训练两种蒸馏及 DMD 施加在什么分布上；两大自认限制（长期记忆、物理理解）。
> **参考答案**：四大升级：①无限时长（1 小时连续生成无可见衰减）②720p@60fps 实时交互 ③多样动作（近战/射箭/施法/开枪 + 文本驱动改天换地）④agentic harness（VLM Director 出事件提案 + DiT Pilot 渲染落地的双 agent 循环）。MoBA 掩码 = 下三角 teacher forcing 因果块（学自回归预测能力）+ 右下角拼接的双向全注意力块（保留基座画质、当正则对抗「抄上下文不学预测」）。后训练两步蒸馏：consistency distillation 把多步去噪压成少步；再用 DMD 分布匹配蒸馏，且施加在长 self-rollout（自回滚）轨迹上——让学生在「自己生成的状态分布」而非 teacher-forced 干净状态上被纠偏。两大自认限制：长期记忆缺失（外观持久≠身份持久，离开上下文窗口的区域回访即重新生成）、物理理解缺失（纯像素学物理无碰撞概念，穿模等 artifact 无法根除）。
> **判分点**：必须答出 四大升级齐全、MoBA 两块各自作用（因果块学预测/双向块正则保画质）、DMD 施加在 self-rollout 分布上、两大限制（记忆与物理）（缺一个即卡点）

> [!question]- L2 解释：为什么纯 teacher forcing 训出的模型上下文越长画质越差？为什么 DMD 要在 self-rollout 轨迹而非 teacher-forced 状态上做？动态 KV cache 调度如何同时"造就实时性"和"造成失忆"——这是同一枚硬币的哪两面？
> **参考答案**：纯 TF 训练时模型永远看到干净的真实上下文，会越来越「依赖/抄上下文」而不学真正的预测；推理时上下文全是自己的生成物，训练-推理分布错配随上下文变长而放大，画质长程退化——这是纯 TF 范式的结构性问题。DMD 放在 self-rollout 上做：学生部署时活在自己的预测分布里、误差逐步复利，只在干净状态上蒸馏覆盖不到「自己犯过错的状态」；在自回滚轨迹上做分布匹配，学生才能在自己的错误分布上被纠偏，直接对抗曝光偏差与漂移。动态 KV cache 的两面：按控制信号只保留最有信息量的历史→算力/显存可控、抑制陈旧内容干扰→实时性成立；但被逐出的历史=被遗忘的世界状态→离开窗口的区域只能重新生成→失忆——同一个「选择性丢弃历史」的机制，用效率换掉了记忆。
> **判分点**：必须答出 TF 的训练-推理分布错配机制（干净上下文 vs 自生成上下文）、DMD-on-rollout=在学生自身错误分布上纠偏（对抗曝光偏差/漂移）、KV 调度「逐出换实时/逐出即遗忘」是同一机制的两面（缺一个即卡点）

> [!question]- L3 应用：你要做一个"AI 生成的可回访虚拟家园"产品，用户明天回来要看到自己昨天布置的房间。基于本文的限制（外观持久≠身份持久、KV 逐出即遗忘），设计一个混合架构：哪些状态必须落到显式外部存储（场景图/资产清单），哪些交给世界模型即兴生成？给出状态分层清单和一致性校验点。
> **参考答案**：分层原则：凡属「身份/所有权」的状态必须落显式外部存储——场景图（房间布局与空间拓扑）、资产清单（用户放置的家具及位置/属性）、用户修改历史（昨天的布置）、NPC/宠物的身份属性；凡属「外观合理即可」的交给世界模型即兴生成——纹理细节、光照天气、环境动态（鸟群/落叶）、非关键背景。回访流程：从外部存储读场景图+资产清单，作为条件（初始帧/prompt）注入世界模型重建场景，即兴层再补细节——不指望模型 KV cache 记住任何东西。一致性校验点：①回访加载后对资产清单逐项校验（关键物品在不在、位置对不对），不一致以外部存储为准重新条件化生成；②会话结束时把用户新修改写回外部存储（状态提交点）；③会话内跨 chunk 用 SAM 类跟踪校验关键对象的身份连续性。
> **判分点**：必须答出 分层原则（身份/所有权状态落显式存储、外观细节即兴生成）、外部存储作为条件重建场景（不依赖模型记忆）、至少两个校验点（回访校验资产清单/会话结束写回/跨 chunk 跟踪）（缺一个即卡点）
