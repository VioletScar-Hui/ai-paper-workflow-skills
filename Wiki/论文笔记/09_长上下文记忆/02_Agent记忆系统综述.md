## 解锁了什么产品能力

1. **跨会话记忆**：用户在 Day 1 说了偏好，Day 10 的 Agent 仍能记住并使用
2. **长时程 Agent**：数小时乃至数天持续运行的 Agent，不依赖单次 context window

## 工程算法解释

### 为什么不能直接用数据库？

Agent 记忆 ≠ 传统 OLTP/OLAP：
- 查询是**语义的**而非精确的（"我昨天说过什么关于出行计划的"）
- 写入是**流式的**（每次对话都在产生新记忆）
- 更新是**语义合并**，不是简单覆盖（"Kim 喜欢素食" → 更新到 "Kim 从 2024 年起吃素"）
- 检索需要**时间感知**（最近的事件优先，但古老的事实也可能突然相关）

### 混合检索为什么更好？

```
单一向量检索：
  "找和'素食餐厅推荐'最像的记忆"
  → 召回高，但精确度随时间下降

混合检索（Dense + BM25 + 图遍历）：
  Step 1: 语义密集检索（向量相似）→ 候选集
  Step 2: BM25 关键词匹配 → 过滤精化
  Step 3: 图遍历（关联实体）→ 补充上下文
  → 在时间距离大时仍能找到正确记忆
```

### 图结构为什么在更新时最可靠？

```
向量/文本存储更新：
  旧事实 → 直接覆盖（容易丢失中间状态）

知识图谱更新：
  (Kim, LIVES_IN, Shanghai) [t1]
  → 新增 (Kim, LIVES_IN, Paris) [t2]
  → 逻辑无效化旧边（而不是删除）
  → 可追溯、可回滚、时序一致
```

## 核心结论（5 条，带时间锚）

1. **没有通用最优架构** 📅 2025
   场景决定架构：对话 QA → 混合混合系统；单次事实召回 → 图结构；时序推理 → 没有任何系统表现好（重大 gap）

2. **混合检索明显优于单一检索** 📅 2025
   Dense + BM25 + 图的组合在召回精度上显著超过任一单独策略，尤其是 temporal query

3. **延迟和质量强烈负相关** 📅 2025
   从 LightMem（3.67s, utility 48.3）到 Cognee（116.5s, utility 84+），代价整整 30x 延迟换 ~1.75x 性能

4. **保留原文 > 激进摘要** 📅 2025
   写入时过度压缩/摘要会导致后续检索和推理的精度下降；建议"晚过滤原则"

5. **图结构是唯一可靠的更新机制** 📅 2025
   基于 append 的系统和 LLM 合并在处理知识更新时容易引入矛盾；图的时间戳版本控制更可靠

## 论文精读卡片

**一句话**：首个对 Agent 记忆系统做系统对比实验的综述（覆盖 15+ 系统），发现延迟与质量强负相关（3.67s 到 116.5s 的 30x 代价换取约 1.75x 性能），图结构是唯一可靠的知识更新机制。

**问题**：LLM Agent 缺乏跨会话持久记忆，现有解决方案（Mem0、Zep、MemTree 等）众多但没有统一评估框架，PM/工程师无从选型。时序查询（"上周我说了什么"）和知识更新（覆盖旧事实）是所有现有系统的共同弱点。

**核心方法**：
- 将所有 Agent 记忆系统形式化为 M_sys = ⟨R, S, Q, U⟩ 四模块：存储结构、存储操作、查询机制、更新机制
- 混合检索：Dense（向量语义）+ BM25（关键词精确）+ 图遍历（实体关联）三路组合，各路不同的时序衰减特性互补
- 图结构更新：用时间戳逻辑无效化旧边而非删除，保持时序一致性和可追溯性

**关键图/公式**：M_sys = ⟨R, S, Q, U⟩ 框架将所有记忆系统统一到四维度，使不同系统可以在同一坐标系下对比。核心洞察是"查询语义化、写入流式化、更新语义合并化"三点区分 Agent 记忆与传统数据库。

**实验设置**：
- 规模/数据：覆盖 15+ 记忆系统；LoCoMo（长对话 QA）、LOCRET（时序推理）等 Benchmark；评测维度包括延迟、Utility Score、更新准确率
- 对比：LightMem、Mem0、Mem0-graph、Zep、MemTree、MemoryOS、Cognee、A-MEM 等商业+开源系统

**最强证据**：图结构（Mem0g/Zep）在知识更新任务上的准确性明显优于 append-based 系统，且支持可追溯的版本控制；"晚过滤原则"（保留原文而非激进摘要）在后续检索精度上有统计显著的提升——这两条对工程选型有直接指导。

**最弱证据**：论文没有统一评测集上的完整对比表（各系统用了不同 Benchmark 验证），导致跨系统的直接数字对比缺少严格控制条件。时序推理任务上"无任何系统表现好"的结论未提供改进思路。

**可复用点**：选型决策矩阵：高频实时对话 → LightMem；知识密集更新 → Zep/Mem0-graph；长期多会话 QA → MemoryOS；快速 MVP → Mem0 API。并行时记住"没有通用最优架构"，先匹配场景再选系统。
