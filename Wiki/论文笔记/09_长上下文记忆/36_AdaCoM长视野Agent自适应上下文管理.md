# AdaCoM：长视野 Agent 的自适应上下文管理

📄 **原文 PDF**：[[RAW/36 - Learning Agent-Compatible Context Management for Long-Horizon Tasks.pdf]]

## PM 速判（2 分钟）

> **这篇论文给 PM 的一句话**：长视野 Agent 的上下文积累会导致"长上下文退化"（遗忘约束、过早放弃、冗余探索）—— AdaCoM 用**独立的小 LLM（Qwen3-4B）作为外部上下文管理器**（RL 训练），在不修改/不重训练底层 Agent 的情况下，对 BrowseComp-Plus 平均提升 **+39%**，且适用于闭源 Agent。

| 项目 | 评估 |
|------|------|
| **核心设计** | 外部 LLM 管理器（小模型） + 冻结 Agent（不需改动）|
| **训练方式** | RL（PPO-style）+ 两级 advantage（结果奖励 + 过程奖励）|
| **平均提升** | BrowseComp-Plus: +39%（vs 无管理的 ReAct 基线）|
| **优势** | 适用于闭源 Agent（无需白盒访问）|
| **成熟度** | 🧪 实验验证，RUC / Alibaba Tongyi Lab |

---

## 核心机制

```
问题：长视野 Agent 的上下文不断累积 → 长上下文退化
  具体表现：约束遗忘 / 过早放弃 / 冗余工具调用

先前方法的局限：
  - 固定策略（如摘要化）对所有 Agent 用一套规则
  - 需要修改/重训练底层 Agent（闭源 Agent 不可用）

AdaCoM 的方法：
  1. 架构解耦：管理器（小 LLM）独立于 Agent，不需改动 Agent
  2. 灵活修改：管理器可以删除/合并/改写任意上下文片段，而非固定摘要
  3. RL 训练：管理器以 Agent 的任务成功率为奖励，学习 Agent-specific 策略

效果：
  - Kimi-K2: +95%（从 18.56 → 36.20）
  - DeepSeek-V3: +47%（从 17.78 → 26.19）
  - 平均: +39%（从 24.17 → 33.60）
```

## 核心结论（带时间锚）

1. **每个 Agent 需要不同的上下文管理策略**，不存在通用最优解 📅 2026
2. **外部管理器可以发现 Agent-compatible 策略而无需修改 Agent** 📅 2026
3. **迁移性**：AdaCoM 跨能力相近的 Agent 迁移最有效（保真度-可靠性权衡）📅 2026

## 论文精读卡片

**一句话**：AdaCoM 用独立的小 LLM（Qwen3-4B）作为外部 RL 训练的上下文管理器，在不修改底层 Agent 的情况下，对 BrowseComp-Plus 平均提升 +39%（Kimi-K2 提升 +95%），且对闭源 Agent 同样有效。

**问题**：长视野 Agent 随任务推进上下文不断积累，导致"长上下文退化"三联症：约束遗忘（早期指令被遗忘）、过早放弃（错误判断任务无解）、冗余探索（重复执行无效操作）。现有固定策略（如统一摘要）无法适配不同 Agent 的行为模式，且通常需要修改底层 Agent。

**核心方法**：
- 架构解耦：独立的小 LLM 管理器（Qwen3-4B）监控 Agent 上下文，不修改 Agent 本身（支持闭源 Agent）
- 灵活修改策略：管理器可删除/合并/改写任意上下文片段（而非固定摘要），通过 RL 学习 Agent-specific 策略
- RL 训练：PPO-style 训练，使用两级 advantage（结果奖励=任务成功率 + 过程奖励=上下文管理动作质量），管理器以目标 Agent 的任务表现为奖励信号

**关键图/公式**：AdaCoM 架构：Agent → 上下文 → 管理器（观察上下文，输出删除/合并/改写操作） → 修改后上下文 → Agent（下一步）；RL 奖励 = w₁×任务成功率 + w₂×上下文管理过程奖励（减少冗余的数量）。

**实验设置**：
- 规模/数据：BrowseComp-Plus（网络搜索长视野任务），多 Agent 测试（Kimi-K2、DeepSeek-V3 等）
- 对比：无管理的 ReAct 基线（平均 24.17）vs 固定摘要策略 vs AdaCoM（33.60），针对每个 Agent 分别测量

**最强证据**：Kimi-K2 在 AdaCoM 管理下从 18.56 提升至 36.20（+95%），DeepSeek-V3 从 17.78 提升至 26.19（+47%）；平均 +39% 提升均在不修改/重训练底层 Agent 的条件下实现。

**最弱证据**：仅在 BrowseComp-Plus 一个基准上验证，长视野任务类型单一（网络搜索）；管理器的 RL 训练针对每个 Agent 需要单独训练（是 Agent-specific 的），跨 Agent 迁移效果有限（文中指出"迁移性在能力相近 Agent 间最佳"）；Qwen3-4B 管理器本身的训练成本和时间未报告。

**可复用点**："外部管理器 + 冻结 Agent"的架构直接可用于接入闭源模型（GPT-4/Claude）时增强上下文管理；长上下文退化的三联诊断（约束遗忘/过早放弃/冗余探索）可作为长视野 Agent 系统的监控指标；管理器使用远比主 Agent 便宜的小模型是可立即复用的成本优化策略。
