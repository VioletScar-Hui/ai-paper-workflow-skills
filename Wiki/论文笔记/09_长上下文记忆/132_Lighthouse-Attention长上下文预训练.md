# Lighthouse Attention：长上下文预训练效率优化

📄 **原文 PDF**：[[RAW/132 - Long Context Pre-Training with Lighthouse Attention.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：长上下文模型的训练瓶颈是 O(N²) 注意力计算——Lighthouse Attention 在训练时用分层稀疏选择替代全注意力，训练完再恢复为标准密集注意力推理，实现 **1.4-1.7× 训练加速**，最终模型效果与从头训练的密集基线相当或更好。

| 项目 | 评估 |
|------|------|
| **核心方法** | 分层金字塔池化 + Top-K 选择（仅训练时，推理时移除） |
| **加速效果** | 1.40×~1.69× 端对端训练速度提升 |
| **GPU 节省** | 37.9h → 22.5-27.0h（B200 GPU 小时） |
| **质量** | 恢复密集 SDPA 后，最终 loss 与全密集基线匹配或更低 |
| **成熟度** | 🧪 小规模（530M 参数）验证，待大模型规模验证 |

## 工作原理（工程解释）

```
问题：
  标准注意力 SDPA = O(N²) 计算 + 内存
  → 训练 128K/1M 上下文模型，计算成本爆炸

Lighthouse 的解法（训练时）：
  1. 金字塔池化：把 Q/K/V 压缩为多分辨率层级摘要
  2. 参数-free 评分：按 ℓ₂ 范数给每个层级条目打分
  3. 选 Top-K 条目：把选中的子序列聚合为 O(N log N) 大小
  4. 只对子序列跑标准 FlashAttention
  5. 将结果散射回原始位置
  
训练完成后：
  → 最后几千步切换回完整 SDPA 训练（"密集恢复"阶段）
  → 推理时完全使用标准注意力，无需任何特殊内核
```

**关键设计选择**：
- 选择步骤是非可微的（无梯度），模型学会产出被选中时有用的表示
- 不增加可学习参数，不增加辅助损失函数
- 对称压缩 Q/K/V（而非只压缩 K/V），保留因果性的同时提升并行度

---

## 核心结论（带时间锚）

1. **长上下文预训练可以用训练时稀疏注意力+推理时密集注意力的两段策略加速** 📅 2026
   分层训练信号不会损害模型使用完整注意力的能力——这是推理时稀疏方法无法保证的。

2. **相同 token 预算下，Lighthouse 模型在 NIAH 长上下文检索上匹配或超越密集基线** 📅 2026
   k=2048 dilated 配置在 Needle-in-a-Haystack（98K 上下文）上均值准确率 0.76 vs 基线 0.72。

3. **每节省 1 GPU 小时，开源社区就距离更长上下文的开源模型近一步** 📅 2026
   Lighthouse 为开源长上下文预训练降低门槛（Nous Research 是主要开源模型贡献者）。

## 论文精读卡片

**一句话**：Lighthouse Attention 在训练时用分层金字塔池化 + Top-K 选择将注意力计算从 O(N²) 降至 O(N log N)，最后几千步切换回密集注意力恢复，端对端训练加速 1.40-1.69×（37.9h→22.5-27.0h B200 GPU 小时），最终模型质量与全密集基线相当或更好（NIAH 98K 上下文 0.76 vs 基线 0.72）。

**问题**：训练长上下文 LLM 的 O(N²) 注意力计算成本是主要瓶颈——128K/1M 上下文的训练成本对大多数研究者望而却步——如何在训练期间降低注意力计算成本，同时不牺牲最终模型的推理质量？

**核心方法**：
- 训练时分层稀疏：金字塔池化压缩 Q/K/V 为多分辨率层级摘要 → 参数-free ℓ₂ 范数评分 → Top-K 选择 → 只对子序列跑 FlashAttention → 散射回原始位置
- 非可微选择（无梯度）：模型被迫学会产出"被选中时有用"的表示，不需要辅助损失
- 密集恢复阶段：最后几千步切换回完整 SDPA，推理时完全使用标准注意力（无需特殊内核）

**关键图/公式**：两阶段策略：训练时稀疏（O(N log N)）+ 推理时密集（标准注意力）——分层训练信号不损害模型使用完整注意力的能力，这是推理时稀疏方法无法保证的核心优势。

**实验设置**：
- 规模/数据：530M 参数（小规模验证）；长上下文 NIAH（Needle-in-a-Haystack，98K 上下文）；B200 GPU 集群
- 对比：全密集 SDPA 基线（37.9 GPU 小时）；k=2048 dilated 配置 vs 其他 Top-K 变体

**最强证据**：k=2048 dilated 配置：训练时间 37.9h→22.5h（快 1.69×），NIAH 均值准确率 0.76 vs 基线 0.72（更好）——同时在速度和质量上胜出密集基线。

**最弱证据**：只在 530M 参数规模验证，是否在 7B/70B 规模保持同等加速比和质量未验证（论文明确指出待大模型规模验证）；NIAH 是长上下文检索的代理指标，不代表所有长上下文任务（如长文档推理）。

**可复用点**："训练时稀疏 + 推理时密集"两段策略作为长上下文训练加速的通用范式；分层金字塔池化 + Top-K 选择的非参数稀疏化设计；密集恢复阶段（最后几千步）作为保证最终模型质量的工程实践。
