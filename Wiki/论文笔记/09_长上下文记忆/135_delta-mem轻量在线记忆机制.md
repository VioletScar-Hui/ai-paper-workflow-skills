# δ-mem：大语言模型的高效在线记忆

📄 **原文 PDF**：[[RAW/135 - delta-mem - Efficient Online Memory for Large Language Models.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：用一个 8×8 矩阵（delta-rule 更新的联想记忆）+ 4.87M 参数（占主模型 0.12%）插件，在冻结 LLM backbone 上实现长期对话记忆，MemoryAgentBench 提升 1.31×——是"轻量记忆插件"方向最小参数量的代表性工作。

| 项目 | 评估 |
|------|------|
| **记忆状态大小** | 8×8 固定矩阵 |
| **参数量** | 4.87M（0.12% backbone 参数） |
| **综合提升** | 1.10× 平均；1.31× MemoryAgentBench；1.20× LoCoMo |
| **不需要** | 全量微调 / backbone 替换 / 显式上下文扩展 |
| **成熟度** | 🧪 学术原型，待工业规模验证 |

## 工作原理

```
三类已有记忆方法的局限：
  文本记忆（RAG类）：灵活但受上下文窗口限制，有检索噪声
  外部记忆（外接模块）：模块化但有集成开销和不对齐问题
  参数记忆（LoRA/Prefix）：高效但静态，不能动态更新
  
δ-mem 的做法：
  在 Transformer 的注意力计算中插入一个固定大小的在线状态矩阵 S
  
  写入：delta-rule 学习（只写"残差"，避免重复写同样的信息）
    S_t = λ·S_{t-1} + β·(v - S_{t-1}·k)·k^T
    
  读取：用当前 query 查询状态矩阵
    r_t = S_{t-1}·q_m
    
  引导：用读出的 r_t 生成 query/output 的低秩修正
    → 影响注意力计算，而非拼接到上下文
    
核心：记忆以矩阵形式压缩，读写成本 O(1)（与历史长度无关）
```

## 核心结论（带时间锚）

1. **联想记忆矩阵（delta-rule）比 RAG 检索和上下文扩展更轻量** 📅 2026
   8×8 矩阵 + 0.12% 参数 → 在记忆密集任务上显著提升，而主流竞品（MLP Memory）需要 76.4% 的 backbone 参数。

2. **记忆通过"引导注意力计算"而非"拼接上下文"生效** 📅 2026
   区别于 RAG 把检索结果放入上下文，δ-mem 直接修正 Q/O 投影——这让记忆影响更深层，也避免上下文窗口被记忆占满。

3. **在"需要测试时学习"的任务上增益最大** 📅 2026
   MemoryAgentBench 的 Test-time NLU 分类（NLU 任务实时学习新类别）是 δ-mem 优势最显著的场景。

## 论文精读卡片

**一句话**：δ-mem 用一个 8×8 联想记忆矩阵（delta-rule 在线更新）+ 4.87M 参数（仅占主模型 0.12%）作为冻结 LLM 的轻量插件，在 MemoryAgentBench 提升 1.31×，而主流竞品 MLP Memory 需要 76.4% backbone 参数——O(1) 读写成本，不依赖上下文扩展或检索索引。

**问题**：长期对话 Agent 需要跨会话记忆，但现有方案各有缺陷（RAG 检索噪声、外部模块集成开销、LoRA/Prefix 静态不可动态更新）——能否用极少参数在不改变主模型的前提下实现动态更新的在线记忆？

**核心方法**：
- 在线状态矩阵 S（8×8 固定大小）插入 Transformer 注意力计算中
- 写入（delta-rule）：S_t = λ·S_{t-1} + β·(v - S_{t-1}·k)·k^T（只写"残差"，避免重复写相同信息）
- 读取：r_t = S_{t-1}·q_m（用当前 query 查询状态矩阵）
- 引导：r_t 生成 Q/O 投影的低秩修正，直接影响注意力计算而非拼接上下文

**关键图/公式**：读写成本均为 O(1)（与历史长度无关）；delta-rule 写入只更新残差（v - S_{t-1}·k）避免重复信息覆盖——这两个设计使矩阵在固定大小下能持续学习新知识。

**实验设置**：
- 规模/数据：MemoryAgentBench（主要基准）、LoCoMo（长对话）；Backbone 冻结，只训练 4.87M 参数插件
- 对比：RAG 类（文本记忆）、外部模块、LoRA/Prefix（参数记忆）、MLP Memory（76.4% backbone 参数）

**最强证据**：MemoryAgentBench 提升 1.31×（Test-time NLU 场景最显著），而竞品 MLP Memory 需要 76.4% backbone 参数量——0.12% 参数获得显著提升，参数效率碾压竞品。

**最弱证据**：只有学术原型验证（未工业规模验证）；8×8 矩阵的容量上限未分析（长对话历史是否会遗忘早期重要信息）；评测基准以学术为主，真实长期对话（数周/数月）的性能未验证；综合平均提升只有 1.10×，MemoryAgentBench 的 1.31× 是特定场景。

**可复用点**：delta-rule 联想记忆矩阵作为 Agent 记忆的轻量化替代方案；"记忆通过引导注意力计算而非拼接上下文"的设计思路（避免上下文窗口被记忆占满）；短期（上下文）+ 在线压缩矩阵（δ-mem）+ 长期外部存储（RAG/MeMo）三层记忆架构模型。
