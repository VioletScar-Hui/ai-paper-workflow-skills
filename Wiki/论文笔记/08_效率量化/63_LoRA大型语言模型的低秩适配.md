# LoRA：大型语言模型的低秩适配

📄 **原文 PDF**：[[RAW/63 - LoRA - Low-Rank Adaptation of Large Language Models.pdf]]

## PM 速判（30秒）
> 一句话：冻结预训练权重，只训练一个旁路低秩矩阵对 BA——可训练参数减少约 10000 倍、训练显存降为约 1/3，效果匹配全参微调，且推理时零额外延迟。今天所有"微调即服务"平台（OpenAI/Together/各云厂商）的底层几乎都是它或它的变体。PM 谈"定制模型"的成本账，起点就是这篇。

## 双层费曼 🗣️
> **给 CEO 的一句话**：以前给大模型做定制像重造一台发动机，现在像给发动机加装一个几十兆的外挂芯片——成本降到千分之一，效果几乎一样，还能随时拔插切换。
> **给工程师的一段话**：微调时权重更新 ΔW 的"本征秩"很低，所以不直接更新 W₀（冻结），而是学一个低秩分解 ΔW = BA（B: d×r，A: r×k，r≪min(d,k)），前向变为 h = W₀x + (α/r)·BAx。A 高斯初始化、B 全零初始化，保证训练起点与预训练模型完全一致。训练只需为 BA 存梯度和优化器状态；推理前把 BA 合并进 W₀，与原模型结构完全相同，零额外延迟——这是它优于 Adapter（串行加层、增加延迟）和 Prefix Tuning（占用序列长度）的关键。

## 问题域定位 🎯
- 这篇论文在回应什么**根本约束**？全参微调 GPT-3 175B 需要为每个参数存梯度 + Adam 双动量，训练显存约 1.2TB；且每个下游任务要存一份 350GB 的完整权重副本——存储、部署、切换全部不可行。
- 之前的方案卡在哪里？Adapter Tuning 在每层串行插入小网络，推理延迟增加（小 batch 下可达 20-30%）；Prefix Tuning 占用宝贵的上下文窗口且优化不稳定；BitFit 等只调 bias 的方法容量不足。
- 它开启/关闭了哪条技术路线？开启了"微调产物 = 可插拔小文件"的范式。此后 QLoRA、AdaLoRA、DoRA、多租户 LoRA serving（S-LoRA）全部建立在这条路线上；它也让开源社区的模型定制生态成为可能。

## 核心机制

```
               前向传播（训练时）
      x ──┬──────────────────────┐
          │                      │
          ▼                      ▼
    ┌──────────┐          ┌────────────┐
    │ W₀ (冻结) │          │ A (r×k)    │ ← 高斯初始化，可训练
    │  d×k     │          └─────┬──────┘
    └────┬─────┘                ▼
         │                ┌────────────┐
         │                │ B (d×r)    │ ← 零初始化，可训练
         │                └─────┬──────┘
         │                      │ × (α/r) 缩放
         ▼                      ▼
         └───────►  (+)  ◄──────┘
                    │
                    ▼
            h = W₀x + (α/r)·BAx

训练：只有 A、B 有梯度（参数量 r×(d+k)，r=1~64）
部署：W = W₀ + (α/r)·BA 一次性合并 → 推理图与原模型完全一致
切换任务：W 减回 BA，换上另一组 A'B'（几十 MB 的文件）
```

## 设计决策解剖 ⚖️
| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 更新的表达形式 | 旁路低秩分解 BA，可合并回 W₀ | Adapter（串行插层）、Prefix Tuning（虚拟 token） | ΔW 本征秩低的假设 + 合并后推理零延迟 | 需要在同一 batch 内同时服务几十个不同 LoRA（不能合并，旁路计算重新出现，需 S-LoRA 类专用 serving） |
| 初始化策略 | A 高斯随机、B 全零 | A/B 都随机 | BA 起点为 0 → 第 0 步就是预训练模型，训练平滑无突变 | 几乎不失效；但若 A 也置零则梯度恒为零，完全无法训练 |
| 作用位置 | 只加在注意力的 Wq、Wv | 所有线性层、FFN 层 | 相同参数预算下实验最优；FFN 收益低 | 领域差距大或要注入新知识时——QLoRA（2023）证明必须覆盖所有线性层才能匹配全参微调 |
| 秩 r 的大小 | 很小（1~8 通常够用） | 大 r（64+） | GPT-3 上 r=1 与 r=64 的子空间高度重叠，任务信息本征维度低 | 目标任务与预训练分布差异极大（新语言、新模态）时低秩容量不足；代码/数学推理任务普遍需 r=32~128 |
| 缩放因子 | α/r 固定缩放 | 学习式缩放、无缩放 | 调 r 时不必重调学习率，α 一次设定即可 | r 很大时 α/r 过度缩小更新，rsLoRA 等后续工作改用 α/√r |

## 成本与量级 💰
- 训练成本量级：GPT-3 175B 场景，训练显存 1.2TB → 350GB（约 1/3），checkpoint 350GB → 35MB（万分之一），训练吞吐还提升约 25%（无需为冻结参数算优化器更新）
- 推理成本 vs 基线：合并后 **1.0×**（零额外延迟）——这是 LoRA 相对所有其他 PEFT 方法的杀手锏
- 我的产品要用：7B 模型 + r=16 LoRA，单张 24GB 消费卡（如 4090）即可微调；若显存再紧张，上 QLoRA

## 证据审计 🔬
- 实验设计公平吗？基本公平：对比了全参微调、Adapter 两个变体、Prefix 系方法，且在 RoBERTa/DeBERTa/GPT-2/GPT-3 四个模型系上验证。但下游任务（WikiSQL、MNLI、SAMSum）都是与预训练分布接近的经典 NLP 任务，天然利好"低秩更新足够"的假设。
- 最强证据：GPT-3 175B 上 4.7M 可训练参数（约为全参的 0.003%）匹配或超过全参微调（WikiSQL 73.4 vs 73.8，MNLI 91.7 vs 89.5）；成立条件是任务与预训练分布接近。
- 最可疑的数字：**"r=1 就够"的子空间重叠分析**，因为它只在 GPT-3 + 这几个任务上做，却常被外推为普适规律——后续社区实践中代码/数学等重推理任务普遍需要 r=32~128。
- 如果我是审稿人，会要求补充：分布外任务（新语言、代码生成）上的 LoRA vs 全参对比；以及"只调 Q/V"结论在更多任务上的稳健性检验（这一条后来果然被 QLoRA 推翻）。
- 最小复现实验：用 numpy 对一个模拟的 ΔW 做 SVD，验证低秩近似的信息保留率（见下方练习，预算：笔记本电脑 5 分钟）；真实版可用 7B 模型 + Alpaca 数据 + 单卡 4090 约 2 小时。

## 可复用点（PM 决策）
- **何时采用**：需要为多客户/多任务定制模型且共享同一基座；显存预算有限；需要频繁迭代微调版本。
- **何时规避**：任务需要注入大量新知识（考虑继续预训练）；对模型行为要做深度改造（全参微调或至少高秩 + 全线性层覆盖）。
- 供应商拷问清单：
  1. "你们的微调是 LoRA 还是全参？LoRA 的话 r 是多少、覆盖哪些层？"（只覆盖 Q/V 且 r≤8 的服务，效果上限低）
  2. "多个客户的 LoRA 是合并部署还是动态加载？动态加载时的延迟开销是多少？"
  3. "微调产物我能导出吗？"（LoRA 权重只有几十 MB，技术上完全可导出，不给导出是商业锁定）

## 动手练习 💻（30分钟）
练习目标：用 numpy 亲手实现 W₀ + BA 低秩更新，验证三件事——零初始化保证起点一致；参数量减少几个数量级；低秩近似能捕获多少"真实更新"的信息。

```python
import numpy as np                          # 导入数值计算库 numpy

np.random.seed(42)                          # 固定随机种子，保证每次运行结果一致

# ========== 第 1 部分：搭一个 LoRA 层 ==========
d, k = 4096, 4096                           # 权重矩阵尺寸，模拟 7B 模型的一个注意力投影层
r = 8                                       # LoRA 的秩，论文中常用 4/8/16
alpha = 16                                  # 缩放超参数 alpha，实际缩放系数是 alpha/r

W0 = np.random.randn(d, k) * 0.02           # 模拟冻结的预训练权重（正态分布小值）
A = np.random.randn(r, k) * 0.01            # A 矩阵：高斯随机初始化（论文设定）
B = np.zeros((d, r))                        # B 矩阵：全零初始化（论文设定）

x = np.random.randn(k)                      # 一个随机输入向量，模拟一个 token 的隐状态

h_base = W0 @ x                             # 原始预训练模型的输出
h_lora = W0 @ x + (alpha / r) * (B @ (A @ x))  # LoRA 前向：主路 + 缩放后的旁路

# 因为 B 全零，旁路贡献为 0，两个输出应完全一致
print("训练起点与预训练模型一致?", np.allclose(h_base, h_lora))   # 期望输出 True

# ========== 第 2 部分：参数量对比 ==========
full_params = d * k                         # 全参微调要更新的参数量：d×k
lora_params = r * (d + k)                   # LoRA 要更新的参数量：B 的 d×r + A 的 r×k
print(f"全参微调: {full_params:,} 个参数")            # 16,777,216
print(f"LoRA(r={r}): {lora_params:,} 个参数")         # 65,536
print(f"压缩比: {full_params / lora_params:.0f} 倍")   # 256 倍（单层）

# 换算显存：Adam 优化器每个可训练参数约需 16 字节（fp32 梯度 + 两个动量 + 主权重）
print(f"单层优化器状态: 全参 {full_params*16/1e6:.0f}MB vs LoRA {lora_params*16/1e6:.2f}MB")

# ========== 第 3 部分：低秩假设到底靠不靠谱？ ==========
# 构造一个"本征秩低"的真实更新 ΔW：由两个瘦矩阵相乘生成（秩最多为 16），再加少量噪声
true_rank = 16                              # 假设真实更新的本征秩是 16
U = np.random.randn(d, true_rank)           # 瘦高矩阵
V = np.random.randn(true_rank, k)           # 矮宽矩阵
dW = U @ V / np.sqrt(d) + np.random.randn(d, k) * 0.01  # 低秩结构 + 噪声

# 对 ΔW 做奇异值分解（SVD）：任何矩阵都能分解为 U·S·V^T，S 的对角线是奇异值
_, S, _ = np.linalg.svd(dW, full_matrices=False)  # 只需要奇异值 S

energy = np.cumsum(S**2) / np.sum(S**2)     # 前 r 个奇异值累计捕获的"能量"（信息量）占比
for test_r in [1, 4, 8, 16, 64]:            # 测试不同的秩
    print(f"r={test_r:>3}: 前 {test_r} 个奇异值捕获 {energy[test_r-1]*100:.1f}% 的更新信息")
# 观察：r=16 时应捕获 95%+ —— 这就是"低秩更新足够"的数学含义
# 思考题：把 dW 换成纯随机矩阵 np.random.randn(d,k)，能量曲线会怎么变？为什么？
```

预期输出：起点一致为 True；单层参数压缩 256 倍；r=16 捕获 95% 以上能量而纯随机矩阵需要几千个奇异值——亲手验证"微调更新本征秩低"这一 LoRA 的立身之本。
