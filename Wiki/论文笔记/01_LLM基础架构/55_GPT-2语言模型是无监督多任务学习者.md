# GPT-2：语言模型是无监督多任务学习者

📄 **原文 PDF**：[[RAW/55 - Language Models are Unsupervised Multitask Learners.pdf]]

## PM 速判
> 一句话：GPT-2 证明只要语言模型足够大、数据足够好，它不需要任何微调就可以在翻译、摘要、问答等任务上"涌现"出零样本能力——"语言模型 = 多任务系统"的命题首次被大规模验证，是 prompt engineering 的思想源头。

## 双层费曼
> **给 CEO 的一句话**：以前想让 AI 学会翻译，你得准备几百万条中英对照的句子。GPT-2 说：不用。只要把 AI 在互联网上的 800 万篇好文章上训练得足够大，它自己对"语言是怎么工作的"就有了深刻理解。你只需用自然语言告诉它"请把下面这句英文翻译成中文"，它就能做——不需要任何翻译训练数据。一个模型，同时会翻译、会写摘要、会回答问题。——这就是今天 ChatGPT 能听懂人话的根本原因。

> **给工程师的一段话**：GPT-2 将 GPT-1 的参数量从 117M 扩展到 1.5B（4 个规模：117M/345M/762M/1.5B），在 WebText（从 Reddit 获至少 3 karma 的帖子的外链页面构造的 40GB 精选文本，覆盖约 800 万文档）上做标准自回归语言模型预训练。核心范式转变：所有 NLP 任务被统一为 p(output | input, task_description) 的条件文本预测——翻译就是 "Translate to French: {english} => {french}"，阅读理解就是 "{passage} Q: {question} A:"。不做任何梯度更新（zero-shot），GPT-2 在 8 个语言任务中的 7 个达到或超越了当时的有监督基线。规模律初步浮现：模型越大，zero-shot 越好。

## 问题域定位
- **回应什么根本约束？** 监督数据的可获得性和任务泛化的矛盾。GPT-1 虽然减少了每个任务需要的标注量，但仍然需要标注数据做微调。对于长尾任务（如特定领域的翻译、小众语言的摘要），标注数据根本不存在。根本问题：能否让一个模型在不接触任何标注的情况下完成任意任务？
- **之前卡在哪？** 没有人尝试过"零样本多任务"。原因：(1) 没有足够大的高质量文本数据集来支撑通用语言理解；GPT-1 的 BooksCorpus 只有 7000 本书，覆盖面窄。(2) 没有人敢声称"语言建模能力等同于任务解决能力"——这需要证据。(3) GPT-1 的规模（117M）可能太小，无法展现零样本能力——多任务泛化可能需要规模阈值。
- **开启/关闭了哪条技术路线？** 开启了"语言模型即世界模型"的路线——GPT-2 的核心哲学是：世界知识、推理能力、任务执行能力都可以从文本预测中学到。这直接导向了 scaling law 研究、GPT-3 的 ICL、以及"无需微调"的通用模型追求。关闭了"每个任务都需要明确监督信号"的假设——虽然 GPT-2 的 zero-shot 尚未达到实用水平，但它的 proof-of-concept 改变了整个领域的信念。

**规模律关键发现**：随着模型从 117M → 345M → 762M → 1.5B，zero-shot 性能在大多数任务上呈现平滑的 log-线性提升，没有明显的平台期。这意味着更大的模型很可能会继续变好——这条曲线直接催生了 GPT-3 的 175B。

## 设计决策解剖

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 任务范式 | 零样本（zero-shot）：仅靠 prompt 描述任务，无任何示例 | 微调（GPT-1 方式）或少样本（later GPT-3 方式） | 这是本论文最激进的选择——作者想回答"语言模型到底能不能不靠任何示例学会做任务"这个根本问题。如果加示例，就变成了"从示例中学"而非"从语言理解中学"。这是哲学选择，不是工程选择 | 当任务描述过于隐晦或需要精确输出格式时，zero-shot prompt 的不确定性导致输出质量波动极大。GPT-3 后来证明在 prompt 前面加 3-5 个示例（few-shot）显著稳定了输出，且不需要改变核心框架 |
| 数据集构造 | WebText（Reddit 3+ karma 外链，800 万页，40GB） | Common Crawl（数 TB 但噪声极高）或 Wikipedia + Books（太窄） | Reddit 点赞充当了天然的"质量过滤器"：(1) 被 Reddit 用户贴出的页面已经过人工筛选，通常是信息丰富、写作良好的内容；(2) ≥3 karma 过滤掉了低质量链接。这个设计后来被证明是 GPT-2 零样本能力的关键——数据质量 > 数据量 | 当模型规模继续扩大（GPT-3 级别），40GB 不够用了。但 GPT-3 沿用了思路：Common Crawl 过滤 + 高质量源加权重采样。此外，Reddit 筛选会引入特定的文化偏见（英语、西方视角、互联网亚文化），对非英语任务不友好 |
| LayerNorm 位置 | Pre-norm（LayerNorm 放在 attention/FFN sub-block 前） | Post-norm（原始 Transformer 的 LayerNorm 在 sub-block 后） | Pre-norm 让训练更稳定：梯度可以通过残差连接直接传播到底层，不需要先经过 LayerNorm 的压缩。这对深层网络（48 层）尤为关键——post-norm 在 48 层下容易出现梯度消失 | 当网络不是特别深（<20 层）时，post-norm 和 pre-norm 差异不大。有些研究发现 pre-norm 会轻微降低最终表示质量（因为残差路径太"自由"），但这在规模面前被证明可忽略 |
| 残差权重缩放 | 初始化时残差层权重按 1/√N 缩放（N 为残差层数） | 标准 He/Xavier 初始化（不考虑层深度） | 随着层数增加（GPT-2 有 48 层），残差分支的累积效应会让输出方差随深度线性增长。1/√N 缩放保证每层输出的方差大致恒定，防止深层激活爆炸 | 当使用 gradient checkpointing 或 mixed precision training 时，缩放因子的精度可能不足；当模型层数不太深（<24）时，不做这个缩放也能正常训练 |

## 成本与量级
- **训练成本**：1.5B 的 GPT-2 在 32 块 TPUv3 上训练约 1 周。总计算量约 100 PFLOP-days。对比：GPT-1 约 1 PFLOP-day（100 倍增长）。按 2019 年云 GPU 价格，约 $40K-$80K 的预训练费用。
- **推理成本**：1.5B 参数的 GPT-2 单次前向约需 3GB 显存，推理延迟约 100-300ms/token（2019 GPU），对于实时应用偏慢（这也是当时"不发布大模型"的部分理由——太容易被滥用但普通用户跑不动）。
- **最小可行配置**：HuggingFace 的 GPT-2（1.5B）可在 1× A100 上本地推理，约 30-50ms/token。如果只想复现零样本实验，用 GPT-2 Medium（345M）即可观察到显著的零样本能力（虽然不如 1.5B），单 T4 即可运行。

## 证据审计
- **实验设计公平吗？** 实验设计更偏向"证明这个方向有价值"而非"证明这个方法最好"。GPT-2 在 8 个任务中的 7 个达到了"有监督基线"的水平，但这 7 个任务中有些被挑选的基线并不是真正的 SOTA。例如翻译任务的"基线"是无监督机器翻译（UNMT），而非当时最强的有监督 NMT。CoQA 上 GPT-2 的 F1 55（vs 有监督 89）——作者选了一个有利的对比方式（vs 无监督基线而非有监督 SOTA），这在一定程度上模糊了 GPT-2 与实用水平的差距。
- **最强证据**：Children's Book Test（CBT）上的 Common Noun 完形填空达到 93.3%（人类水平约 96%）——且这个提升是平滑的（从 117M 的 85% → 1.5B 的 93.3%），展示了清晰的规模律。LAMBADA（长程依赖语言建模）从 GPT-1 的 63.3% 提升到 59.2%（等等，这里是 perplexity，越低越好：99→8.6，准确率 19%→52.7%）——这个任务需要模型理解长达 50+ 个 token 的上下文才能正确预测最后一个词，证明了 GPT-2 掌握了真正的长程理解而不仅仅是模式匹配。
- **最可疑的数字**：摘要任务中报告的"human quality ratings"。GPT-2 在 CNN/DailyMail 上生成摘要的"人类评分"声称与 ground truth 摘要"质量相似"，但这一评估使用的是单维度 1-3 分评分，且评估者对"机器生成摘要"的评判标准通常比"人工摘要"更宽容（已知评估偏差）。此外，GPT-2 最擅长的是提取式摘要（从原文复制句子）而非生成式摘要（用自己的话重新表达），文中没有区分这两种能力的贡献。
- **审稿人会要求补充**：(1) 不同数据源（Reddit 外链 vs Wikipedia vs Books）对各任务零样本能力的消融贡献——这能区分"规模"和"数据质量"各自的作用。(2) 零样本能力与预训练数据中相似任务的出现频率之间的关系——模型是真的"学会了"翻译，还是仅仅在预训练数据中见过翻译例句？(3) 更多次数的重复实验（不同随机种子）以排除"运气好"——论文只 train 了一组模型。
- **最小复现实验**：用 HuggingFace 的 GPT-2（1.5B）在三个任务上测试 zero-shot prompt 设计不同的效果：(1) 翻译（en→fr），(2) 摘要（TL;DR），(3) QA（Q: ... A:）。对比有无自然语言任务描述的性能差异。预算：单 A100，数小时推理（无需训练）。核心验证：prompt 设计对零样本能力的影响，以及是否真的存在"涌现"（345M 和 1.5B 之间的能力跳跃）。

## 可复用点
- **何时采用**：当你有零标注的 NLP 任务需求时，GPT-2 的思路（prompt-based 零样本推理）是首选策略，但应该用现代替代方案：(1) 用 GPT-3.5/4 或 Claude API 直接做 few-shot/zero-shot 推理；(2) 用 FLAN-T5 或 Alpaca 等 instruction-tuned 开源模型做零样本推理。GPT-2 的历史价值：验证了这条路可行，但本身已不是最佳选择。
- **何时规避**：纯 zero-shot 对于需要精确输出格式的任务（如结构化信息提取、代码生成中的语法约束）波动太大。此时应该：加 few-shot 示例（GPT-3 方式），或考虑微调（GPT-1 方式），或使用 constrained decoding（如 outlines 库的 JSON schema decoding）。
- **供应商拷问清单**："你们的模型预训练数据是怎么筛选和清洗的？数据质量如何保证？""你们的模型支持多大规模的零样本推理？零样本和少样本性能差距多大？""预训练数据中是否包含了评估基准的数据——如何防止数据污染？"

## 关联网络

- [[Wiki/论文笔记/01_LLM基础架构/60_GPT-3语言模型是小样本学习者]] — GPT-3 将 GPT-2 的零样本范式扩展为 few-shot ICL，增加示例显著提升了任务执行的稳定性和准确性。GPT-2 的"语言模型即任务求解器"哲学在 GPT-3 中完全实现
- [[Wiki/概念/03_推理与评测/思维链与推理模型]] — Chain-of-Thought prompting 的基础是 GPT-2 建立的"语言模型可以理解并执行自然语言任务指令"这一前提。没有 GPT-2 的概念验证，就没有后续的 CoT
- **冲突/印证**：与 BERT [[Wiki/论文笔记/01_LLM基础架构/53_BERT深度双向Transformer预训练]] 在哲学上构成冲突——BERT 证明"针对理解任务，双向 encoder + 特定预训练目标（MLM）是最优的"，GPT-2 则主张"只要语言模型够大，什么都不需要的单向 LM 也能做所有任务"。短期看 BERT 在 NLU 上是正确的（GPT-2 的零样本表现远不如 BERT 微调），长期看 GPT-2 的 scaling 哲学胜出。**印证**：GPT-2 的规模律趋势与 Kaplan et al. (2020) 的 scaling laws 论文完全一致——验证了"大模型更好"不是个别现象而是系统规律。

## 动手练习（40-60行，可运行Python代码）
练习目标：设计 prompt 让通用模型（GPT-2）同时完成翻译、摘要、问答三个任务——证明 zero-shot transfer 的存在，并观察模型规模对零样本能力的影响。

```python
"""
GPT-2 动手练习：设计 prompt 实现零样本多任务迁移
练习目标：用一个未微调的 GPT-2 同时完成翻译/摘要/QA，验证 GPT-2 的核心 claim
环境：pip install transformers torch
"""

from transformers import GPT2LMHeadModel, GPT2Tokenizer
import torch

# ============================================================
# 第 1 步：加载两个规模的 GPT-2 以对比规模效应
# ============================================================
print("=" * 60)
print("GPT-2 零样本多任务实验")
print("=" * 60)

# 加载 GPT-2 Medium（345M）— 观察中等模型的零样本能力
# 加载 GPT-2 XL（1.5B）— 观察大模型的涌现能力
# 两个模型都在 WebText 上预训练，均未在任何下游任务上微调
device = "cuda" if torch.cuda.is_available() else "cpu"
print(f"使用设备: {device}")

tokenizer = GPT2Tokenizer.from_pretrained("gpt2")
tokenizer.pad_token = tokenizer.eos_token

model_medium = GPT2LMHeadModel.from_pretrained("gpt2-medium").to(device)
model_medium.eval()
print("已加载 GPT-2 Medium (345M)")

# 注：如果显存不够，可只加载 Medium 或 Small (117M)
# model_xl = GPT2LMHeadModel.from_pretrained("gpt2-xl").to(device)
# model_xl.eval()
# print("已加载 GPT-2 XL (1.5B)")

# ============================================================
# 第 2 步：定义通用推理函数
# ============================================================
def generate_with_prompt(model, tokenizer, prompt, max_new_tokens=50):
    """给定 prompt，用 GPT-2 生成续写（模拟零样本任务执行）"""
    inputs = tokenizer(prompt, return_tensors="pt").to(model.device)
    with torch.no_grad():
        outputs = model.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            do_sample=True,
            temperature=0.7,
            top_p=0.9,
            pad_token_id=tokenizer.eos_token_id,
        )
    # 只返回新生成的部分（去掉 prompt）
    full_text = tokenizer.decode(outputs[0], skip_special_tokens=True)
    return full_text[len(prompt):].strip()

# ============================================================
# 第 3 步：三个零样本任务测试
# ============================================================

# 任务 A：翻译（英→法）—— 需要语言转换能力
prompt_translate = (
    "English: The weather is beautiful today.\n"
    "French: Le temps est beau aujourd'hui.\n\n"
    "English: I love reading science fiction books.\n"
    "French:"
)
print(f"\n{'='*60}")
print("任务 A: 翻译 (English → French)")
print(f"Prompt: ...English: I love reading science fiction books.\nFrench:")
result_A = generate_with_prompt(model_medium, tokenizer, prompt_translate, max_new_tokens=20)
print(f"GPT-2 生成: {result_A}")

# 任务 B：摘要（TL;DR 格式）—— 需要信息压缩能力
prompt_summarize = (
    "Article: Scientists have discovered a new species of deep-sea fish "
```
