> **这篇论文给 PM 的一句话**：Agent 在发布第一天的评测成绩**不能预测**它在第 50 次会话或第 200 次会话时的可靠性——即使模型权重固定，随着 Agent 压缩对话历史、往记忆库写入更多信息、处理事实更新和系统维护，**可靠性会系统性下降**；AgingBench 提供了四类老化机制和诊断框架，让 PM 能说出"我的 Agent 正在因为什么原因老化"。

## 四类老化机制（带时间锚）📅 2026

| 老化类型 | 机制 | 典型症状 | 典型场景 |
|---------|------|---------|---------|
| **压缩老化** | 写入时摘要丢失了未来会查询到的细节 | "我的用药剂量是多少？" → 只记得"每天一次"，忘了剂量数值 | 医疗助手、长期个人助理 |
| **干扰老化** | 相似记忆越来越多，目标记录被淹没 | "给 John Smith 发邮件" → 混淆了 John Smyth | 企业知识库、多客户管理 |
| **修订老化** | 事实更新后，衍生状态没有同步传播 | 预算余额（初始值 + 每次增减）因遗漏一次增量而永远跑偏 | 财务助手、项目管理 |
| **维护老化** | flush/压缩/迁移/prompt 变更等日常运维事件静默地改变行为 | 数据库重建后，之前记住的约束失效 | 所有长期部署系统 |

## 诊断框架：三级反事实探针

```
P1 (写入探针)：给 Agent 写入完整的当前状态 → 如果回答正确，说明问题在写入阶段
P2 (检索探针)：直接注入正确的记忆块到上下文 → 如果正确，说明问题在检索阶段
P3 (利用探针)：把正确答案直接放到上下文 → 如果正确，说明问题在利用/理解阶段

诊断路径：
  P1 失败 → 写入时就丢了（压缩老化的直接信号）
  P1 成功 + P2 失败 → 检索时找不到（干扰老化）
  P2 成功 + P3 失败 → 检索到了但没用好（理解/利用问题）
  P3 都成功 → 不是内存问题，是模型推理问题
```

## 核心结论

1. **老化不是单维度的**：行为测试（回答是否正确）可能显示良好，但事实精度（细节值是否准确）已在衰减 📅 2026
2. **派生状态最脆弱**：累计值（预算 = 初始 + Σ增减）一旦丢失增量就永久偏差，且越滚越大 📅 2026
3. **干预有效**：
   - 修订老化：类型化状态覆盖（JSON sidecar 存储精确数值）→ 错误减少 25-47%
   - 主动控制：阈值触发的运行时控制器 → 达到全干预效果的 91%

## 对 AI PM 的启示

| 场景 | 洞察 |
|------|------|
| **产品上线前评估** | Day-1 评测不等于长期可靠性；需要跨多会话的纵向测试 |
| **SLA 设计** | 为"第 X 次会话后的可靠性"设置 SLA，而不仅是"首次准确率" |
| **运维监控指标** | 追踪事实精度（具体数值准确率），而非仅对话成功率 |
| **派生状态的存储** | 预算/计数/累计值等**不要只存在自然语言记忆**中；用结构化 sidecar（如 JSON）存储 |
| **维护窗口风险** | 内存压缩/系统升级等维护事件会静默影响 Agent 行为，需要回归测试 |

## 论文精读卡片

**一句话**：AgingBench 定义了压缩/干扰/修订/维护四类 Agent 老化机制，实验（7 场景×14 模型×~400 运行×8-200 会话）证明行为测试正常但事实精度已衰减，类型化状态覆盖（JSON sidecar）可减少 25-47% 修订老化错误。

**问题**：现有 Agent 评测只测 Day-1 性能，无法预测 Agent 在第 50/200 次会话后的可靠性——而部署 Agent 的可靠性会因压缩历史、累积记忆、运维维护等原因系统性下降，这是 PM 和工程团队都忽视的问题。

**核心方法**：
- 定义四类老化机制：压缩老化（写入摘要丢失细节）/ 干扰老化（相似记忆互相污染）/ 修订老化（事实更新未传播）/ 维护老化（运维事件静默改变行为）
- 三级反事实诊断探针：P1（写入完整状态）/ P2（注入正确记忆块）/ P3（直接提供正确答案），逐级定位故障阶段
- 主动干预：类型化状态覆盖（JSON sidecar 存精确数值）+ 阈值触发运行时控制器

**关键图/公式**：三级探针诊断路径：P1 失败→写入时丢失（压缩老化）；P1 成功+P2 失败→检索失败（干扰老化）；P2 成功+P3 失败→利用失败（推理问题）；三者全通→模型推理问题非记忆问题。

**实验设置**：
- 规模/数据：7 个任务场景（医疗/财务/企业/个人等），14 个模型，~400 次运行，8-200 个会话
- 对比：无干预基线 vs 类型化状态覆盖 vs 主动运行时控制器

**最强证据**：类型化状态覆盖（JSON sidecar）减少修订老化错误 25-47%；主动运行时控制器达到全干预效果的 91%；行为测试正常而事实精度已衰减——"表面正常"掩盖了真实可靠性下降。

**最弱证据**：仅测试 8-200 会话，超长期（1000+ 会话）的老化曲线未知；四类老化机制的相互作用（如同时出现压缩+干扰老化）未系统测试；14 个模型中不同架构的老化速率差异未重点分析。

**可复用点**：三级反事实诊断探针（P1/P2/P3）是现成可用的调试框架，用于定位任何 Agent 记忆故障；JSON sidecar 存储累计/精确数值（预算/计数/状态）是防止修订老化的最小成本干预。

- 为部署的 Agent 产品设计"老化测试"：在 50/100/200 会话后的纵向事实精度测试，而不只是 Day-1 准确率
