# 从成功之流追踪 Agentic 失败（Tracing Agentic Failure from the Flow of Success）

📄 **原文 PDF**：[[RAW/182 - Tracing Agentic Failure from the Flow of Success.pdf]]
arXiv:2607.12747v1（2026-07-14），30 页（正文 9 页 + 详尽附录），UW-Madison × MSR，代码数据开源

## PM 速判（30秒）
> 一句话：把「Agent 失败归因」（几十上百步的轨迹里哪几步导致任务失败）从「用前沿 LLM 读轨迹打标」翻转成**无监督单类学习**：只用约 100 条**成功**轨迹训练一个 3 层 MLP 驱动的 Neural CDE，学会「成功轨迹在隐空间里的正常流动」，推理时给失败轨迹每一步打偏离分——结果 F1 比提示 GPT-5 高 20 个点（域内）/7 个点（OOD），**零 token 成本、7-16 毫秒出结果、快 200-5000 倍**、显存不到 1GB。PM 必须知道：失败数据难标（标注贵且天然有歧义），但成功数据是系统正常运行的免费副产品——这个「只学正常、异常自现」的思路能把 Agent 可观测性做成实时在线服务而不是离线人工尸检。

## 双层费曼 🗣️
> **给 CEO 的一句话**：Agent 出错后要人工回看几百步日志找病根，一次几小时；这个方法像给流水线装了心电图机——它只见过健康心跳（成功任务的运行模式），任何一步偏离健康节律就立刻报警标红，不用请专家（前沿大模型）会诊，毫秒级、几乎零成本，而且比请 GPT-5 会诊找得还准。
>
> **给工程师的一段话**：方法叫 OAT（One-class Agent Tracing）。表征：每步 t 取执行该步的 LLM（Qwen3.5-27B）生成 action a_t 时的末层 hidden states 做 mean-pooling，PCA 降到 64 维，得 H(τ)=(h_1..h_T)，时间归一化到 [0,1]。建模：把成功轨迹当作连续潜路径的不规则采样，用 Neural CDE——z(u)=z(0)+∫f(v,z;θ_f)dX̃(v)，控制路径 X 由步表征三次样条插值而成，其导数在每个积分步持续调制潜动力学（对比 Neural ODE 只吃初始条件、只能表达单一确定流，无法容纳「多条不同动作序列都能成功」）；创新点是**门控控制路径**：gating 网络 q 对样条导数逐元素调权，OOD 输入的异常导数被抑制，防止分布外控制信号搅乱潜状态（OOD AUROC +0.172，域内只损 0.028）。训练目标：重建每步表征 Σ‖h_t-ĥ(u_t)‖²，只用成功轨迹。推理：失败轨迹每步的重建误差 e_t 即异常分；判定用 top-k（k=3）或 conformal prediction（校准集取成功轨迹步分的 1-α 分位做阈值，α=0.2，对分布内步的假阳率有分布无关保证）。数据：MCP-Atlas 采样（Qwen3.5-27B 跑 203 任务→103 成功训练/88 失败人工标注测试，平均 7.2 步）；OOD 用 Who&When（GPT-4o 生成的 184 条多智能体失败轨迹，平均 20.3 步，另用 CORAL 对齐二阶统计量）。结果：域内 F1 0.435（CP）vs GPT-5 0.181、GPT-4o 0.212；OOD F1 0.225（top-k）vs GPT-5 0.152；AUROC 域内 0.629 / OOD 0.758。

## 问题域定位 🎯
- **根本约束**：失败归因的监督信号天然稀缺且脏——步级错误标注要靠「若在此步干预能否翻盘」的反事实 oracle，人工标不出也标不一致；而提示法要前沿 LLM 在线读全轨迹，token 成本与延迟使其无法部署为实时监控。Who&When 已证明最强推理模型的定位准确率不足 15%。
- **之前卡在哪**：监督路线（AgentTracer 用 GRPO 在合成失败轨迹上后训练、GraphTracer）被标注瓶颈卡死且只建模单步干预、抓不住复合错误；提示流水线路线贵且慢；机器人学有「只学正常执行、整条轨迹级报异常」的传统，但从未下探到**步级**归因。
- **开启/关闭的路线**：开启「无监督失败归因」新问题设定与「LLM 隐表征作为轨迹动力学载体」的路线（连续时间建模第一次接进 agentic 诊断）；削弱「失败归因必须靠更强 LLM 读轨迹」的默认路线。

## 核心机制（ASCII 图）

```
 训练阶段（只见成功轨迹，无任何步级标注）
   成功轨迹 τ: Q → a1 → a2 → ... → aT
        │ 每步取执行 LLM 的末层表征(mean-pool)+PCA64
        ▼
   h_Q, h_1 ... h_T  ──三次样条插值──►  控制路径 X(u), u∈[0,1]
        │                                   │ dX/du
        │                          ┌────────▼─────────┐
   z(0)=g2(h_Q) ──► Neural CDE: dz = f(v,z)·[q(dX/du)⊙dX/du]·dv
        │                          └──── 门控 q 抑制OOD导数 ────┘
        ▼
   重建 ĥ(u_t)=g1(z(u_t))，损失 Σ‖h_t-ĥ(u_t)‖² → 学会"成功的流形"

 推理阶段（给失败轨迹）
   每步异常分 e_t = ‖h_t - ĥ(u_t)‖²   （偏离成功动力学的程度）
        │
        ├─ Top-k：取分最高的 k=3 步（需先验知道错误步数量级）
        └─ Conformal：阈值 λ = 校准集成功步分的(1-α)分位
                      e_t > λ 即标错 → 对正常步误报率≤α（分布无关保证）
   输出：失败贡献步集合 ŷ(τ)（支持多步复合错误，非单步definite root cause）
```

### 数据与标注细读（附录 D/E）
- **MCP-Atlas 侧**：36 个真实 MCP server、220 个工具、1000 任务的公开子集里选了 203 个可免费访问 API 的任务；Qwen3.5-27B 既当执行 agent 又当 claims-rubric 的 judge（人工复核全部判分）；103 成功 / 100 失败，剔除 12 条纯基础设施故障（某搜索 API 恒超时）后标注 88 条。
- **标注规则**：三类错误步——推理内容幻觉、工具调用错参数、未妥善处理的工具报错返回；探索性搜索的第一次失败尝试不算错，**同一查询原样重发才算**（不适应=错误）；作者标注+歧义共识裁决，无第三方标注者。
- **Who&When 侧**：GAIA + AssistantBench 任务、CaptainAgent 与 Magnetic-One 两套多智能体系统、GPT-4o 底座；每条只标「第一个决定性错误」单步——与 OAT 的「多步贡献集合」定义存在口径错位，OOD 指标天然吃亏也天然模糊。

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 监督形态 | 单类学习：只用成功轨迹，把失败步当「偏离正常流」的异常 | 监督训练（步级标注失败轨迹）/ 提示前沿 LLM | 成功轨迹是正常运营免费副产品；步级失败标注贵且依赖不可得的反事实 oracle | 「异常≠失败原因」：新颖但正确的解法路径也会高分误报；系统性失败（所有轨迹都带同种坏习惯、成功只是运气）学不出来——正常流本身被污染 |
| 轨迹建模 | Neural CDE（观测持续调制潜动力学）+ 门控控制路径 | Neural ODE（仅初始条件驱动）/ RNN / Transformer | ODE 的确定流装不下「多条路都能成功」；离散模型不吃不规则变长轨迹；消融证明 CDE 全面胜 ODE 与 RNN | 轨迹极短（2-3 步）时连续建模没有信息量优势；步语义剧变（新工具集/新 agent 拓扑）时样条插值的「连续性假设」本身不成立 |
| 表征来源 | 执行 agent 同款 LLM（Qwen3.5-27B）末层 mean-pooling + PCA64 | 提示 LLM 输出文本判断 / 浅层表征 / 末 token | 隐表征含超越生成文本的丰富信号；消融显示越深层越好（64 层 > 早层）、mean-pool > last-token | 被诊断系统用闭源模型时拿不到 hidden states，只能用代理模型重编码——表征与真实生成过程脱钩（Who&When 上正是这么做的，性能确实明显低于域内） |
| 判定阈值 | conformal prediction：成功步分布的分位数阈值，误报率≤α 有分布无关保证 | 固定 top-k / 人工调阈值 | 错误步数量随任务变化（MCP-Atlas 平均 1.56、最多 12），自适应阈值免先验；CP 给的是可解释的运营参数 α | CP 保证的是「对**分布内正常步**的假阳率」，不是「对真实错误步的召回」——分布漂移时保证失效（所以才需要 CORAL 补丁） |
| OOD 适配 | PCA 只在域内拟合 + CORAL 对齐 OOD 表征的二阶统计量 | 直接零样本迁移 / 用 OOD 数据微调 | 无标注 OOD 场景下对齐协方差是最便宜的域适配 | CORAL 需要拿到 OOD 数据集合的统计量——严格说是 transductive（先看见测试分布才校准），纯在线单条轨迹到来时不可用 |

## 成本与量级 💰
- **训练**：~100 条成功轨迹（103 条的 80% 训练 / 20% 校准）、3 层 MLP（隐层 64）+ 门控网络（隐层 12）、300 epoch——单卡分钟级，几乎零门槛。
- **推理**：**0 token 成本**、latency 7ms（MCP-Atlas）/ 16ms（Who&When），对比 GPT-4o 约 4.2-4.5 秒、GPT-5 约 38-40 秒（3000 输出 token 量级）→ 200-5000 倍加速；部署 <1GB VRAM（不含表征提取的 27B 模型——这笔账见证据审计）。
- **数据成本结构的翻转**：监督路线要标 88 条失败轨迹的步级错误（作者自己动手+共识裁决才搞定）；本方法只要判「整条成功与否」（claims rubric + LLM judge + 人工复核），标注粒度从步级降到轨迹级。
- **我的产品最小可行配置**：日志里攒 100+ 条成功轨迹 → 用产品同款（或最近的开源）模型抽步表征 → 训 OAT → 以 α=0.2 的 CP 阈值上线做失败工单的自动标红，人工只复核标红步。

## 证据审计 🔬
- **实验公平吗**：三处必须警惕。①**域内设置对 OAT 有天然主场优势**：训练轨迹、测试轨迹、表征提取用的全是同一个 Qwen3.5-27B——模型「自己的表征流」当然最懂自己；而 GPT 基线只能读文本。②基线弱得可疑：**GPT-5 域内 F1 0.181 连 Random-Step 的 0.255 都不如**——很大程度是集合式指标的口径伪影（random 恰好只选 1 步而真值平均 1.56 步，precision 占便宜；GPT 输出步集合大小不受控），这暴露的是指标设计而非模型能力。③OOD 结果依赖 CORAL 用测试集统计量做对齐（transductive），纯在线场景成绩会低于表中数字。
- **最强证据**：效率与消融。200-5000× 加速与 0 token 是硬事实；CDE>ODE、CDE>RNN、门控 OOD +0.172 AUROC、深层>浅层、mean-pool>last-token 的消融链条完整自洽；OOD AUROC 0.758（结构完全不同的多智能体轨迹、不同底座模型生成）说明「偏离成功流」的信号真实跨域存在。
- **最可疑的数字**：域内 hit rate 0.777（top-k=3）——MCP-Atlas 轨迹平均仅 7.18 步，随机选 3 步命中≥1 个错误步（平均 1.56 个）的期望本来就高（粗算约 55-60%），0.777 的绝对值远没有相对随机 1 步基线（0.284）看起来那么神；论文没报「随机选 3 步」的对照。另外作者自标注自评测（无独立标注者、无 inter-annotator agreement 数字），定义上「meaningfully degrades」的主观性未被量化。
- **如果我是审稿人**：①要求补 Random-3 与「GPT 限定输出 k=3 步」的口径对齐基线；②失败案例分析承认 OAT 常抓到「失败被显式说出来的那步」而非根因——要求按「根因步 vs 症状步」分开报召回；③要求报告无 CORAL 的纯零样本 OOD 数字；④表征提取依赖 27B 模型前向，端到端延迟应含这一段（7ms 只是 CDE 部分）。
- **最小复现实验**：不需要 LLM——本笔记练习用线性动力系统模拟「成功流+注入异常步」验证单类残差+conformal 阈值的机制有效性；真实复现用作者开源代码 + 任意 MCP agent 日志 100 条成功轨迹即可，主要成本是抽表征的 GPU 时数（<10 美元）。

## 可复用点（PM 决策）
- **何时采用**：①Agent 产品有稳定的成功轨迹日志流、失败率不高但失败诊断贵（客服工单升级、代码 agent 回归分析）；②需要实时/在线失败标红而非离线尸检；③合规要求本地部署、不能把轨迹发给前沿 API。
- **何时规避**：①agent 行为高度多样/探索性强（新颖成功路径会被当异常轰炸）；②系统性缺陷场景（成功轨迹本身带病，单类学习学到的「正常」就是病态）；③闭源模型且拿不到 hidden states、任务域又与代理模型差太远。
- **供应商拷问清单**：
  1. 你们的失败归因是提示大模型读日志，还是有训练过的轻量模型？单条轨迹的归因成本和延迟是多少？
  2. 训练需要什么标注？步级失败标注的标注者一致性有数字吗？
  3. 归因的是「根因步」还是「症状步」（失败被说出来的那步）？两者分开评过吗？
  4. 误报率可控吗——阈值有 conformal 类的统计保证还是拍脑袋？α 调大调小的 precision/recall 曲线？
  5. 换 agent 拓扑/换底座模型后（OOD）性能掉多少？域适配需要拿到多少目标域数据？
  6. 新颖但正确的解法路径会不会被标红？对探索性行为的白名单机制是什么？

## 动手练习 💻（约 40 分钟）
练习目标：用一个线性动力系统玩具版复现 OAT 机制——只在「成功流」上学动力学，用重建残差+conformal 阈值定位失败轨迹里被注入的异常步。

```python
import random, math                          # 全标准库；用线性动力学代替 Neural CDE

random.seed(0)
D = 4                                        # 潜表征维度（论文里是 PCA 后 64 维）

# "成功流"的真实动力学：h_{t+1} = A·h_t + 微噪声（论文里由 Neural CDE 学出）
A = [[0.9 if i == j else (0.1 if (i + 1) % D == j else 0.0)
      for j in range(D)] for i in range(D)]  # 一个稳定的旋转衰减矩阵

def step(h, noise=0.02):
    """按成功动力学走一步（每维加小噪声，模拟成功轨迹的自然波动）"""
    return [sum(A[i][j] * h[j] for j in range(D)) + random.gauss(0, noise)
            for i in range(D)]

def gen_traj(T, fail_steps=()):
    """生成一条轨迹；fail_steps 里的步注入大幅偏离（模拟幻觉/错参数步）"""
    h = [random.gauss(0, 1) for _ in range(D)]
    traj = [h]
    for t in range(1, T):
        h = step(h)
        if t in fail_steps:                  # 异常步：偏离成功流形的跳变
            h = [x + random.choice([-1, 1]) * random.uniform(0.8, 1.2) for x in h]
        traj.append(h)
    return traj

# ---- 训练：最小二乘拟合动力学 Â（对应 OAT 训练 f 重建成功流）----
train = [gen_traj(random.randint(6, 12)) for _ in range(80)]     # 80 条成功轨迹
X, Y = [], []
for tr in train:
    for t in range(len(tr) - 1):
        X.append(tr[t]); Y.append(tr[t + 1])                     # (h_t, h_{t+1}) 对
A_hat = [[0.0] * D for _ in range(D)]
for i in range(D):                           # 逐维岭回归（正规方程，纯手写）
    G = [[sum(x[a] * x[b] for x in X) + (0.01 if a == b else 0)  # X^T X + λI
          for b in range(D)] for a in range(D)]
    b_vec = [sum(x[a] * y[i] for x, y in zip(X, Y)) for a in range(D)]
    for c in range(D):                       # 高斯消元解线性方程组
        piv = G[c][c]
        for r in range(c + 1, D):
            f = G[r][c] / piv
            for k in range(c, D): G[r][k] -= f * G[c][k]
            b_vec[r] -= f * b_vec[c]
    w = [0.0] * D
    for c in range(D - 1, -1, -1):
        w[c] = (b_vec[c] - sum(G[c][k] * w[k] for k in range(c + 1, D))) / G[c][c]
    A_hat[i] = w

def anomaly_scores(tr):
    """每步异常分 = 实际表征与预测表征的距离平方（对应论文式(10)）"""
    scores = [0.0]
    for t in range(1, len(tr)):
        pred = [sum(A_hat[i][j] * tr[t - 1][j] for j in range(D)) for i in range(D)]
        scores.append(sum((a - b) ** 2 for a, b in zip(tr[t], pred)))
    return scores

# ---- conformal 校准：成功轨迹步分的 (1-α) 分位当阈值（论文式(12)）----
calib = [s for _ in range(20) for s in anomaly_scores(gen_traj(10))]
alpha = 0.2
lam = sorted(calib)[int((1 - alpha) * len(calib)) - 1]

# ---- 推理：失败轨迹（第 3、7 步注入错误），看能否标出 ----
fail = gen_traj(10, fail_steps={3, 7})
scores = anomaly_scores(fail)
flagged = [t for t, s in enumerate(scores) if s > lam]
print(f"conformal 阈值 λ={lam:.3f}（正常步误报率≤{alpha}）")
print("步号:异常分 =", {t: round(s, 2) for t, s in enumerate(scores)})
print(f"标红步 = {flagged}，真值 = [3, 7]")
# 实测（seed=0）：恰好标出 [3, 7]，与真值完全一致，其余步分数≈0。
# 注意本玩具里注入步之后的步不报警——因为下游演化仍遵循学到的动力学
# （h_4 = A·被污染的h_3，预测与实际同源）；真实 OAT 中传播步常一并高分，
# 因为 LLM 的表征流在错误后整段偏离成功流形（论文案例：幻觉步+传播步双标红）
```

## 自测三层 🎓
> 判分点随笔记入库；自测先作答再展开。L1 不过不进 L2/L3——答错即记卡点。

> [!question]- L1 复述：OAT 的训练数据是什么、不需要什么？Neural CDE 相比 Neural ODE 多了什么机制（控制路径）？conformal 阈值保证的是什么、不保证什么？
> **参考答案**：训练数据 = 约 100 条成功轨迹，每步取执行 LLM 的末层 hidden states 做 mean-pooling 再 PCA 到 64 维；不需要任何步级失败标注，也不需要失败轨迹参与训练——标注粒度从步级降到轨迹级成败。Neural ODE 只吃初始条件、只能表达单一确定流，装不下「多条不同动作序列都能成功」；Neural CDE 引入控制路径 X（步表征的三次样条插值），其导数在每个积分步持续调制潜动力学，OAT 再加门控网络 q 对样条导数逐元素调权、抑制 OOD 异常导数。conformal 阈值（校准集成功步分的 1-α 分位）保证的是对分布内正常步的假阳率≤α（分布无关）；不保证对真实错误步的召回，且分布漂移时保证失效（所以 OOD 要 CORAL 补丁）。
> **判分点**：必须答出 只用成功轨迹+无需步级失败标注、CDE 的控制路径在积分全程调制动力学（对比 ODE 只吃初始条件）、conformal 保证正常步假阳率≤α 而非错误步召回（缺一个即卡点）

> [!question]- L2 解释：为什么「只学成功」能定位失败？这个假设在哪两类场景会碎（新颖正确路径误报、系统性带病成功）？为什么域内表格里 GPT-5 会输给随机选步基线——这说明指标口径的什么问题？
> **参考答案**：成功轨迹在隐空间形成可学习的「正常流形」，模型只学重建这个流；失败步作为偏离流形的异常自然显现（重建误差即异常分），因此无需知道失败长什么样、也绕开了步级标注对反事实 oracle 的依赖。两类失效场景：①agent 探索出新颖但正确的解法路径——同样偏离已见成功流，会被高分误报；②系统性失败——所有轨迹都带同种坏习惯、成功只是运气，「正常流」本身被污染，学到的正常就是病态。GPT-5 输给 Random-Step 是集合式指标的口径伪影：Random 恰好只选 1 步而真值平均 1.56 步，precision 占便宜；GPT 输出的步集合大小不受控被 precision 惩罚——暴露的是指标设计（缺 Random-3、缺限定 GPT 输出 k 步的口径对齐基线）而非模型能力。
> **判分点**：必须答出 单类学习原理（学成功流形、偏离即异常、免步级标注）、两类失效场景（新颖正确路径误报/系统性带病成功）、GPT-5 输随机是集合大小不受控的口径伪影（缺一个即卡点）

> [!question]- L3 应用：你的代码 Agent 产品每天产生 5000 条轨迹（95% 成功），现有失败诊断靠工程师抽查。设计一个基于 OAT 思路的失败标红流水线：写出训练数据来源、表征提取模型选择（产品用闭源 API 时怎么办）、α 的初始值与调参依据、以及上线前必须做的两个对照实验（提示：Random-k 口径基线、根因/症状分层评估）。
> **参考答案**：训练数据：从产品日志按轨迹级成败标签（LLM judge + 抽样人工复核）筛出成功轨迹，攒 100+ 条即可起训。表征提取：产品用开源模型则直接取执行模型的末层 hidden states；用闭源 API 拿不到 hidden states 时，用最接近的开源代理模型对轨迹文本重编码——表征与真实生成过程脱钩，预期性能下降（对应本文 OOD 设置，F1 从 0.435 降到 0.225 量级）。α 初始取 0.2（论文默认），调参依据是人工复核带宽与误报承受度：α 越大标红越多、召回越高但复核成本越高，按线上 precision/recall 曲线找平衡。两个对照实验：①Random-k 口径对齐基线——随机选同样多步数的命中率作对照，排除「多选步占便宜」的伪影；②根因/症状分层评估——OAT 常抓到「失败被显式说出来的那步」而非根因，按根因步 vs 症状步分开报召回，确认标红对工程师定位真有用。
> **判分点**：必须答出 成功轨迹+轨迹级标签即可训练、闭源时用开源代理模型重编码且性能会降、α 与复核带宽/误报承受度挂钩、两个对照实验（Random-k 口径对齐 / 根因 vs 症状分层）（缺一个即卡点）
