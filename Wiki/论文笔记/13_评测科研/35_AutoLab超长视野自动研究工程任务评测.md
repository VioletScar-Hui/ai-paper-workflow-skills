# AutoLab：前沿模型能解决超长视野自动研究和工程任务吗？

📄 **原文 PDF**：[[RAW/35 - AutoLab - Can Frontier Models Solve Long-Horizon Auto Research and Engineering Tasks.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：在 36 个真实的超长视野工程任务上测试了 17 个模型——成功的决定性因素**不是初始尝试质量，而是持续迭代的次数**；Claude Opus 4.6 以 Avg@3=0.77 全面领先，大多数模型因过早停止或预算耗尽而失败。

| 项目 | 评估 |
|------|------|
| **基准规模** | 36 任务 × 4 域（系统优化 15、谜题挑战 10、模型开发 7、CUDA 4）|
| **测试模型** | 17 个前沿模型，包括 Claude、GPT、Gemini、DeepSeek、Kimi 等 |
| **第一名** | Claude Opus 4.6: Avg@3=0.77, Best@3=0.85，四类全部第一 |
| **核心发现** | 成功 = 持续迭代（benchmarking→editing→feedback 循环），而非初始质量 |
| **成熟度** | 🔧 已发布基准，多机构联合 2026 |

## 核心发现

### 1. 持久迭代 > 初始质量
成功者的共同特征：**不断循环"运行基准→修改代码→融合反馈"**，即使早期迭代没有收益。
失败模式两类：
- **过早终止**（Premature Termination）：模型认为已经"足够好"就停下
- **预算耗尽**（Budget Exhaustion）：大量活动但无进展（缺乏策略性）

### 2. 稳定性排名（也很重要）
| 模型 | Avg@3 | Best@3 | 变异系数 CV（越低越稳） |
|------|-------|--------|----------------------|
| Claude Opus 4.6 | 0.77 | 0.85 | **0.13（最稳）** |
| Gemini 3.1 Pro | 0.57 | 0.68 | 0.20 |
| GPT-5.4 | 0.47 | 0.63 | 0.33 |
| Kimi K2.6 | 0.52 | 0.67 | 0.37 |
| DeepSeek V4 Pro | 0.45 | 0.60 | 0.42 |

> Claude 不仅均值最高，**方差也最低** — 生产环境需要的正是这种可靠性。

### 3. 时间感知是关键能力 📅 2026
高分模型能根据剩余时间调整策略（"还有 1 小时，我应该尝试更激进的方法"）；
低分模型不知道时间预算或不会利用它。

## 对 AI PM 的启示

| 场景 | 洞察 |
|------|------|
| **模型选型（长视野任务）** | 需要持续迭代/自主工程优化的任务：Claude Opus 4.6 显著优于其他选项（Avg@3=0.77 vs 第二名 0.57）|
| **不能只看 Best@3** | Best@3 夸大了高方差模型的表现；生产环境应看 Avg@3 和 CV；一次跑对不代表可靠 |
| **Harness 设计** | 给 Agent 提供明确的剩余时间信号和迭代预算感知是关键；不要让 Agent 自猜剩余时间 |
| **失败模式监控** | 追踪"提前停止率"（没用完 budget 就停）和"低效迭代率"（迭代了但没进展）|

## 论文精读卡片

**一句话**：在 36 个真实超长视野工程任务上测试 17 个前沿模型，发现 Claude Opus 4.6 以 Avg@3=0.77（第二名 0.57）全面领先，且成功的决定性因素是持续迭代次数而非初始质量，时间感知是区分高分模型的关键能力。

**问题**：现有 Agent 基准（SWE-bench、AIME 等）任务短、结构化强，无法评估需要数小时持续迭代的真实研究工程任务。前沿模型在超长视野自主任务上的实际能力差距和失败模式尚不清楚。

**核心方法**：
- 构建 AutoLab 基准：36 个真实任务跨四类领域（系统优化 15 个、谜题挑战 10 个、模型开发 7 个、CUDA 优化 4 个），均需多轮持续迭代
- 使用 Avg@3（3 次运行平均值）和 Best@3 双指标，以及变异系数 CV 衡量稳定性，避免单次高方差结果误导
- 识别两类失败模式：过早终止（Premature Termination，未用完 budget 就停止）和预算耗尽（Budget Exhaustion，持续迭代但无进展）

**关键图/公式**：稳定性排名表——Claude Opus 4.6: Avg@3=0.77, CV=0.13（最稳）vs Gemini 3.1 Pro: Avg@3=0.57, CV=0.20 vs GPT-5.4: Avg@3=0.47, CV=0.33；核心洞察：成功者行为特征 = 循环"运行基准→修改代码→融合反馈"，而非依赖初始质量。

**实验设置**：
- 规模/数据：36 任务 × 4 领域，17 个前沿模型（Claude Opus 4.6 / Gemini 3.1 Pro / GPT-5.4 / Kimi K2.6 / DeepSeek V4 Pro 等），每模型每任务运行 3 次（Avg@3 + Best@3 统计）
- 对比：17 个模型全面横向对比，双指标（Avg@3 稳定性 + Best@3 峰值）+ CV 变异系数

**最强证据**：Claude Opus 4.6 Avg@3=0.77 vs 第二名 0.57（差距 35%），且 CV=0.13 最低（方差最小）；四类子任务全部排名第一——这是全面领先，不是某类任务的偏科。

**最弱证据**：仅 36 个任务，样本量有限；所有任务为 UW/Stanford/MIT 等精英机构设计，任务分布可能有系统偏差（偏向计算机科学）；时间感知能力的评估方法（如何判断模型"知道"剩余时间）未完整说明；Claude Opus 4.6 是评测时最新模型，先发优势难以排除。

**可复用点**：Avg@3 + CV 作为 Agent 评测的双指标标准直接可用于内部 Agent 质量评估，避免 Best@3 高方差模型的误导；两类失败模式诊断（过早终止率 + 低效迭代率）可作为 Agent 系统监控指标；给 Agent 提供明确剩余时间信号和迭代预算的 harness 设计原则可直接应用。

**和哪些论文相关**：
- [[Wiki/概念/04_Agent框架/动态智能体脚手架]] — AutoLab 验证了持续迭代的动态 Agent 框架是长视野任务成功的关键，静态一次性生成无法胜任
- [[Wiki/概念/04_Agent框架/学习型编排器]] — 时间感知和策略性迭代管理是高分模型展现的编排能力，AutoLab 提供了评测维度

**我能拿它做什么**：
- 在内部 Agent 系统评测中采用 Avg@3 + CV 而非 Best@1，选型决策更可靠
- 在 harness 设计中加入明确的剩余时间信号（如"你还有 X 分钟/Y 次迭代"），帮助模型实现时间感知
- 监控生产 Agent 系统的"过早终止率"（budget 未用完就停止）和"低效迭代率"（持续迭代但无进展）
