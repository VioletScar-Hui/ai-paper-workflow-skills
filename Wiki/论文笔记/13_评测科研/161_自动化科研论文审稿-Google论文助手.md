# 迈向自动化科研审稿：Google 的论文助手工具（Towards Automating Scientific Review with Google's Paper Assistant Tool）

📄 **原文 PDF**：[[RAW/161 - Towards Automating Scientific Review with Google's Paper Assistant Tool.pdf]]

## PM 速判（30秒）
> 一句话：Google 用"分段+分层算力预算+并行深度审查+搜索落地校验"的 4 阶段推理扩展流水线（PAT），在 STOC/ICML 两大会议做"论文提交前自查"试点（超4700篇），把数学证明错误检出率从零样本 Gemini 3.1 Pro 的 55.2% 提到 89.7%；PM 必须关注的原因是——它不是又一个"AI 打分器"，而是给出了一套关于"AI 在同行评审中到底该扮演什么角色"的四级分类法（作者工具→评审工具→支持性评审→全自动评审），这直接决定了任何"AI 审稿/AI 质检"类产品该做多深、责任边界划在哪。

## 双层费曼 🗣️
> **给CEO的一句话**：论文投稿量涨得比人类审稿人能看的速度快得多（三大AI会议合计投稿量六年涨了4倍多），Google做了一个"AI 论文私教"，能在你正式投稿前帮你先挑出证明里的硬伤和实验里的漏洞，作者用完普遍说"还想再用"、还有三分之一的人因此跑了新实验。
>
> **给工程师的一段话**：PAT 不是单次调用大模型读全文，而是先用 segmenter agent 把论文按语义主题（引言/理论/方法/实验）切成可重叠、可不连续的片段，再按片段复杂度动态分配"轻/中/高"三档思考算力（证明部分给最多算力），每个片段由独立的 Deep Review agent（以全文为上下文）并行深度审查，最后由 synthesis agent 跨片段去重、判严重度，并调用 Google 搜索核实引用的论文/定理是否真实存在（对抗幻觉），本质是用"分工+分层预算+落地校验"来同时解决单次调用的上下文容量瓶颈和 Pass@k 多次采样的精度暴跌问题。

## 问题域定位 🎯
- **回应什么根本约束**：AI 辅助科研的产出速度已经超过人类同行评审的验证能力——论文给出硬数据：ICLR+ICML+NeurIPS 三大会议合计投稿量从 2020 年的 17,051 篇涨到 2026 年估计的 73,883 篇（六年+62.9%的年增速估算），同时 2024 年至少 17.5% 的 CS 领域 arXiv 摘要已显示 AI 生成痕迹（特定生物医学子领域高达 40%）。人类"逐行验证密集证明"这件事本身就要几天，根本不可能线性扩展去匹配这个投稿量。
- **之前卡在哪**：此前的"AI 辅助审稿"讨论大多停留在"reasoning 模型能不能做科学题"，而非"如何把模型改造成专门做错误检测/manuscript review 的系统"——论文明确说这块工作相对少。同时朴素的两条技术路径都有硬伤：单次整篇输入受限于上下文窗口和"思考 token"预算（验证复杂数学论断需要海量思考 token，容易超出单次调用容量）；Pass@k 独立多次采样虽然提升召回，但会显著拉低精度（如果模型每次有10%概率命中一个真错误、每次报10条问题，跑10次意味着人要在~100条候选里才能捞到1条真错误），且多次调用之间没有协调，可能反复扎堆同一段落而漏掉别的部分。
- **开启/关闭了哪条技术路线**：PAT 用"分段规划 + 动态算力预算 + 并行专项深度审查 + 全局综合去重与搜索落地"这套编排取代了"单次调用"或"无协调 Pass@k"，把"推理扩展（inference scaling）"从简单粗暴的多次采样，升级为有结构、有预算分配的多 Agent 协同——同时论文也明确提出了一套四级角色分类法（Role 1-4），为"AI 到底能不能替代人类评审做录用决策"这个更敏感的问题划定了讨论框架，是这篇论文真正想推动的政策/产品设计话题。

## 核心机制

```
输入完整论文手稿（PDF）
        │
        ▼
┌───────────────────────────────────────────────┐
│ Stage 1  文档分段 Segmenter Agent                  │
│  按逻辑主题切分：引言/理论/方法/实验/结论等              │
│  片段可重叠、可非连续                                │
└───────────────────────┬───────────────────────┘
                         ▼
┌───────────────────────────────────────────────┐
│ Stage 2  自适应算力预算 Adaptive Budgeting             │
│  按片段信息密度/复杂度动态分配思考量：                    │
│   ・Light  Thinking → 引言、结论                     │
│   ・Medium Thinking → 方法论、实验                    │
│   ・High   Thinking → 理论、证明                      │
│  （难的部分多给算力，简单手稿省算力）                     │
└───────────────────────┬───────────────────────┘
                         ▼
┌───────────────────────────────────────────────┐
│ Stage 3  深度审查 Deep Review Agents（每片段一个）        │
│  由高级版 Gemini Deep Think 或其他专有推理扩展流水线驱动    │
│  每个 agent 只负责自己的片段，但输入含全文作为上下文        │
│  （并行深度思考，减少幻觉、提升错误检出）                   │
└───────────────────────┬───────────────────────┘
                         ▼
┌───────────────────────────────────────────────┐
│ Stage 4  全局综合 Synthesis Agent                     │
│  跨片段去重批评意见、判断严重度                          │
│  调用 Google 搜索做落地校验（核实引用论文/定理是否真实存在）  │
└───────────────────────┬───────────────────────┘
                         ▼
                  PAT 最终审稿报告
     （只报"客观错误+改进建议"，不产出评分/录用推荐）
```

论文原文强调：这套编排"明确解决"了前两种基线的两个问题——分段让每个模型只需在自己负责的片段内深挖，不必在其他部分浪费思考 token，从而更容易停在上下文预算内；Deep Review Agent 让同一片段内的多次模型调用彼此协同（而非互相独立、各自为战），配合动态预算进一步提升每个片段审查的深度和效率；最后 synthesis agent 通过"落地校验+去重"抵消了 Pass@k 式扩展典型的精度衰减问题。

**配套的"AI 介入评审四级角色分类法"（Section 4，全文另一核心贡献）**：论文类比 SAE 自动驾驶分级和数学研究自主性分级，提出四级角色框架，用于讨论"AI 到底该在同行评审里扮演什么角色"：
- **Role 1（作者工具）**：AI 只帮作者在投稿前自查，作者对论文全权负责——PAT 在 STOC/ICML 的试点就属于这一级。风险是可能把"明显的问题"提前擦掉，让论文显得比实际更扎实，反而加重人类评审员甄别"真正扎实"与"被AI精心打磨过"论文的负担。
- **Role 2（评审者工具）**：AI 帮人类评审员理解论文、起草评审意见，但最终评审仍由人类全权负责。风险是评审员可能要花更多精力去核实"AI有没有幻觉"，而不是去核实论文本身；若无明确使用政策，评审员甚至可能隐瞒AI使用、在rebuttal阶段为保全权威而坚持AI给出的错误论点。
- **Role 3 / 3.5（支持性评审 / 带评分的支持性评审）**：AI 独立生成一份完整评审（不预先看到其他人类评审意见），Role 3 只给客观评估（如验证证明/实验设计），Role 3.5 额外给出主观评分/录用建议。人类的角色从"评审人"上移为"领域主席（AC）"，只需要判断是否采纳AI评审。
- **Role 4（评审全自动化）**：论文引用 NeurIPS 2021 一致性实验[1]（复现自2014年的实验[5]）：把10%投稿分别送两个独立评审委员会，发现录用决策的**不一致率高达23%**；而当年整体录用率为22.7%，若完全随机选择，不一致率理论上会是**35%**——也就是说人类评审的不一致程度其实更接近"纯随机"而非"完全一致"；排除掉ACs信心较低的边界稿件后，不一致率降到**16%**。论文据此提出设想中的"AIrXiv"——一个只收录经AI多轮自动评审/交互式rebuttal打磨过的预印本仓库，作为介于普通预印本与传统同行评审期刊之间的新发表层级。

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|---|---|---|---|---|
| 如何应对长文/深度数学验证 | 先分段（segmenter）+ 按段动态分配算力 | 单次整篇输入丢给单个模型调用 | 单次调用受限于有效上下文窗口，验证复杂数学论断需要生成大量"思考 token"，很容易超出单模型的容量上限 | 若论文本身短小、逻辑单一无需切分，分段反而增加不必要的编排开销 |
| 如何在提升召回的同时不牺牲精度 | 分段协同的 Deep Review Agent + 全局去重/严重度分级 | 独立多次采样 Pass@k 后靠人工/简单合并筛选 | Pass@k 虽提升召回但显著拉低精度（论文举例：10次采样×每次10条候选≈100条待核查线索，才能捞出1条真错误），且各次调用之间无协调，可能重复扎堆同一段落、遗漏其他部分 | 当论文的错误恰好分散在段落交界处、逻辑依赖跨越多个片段时，"分段独立审查"本身也可能漏检真正的跨段逻辑错误 |
| 如何抑制幻觉（编造不存在的论文/定理） | Synthesis Agent 用 Google 搜索做外部落地校验 | 只靠模型自我一致性/多数投票内部去噪 | 搜索能直接证伪"引用了不存在的论文/定理"这类具体、可验证的幻觉，比纯模型内部投票更可靠 | 对未公开发表、无法被搜索引擎索引的最新成果、私有数据集或未上网的内部资料，这种外部落地校验会失效——论文自己也承认"日期幻觉/知识截止过时"仍是试点中最常被吐槽的问题之一 |
| PAT 当前的产品定位 | 只做客观错误检测和改进建议，不产出主观评分/录用推荐（对应分类法中的 Role 1，not Role 3.5） | 直接输出可用于决策的评分/接收建议 | 论文明确表态：这样能保留人类对评审结果的最终控制权，降低"AI 误判影响录用决策"的风险，也符合当前试点"仅供作者投稿前自查"的定位 | 一旦产品或会议政策想让 PAT 类工具升级到 Role 3/3.5（作为可替代或补充人类评审的"支持性评审"甚至打分者），现在这套"只报错不评分"的设计边界就必须被重新论证和扩展 |

## 成本与量级 💰
- 论文**未披露**具体的推理成本量级：没有给出单篇论文审查消耗的 token 数、API 调用次数、美元成本或平均处理时长，只定性描述了"Light/Medium/High Thinking"三档算力分配这一相对结构，没有量化每档的具体计算预算。
- 底层模型：STOC 与 ICML 两个试点均由"高级版 Gemini 2.5 Deep Think"驱动；SPOT 基准的案例研究里对比的模型换成了 Gemini 3.1 Pro（零样本 vs PAT 编排）。两次试点用的模型版本本身就不同，论文没有解释具体差异或统一口径。
- 唯一可确认的量级信息：STOC（2025年11月）+ ICML（2026年1月）两个试点合计审查了**超过4,700篇**投稿；作者调查回收样本为 STOC n=124、ICML n=733（相对4700+的总投递量，回收比例、抽样方式论文均未披露）。
- 最小可行配置：论文未给出可复现的开源实现或参数配置，PAT 是 Google 内部专有系统，外部团队目前无法直接复现该流水线，只能参照其描述的四阶段逻辑自行搭建近似版本（见"动手练习"）。

## 证据审计 🔬
- **论文自述的三大局限**（Section 3.2，来自试点作者反馈的直接归纳，而非事后补充的免责声明）：①日期幻觉与知识截止过时（模型对"现在是哪一年"、最新文献动态的判断会出错）；②PDF 解析问题（复杂排版/公式抽取失真）；③错误地断言某个证明或论证不成立，源于模型自身推理失误或对论文的误解。作者称前两项已通过"更好的搜索工具和解析"缓解，但明确承认第三项"是任何基于LLM的系统固有的问题"，仍在通过改进PAT的推理能力持续应对——这意味着"假阳性纠错"（把对的说成错的）目前没有被解决，只是被归类为"需要长期投入"的开放问题。真实的定性证据也印证了这一风险的双面性：既有 Vijay Vazirani（UC Irvine）"指出了我算法里一个致命bug"、Jason Li（CMU）"指出一个技术错误，虽容易修但仍花了我两小时才写清楚"这样的正面案例，也有作者自陈"31%的ICML受访作者因PAT的反馈跑了全新实验"这种高投入回应，说明当PAT指出的问题成立时，作者愿意付出的修正成本相当可观，这也反向说明一旦第三类"假阳性断言"发生，代价同样不容小觑。
- **实验设计是否公平**：SPOT 案例研究把评测集从原始 SPOT 基准里筛到只剩"数学/计算机科学类别下的方程/证明错误"，最终仅 **26 篇论文、29 个错误**——这是一个刻意挑选出的、对"推理密集型审查工具"最有利的子类别（公式/证明错误恰恰是深度思维链最擅长的领域），并非在 SPOT 全量、多模态错误类型上做的评测。同时评分标准也被换了：原始 SPOT 论文用的是"严格关键词匹配"打分,而这篇论文改用作者自建的"逻辑等价"推理式评分器，论文自己承认"因此我们的数字与 SPOT 论文中的数字不可直接比较"——评分器由同一批开发 PAT 的作者设计和审核（"作者中的一名人类评审员核对了每条 autograder 判分"），既是运动员也是裁判员，缺乏独立第三方复核。
- **最强证据**：Table 2——在这 26 篇/29 错误的筛选子集上，PAT（Gemini 3.1 Pro 驱动）检出准确率达到 **89.7%**，相对零样本 Gemini 3.1 Pro 的 **55.2%** 和原始 SPOT SOTA 的 **21.1%** 有明显提升；具体案例是一篇关于对偶 Banach 空间的论文，零样本基线接受了一个错误的"完全压缩性"论断，而 PAT 构造出具体反例，指出使主定理失效的致命漏洞——这是论文中唯一给出"模型行为差异"细节的可验证证据，成立条件是"限定在数学/证明类错误、且用作者自定义的逻辑等价评分器"。
- **最可疑的数字**："34%的提升"（摘要原话为"34% improvement over zero-shot recall"）——55.2% 到 89.7% 实际是 **34.5 个百分点**的绝对差，如果按相对提升计算则是约 **62.5% 的相对增幅**（(89.7-55.2)/55.2）。摘要用"34% improvement"这种表述容易让读者混淆"百分点差"和"相对提升率"两种完全不同量级的说法，且论文正文自己也用"34% gain improvement"这种略显冗余、含糊的措辞，没有明确澄清是哪种计算口径。
- **原始调查数据全貌**（Table 3，STOC n=124 / ICML n=733）：

| 调查问题 | STOC 结果 | ICML 结果 |
|---|---|---|
| 还想再用 PAT | 97% | 92.1% |
| 提升了论文清晰度/可读性 | 85.1% | 87.0% |
| 认为 PAT 有教育价值 | 75.2% | 83.9% |
| 反馈"非常"或"大部分"有帮助 | 92.7% | 90.7% |
| 反馈"大部分"或"全部"有依据（无幻觉） | 55.8% | 64.8% |
| 发现了需一小时以上修复的实质性理论漏洞 | 11.6% | 35.4% |
| 因此跑了全新实验 | 未设置该题 | 31% |

  这张表本身就暴露了一个耐人寻味的反差：ICML（非理论会议、数学严谨度门槛通常更低）反而比 STOC（理论计算机科学顶会）测出更高比例的"实质性理论漏洞"（35.4% vs 11.6%），论文对此的解释是"ICML投稿的数学严谨度本来就更参差"，但这也说明同一款工具在不同审稿严格度的会议里检出率差异巨大，不能simple地把STOC或ICML任一结果当作PAT的通用能力上限。
- **另一处可疑信号**：Table 3 的"Feedback Mostly or All Grounded（反馈大部分或全部有依据/无幻觉）"一栏，STOC 只有 55.8%、ICML 只有 64.8%——换句话说，作者自己上报的调查显示，**三到四成的 PAT 反馈没有被作者认定为"完全或大部分有依据"**，这其实是全文最重要的风险量化数字，但论文把它包装成"我们认为这是一个强正面结果"，弱化了其暴露的幻觉/不实反馈比例。
- **审稿人会要求补充**：①更大规模、跨学科（非纯 Math/CS）的错误检测验证集，而不是筛到只剩 26 篇的子集；②独立第三方评分而非作者自审 autograder；③Pass@k 基线在 SPOT 数据集上的真实测量数字（论文只用一个假设性数学例子"10次×10条→~100条候选"来论证精度衰减，并未实际跑出 Pass@k 在同一 26 篇数据集上的准确率/精度数字做对照）；④PAT 的"假阳性率"——即把本来正确的证明/论证误判为错误的比例，论文承认这是试点中被反复提及的三大问题之一，却没有给出任何具体百分比。
- **背景数据也值得警惕**：论文在 Section 4 引用 Pangram Labs 的研究[12]称"21%的ICLR 2026评审是完全由AI生成的"，以此论证"AI已经在事实上介入评审、不如正视并规范它"——但这个21%的数字来自第三方AI文本检测工具 Pangram，检测器本身的准确率、误报率论文并未评估或复核，直接引用作为论证前提存在"用一个未经验证的检测结果去论证监管必要性"的风险。相比之下，AAAI-26 AI Review Pilot[2]（为每篇主赛道投稿生成一份明确标注身份的LLM评审）被作者作为"正面例子"提出，但论文没有披露该试点的评审质量/准确率数据，只是定性认可其"政策透明"的做法。
- **最小复现实验**：用同一批筛选出的 Math/CS 证明错误论文（或自建一个 20-30 篇规模的小型错误集），跑三条对照线——①单次模型问答，②Pass@k（如 k=10）多数投票合并，③"分段+分层预算+独立审查+人工复核"的简化版 PAT 流程；用"人工确认成立的严重错误数 / 总错误数"作代理指标，同时统计人工需要审阅的候选条目总数（代理"精度"指标）。预算：几十次 LLM API 调用（数十美元级别）即可初步验证"结构化编排是否显著优于朴素 Pass@k"这一核心论点，而不需要真正复现 PAT 的工程量级。

## 可复用点（PM决策）
- **何时采用**：文档强合规/强逻辑密度的前置质检场景——比如论文/技术报告/专利文书的投递前自查、内部数据分析报告的逻辑与统计漏洞审查、代码变更前的风险评估文档审阅——这些场景的共同点是"错误具体、可验证、有客观对错"，符合 PAT"只报客观错误、不做主观评分"的产品边界。
- **何时规避**：凡是需要主观价值判断、创新性/novelty 评估、跨领域"是否值得发表"的决策场景，都不适合直接套用 PAT 这套机制——论文自己也强调 PAT 现阶段刻意不做这类判断，一旦让它去做（对应 Role 3.5 甚至 Role 4），风险等级完全不同,需要额外的问责机制设计。
- **供应商拷问清单**（如果我要采购/评估类似的"AI 自动审稿/文档质检"工具）：
  1. 你们的自动质检工具在什么类型的内容/文档上一致性最低？（对照本文：ICML 场景下"发现实质性理论漏洞"的比例是 35.4%，STOC 只有 11.6%——同一工具在不同严谨度要求的场景下表现差异巨大，供应商必须能说清楚这种差异的边界）
  2. 你们的"事实落地校验"（grounding）能覆盖哪些数据源？遇到无法被检索引擎索引的私有/未公开内容时如何降级处理，会不会在没有把握时依旧输出"确定性很高"的结论？
  3. 你们能提供的"误报率"（把本来正确的内容判定为错误）具体数字是多少？如果拿不出量化数字，那就是一个需要在采购前压力测试的红线问题。
- **用四级角色分类法自查产品定位**：任何"AI审稿/AI质检"类产品在立项时都该先明确自己想停在哪一级——停在 Role 1/2（工具，人类担责）还是想推进到 Role 3/3.5（AI独立出具评估，人类只做仲裁）。论文的态度很明确：现在的技术水平（包括PAT自己）只被作者认为能可靠地停留在 Role 1/2，贸然把AI质检结果当作Role 3.5式的"评分/录用依据"去驱动实际业务决策（如自动拒绝某些提交），在当前证据强度下是不负责任的——这也是给"过度承诺AI审核能力"的供应商话术最直接的一条反驳依据。

  - [[Wiki/论文笔记/03_Agent系统设计/43_AutoScientists自组织Agent团队科学发现]]——AutoScientists 处于科研流程的"生成端"（自组织 Agent 团队自主提出假设、设计并执行实验），PAT 处于"验证端"（检验别人/别的系统已经产出的论文手稿是否有错）。论文开篇的核心论证逻辑正是这层因果关系："AI 辅助科学产出的速度已经超过人类验证能力,因此必须也用 AI 来加速验证"——AutoScientists 代表的正是那个不断加速产出、给验证端制造压力的"生成端"力量,两篇论文分居科研自动化流水线的两端,互为因果而非重复。
  - [[Wiki/论文笔记/05_推理思维链/138_AI协数学家数学研究智能体工作台]]——同样是数学研究场景下的"生成端"工具（辅助数学家做研究/证明搜索的智能体工作台），而 PAT 恰好是这类系统产出物（数学论文手稿）在发表前需要经过的"质检关卡"——如果一个团队既用 138 这类工具加速产出数学成果、又用 PAT 类工具把关审校，两者构成完整的"生成-验证"闭环产品组合。
- **冲突/印证**：如上所述，与 47_CUSP 在"LLM 科学任务校准缺陷"上构成**印证关系**（两篇论文独立发现 LLM 在开放性科学判断任务中容易过度自信、误判风险不可忽视）；与 43_AutoScientists、138_AI协数学家 则构成**流程互补关系**而非直接冲突——PAT 论文本身也明确写道，AI 生成科学产出的加速正是驱动其审稿工具诞生的根本原因。

## 动手练习 💻
> 练习目标：用一个简化的三步流程模拟 PAT 的核心机制——把论文摘要切成"理论/方法/实验"三个假想片段、给每个片段分配不同权重的"审查严格度"，并输出模拟的多维度打分与问题清单，体会"分段+分层预算"与"单次整体打分"的思路差异（不调用真实 LLM API，用规则模拟评分逻辑，便于离线运行）。

```python
import re

# 模拟三个论文片段及其内容（真实场景中这里应替换为LLM分段结果）
SEGMENTS = {
    "理论/证明": "we prove that the bound holds for all n, assuming the matrix is invertible",
    "方法论":     "we apply gradient descent with learning rate 0.01 without ablation on other rates",
    "实验":       "our method outperforms baseline by 2% on one dataset, no significance test reported",
}

# 模拟 PAT 的 Stage 2：按片段类型分配"思考预算"（Light/Medium/High）
BUDGET = {"理论/证明": "High", "方法论": "Medium", "实验": "Medium"}

# 每类片段对应的检查规则（模拟 Deep Review Agent 的关注点，真实系统里这是LLM推理，这里用关键词规则简化替代）
CHECK_RULES = {
    "理论/证明": [
        (r"assum\w+", "发现未经充分论证的假设（assuming...），需要核实该假设是否在前文被证明或过强"),
        (r"for all", "发现全称量词论断（for all n），需要核实是否有反例或边界条件未讨论"),
    ],
    "方法论": [
        (r"without ablation", "缺少消融实验，无法确认该设计选择（如学习率）是否为最优或影响结论"),
    ],
    "实验": [
        (r"no significance test", "结果提升未做显著性检验，2%的提升可能落在噪声范围内"),
        (r"outperforms baseline by \d+%", "仅报告单一提升幅度，未说明是否在多个数据集/多次运行下稳定"),
    ],
}

def deep_review(segment_name, text):
    """模拟Stage3：对单个片段做深度审查，返回该片段发现的问题列表"""
    issues = []
    for pattern, message in CHECK_RULES.get(segment_name, []):
        if re.search(pattern, text, re.IGNORECASE):
            issues.append(message)
    return issues

def synthesize(all_issues):
    """模拟Stage4：全局综合——按严重度排序并去重（此处用长度做严重度代理，仅作示意）"""
    unique_issues = list(dict.fromkeys(all_issues))  # 简化去重
    ranked = sorted(unique_issues, key=len, reverse=True)  # 简化"严重度"：描述越长视为越具体越重要
    return ranked

def run_pat_simulation():
    print("=== PAT 简化模拟：分段 -> 分层预算 -> 深度审查 -> 全局综合 ===\n")
    all_issues = []
    for name, text in SEGMENTS.items():
        budget = BUDGET[name]
        issues = deep_review(name, text)
        print(f"[片段: {name}] 分配算力档位: {budget}")
        for issue in issues:
            print(f"   - 发现问题: {issue}")
        all_issues.extend(issues)
        print()

    print("=== 全局综合报告（去重+按严重度排序）===")
    final_report = synthesize(all_issues)
    for i, issue in enumerate(final_report, 1):
        print(f"{i}. {issue}")

if __name__ == "__main__":
    run_pat_simulation()
```

> 运行后你会看到：High预算档位的"理论/证明"片段被分配了最严格的检查规则（假设合理性、全称论断反例），这正是论文里"Theory, Proofs → High Thinking"的设计意图；"实验"片段被抓出"无显著性检验"和"单一提升幅度"两类问题，对应论文里 PAT 在 ICML 场景中"指出missing comparisons and experiments"的能力。真实 PAT 用的是 LLM 推理而非关键词规则，但这个练习能帮你直观感受"分段+分层预算+分别审查+最后综合"这套编排逻辑,而不是一次性把全文丢给一个模型笼统打分。
