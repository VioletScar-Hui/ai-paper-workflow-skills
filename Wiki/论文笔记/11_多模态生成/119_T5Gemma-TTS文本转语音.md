## 核心技术：为什么编解码器 > 解码器-only

```
解码器-only 架构（VALL-E 等主流 TTS）的问题：

[文本 tokens: T个] + [音频 tokens: S个] → Causal Attention
      |_____________________________|
      当 S >> T 时，文本tokens的"注意力权重"越来越小
      → 长语音（有声书/文档朗读）质量严重下降

T5Gemma-TTS 的解法（编解码器）：
  Text → [Bidirectional Encoder] → 固定大小表示矩阵
                                          ↓
  Audio ← [Decoder] ← Cross-Attention（每层都能"看到"完整文本）
  
  → 文本条件通过独立的 Cross-Attention 路径，
    不随音频序列增长而稀释
```

## PM-RoPE 时长控制

```
问题：自回归生成中，模型不知道"已生成了多少比例"
解法：Progress-Monitoring RoPE
  → 在 26 个 Cross-Attention 层中注入"归一化生成进度信号"
  → 模型始终知道自己在目标时长的哪个位置
  
效果：
  Duration Accuracy: 0.79（有PM-RoPE）vs 0.46（无PM-RoPE）
  → 提升 71%，对需要精确控制时长的应用价值大
```

## 核心结论（带时间锚）

1. **编解码器架构对长语音 TTS 更优** 📅 2026.04
   在有声书、长文档朗读等场景，传统 decoder-only TTS 的文本条件稀释问题显著，encoder-decoder 架构提供结构性解决方案。

2. **跨语言泛化：未见过语言（韩语）的效果良好** 📅 2026.04
   T5Gemma 骨干的多语言预训练知识使韩语（未见过）达到与 XTTSv2 相当的水平——说明基础模型质量对跨语言零样本能力的关键作用。

3. **PM-RoPE 时长控制是产品化 TTS 的关键技术** 📅 2026.04
   音频广告、配音、辅助功能等场景需要精确时长控制，PM-RoPE 使时长准确率从 46% 提升至 79%。

## 论文精读卡片

**一句话**：T5Gemma-TTS 通过编解码器架构解决了 decoder-only TTS 长文本条件稀释问题，配合 PM-RoPE 将时长准确率从 46% 提升至 79%，日语超越 XTTSv2，且韩语（训练集中没有）达到竞争性水平。

**问题**：现有主流 TTS 模型（VALL-E 等）使用 decoder-only 架构，当音频 token 数量远大于文本 token 时，文本条件的注意力权重被稀释，导致长语音（有声书、文档朗读）质量严重下降；且缺乏精确的时长控制能力。

**核心方法**：
- 编解码器架构：文本→双向编码器→固定大小表示；音频←解码器（通过 Cross-Attention 每层都能看到完整文本，不随音频序列增长而稀释）
- PM-RoPE（Progress-Monitoring RoPE）：在 26 个 Cross-Attention 层中注入归一化生成进度信号（当前位置/目标时长），让模型始终知道自己在目标时长的哪个位置
- 基础模型：T5Gemma 4B（2B 编码器 + 2B 解码器）；训练数据约 17 万小时（英/中/日）

**关键图/公式**：PM-RoPE 效果——时长准确率（Duration Accuracy）从 0.46（无 PM-RoPE）→ 0.79（有 PM-RoPE），提升 71%；Cross-Attention 确保文本条件不随音频序列增长而稀释。

**实验设置**：
- 规模/数据：约 17 万小时训练数据（英/中/日），测试语言包括日语、韩语（不在训练集）、中文
- 对比：XTTSv2（主要竞品）、F5-TTS；指标：SIM（说话人相似度）、CER（字符错误率）、Duration Accuracy

**最强证据**：日语 SIM 0.677（XTTSv2: 0.622，统计显著优）、CER 0.126（XTTSv2: 0.166）；韩语 SIM 0.747 vs. XTTSv2 0.741（未见过语言几乎相当）；PM-RoPE 时长准确率提升 71%。

**最弱证据**：这是学术研究（非商业发布），评测数据集规模较小；中文 SIM 0.722 低于 F5-TTS（0.864），说明在该语言上仍有差距；模型权重未开放，可复现性有限。

**可复用点**：PM-RoPE 时长控制原理——在 Cross-Attention 层注入"当前进度/总目标"归一化信号，可用于任何需要精确长度控制的生成任务（不只是 TTS），是产品化 AI 音频生成的关键技术组件。
