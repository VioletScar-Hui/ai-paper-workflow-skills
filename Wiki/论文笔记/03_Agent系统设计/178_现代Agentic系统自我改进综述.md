# 现代 Agentic 系统的自我改进：一篇综述（Self-Improvements in Modern Agentic Systems: A Survey）

📄 **原文 PDF**：[[RAW/178 - Self-Improvements in Modern Agentic Systems - A Survey.pdf]]
arXiv:2607.13104v1（2026-07-14），约 97 页（正文 57 页 + 40 页参考文献），Schmidhuber 实验室出品

## PM 速判（30秒）
> 一句话：把「Agent 自我改进」统一形式化为 A_t = (θ_t, Σ_t)——基础模型参数 θ 加操作脚手架 Σ=(prompt, memory, tools, 控制逻辑 g)——上的**自诱导更新算子 U**，据此把整个领域切成「改模型参数（慢、贵、稳）」和「改脚手架（快、可逆、可审计）」两条路线，并给出各自的信号来源分类。PM 必须知道：你产品里的「Agent 越用越聪明」到底是在改哪一层、用什么信号驱动、出错时能不能回滚——这套分类法就是问供应商的提纲。

## 双层费曼 🗣️
> **给 CEO 的一句话**：AI Agent 有两种「自我成长」方式——一种像改员工的大脑（重训模型，贵、慢、改坏了难查），一种像改员工的工作手册和工具箱（改提示词/记忆/工具，便宜、当天生效、随时能撤回）；这篇论文把市面上所有做法归进这两个抽屉，并警告：让 Agent 自己给自己打分的那个「考官」是最容易被钻空子的环节，必须独立管控。
>
> **给工程师的一段话**：论文把 agent 配置定义为 A_t=(θ_t, Σ_t)，Σ_t=(p_t, m_t, T_t, g_t)。自我改进 = 执行算子 E 用当前策略 π 在任务上下文 C_t 里跑出学习信号 S_t（轨迹/评审/偏好/补丁），再由更新算子 U 把 S_t 提交为持久变更：θ 路线对应 SFT/RL/DPO（信号三类：自生成示范 D_t、内生评估反馈 e_t、外部探索经验 τ_t，后者又分真实环境和世界模型代理环境）；Σ 路线按组件分为 prompt 优化（标量反馈/文本批评/种群进化/文本梯度四代范式）、memory 进化（对象×结构×CRUD 处理）、tool 治理（路由/迭代精化/自主创建）、full scaffolding（STOP、Gödel Agent、DGM、HGM、AlphaEvolve、Live-SWE-Agent 这类改自己代码的，更新自指：Σ_{t+1}=I_{Σt}(Σ_t;S_t)，用 verifier 门控 V(Σ̃)=1 才提交）。关键区分：瞬态执行状态 X_t（KV cache、对话历史）不算自我改进，只有跨任务边界持久化的更新才算。

## 问题域定位 🎯
- **根本约束**：真正的自我改进要求系统能检查并改写自己的优化逻辑（自指），但历史上自指搜索空间是汇编级代码或原始突触权重，搜索不可行。FM 用自然语言把「可行修改」的搜索空间压缩到语义层，才让 1987 年 Schmidhuber 自指学习、2003 年 Gödel Machine 的老问题变得工程可做。
- **之前卡在哪**：EURISKO（1983）级别的符号自改依赖人类当外部评估器手动剪枝；Gödel Machine 要求数学证明改进才提交，实践中证不出来。现在的瓶颈换成了：自生成信号不可靠（模型自信地错、评审被博弈）、以及改进和评估共用一套基准导致的过拟合。
- **开启/关闭的路线**：开启「skill = 可复用的更新算子实例」这一视角（skill 与存储基质正交：可序列化为工具/提示/记忆/权重/控制逻辑，meta 级 skill 作用于 A_t 自身、可自我改进自己的改进器）；试图关闭「把 scaffold 微调和模型微调当两个孤立领域研究」的碎片化路线（Table 1 直接对比 Gao 2026a、Fang 2025a、Tao 2024 三篇综述的覆盖维度）。

### 机制细读一：FM 改进三类信号的失效模式（§5）
- **自生成示范 D_t**：Self-Instruct 式种子扩增 → Evol-Instruct 复杂度进化 → 课程化分解（Ladder）→ TT-SI（测试时按不确定性检测弱项、定向生成样本做 LoRA 微调，样本效率高一个量级）。失效模式：递归训练自生成数据导致**模型坍缩与遗忘**（Shumailov 2024）、多样性收缩成「知识气泡」。防线：保留人工锚定数据混训（Gerstgrasser 2024 证明可防坍缩）、外部校验器/定理证明器过滤、多样性感知的池扩增。
- **内生评估反馈 e_t**：rubric 评审（Constitutional AI → Meta-Rewarding 连评审都自我评审）、一致性信号（TTRL 多数投票当奖励、INTUITOR 自我确信度当内在奖励——校准差时会放大共同错误）、纠错批评（Reflect-Retry-Reward）。核心风险：评估器与被优化策略同源，**共享盲区**，重复使用会奖励表面合规。
- **外部探索经验 τ_t**：真实环境（unit test 可编程验证 / 学习型奖励模型 WebRL / 自生成任务 Absolute Zero——出题自主但判分仍归环境）；世界模型代理环境（WebEvolver 预测下一网页、WMPO 像素级 rollout，FM 预训练先验大幅降低拟合代理环境的交互需求）。特有失效：语言层 reward hacking（verifier 规范本身是语言对象可被操纵）、能力回退（窄奖励 RL 侵蚀预训练通用能力）、世界模型幻觉动力学被策略利用。

### 机制细读二：记忆作为信号驱动的生命周期（§6.2）
- 记忆状态 m_t=(对象, 结构)，处理 = 由 S_t 参数化的 CRUD：**C** 选择性蒸馏（语义压缩/上下文感知的增改删决策/边界受控写入，过写→检索噪声，欠写→能力损失）；**R** 混合启发式（相关+新近+重要）/结构感知检索/检索门控省 token；**U** 定期复盘衰减、局部刷新、迭代蒸馏、离线聚合；**D** 多级剪枝、共识驱逐（分布式防误删）、分层驱逐（OS 式）。
- 对象二分：显式（处理过的轨迹→泛化 / 精选原始内容→精确 / 外部知识→可验证）vs 隐式（latent/KV 注入→紧凑快速但不可审计、会表示漂移）。合规场景闭眼选显式。

### 机制细读三：评估协议的五条军规（§8，对 PM 即验收标准）
1. 报**固定预算 B_max 下的全轨迹曲线 m_t**（含平台期与回退），不许只报峰值；多种子报方差。
2. 迁移测试必须在与优化信号不重叠的 held-out 分布上，可用隐藏集或知识截止后新构任务。
3. 成本透明分解（算力/token/时钟/人类介入量化）——任何人类干预都稀释「自我」。
4. 追踪已解任务回归率、尾部风险、安全违规随迭代的变化，不止均值成功率。
5. judge 评估时：驱动更新的 judge 与最终报告的 judge 必须不同配置（否则过拟合评审偏好）；judge 预算独立于 agent 预算并公开。

### 机制细读四：六大应用域即六种「改进环」（Table 5 摘要）

| 域 | 沙箱与信号 | 主瓶颈 | 主改进目标 | 代表系统 |
|----|-----------|--------|-----------|---------|
| 软件工程 | 编译器/unit test/CI，确定性二值反馈，失败可逆 | 仓库约束下的正确性、接口效率 | 以 Σ 为主，部分自改代码或微调 θ | DGM、HGM、Live-SWE-agent |
| Web 导航 | 模拟/插桩浏览器，稀疏完成信号，部分可观测 | 动态布局 grounding、跨站点分布漂移 | Σ（感知-动作 grounding、轨迹策展） | WebRL、WebEvolver、SkillWeaver |
| 游戏策略 | 引擎可重置、胜负/标量奖励、自博弈 | 长视野规划、不完全信息、多智能体非传递性 | θ/策略参数 + 搜索规划组件 | Richelieu、DipLLM、MARSHAL |
| 科学发现 | 工具增强研究环，实验指标昂贵且噪声大 | 评估贵、知识碎片化、验证难 | Σ（工具编排/协议/评审 rubric） | AI Scientist、AI co-scientist、SciAgents |
| 具身机器人 | 模拟器+有限真机 rollout，安全约束 | 数据采集与安全、sim-to-real、动力学信用分配 | θ 数据飞轮 + 课程/安全脚手架 | RoboCat、SOAR、SEEA-R1 |
| 通用电脑控制 | 虚拟桌面、状态检查 | 应用多样性、状态追踪、不可逆动作 | Σ（层级规划/检索/课程）+ 轨迹训练 | OS-Copilot、UI-Genie、SEA |

共性规律：**沙箱的保真度、可扩展性和成本决定该域的主导改进路线**——反馈越可编程（SWE），θ 路线越可行；反馈越贵越弱（科学发现），越依赖 Σ 层的工件积累。

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|--------|----------|------------|--------|---------------|
| 分类主轴 | 先按「改什么」（θ vs Σ）再按「信号来源」 | 按「何时进化/如何进化」分（Gao 2026a 的时序轴） | θ/Σ 二分对应完全不同的成本、可逆性、信用分配特性，是工程决策的第一分叉 | 当出现 θ-Σ 联合优化（论文自己承认是未来方向）时，二分法的信用分配假设失效——失败该改 prompt 还是该算梯度无法先验判定 |
| 自我改进的判定标准 | 只有持久化（跨任务边界存续）的更新才算，瞬态 X_t 不算 | 把 in-context 适应也算进自我改进 | 否则每次对话都是「自我改进」，概念失去区分度；持久性才带来复利 | 长上下文时代 X_t 生命周期逼近「持久」（缓存跨会话复用、上下文即记忆），瞬态/持久边界变模糊 |
| 评审器（critic）定位 | 视为「被治理的基础设施」：与生成器解耦、只允许单调进化（如只增测试）、人类审计门控 | 让 agent 自主进化自己的评审器（共同进化） | 闭环里的 critic 是攻击面，agent 能力上限受 critic 抗博弈性瓶颈；提案者兼验收者=自我确认循环 | 任务超出人类审计能力（超长视野科研）时，人类门控成为吞吐瓶颈；单调加测试也会累积测试债 |
| 参数固化时机 | 先在 Σ 层探索验证、稳定后再蒸馏进 θ（快探索→慢固化） | 直接在线 RL 改 θ | Σ 层错误可回滚，θ 层回归难追踪；且参数固化是有损压缩，会丢弃罕见但关键的错误恢复策略 | 需要跨域迁移的能力必须进 θ 才能泛化；纯 Σ 层积累会导致上下文膨胀反噬（token 成本、检索噪声） |
| Full-scaffolding 安全模型 | Agent = 不可信代码跑在受保护运行时里，更新经 verifier 门控（功能正确+工具权限+扰动鲁棒） | 依赖基础模型的初始对齐 | 一次性 prompt injection 在自改系统里会变成持久架构漏洞（投毒记忆被提交为稳定更新） | verifier 本身用 LLM 实现时（Agent-as-a-Judge），门控被语言层攻击穿透 |

## 成本与量级 💰
- **θ 路线**：迭代 SFT/RL 训练成本高（GPU 时数随模型规模），且每次 θ 更新使先前安全边界失效，需重新对抗测试；TT-SI（测试时按不确定性触发 LoRA 微调）是低成本变体，按实例适配。
- **Σ 路线**：以推理 token 计费。文中具体量级锚点：GLoW 用双尺度文本世界记忆在文字游戏上达到比 RL 基线少 100–800 倍真实环境交互；prompt 进化类（Promptbreeder/GEPA）成本主要在种群评估的重复 rollout。
- **工程复杂度**：组件级 Σ 改进（记忆/prompt）约 1–2 人月可上生产；full-scaffolding（DGM 式档案树+沙箱+verifier 门控）是重基建，量级在数人月以上且需持续安全审计。
- **我的产品最小可行配置**：冻结 θ + 显式记忆对象（可读可删）+ verifier 门控的 prompt/工具更新 + 版本历史 Σ_{1:t} 支持回滚；不碰自指改代码。

## 证据审计 🔬
- **实验公平吗**：这是综述，无自有实验，但它的「证据」是选择与叙事框架本身。最大的偏置：**Schmidhuber 自引密度极高**——历史章节把最小二乘法（1805）称为「线性神经网络」、把 in-context learning 直接等同于 1991 年 fast-weight programmer（ULTRA），把整条脉络锚定到通讯作者本人 1987–2003 的工作上。这些等价关系（ICL≈FWP）在学界是有争议的类比而非共识定论，读者应当作「一家之史学」。
- **最强证据**：分类法的完备性检验——Fig.3 把约 300 篇工作无残留地装进 θ×{D,e,τ} + Σ×{p,m,T,Σ全量} 的格子里，且 Table 2（prompt 四范式的优劣对照）、Table 5（六大应用域的沙箱/信号/瓶颈/迭代模式矩阵）给出了可操作的横向对比。成立条件：接受「持久化更新才算自我改进」的定义。
- **最可疑的数字**：Table 3「记忆对象记分卡」用 1–5 蓝色方块给四类记忆对象打分，注脚承认是「文献印象式的定性评估，非统一基准」——这是把主观判断可视化成伪定量。另一个：GLoW 的「100–800×更少交互」直接转引原文，综述未核查其基线 RL 是否刻意弱设。
- **如果我是审稿人**：①要求 Table 1（与其他三篇综述的维度对比）由第三方标注而非作者自评——目前「Ours」列全勾是典型的自利表格；②历史章节需给出非 Schmidhuber 谱系的平行叙事（如 Bengio 1991 学习规则参数化只有一句）；③「skill 作为可复用更新算子」是本文原创概念，需至少一个案例研究证明该抽象能预测什么（目前只是重描述）。
- **最小复现实验**：不可复现「综述」，但可复现其核心论断「Σ 层改进快而易过拟合、θ 层慢而稳」：取一个 20 题固定评测集 + 20 题 held-out，跑 5 轮 prompt 自我改进（用评测集反馈），对比两个集合的增益差即可验证过拟合论断，预算 < 50 美元 API。

### 补充：历史脉络与未来方向速查
- **五段历史**（Fig.4）：1790s–1960s 最小二乘/控制论/图灵子机（学习系统但架构固定）→ 1960s–80s 符号自改（自复制自动机、AM/EURISKO 把启发式当一等对象）→ 1980s–2000s 元学习兴起（自指权重矩阵 FWP、success-story 算法用回溯撤销坏的自我修改、NEAT、AIXI、Gödel Machine）→ 2000s–20s 形式化与架构级（反思神谕、逻辑归纳、有界 RSI、NAS、自博弈）→ 2020s FM 时代（ReAct/Reflexion、RLVR、开放式进化）。
- **六个未来方向**（§9.2，两主题）：主题 A 终身适应算法——①测试时持续适应（运行中改检索/路由/记忆策略，防局部更新蚀全局）②主动探索与好奇心（预测误差/验证器分歧作内在奖励）③参数蒸馏与 θ-Σ 联合优化（把 System 2 的脚手架策略压进 System 1 权重，信用分配是硬骨头）；主题 B 复杂性与开放世界——④资源受限的改进动力学（改进效率而非峰值，轻量不变量检查门控昂贵神经评估）⑤多 Agent 协作共同进化（共享回归测试/补丁/工具包工件，需版本控制协议防级联攻击）⑥开放世界分布漂移（放弃静态排行榜，用持续漂移的非平稳模拟器逼出抗遗忘的改进环）。

## 可复用点（PM 决策）
- **何时采用**：产品有可验证反馈源（测试/编译/规则校验）且需要跨会话累积能力时，优先 Σ 层（记忆+prompt）自我改进；反馈弱、任务开放时不要开自改闭环。
- **何时规避**：①无独立 verifier 就让 agent 自评自改（自我确认循环）；②在非平稳环境（网页/UI 常改版）里固化 site-specific 记忆；③需要严格合规审计的场景使用隐式（latent）记忆——不可解释、无法定点删除。
- **供应商拷问清单**：
  1. 你们的「越用越聪明」改的是 θ 还是 Σ？改 Σ 的话，改哪个组件，版本历史 Σ_{1:t} 能否一键回滚？
  2. 更新信号来自哪类：自生成示范/自评反馈/环境验证？自评者和被改者是否同一个模型同一套 prompt？
  3. 有没有 verifier 门控？verifier 会不会被 agent 修改（评审器进化是否只允许单调加测试）？
  4. 报的是学习曲线（固定预算下逐迭代）还是单点峰值？held-out 迁移和已解任务回归率是多少？
  5. 记忆投毒的防线是什么？一次 prompt injection 会不会被固化为持久更新？
  6. 参数固化（蒸馏进权重）后，之前的安全测试重跑了吗？

### 术语对照（论文用语 ↔ 工程圈俗语）
- scaffold（Σ）↔ harness / 脚手架 / 编排层——论文明说二者同物，选 scaffold 是为了强调「围绕 FM 的可修改结构」
- 自诱导更新算子 U ↔ 「学习循环」「进化 loop」；执行算子 E ↔ rollout + 信号抽取
- meta 级 skill ↔ 「会写工具的工具」「改自己 prompt 的 prompt」；object 级 skill ↔ 分层 RL 的 option
- 瞬态执行状态 X_t ↔ 会话上下文/KV cache——用完即弃，不构成自我改进
- 参数固化/蒸馏 ↔ 「把 SOP 练成肌肉记忆」；代价是丢掉稀有错误恢复策略的有损压缩

## 动手练习 💻（约 30 分钟）
练习目标：复现本文最核心的工程论断——「无门控的自我改进会漂移，verifier 门控 + 版本回滚才能单调变好」。

```python
import random                                # 随机库：模拟自我改进的随机提案

random.seed(42)                              # 固定种子，保证可复现

# 把 agent 的"脚手架质量"抽象成一个 0~1 的标量 sigma
# 真实世界里它是 prompt/记忆/工具配置的综合效果
TRUE_OPT = 0.85                              # 环境的真实最优配置（agent 不可见）

def true_score(sigma):
    """环境的真实通过率：离最优越近越高（agent 只能靠采样估计）"""
    return max(0.0, 1.0 - abs(sigma - TRUE_OPT) * 2)

def noisy_eval(sigma, n=20):
    """verifier：跑 n 个任务估计通过率（对应论文的 unit test 反馈）"""
    return sum(random.random() < true_score(sigma) for _ in range(n)) / n

def self_judged_eval(sigma, bias=0.15):
    """自评：模型给自己打分，带系统性乐观偏置（论文警告的自我确认循环）"""
    return min(1.0, noisy_eval(sigma) + bias * random.random())

def propose(sigma):
    """改进算子 U 的提案步：在当前配置附近随机改一版（模拟 LLM 改 prompt）"""
    return min(1.0, max(0.0, sigma + random.gauss(0, 0.15)))

def run_loop(gated, rounds=30):
    """跑一条自我改进链。gated=True 时启用 verifier 门控 + 回滚"""
    sigma, history = 0.3, []                 # 从较差的初始脚手架出发
    best_eval = noisy_eval(sigma)            # 记录当前已接受版本的估计分
    for t in range(rounds):
        cand = propose(sigma)                # 1) 提案新脚手架 Σ̃
        if gated:
            cand_eval = noisy_eval(cand)     # 2a) 独立 verifier 评估提案
            if cand_eval >= best_eval:       # 3a) 只有不退步才提交（V=1）
                sigma, best_eval = cand, cand_eval
            # 否则丢弃提案 = 回滚到版本历史里的上一个 Σ
        else:
            if self_judged_eval(cand) >= self_judged_eval(sigma):
                sigma = cand                 # 2b) 自评通过就提交，无回滚
        history.append(true_score(sigma))    # 记录真实性能（上帝视角）
    return history

gated_hist  = run_loop(gated=True)           # 门控版：论文推荐的安全闭环
free_hist   = run_loop(gated=False)          # 自评版：自我确认循环

print("轮次 | verifier门控 | 自评无门控")
for t in range(0, 30, 5):                    # 每 5 轮打印一次真实性能
    print(f"{t:4d} |    {gated_hist[t]:.2f}     |   {free_hist[t]:.2f}")
print(f"最终 |    {gated_hist[-1]:.2f}     |   {free_hist[-1]:.2f}")
# 实测（seed=42）：门控版 5 轮 0.44 → 10 轮起 0.97+，自评版 30 轮始终 0.00——
# 乐观自评把"接受与否"退化成抛硬币，永远走不出低分区；
# 门控版最终 0.84 略低于峰值：noisy verifier 也会晚期误收稍差提案（评估噪声的代价）
# 对应论文结论：critic 是被治理的基础设施，提案者不能兼任验收者，且 verifier 质量=改进上限
```

## 自测三层 🎓
> 判分点随笔记入库；自测先作答再展开。L1 不过不进 L2/L3——答错即记卡点。

> [!question]- L1 复述：本文的两条自我改进路线各改什么、各有哪三/四个子类？「skill 作为可复用更新」为什么与存储基质正交？
> **参考答案**：路线一改基础模型参数 θ（Σ 冻结），学习信号三类——①自生成示范 D_t（Self-Instruct/Evol-Instruct 式扩增）②内生评估反馈 e_t（rubric 评审 / 一致性信号 / 纠错批评）③外部探索经验 τ_t（真实环境验证或世界模型代理环境）。路线二改操作脚手架 Σ（θ 冻结），按组件四类——①prompt 优化 ②memory 进化 ③tool 治理 ④full scaffolding（自指改自己代码，verifier 门控 V(Σ̃)=1 才提交）。skill 被定义为「可复用的更新算子实例」，同一个 skill 可序列化为工具、提示、记忆、权重或控制逻辑中任意一种载体，所以与存储基质正交。
> **判分点**：必须答出 θ 路线三类信号（自生成示范/内生评估反馈/外部探索经验）、Σ 路线四组件（prompt/memory/tool/full scaffolding）、skill=更新算子实例可落到多种载体（缺一个即卡点）

> [!question]- L2 解释：为什么论文坚持「参数固化是有损压缩」并建议先 Σ 后 θ？如果反过来（先 RL 改 θ 再调 scaffold）会在信用分配和安全测试上遇到什么具体麻烦？
> **参考答案**：把 Σ 层显式策略蒸馏进权重是压缩，必然丢信息——最先丢掉的是罕见但关键的错误恢复策略；而 Σ 层更新可回滚、可审计，所以正确顺序是「快探索（Σ 层试错验证）→慢固化（稳定后再蒸馏进 θ）」。反过来先 RL 改 θ 的麻烦：①信用分配——失败时无法先验判定该改 prompt 还是该算梯度，θ 层回归难追踪定位；②安全测试——每次 θ 更新都使先前的安全边界失效，必须重新做对抗测试，成本随迭代膨胀。
> **判分点**：必须答出 有损压缩丢弃罕见错误恢复策略、Σ 可回滚可审计所以先探索后固化、θ 更新令先前安全测试失效需重跑（缺一个即卡点）

> [!question]- L3 应用：你负责一个客服 Agent，供应商提供「自动从历史工单学习话术」功能。用本文框架写出三个验收条件（更新目标层、信号独立性、回滚与回归测试），并说明哪种记忆对象（处理过的经验轨迹 vs 原始工单 vs 隐式向量）最适合合规要求高的金融客户。
> **参考答案**：验收条件——①更新目标层：问清「学习」改的是 θ 还是 Σ 的哪个组件；若是 Σ，要求版本历史 Σ_{1:t} 可一键回滚。②信号独立性：给更新打分的评审者不能与被改的 agent 同模型同 prompt，需独立 verifier 门控，且 verifier 不可被 agent 修改（评审器至多单调加测试）。③回滚与回归测试：每次更新后追踪已解任务回归率与安全违规率；若做参数固化（蒸馏进权重），必须重跑安全测试。记忆对象：金融合规选显式记忆（原始工单最精确可溯源；处理过的经验轨迹泛化更好但需保留出处链），排除隐式向量——latent/KV 注入不可解释、无法定点删除，满足不了审计与数据删除要求。
> **判分点**：必须答出 三条验收各自的机制要点（目标层+版本回滚 / verifier 独立且不可被改 / 回归率+固化后重跑安全测试）、显式记忆胜出理由（可审计可定点删除）、排除隐式向量理由（不可解释/无法定点删除）（缺一个即卡点）
