## 核心概念框架

### Agentic（代理性）vs Agentive（自主性）

→ 详见：[[Wiki/概念/04_Agent框架/Agentic与Agentive区分]]

**核心区分**：
- **Agentic（当前全部产品）**：能力在外部工程（工具调用、提示词、硬编码流程）
- **Agentive（理论目标）**：能力从内部自发涌现（持久目标、演化身份、自我学习）

## 工程架构（GIC 架构）

论文提出 Goal-Identity-Configurator (GIC) 架构，是通向 Agentive 系统的蓝图：

```
┌─────────────────────────────────────────────┐
│              GIC Agent Model                 │
├─────────────────────────────────────────────┤
│  Layer 5: 自导向学习                         │
│    从真实 + 模拟经验中主动学习，填补弱点        │
├─────────────────────────────────────────────┤
│  Layer 4: 自我调节（System III）              │
│    学会何时"快思考"(System I)/                │
│    "慢思考"(System II)                        │
├─────────────────────────────────────────────┤
│  Layer 3: 模拟规划（System II）               │
│    内部世界模型 ←→ Agent模型（分离！）         │
│    世界模型预测"会发生什么"                    │
│    Agent模型决定"该做什么"                    │
├─────────────────────────────────────────────┤
│  Layer 2: 演化身份                           │
│    持久、自我更新的角色认知（无需重训）          │
├─────────────────────────────────────────────┤
│  Layer 1: 层级目标分解                       │
│    长期目标 g → 子目标链 g_t                  │
│    目标持久，不因对话结束而消失               │
└─────────────────────────────────────────────┘
```

**关键工程直觉（Agent模型 vs 世界模型的分离）**：

```
当前 LLM 做法（问题所在）：
  单一 LLM 同时负责：决定该做什么 + 预测世界会怎样
  → 两个目标冲突（reward驱动 vs 预测准确度驱动）
  → 规划可靠性 + 模拟可靠性都受损

GIC 做法（建议方向）：
  Agent Model π(a|s,g,i)：负责"该做什么"（reward 驱动训练）
  World Model μ(s'|s,a)：负责"会发生什么"（预测精度驱动训练）
  → 前者选动作，后者模拟结果 → 更可靠的规划
```

## 五维度 Agent 能力评估

| 维度 | 问题 | 当前产品现状 | 理想目标 |
|------|------|------------|---------|
| 目标 | 目标从哪来？持续多久？ | 每次提示词注入 | 持久的层级内在目标 |
| 身份 | 有无稳定自我认知？ | 无 | 持久演化的自我模型 |
| 决策 | 怎么思考？固定还是自调节？ | 固定 CoT/流程 | System I/II/III 自适应 |
| 自我调节 | 能否知道自己在做什么？ | 极其有限 | 学习型元认知 |
| 学习 | 怎么变强？ | 离线重训 | 运行时自导向学习 |

## 核心结论（带时间锚）

1. **当前 "AI Agent" 都是 Agentic，非 Agentive** 📅 2026.06
   Claude Code、Cursor、AutoGPT 等全部依赖外部脚手架。这不是贬低，而是准确定位——产品期望要匹配真实能力层级。

2. **世界模型 ≠ Agent 模型，不能混为一谈** 📅 2026.06
   近期有产品把"预测未来"和"决定行动"合并进同一 LLM，论文认为这从根本上损害了规划质量。未来架构应分离两者。

3. **真正的自主性需要"内化"而非"外挂"** 📅 2026.06
   把工具、记忆、规划通过脚手架挂在 LLM 外面 ≠ 让 LLM 真正具备这些能力。真正的自主体需要这些结构成为模型本身的内在属性。

4. **持久目标是真正 Agentive 的充要条件** 📅 2026.06
   没有跨对话/跨任务的持久目标，Agent 就只是"高级任务执行器"，而非"自主体"。

## PM 实用工具：AI Agent 产品评估清单

遇到新的 "AI Agent" 产品时，用这五个问题快速定级：

```
[ ] 它的"目标"是每次提示词给的，还是持久的？
    → 如果是前者：Agentic Level 1

[ ] 出了预定义的任务范围，它还能自主应对吗？
    → 如果不能：Agentic Level 2 最多

[ ] 它是否会在运行过程中主动更新自己的知识/能力？
    → 如果不能（需要重训）：还没到 Agentive

[ ] 它在哪些场景下行为变不可预测/不可控？
    → 这揭示了外部脚手架的边界

[ ] 厂商说"能自主学习"时，是推理时更新还是离线重训？
    → 区别巨大
```

## 论文精读卡片

**一句话**：MBZUAI+CMU 的批判性理论论文划定"Agentic"（外部脚手架驱动）与"Agentive"（内部涌现驱动）的本质区别，并给出通向真正自主体的 GIC 五层架构蓝图——当前包括 Claude Code、Cursor 在内的所有产品都只在 Layer 1。

**问题**：AI Agent 这个词被滥用，营销话术模糊了产品真实能力边界。当前所有"Agent"都依赖外部脚手架（工具调用、硬编码流程、提示词注入目标），用户和 PM 无法准确评估产品的真实自主程度，也无法预判边界场景的失败模式。

**核心方法**：
- Agentic vs Agentive 的操作性定义：能力来源于"外部工程"还是"内部涌现"
- GIC（Goal-Identity-Configurator）五层架构：Layer 1 层级目标分解 → Layer 2 演化身份 → Layer 3 Agent 模型与世界模型分离 → Layer 4 System I/II/III 自调节 → Layer 5 自导向学习
- Agent 模型与世界模型强制分离：π(a|s,g,i)（reward 驱动）和 μ(s'|s,a)（预测精度驱动）的训练目标冲突，单 LLM 承担两者必然损害两者质量

**关键图/公式**：Layer 3 的核心洞察：世界模型 μ(s'|s,a) 和 Agent 模型 π(a|s,g,i) 的训练目标从根本上冲突——前者最大化预测准确性，后者最大化累积奖励。把两者合并进同一个 LLM（当前主流做法）是在用一个损失函数优化两个对立目标。

**实验设置**：
- 规模/数据：纯理论框架，无实验数据；五维度评估表（目标/身份/决策/自我调节/学习）对当前主流产品做定性分析
- 对比：Claude Code、Cursor、AutoGPT 等主流 Agent 产品的能力层级定位

**最强证据**：五维度评估框架是论文最有价值的实用工具——它提供了可操作的问题清单，任何 PM 都可以用来快速定级 Agent 产品，且评估结果与产品行为高度一致（所有评估结果都在 Level 1-2 之间）。

**最弱证据**：纯理论论文，GIC 架构完全未经工程验证；Layer 3-5 是否可工程实现存疑；论文断言"持久目标是充要条件"但没有证伪测试；预判时间线（2027-2030 达到 Agentive）缺乏实证依据。

**可复用点**：五问题快速定级工具：①目标是提示词给的还是持久的？②超出预定任务范围还能自主应对？③运行中会更新自己的知识/能力？④何时行为不可预测？⑤"自主学习"是推理时更新还是离线重训？——这五问对评估任何 Agent 产品都立即可用。
