# 弱推理模型的 Agentic 增强

📄 **原文 PDF**：[[RAW/126 - Agentic Systems as Boosting Weak Reasoning Models.pdf]]

## PM 速判（3 分钟）

> **这篇论文给 PM 的一句话**：8个 GPT-5.4 nano（弱模型）+ 批评/比较器编排 = 76.4% SWE-bench 通过率，与 Gemini 3 Pro、Claude Opus 4.5 Thinking **完全相当**——但理论上证明了：仅靠采样数量**不能**替代验证信号（测试/执行/类型检查），弱模型的共同盲点无法通过增加数量来克服。

## 关键发现：弱模型委员会能匹配强模型

```
SWE-bench Verified 通过率：

单模型：
  GPT-5.4 nano（单次）:  69.8%
  GPT-5.4 mini:          73.0%
  Gemini 3 Pro:          76.4%
  Claude Opus 4.5 Thinking: 76.4%  ← 基准线
  GPT-5.4:               78.2%
  Claude Opus 4.7:       82.0%
  GPT-5.5:               82.6%
  
委员会编排：
  8× GPT-5.4 nano + 批评/比较器: 76.4%  ← 匹配 Opus 4.5 Thinking！
  Oracle best-of-8:              79.0%  ← 上限
```

**这意味着什么**：cheap model × 8 ≈ frontier model 的效果（但需要测试/执行验证基础设施）

## 理论框架：四个维度

```
委员会协议 Π(k, m, r)：
  k个提案者（Proposers）  → 生成多个候选解
  m个批评者（Critics）    → 过滤每个候选（至少一次拒绝则丢弃）
  r个比较者（Comparators）→ 对幸存者进行 Copeland 投票排序

四个关键量：
  ① 覆盖（Coverage）：正确解出现在候选池中的概率
  ② 可识别性（Identifiability）：系统能识别正确解的能力
  ③ 进展（Progress）：局部选择的组合产生全局进展
  ④ 多样性（Diversity）：提案者探索不同失败模式的能力
```

---

## 最关键的理论结论

```
定理1（桥定理）：
  覆盖 + 可识别性 → 可靠的 Boosting
  
命题1（不可能性）：
  覆盖 ≠ 可识别性
  "采样更多候选" 可以放大覆盖
  但 不能 凭空创造出有效的批评者/比较者
  
  → 必须有额外的局部健全性信号：
    执行反馈（代码跑对了吗？）
    测试通过（单元测试绿了吗？）
    类型检查（类型系统接受吗？）
    证明验证（Lean/Coq 验证通过了吗？）
```

**PM 翻译**：多 Agent 系统奏效，不是因为"投票取众数"，而是因为有**可执行的验证信号**来筛选候选方案。

## 共同盲点问题（提案者上限）

```
Oracle best-of-8 = 79.0%（而非接近100%）

为什么？
  100% - 79% ≈ 21% 的任务，8个 nano 模型都无法产生正确解
  这是"共同盲点"（Shared Blind Spots）
  
  → 这 21% 的任务不能通过更多 nano 采样来克服
  → 需要：更强的模型（扩大覆盖）OR 更多样的提案者（减少盲点重叠）
  
  多样化策略：
    不同系统提示的同一模型
    不同规模/系列的模型混合
    不同搜索策略（贪婪 vs 树形）
```

## 核心结论（带时间锚）

1. **验证信号是 Agentic 系统奏效的关键，而非智能体数量** 📅 2025
   测试执行、类型检查等"可机器验证"的信号是批评者/比较者能工作的前提——这解释了为什么代码/数学场景中的多 Agent 系统效果最好。

2. **弱模型 × 多次采样 + 验证 ≈ 强模型（在覆盖范围内）** 📅 2025
   8× nano 匹配 Opus 4.5 Thinking——成本可能相差 10-100×——意味着对于有好的验证基础设施的场景，用便宜模型比用贵模型更经济。

3. **多样性是逃离共同盲点的唯一途径** 📅 2025
   同质化提案者（同一模型多次采样）有硬性覆盖上限；混合不同提案者系统（不同模型、不同提示策略）才能超越这个上限。

## 对 Agent 产品 PM 的启示

| 设计决策 | 框架洞察 |
|---------|---------|
| **何时用多 Agent** | 任务有可执行验证信号（测试/代码运行/数值检验）时，多 Agent 效益显著 |
| **何时用强模型** | 任务无法自动验证、需要主观判断时，更强的单模型更有效 |
| **成本优化** | 在代码/数学 Agent 中用 mini/nano + 好的测试框架，可大幅降低 token 成本 |
| **覆盖上限评估** | 先测 Oracle best-of-k（用人工正确答案选择），确定现有提案系统的理论上限 |
| **提案者多样性** | 若 Oracle 上限低，说明提案者同质——需要换不同系列/不同提示的模型组合 |

## 论文精读卡片

**一句话**：8 个 GPT-5.4 nano 组成的委员会（批评/比较器编排）在 SWE-bench Verified 达到 76.4%，与单个 Claude Opus 4.5 Thinking 完全相当——但理论证明仅靠采样数量不能替代验证信号，共同盲点（21% 任务 8个 nano 均无解）只能靠更强模型或更多样提案者突破。

**问题**：弱模型通过多 Agent 编排能否匹配强模型性能？多 Agent 系统有效的数学原理是什么？以及何时纯靠增加数量无法提升效果？

**核心方法**：
- 委员会协议 Π(k, m, r)：k个提案者生成多候选，m个批评者过滤（有一次拒绝则丢弃），r个比较者用 Copeland 投票排序
- 四维理论框架：覆盖（正确解在候选池中的概率）× 可识别性（系统识别正确解的能力）× 进展 × 多样性
- 关键不可能性命题：覆盖 ≠ 可识别性——多采样可放大覆盖但不能凭空创造有效批评者，必须有执行反馈/测试通过/类型检查等局部健全性信号

**关键图/公式**：桥定理：覆盖 + 可识别性 → 可靠 Boosting；命题1：单纯采样只能扩大覆盖，不能提供可识别性——验证信号是使多 Agent 系统奏效的必要条件，不是充分条件。

**实验设置**：
- 规模/数据：SWE-bench Verified（真实代码修复任务）；8× GPT-5.4 nano 委员会
- 对比：GPT-5.4 nano 单次（69.8%）、GPT-5.4 mini（73.0%）、Gemini 3 Pro（76.4%）、Claude Opus 4.5 Thinking（76.4%）、GPT-5.4（78.2%）

**最强证据**：8× nano 委员会 = 76.4%（与 Opus 4.5 Thinking 完全相当）；Oracle best-of-8 = 79.0%（揭示硬性覆盖上限）——两个数字共同说明多 Agent 编排的能力边界。

**最弱证据**：实验只在 SWE-bench 代码场景（有天然测试验证信号）验证，理论框架能否推广到无法自动验证的主观任务（创意/策略）未验证；委员会实际成本（8× API 调用）vs 单个强模型的经济性分析不够完整。

**可复用点**：Oracle best-of-k 测试作为评估提案系统理论上限的快速工具；"覆盖上限低 → 提案者同质 → 需要换不同系列/提示模型"的诊断逻辑；验证信号优先于 Agent 数量的设计原则。
