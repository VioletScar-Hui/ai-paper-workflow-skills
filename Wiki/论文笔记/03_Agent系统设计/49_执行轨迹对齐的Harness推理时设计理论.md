# 执行轨迹对齐的 Harness：推理时设计理论

📄 **原文 PDF**：[[RAW/49 - Harnesses for Inference-Time Alignment over Execution Trajectories.pdf]]

## PM 速判（2 分钟）

> **这篇论文给 PM 的一句话**：Harness 设计本质上是对齐问题——**工作流粒度必须与 Agent 的实际可控进度对齐，引导（guidance）必须与任务证据对齐**；最反直觉的发现：**部分 Harness（只指定初始步骤）往往比全程指定的 Harness 效果更好**——过度规定会降低成功率。

| 项目 | 评估 |
|------|------|
| **理论框架** | Harness = 工作流（任务分解）+ 引导（动作分布重塑）|
| **关键原则1** | 粒度-能力对齐：子目标规模必须匹配 Agent 可控进度 |
| **关键原则2** | 引导-证据对齐：引导偏离任务证据 → 幻觉执行 |
| **反直觉发现** | 部分 Harness（只规定初始步骤）> 全程规定工作流 |
| **成熟度** | 🔬 理论 + 实验，南方科技大学，2026 |

## 三类失败模式（带时间锚）📅 2026

| 失败类型 | 描述 | 原因 |
|---------|------|------|
| **过度分解** (Over-decomposition) | 子任务太细，Agent 在每个子任务上都有偏差，累积误差大 | 粒度 > Agent 可控进度单位 |
| **过度剪枝** (Over-pruning) | 引导太强，有效的替代动作被剪掉 | 引导压缩了本该探索的空间 |
| **幻觉执行** (Hallucinated execution) | Agent 遵循引导而非任务证据，产生看起来正确但实际错误的输出 | 引导与任务证据不对齐 |

## 部分 Harness 原则

```
完整 Harness 的问题：
  - 规定越多 → 每一步都有对齐风险
  - 后期步骤的引导不确定性大 → 有害于 Agent 自主执行

部分 Harness：只规定前 M 步，剩余由 Agent 自主执行
  最优停止条件：当追加第 m+1 个规定步骤的边际成本 > 尾部风险收益时停止
  
实验结论：部分 Harness 在终端 Agent 基准上超过全程规定 Harness
```

| **Harness 设计原则** | "规定到模型做不到为止，然后让 Agent 自由"——不是越详细越好 |

## 论文精读卡片

**一句话**：Harness 设计本质是对齐问题——工作流粒度必须匹配 Agent 可控进度，引导必须与任务证据对齐；最反直觉的发现：部分 Harness（只规定初始 M 步）在终端 Agent 基准上超过全程规定 Harness。

**问题**：为什么精心设计的 Harness（工作流分解+引导）有时反而降低 Agent 性能？过度规定工作流和引导的边界在哪里？缺乏统一理论使得 Harness 设计依靠直觉而非原则。

**核心方法**：
- 建立 Harness 统一理论框架：Harness = 工作流（任务分解 → 子目标序列）+ 引导（动作分布重塑）
- 定义三类失败模式：过度分解（粒度>Agent 可控进度单位）/ 过度剪枝（有效动作被引导排除）/ 幻觉执行（Agent 遵循引导而非任务证据）
- 推导部分 Harness 最优停止条件：追加第 m+1 步的边际收益 < 尾部风险时停止

**关键图/公式**：部分 Harness 原则：只规定前 M 步，当"追加第 m+1 个规定步骤的边际成本 > 尾部风险收益"时停止；规定越多→每步对齐风险越高→后期步骤有害。

**实验设置**：
- 规模/数据：终端 Agent 基准（如 SWE-bench 类任务），不同 M 值的部分 Harness vs 全程规定 Harness
- 对比：无 Harness 基线 / 不同粒度全程 Harness / 不同 M 值的部分 Harness

**最强证据**：部分 Harness 在终端 Agent 基准上超过全程规定 Harness——反直觉地证明"规定越少有时越好"；三类失败模式在实验中均被复现，说明理论框架有实证对应。

**最弱证据**：最优 M 值（部分 Harness 停止点）的确定方法依赖事后分析，实际部署时如何预先确定 M 未给出实用指导；框架基于特定终端 Agent 任务类型，在对话/创意任务上的适用性未验证。

**可复用点**：Harness 设计工程实践：先测无 Harness 基线 → 加粗粒度分解（验证是否提升）→ 如不提升，停止细化；引导内容检查：引导是否帮 Agent 关注证据（好），还是替 Agent 做判断（坏）。
