# Reinforcement Learning with Metacognitive Feedback Elicits Faithful Uncertainty Expression in LLMs

📄 **原文 PDF**：[[RAW/164 - Reinforcement Learning with Metacognitive Feedback Elicits Faithful Uncertainty Expression in LLMs.pdf]]

## PM 速判（30秒）
> 一句话：这篇论文不再用"答案对不对"当奖励，而是额外奖励模型"预判自己表现的准不准"（元认知能力），把这个信号叠加进 GRPO 的 advantage 计算里，专门用来解决"模型嘴上说的置信度和它真实内心的置信度对不上"这个老大难问题（忠实校准，Faithful Calibration，区别于"置信度对不对准确率"的传统事实校准）。
> PM 必须关注的原因：这是少数把"模型能否自评表现"直接变成可复现 RL 训练信号、而不是停留在提示词工程或人工标注的工作——如果这个范式成立，未来"Agent 知道自己什么时候该说'我不确定'"可以通过训练而非 prompt 来内建，直接影响一切需要风险分级、拒答、人机协作的产品（医疗问诊、法律咨询、Agent 自主执行前的自我把关）。

## 双层费曼 🗣️
> **给CEO的一句话**：我们教 AI 在训练时不仅要"答对"，还要"知道自己刚才那句话该有多大把握"，练出这项"自知之明"后，它嘴上说的置信度就会更真实地反映它内心的把握，用户就能更准确地判断什么时候该多留个心眼。
> **给工程师的一段话**：在 GRPO 采样的一组 G 个 completion 中，除了常规奖励（正确性、格式、事实校准、置信度忠实度 rfaith），额外让模型在线推理输出一个自评分 Fpred（"我这次输出的置信度有多忠实于我的真实内在置信度"），并用采样一致性估计出真实值 Fgold，构造 Zg=1-(Fpred-Fgold)²。当某个 completion 的忠实度奖励高于组内均值时，用 (k+Zg) 去放大它在 advantage 中的权重，从而让"既表现好、又能准确自评"的样本被优先强化。

## 问题域定位 🎯
- **回应什么根本约束**：LLM 长期存在"高置信度幻觉"——说错话时语气依然斩钉截铁，或反过来对自己明明知道的东西过度谦虚。已有工作要么优化"事实校准"（置信度对齐准确率，如温度缩放、Brier Score 微调），要么优化"语言学校准"（让模型用更自然的 hedge 词），但都没有解决"忠实校准"（Faithful Calibration，FC）——模型表达出来的确定性是否真的匹配它内心估计的确定性，而不是匹配它是否真的答对了。一个模型完全可能"事实上校准得很好"（说 70% confident 时确实 70% 概率对），却依然"不忠实"（它内心其实只有 40% 把握，但因为运气好蒙对了，导致统计上看起来校准）。
- **之前卡在哪**：此前解决 FC 的路子只有三条，且都只覆盖语言学层面（没人碰数值层面的忠实校准）：(1) 元认知提示（MetaFaith，同一作者前作，EMNLP2025）——依赖指令遵循能力，且会降低任务准确率；(2) 线性探针/steering——只能用于开源模型，且依赖预定义探针，难以泛化到新场景；(3) SFT + 简单句式模板（FUT，Eikema et al. 2025）——泛化能力弱、长文本中 hedge 用词高度重复不自然。三条路都没有把 RL 用在 FC 上，也没人把"模型自评表现准不准"这件事本身变成训练信号。
- **开启的技术路线**：把"元认知监控信号"（模型对自己表现的自我评估准确度）直接塞进 GRPO 的 advantage 计算，形成一个新的内在反馈（internal feedback）类别——不再局限于用置信度/熵本身做 reward（如 self-certainty、语义熵缩放 advantage 的 SEED-GRPO 等前序工作），而是往上再抽象一层：奖励"模型对自己置信度是否忠实这件事的判断力"。同时验证了这种"元认知反馈"能避免此前 RLIF（RL with Internal Feedback）文献报告的"训练后期性能衰退"问题（Zhang et al. 2025 观察到纯内在反馈会随训练推进而收益递减，本文声称 RLMF 不受此限）。

## 核心机制

```
【Stage 1：RLMF + 元认知数据选择 —— 校准数值置信度】

  Prompt q
     │
     ▼
  Policy Model 采样 G=32 个 completion  r1 ... rG
  每个 completion 格式：<sentence>...</sentence><confidence> c </confidence> 逐句

     │                                   │
     ▼                                   ▼
  计算复合奖励 ρg                    估计元认知信号
  ρg = wfaith·rfaith                Fgold = 句子中 |c_i - g_i|<τ 的比例（τ=0.10）
      + wfactual_calib·rfactual_calib     g_i = 采样一致性估计的"内在置信度"
      + wacc·racc                   Fpred = 模型在线推理自评："我这次的置信度
      + wstrict·rstrict + wsoft·rsoft            忠实吗？" (0~1 一个数)
                                     Zg = 1-(Fpred - Fgold)²  ∈[0,1]
     │                                   │
     └────────────┬──────────────────────┘
                   ▼
        拆分 Ag = (og-ō) + (fg-f̄)
        fg = wfaith·rfaith（主任务信号：置信度忠实度）
        og = 其余奖励之和（正确性/事实校准/格式，属于约束项）

                   ▼
        元认知优势缩放（RLMF 核心创新）
        A_RLMF_g = (og-ō) + (fg-f̄)·(k+Zg)   若 fg > f̄（表现优于组均值）
                 = (og-ō) + (fg-f̄)            否则
        k=1，防止"表现好但元认知差"的 completion 被压到
        "表现差"的 completion 之下

                   ▼
        GRPO 策略更新（不做 std 归一化，Ag=ρg-ρ̄，缓解难度偏差）


【配套：元认知数据选择】
  离线让模型对 D_train 生成回答+语言化置信度
  → 模型自评 0-100 分"语言置信度与内在置信度的一致程度"
  → 取最高分 N/2 + 最低分 N/2 共 2000 条（PopQA train）用于上面的 RLMF 训练
  （对比：纯随机选、纯 active learning 选"模型表现差的样本"均不如高低两端组合）


【Stage 2：数值 → 语言不确定性的定向改写（与 Stage1 解耦，可重复使用）】
  Stage1 输出的忠实数值置信度 c_i
     │
     ▼
  按 0.05 一档的分箱，从人类标注的 hedge 词库（如 "fairly certain"/"I suspect"）
  中采样 20 个候选 hedge
     │
     ▼
  用 Gemini-2.5-Flash-Lite 做定向改写：保留事实内容，只替换/嵌入 hedge，
  匹配目标风格（用户偏好、受众、场景）
     │
     ▼
  自然、语境自适应、不重复的语言化不确定性表达
```

## 设计决策解剖 ⚖️

| 决策点 | 他们的选择 | 被放弃的方案 | 为什么 | 这个选择何时失效 |
|---|---|---|---|---|
| 元认知信号怎样接入 advantage | 只放大 **fg（忠实度分量）**，且只在 fg>组均值时放大（cMFG*=0.84） | (a) 放大整条 Ag（0.71）；(b) 不论 fg 高低都对全组放大（0.69） | 论文的假说是：先满足"任务表现好"这个前提，元认知信号才用来在优等生里面二次排序；对表现本就差的 completion 强行加权元认知分反而引入噪声（§C.2.2 消融证实后两种方案掉点明显） | 当"表现好"这个判据本身噪声很大（比如任务型 reward 本身就模糊、组内 completion 高度同质导致 f̄ 阈值失去区分度）时，这种"先卡阈值再叠加"的设计会退化成近似随机加权 |
| Zg 的数学形式 | 二次型 Zg=1-(Fpred-Fgold)²（借鉴 Brier Score 思路，cMFG*=0.84） | 线性绝对差（0.77）、3/4 次方根（0.62）、平方根（0.74） | 二次型对"差距很大"惩罚更猛，但不像根号形式那样对"中等差距"也过度打压，论文做了完整消融对比（Table 12） | 当模型自评分数天然聚集在极端值（0 或 1 附近，即 Fpred/Fgold 分布高度双峰）时，二次型区分度会变差，此时线性差可能更稳健 |
| k（防塌陷加常数）取值 | k=1（cMFG*=0.84），理论依据是保证"高忠实度但低元认知"的 completion 不会被压到"低忠实度"completion 之下 | k=0（0.69，明显更差）；k=2（0.76）；k=4（0.71，出现"经验性坍塌"） | k 过小则元认知差的强 completion 排序被打乱；k 过大则元认知信号被稀释、advantage 尺度失衡 | 换到 Zg 分布方差更大或系统性偏移的模型/任务上，固定 k=1 可能不是最优——论文没有给出如何自适应设定 k 的机制，属于人工超参 |
| 元认知数据选择：高分+低分各一半 | 各取 N/2（Llama 0.84 > Random 0.80 > Active Learning 0.79；Qwen3-8B 0.83 > Random 0.76 > AL 0.72） | 只取最高分、只取最低分、随机高/低分段 | 高分样本改善高置信度区间的 FC，低分样本改善低置信度区间的 FC，二者互补（Table 19 逐 bin 分析证实） | 当模型自评（0-100 打分）本身噪声很大时该策略失效——Qwen3-8B 上"单样本自评选择"(0.51)反而不如需要 20 次采样求均值的"更聪明版"选择(0.62)，说明选择质量高度依赖模型自评的可靠性，廉价单样本自评在某些模型上不可信 |
| GRPO advantage 是否做 std 归一化 | 去掉标准差归一化，Ag=ρg-ρ̄（跟随 Liu et al. 2025 的"难度偏差"论证，0.78 vs 0.72） | 保留标准差归一化（传统 GRPO 写法） | 归一化会放大"组内奖励方差小"（即难度均一）时的梯度信号，引入难度偏差 | 若不同 prompt 间奖励量纲/方差差异极大（如混合多种任务类型联合训练），去归一化可能导致某些 batch 的梯度尺度失控，此时归一化的原始动机（稳定训练）会重新变得必要 |
| 置信度打分粒度：逐句 vs 逐声明/整段 | 逐句（sentence-level）打分，用 nltk 分句后每句附一个 confidence 标签（脚注 2 明确权衡） | 更细的声明级（claim-level，需先做声明抽取）；更粗的整回复级（response-level） | 逐句在"计算效率、可解释性、与自然语言结构的对齐"三者间取得平衡，且天然匹配后续 Stage 2 逐句改写 hedge 的流程 | 当一句话里混杂了多个确定性完全不同的事实点时（例如"张三生于某年某月，具体日期我不确定"），逐句打分会被迫用一个数字盖住句内的确定性差异，此时需要退回声明级切分才能忠实反映真实的置信度分布 |

## 成本与量级 💰
- **模型规模**：训练侧仅覆盖开源模型 Qwen3（1.7B/4B/8B）与 Llama3.1-8B-Instruct；GPT-5、Gemini-3.1-Pro、Gemini-3-Flash 只作为"加了 MetaFaith 提示词"的对照基线，并未参与 RLMF 训练（不是同台竞技的公平能力对比，只是"忠实校准这项任务上"的对比）。
- **训练资源**：LoRA（非全参微调），rank=64、alpha=64、dropout=0.05，作用于全部线性层（q/k/v/o/gate/up/down）；每个 RLMF 实验用 6 张 GPU（A6000 48GB / A100 80GB / H100 80GB 混合），其中 4 张做策略更新、1 张做 completion 采样（vLLM）、1 张跑判官模型（Qwen3-32B-FP8，做一致性判断与准确率打分）。
- **数据与步数**：Pre-SFT 阶段 1800 条训练样本（5 epoch，教会模型输出格式）；RLMF 阶段 2000 条元认知筛选样本（来自 PopQA 训练集），G=32 采样、有效 batch size=64、1500 步；τ=0.10、KL β=0.1、学习率在 {5e-6,1e-5,2e-5} 中搜索。
- **评测规模**：10 个数据集（PopQA/SelfAware/SimpleQA/HaluEval/MMLU/SciQ/MATH/UMWP/ARC-Challenge/SuperGLUE）各采样 1000 条测试样本，即每个模型配置约 1 万条评测样本；Stage 2 改写用 Gemini-2.5-Flash-Lite（温度 0.5，上限 2000 token），换成 GPT-5-Mini 或 Qwen3-8B 结果相近（0.79~0.84 cMFG*），说明改写环节对具体模型不敏感。
- **最小可行配置**：论文未直接给出，但从消融可推断——单卡也能跑通 Pre-SFT（单 GPU + LoRA + Unsloth）；RLMF 训练本身至少需要"策略采样 + 判官模型"两类角色分离的 GPU 资源，作者用 6 卡是为了并行度，理论上可压缩到 2-3 卡（牺牲吞吐）。
- **未披露项**：论文没有报告端到端训练墙钟时间、总 GPU-小时数或美元成本；也没有报告多随机种子下的方差（所有实验似乎单一种子 seed=42）。

### 10 个评测数据集速览（覆盖场景与难度分层）
- PopQA（PQA）：实体密集型 QA，含大量长尾实体，训练集来源，也是主评测集之一
- SelfAware（SA）：含可答/不可答问题混合，专测知识边界识别
- SimpleQA（SQA）：针对 GPT-4 对抗构造的高难度事实性问答，域外泛化测试的关键数据集
- HaluEval（HE）：覆盖 QA/摘要/对话的幻觉检测基准
- MMLU：57 个学科的知识与推理能力基准
- SciQ（SQ）：科学选择题，四选一
- MATH（MT）：高中竞赛数学题，测试长文本推理场景下的 FC
- UMWP（UM）：含不可答问题的数学题，用于测试幻觉/拒答能力
- ARC-Challenge（AC）：需要多信息源整合的高难度科学问答
- SuperGLUE（SG）：自然语言理解基准（本文采样 boolq/copa/wic/wsc 子集）

## 证据审计 🔬
- **实验设计是否公平**：基线选取存在潜在的"自己人对自己人"问题——被拿来对比的两个先前 SOTA 之一 MetaFaith 正是本文第一作者 Liu 自己此前发表在 EMNLP2025 的工作，评测指标 cMFG（本文改进版 cMFG* 的前身）也来自与其密切合作的 Yona et al. 2024。也就是说，问题定义、旧基线方法、旧评测指标、新方法、新评测指标可能出自同一小圈子的连续迭代，虽然不必然有问题，但削弱了"独立第三方复现验证"的说服力。
- **最强证据**：Table 1 显示 Llama3.1-8B-Instruct 从原始 cMFG*=0.60 提升到 +RLMF 的 0.84（数值设定）与 0.82（语言化设定），且在训练集之外的 9 个域外任务上都保持稳定提升（成立条件：仅在 PopQA 单一数据集上训练即可泛化到 MATH、SimpleQA 等域外任务，Table 2 显示换成 SelfAware/HaluEval/UMWP 做训练集依然能拿到 0.80~0.81 的跨任务平均分，证明结论对训练数据选择不敏感）。
- **最可疑的数字**："RLMF 比标准 RL 高出最多 63%"，因为这个百分比来自 Qwen3-8B 一行：+RL 的 cMFG*=0.51，低于**完全不训练的原始模型（0.54）**——也就是说，"标准 RL"这个对照组本身在 Qwen3-8B 上训练完还比不训练更差（尤其在 ARC-Challenge 上从 0.07 掉到 0.32 才勉强及格，SuperGLUE 上 0.62 掉到 0.38），这说明"标准 RL 会让 FC 变差"这件事本身放大了 RLMF 相对提升的百分比观感，63% 这个数字更多是"标准 RL 拖了后腿"造成的相对值膨胀，而非 RLMF 绝对性能有多惊艳（RLMF 的 0.83 本身固然也不错，但"63%"这个包装数字容易误导）。
- **审稿人会要求补充**：(1) 多随机种子下的方差/置信区间（目前全篇看不到任何 error bar）；(2) 更大参数规模（>8B，尤其闭源模型)上的 RLMF 全流程训练结果，而不只是对闭源模型做提示词对比；(3) LoRA vs 全参微调的效果差异，因为作者自己承认用 LoRA 只是为了"改变输出格式/表达方式"而非"改变底层能力"，但这恰恰是 FC 任务最核心的诉求，全参是否会有质变结果未知。
- **最小复现实验**：用 Qwen3-1.7B + PopQA 训练集（G=8 而非 32）+ SelfAware 测试集（200 条而非 1000 条）+ 300 步（而非 1500 步）+ 用一个开源小模型代替判官（如 Qwen3-8B 而非 32B）跑通"Zg 计算 → advantage 缩放 → GRPO 更新"全链路，代理指标用 cMFG*（或退化为简单的 sentence-level |c_i-g_i| 均值），预算：2 张消费级 GPU（如 4090/A6000）+ 数小时。
- **额外的旁证与弱点**：Fig.3 的可靠性图显示，原始模型和 FUT 基线在"内在置信度较低的分箱"（intrinsic confidence 接近 0）系统性地表达置信度与真实内在置信度不符（即模型嘴上没有相应地表达出低确定性），而 RLMF 在所有置信度分箱上都保持较高且平稳的忠实度——这是比单一汇总数字更有说服力的细粒度证据。但支撑"96% 平均胜率"（人类偏好多样性/自然度/帮助性/情境适配性）这一亮眼结论的人类评估规模偏小：仅 3 名标注者（均为与 LLM 打交道的研究生）、120 个样例（3 个数据集 × 20 条 × 2 个模型），Krippendorff's alpha=0.93 虽然一致性不低，但样本量和标注者背景（非普通终端用户）都限制了该结论向真实产品场景的外推力。

## 可复用点（PM决策）
- **何时采用**：产品需要模型"自己说出的置信度"承担实际决策权重的场景（比如医疗/法律/金融的初筛助手需要"这句话我有多确定"这个信号去驱动"是否转人工复核"的规则），且团队具备跑 GRPO/RL 微调的工程能力（不是纯 prompt 层面能糊弄过去的）。RLMF 的价值主张核心在于：不牺牲任务准确率的前提下改善忠实校准（Table 1 显示 Acc 基本持平甚至提升），这点比 MetaFaith/FUT 都强（它们会牺牲准确率）。
- **何时规避**：(1) 只是想要"看起来更谦虚"的话术层面效果——直接上 Stage 2 的 rewriting 或轻量提示词工程即可，不必上整套 RL；(2) 团队没有可靠的"内在置信度"估计手段（本文靠 K=20 次采样一致性 + NLI 判官模型，本身有成本且依赖判官模型质量）；(3) 目标任务的"表现"本身难以用简单标量刻画（本文的 fg/og 拆分依赖任务奖励可分解性，复杂 Agent 任务未必能这样干净地拆分）。
- **供应商拷问清单**：
  1. 你们所谓的"置信度校准"，指的是"忠实校准"（表达置信度对齐模型内在置信度）还是"事实校准"（置信度对齐真实准确率）？这是两件不同的事，供应商常常混着讲。
  2. 你们的"内在置信度"是怎么估计出来的？是靠采样一致性（多次生成取一致性），还是靠模型内部 logit/熵，还是纯粹靠再问模型一次？不同方法的可信度差异很大，直接决定了整套校准结果是否只是"自我循环论证"。
  3. 校准能力是在单一数据集上调出来的，还是验证过跨任务/跨领域泛化？（本文的核心卖点之一就是"只在 PopQA 上训练，也能泛化到 MATH/SimpleQA"，但这类跨任务泛化能力是否可迁移到贵司具体业务场景需要单独验证，不能默认成立。）
  4. 用了 LoRA 还是全参微调？如果只是 LoRA 改变输出格式/措辞风格，是否真的改变了模型的"内在自我认知能力"，还是只是学会了"更擅长说场面话"？这决定了校准效果的鲁棒性上限。

- **冲突/印证**：与 `[[Wiki/论文笔记/06_训练对齐RL/79_RLAIF对比RLHF用AI反馈扩展强化学习]]` 形成印证——RLAIF 论文的核心论点是"AI 反馈可以在效果上追平甚至超过人类反馈"，本文进一步印证了"内在/自我生成的反馈信号"这条路径可以继续往更抽象的层级（从"AI 打分"到"模型对自己打分能力的打分"）扩展且依然有效；但本文也与更早的 RLIF（RL with Internal Feedback，Zhang et al. 2025，见 References [123]）观察到的现象存在部分冲突——RLIF 文献报告"纯内在反馈训练到后期会性能衰退"，本文声称元认知反馈不受此限（§5"Analysis in §D.3 shows that models' metacognitive performance consistently improves as RLMF training progresses"），但论文并未提供超过 1500 步的长程训练曲线来正面验证"永不衰退"这一更强断言，这是值得警惕的一处论证跳跃。

## 动手练习 💻
```python
# 目标：用一个极简的玩具模型，模拟论文核心机制——
# 元认知优势缩放（Metacognitive Advantage Scaling）如何影响 GRPO 的 advantage 计算。
# 不涉及真实 LLM 推理，只演示数值逻辑，便于直觉理解 Zg 和 k 的作用。

import random

def compute_zg(f_pred, f_gold):
    """元认知信号 Zg：模型自评表现(f_pred)与真实表现(f_gold)的接近程度。
    二次型公式，Zg=1 代表完美的元认知（自评和真实完全一致）。"""
    return 1 - (f_pred - f_gold) ** 2

def compute_rlmf_advantage(fg, f_mean, og, o_mean, zg, k=1.0):
    """论文式(4)：只在 fg 高于组均值时，用 (k+Zg) 放大忠实度分量。"""
    base_other = og - o_mean          # 其余奖励（正确性/格式）照常计算
    faith_delta = fg - f_mean         # 忠实度分量相对组内均值的差
    if fg > f_mean:
        return base_other + faith_delta * (k + zg)
    else:
        return base_other + faith_delta  # 表现本就低于均值，不做元认知放大

# 模拟一组 G=4 个 completion 的场景
random.seed(42)
completions = []
for i in range(4):
    fg = round(random.uniform(0.3, 0.9), 2)      # 该 completion 的"忠实度奖励"
    og = round(random.uniform(0.2, 0.8), 2)       # 其余奖励之和
    f_pred = round(random.uniform(0.2, 0.9), 2)   # 模型自评"我这次忠实吗"
    f_gold = round(random.uniform(0.2, 0.9), 2)   # 真实忠实度水平（用采样一致性估计）
    completions.append({"fg": fg, "og": og, "f_pred": f_pred, "f_gold": f_gold})

f_mean = sum(c["fg"] for c in completions) / len(completions)
o_mean = sum(c["og"] for c in completions) / len(completions)

print(f"组内忠实度均值 f_mean={f_mean:.3f}, 其余奖励均值 o_mean={o_mean:.3f}\n")

for idx, c in enumerate(completions):
    zg = compute_zg(c["f_pred"], c["f_gold"])
    # 标准 GRPO advantage（无元认知缩放，仅作对比）
    standard_adv = (c["og"] - o_mean) + (c["fg"] - f_mean)
    # RLMF 元认知缩放后的 advantage
    rlmf_adv = compute_rlmf_advantage(c["fg"], f_mean, c["og"], o_mean, zg)

    print(f"completion {idx}: fg={c['fg']}, Fpred={c['f_pred']}, Fgold={c['f_gold']}, "
          f"Zg={zg:.3f} | 标准Adv={standard_adv:+.3f}  RLMF Adv={rlmf_adv:+.3f}")

# 核心直觉：两个 fg 相近、都高于均值的 completion，Zg（自评准不准）越高的那个
# 会在 RLMF 下获得更大的 advantage，从而在策略更新中被更强地强化——
# 这就是"教模型不仅要表现好，还要更准确地知道自己表现得怎么样"的数值实现。
```
