# DPO：直接偏好优化（Direct Preference Optimization）

> **一句话定义**：DPO 不需要显式奖励模型，直接用人类偏好对（y_w 优于 y_l）优化语言模型策略——将 RLHF 的"训练奖励模型 → PPO 强化学习"两步压缩成一步对比损失，是当前最主流的 PPO 简化替代方案。

---

## 寓言学习

### 寓言正文

健身房里，私教阿泽以前带学员定制课表是这样的：先请馆里资历最深的教练当"评审"，把每一版课表按学员的反馈打分——这版比上版好在哪、差在哪，评出一个分数，阿泽再照着分数一点点调整课表，来来回回改好几轮才能定下来。评审这道工序不便宜，评审教练一天只能看得过来几个学员的课表。

后来阿泽换了个做法：不请评审教练打分，直接让学员每周从两版课表里选一个更喜欢的，记一笔"这周 A 版比 B 版更受欢迎"。攒够几十条这样的比较记录后，阿泽照着这些记录的方向，一次性把课表往"学员更喜欢的那种风格"上调整，不用再请评审、也不用来回改好几轮。省了评审这道工序，效率明显快了。

阿泽调整课表时留了个手：每次改动的幅度都卡在一个不大的范围内，绝不会因为学员这周偏好"轻松点的训练"，就把整份课表推翻重来，还是尽量贴着学员原本熟悉的那套底子改。

有个学员到了冬天开始跑马拉松备赛，训练需求整个变了——原来"哪版课表更受欢迎"的那批老记录，全是备赛之前攒下的，跟现在的状态完全对不上。阿泽照着老记录的方向继续微调，学员却越练越觉得不对路。等阿泽反应过来，重新收集了一批新的比较记录，课表才算是真正跟上了这位学员当下的状态。

### 概念解析

**概念名称**：DPO（直接偏好优化，Direct Preference Optimization），属于大语言模型后训练/对齐问题域，是 RLHF 的简化替代方案。

**学习卡片**
- 核心张力：想要用"哪个更好"的比较结果来调整模型行为，但先训练一个独立的评分体系（奖励模型）再据此做在线强化学习，链条长、成本高、还不稳定；能不能跳过"先训练评分体系"这一步，直接从比较记录里求出调整方向？
- 关键不变量：优化目标始终是让当前策略相对参考策略、在"胜者"方向上的概率提升、在"败者"方向上的概率下降，而且调整幅度必须被一个系数约束住，不能无限制地偏离参考策略。
- 触发条件：已经有一批"A 比 B 更好"的成对偏好数据，且不需要针对当前策略实时生成新对比样本来响应变化。
- 常见误解/失败模式：以为省掉了评分模型这一步，训练就完全没有代价；实际上偏好数据是固定的、离线收集的，一旦真实情况发生变化，策略还是照着旧数据的方向调整，无法像在线方法那样当场发现"方向已经不对了"。
- 非适用边界：如果任务需要根据策略当前状态实时生成新的比较样本来验证和探索（比如推理任务需要不断验证新生成答案是否正确），固定的离线偏好对没法提供这种动态反馈，直接优化对比损失不够用。

**一句话核心定义**：DPO 是把"先训练奖励模型、再用强化学习优化策略"这两步，压缩成一个可以直接在偏好对上求解的对比损失函数，用一次监督式训练替代了在线强化学习的完整链条。

**它试图解决的问题**：RLHF 标准流程需要维护奖励模型、策略模型、参考模型、价值函数四套系统，训练不稳定、成本高；DPO 想用更轻量、更稳定的方式，直接从"哪个答案更好"的数据里求出同样的优化方向。

**故事元素映射**：
- 请资历最深的教练当评审打分、再照分数反复改课表 = RLHF 的两步流程：训练奖励模型，再用强化学习（PPO）在线优化。
- 不请评审，直接用"A 比 B 更受欢迎"的记录一次性调整方向 = DPO：跳过独立奖励模型，直接在偏好对上做对比优化。
- "每次改动幅度卡在不大范围内，贴着学员原本熟悉的底子改" = DPO 损失函数里的 β 系数，约束当前策略相对参考策略的偏离程度。
- 备赛需求变了但老比较记录没跟上，阿泽照旧方向调整导致脱节 = DPO 依赖固定离线数据集，无法像在线强化学习那样实时采样响应策略/环境的变化，存在分布偏移风险。

**比喻边界**：故事里"选 A 还是选 B"简化了真实的偏好数据规模和噪声——真实场景里偏好标注可能存在标注者之间不一致、文化偏见等问题，会直接污染优化方向；此外，DPO 数学上依赖 Bradley-Terry 偏好模型和 RLHF 最优策略的解析解推导，故事只承载了"跳过独立评分环节、直接从比较记录里求方向"这一层直觉，没有展示背后的公式推导。

**非适用例**：如果健身房想训练学员"如何正确完成硬拉"这种有客观对错标准的动作（姿势对不对、有没有拉伤风险可以直接用规则判断），那不需要"学员喜欢哪版课表"这种比较偏好机制，直接用动作标准打分校正就够了——这类有客观验证方式的任务不是 DPO 要解决的问题。

**现实例子**：Rafailov et al.（2023）提出 DPO 后，它迅速成为主流的离线对齐方法，只需要 Policy 和 Reference 两个模型（而不是 RLHF 的四个），训练像标准监督学习一样稳定；但在 DeepSeek-R1（2025）的数学/代码推理训练里，团队仍然选择 GRPO 这种在线强化学习方法而非 DPO，正是因为推理任务需要不断生成新答案、验证对错，DPO 的离线特性在这类场景里效果偏弱。

### 检验问题

1. 理解检验：如果阿泽完全不设"每次改动幅度不能太大"这条限制，只要学员这周更喜欢某个方向就立刻大幅改动课表，你觉得会出现什么问题？这对应 DPO 里哪个机制原本要防止的情况？
2. 迁移检验：一家在线教育公司想用"学生更喜欢哪种讲解方式（A 老师 vs B 老师风格）"的历史投票数据，直接训练一个内容生成模型去模仿更受欢迎的风格。半年后学生群体的构成和偏好发生了明显变化，你预测这套训练方式会遇到什么问题？这属于故事里阿泽学员备考马拉松那个环节暴露的哪一类局限？

## 从 RLHF 到 DPO：一步压缩

```
RLHF 标准流程（InstructGPT，2022）：
  Step 1: SFT（监督微调）
  Step 2: 奖励模型训练（RM）：偏好对 (y_w, y_l) → 标量奖励 r(x,y)
  Step 3: PPO RL：用 RM 信号在线优化策略 π_θ
  
  问题：
    ① 需要独立训练 RM（额外计算/显存）
    ② PPO 在线 RL 训练不稳定（超参敏感）
    ③ 需要维护 Policy + Critic + Ref + RM 四个模型

DPO（Rafailov et al. 2023）：
  关键洞察：RLHF 的最优策略有解析解，
             RM 和策略可以合并用一个损失函数直接求解
  
  Step 1: SFT（同 RLHF）
  Step 2: DPO 损失（直接在偏好对上优化）
  
  优点：
    ✅ 无需独立 RM
    ✅ 无需在线 RL（离线优化）
    ✅ 只需 Policy + Ref 两个模型
    ✅ 训练更稳定
```

## DPO 损失函数

```
DPO 目标（对比损失）：

L_DPO = -log σ(
    β · (log π_θ(y_w|x) - log π_ref(y_w|x))
  - β · (log π_θ(y_l|x) - log π_ref(y_l|x))
)

其中：
  y_w：人类偏好对中"更好"的回答（winner）
  y_l：人类偏好对中"更差"的回答（loser）
  π_θ：当前策略（训练目标）
  π_ref：参考策略（SFT 模型，冻结）
  β：控制偏离参考策略的程度（类似 RLHF 的 KL 系数）
  σ：sigmoid 函数

直觉：
  - 提升 π_θ 相对 π_ref 给出 y_w 的概率（对比基线）
  - 降低 π_θ 相对 π_ref 给出 y_l 的概率（对比基线）
  - β 越大：越倾向于保持接近 π_ref（保守）
  - β 越小：更激进地拟合偏好对（激进）

数学依据：
  RLHF 最优策略满足：π*(y|x) ∝ π_ref(y|x) · exp(r(x,y)/β)
  代入 Bradley-Terry 偏好模型后化简得 DPO 损失
  → DPO 是 RLHF 目标的封闭形式解析解
```

## DPO vs. RLHF（PPO）对比

| 维度 | RLHF（PPO）| DPO |
|------|-----------|-----|
| **奖励模型** | 需要独立训练 RM | 不需要（隐式在损失中）|
| **训练范式** | 在线 RL（需要实时采样）| 离线（固定偏好数据集）|
| **模型数量** | 4（Policy+Critic+Ref+RM）| 2（Policy+Ref）|
| **训练稳定性** | 不稳定（PPO 超参敏感）| 稳定（监督学习）|
| **动态反馈** | 支持（在线生成新样本）| 不支持（固定数据集）|
| **分布偏移** | 自动处理（在线采样）| 脆弱（对 OOD 数据敏感）|
| **实现成本** | 高（PPO 基础设施）| 低（标准训练循环）|

## DPO 变体

```
SimPO（Simple Preference Optimization，2024）：
  去掉 π_ref 参考模型，直接用长度归一化序列概率
  损失更简单，且不需要参考模型推理（节省显存）
  
ORPO（Odds Ratio Preference Optimization，2024）：
  把偏好对比直接嵌入 SFT 损失，一步完成 SFT + 对齐
  无需独立 SFT 阶段，适合资源受限场景

IPO（Identity Preference Optimization，2023）：
  发现 DPO 对偏好对的过拟合问题
  添加正则项防止模型为偏好对的每个 token 概率对崩塌

KTO（Kahneman-Tversky Optimization，2024）：
  不需要成对偏好（只需单样本"好/坏"标注）
  基于前景理论，对标注数量要求更低
```

## DPO 的核心局限

```
局限 1：离线偏好对的分布偏移
  DPO 训练时使用固定的偏好数据集（离线）
  → 策略 π_θ 偏离后，偏好对的分布与 π_θ 生成的分布不匹配
  → 可能导致训练信号偏差，尤其在多轮迭代后

局限 2：无法处理动态反馈
  PPO 可以实时采样新数据，响应策略变化
  DPO 偏好对固定，无法主动探索 → 推理场景（数学/代码）效果弱于 GRPO

局限 3：需要高质量偏好对
  偏好对质量直接决定对齐质量
  → 嘈杂标注 / 文化偏见 / 不一致标注都会直接传入损失函数

局限 4：隐式 RM 不可检查
  PPO 的 RM 可以独立评估、调试
  DPO 的"奖励"是隐式的 → 难以诊断对齐问题
```

## PM 决策框架：什么时候用 DPO / PPO / GRPO

| 场景 | 推荐算法 | 理由 |
|------|---------|------|
| 通用对话/指令跟随对齐 | **DPO** | 稳定、成本低、效果与 PPO 接近 |
| 有大量人工偏好标注 | DPO / SimPO | 直接利用偏好对，无需在线 RL |
| 标注资源有限（只有好/坏标签）| KTO | 不需要成对偏好 |
| 快速对齐迭代（小团队）| DPO 或 ORPO | 基础设施成本低 |
| 数学 / 代码推理强化 | **GRPO** | 结果可验证 + 在线探索，DPO 效果弱 |
| 复杂推理 + 动态反馈 | **PPO** | 在线采样，探索能力强（成本高）|
| 敏感/安全对齐（合规优先）| PPO + RM | RM 可独立审查，合规风险更低 |

## 补充:更严谨的机制与公式(源自 Alisa's Book of LLMs)

这一节把"DPO 为什么不需要显式训练奖励模型"这个核心洞察，按完整推导链条讲一遍：RLHF 目标 → 闭式最优解 → 反解出奖励 → 代入偏好模型 → 配分函数抵消 → 得到 DPO 损失。

### 第一步：KL 正则化目标存在闭式最优解

前面 RLHF 一节写过目标函数 $\mathcal{J}^{\text{RLHF}}(\theta) = \mathbb{E}\left[R(\tau) - \beta D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})\right]$。这个带 KL 正则项的优化问题，其实不需要真的跑强化学习去逼近，它存在一个解析解——也就是说，在给定奖励函数 $R(y)$、参考策略 $\pi_{\text{ref}}$ 和系数 $\beta$ 的情况下，能直接写出"理论上最优的策略长什么样"：

$$\pi^*(y|x) = \frac{1}{Z(x)}\pi_{\text{ref}}(y|x)\exp\left(\frac{1}{\beta}R(y)\right)$$

这里 $Z(x) = \sum_y \pi_{\text{ref}}(y|x)\exp(R(y)/\beta)$ 是配分函数（归一化常数），保证所有 $y$ 上 $\pi^*(y|x)$ 加起来等于 1。直觉上看，最优策略就是"在参考策略的基础上，按奖励的高低做指数加权重新分配概率"——奖励越高的 $y$，相对参考策略被放大得越多。

### 第二步：反解出奖励

第一步的公式建立了"最优策略"和"奖励函数"之间的一一对应关系。既然给定奖励能推出最优策略，那反过来，只要知道最优策略 $\pi^*$，也能把奖励函数反解出来。对上面的式子两边取对数、移项：

$$R(y) = \beta\log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta\log Z(x)$$

这一步是整个推导里最关键的洞察：**奖励函数可以完全用策略本身（相对参考策略的对数概率比）来表达**，不再需要单独训练一个打分网络。也就是说，如果我们已经有一个策略模型，就已经隐含定义了一个奖励函数，两者是同一枚硬币的两面。

### 第三步：代入 Bradley-Terry 偏好模型

回忆奖励模型一节的 Bradley-Terry 偏好公式 $P(y_w \succ y_l) = \sigma(R(x,y_w) - R(x,y_l))$。把第二步反解出来的 $R(y)$ 代入这个公式里的 $R(x,y_w)$ 和 $R(x,y_l)$：

$$R(x,y_w) - R(x,y_l) = \left[\beta\log\frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} + \beta\log Z(x)\right] - \left[\beta\log\frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)} + \beta\log Z(x)\right]$$

### 第四步：配分函数在做差时正好抵消

注意上面两个方括号里都有一个 $\beta\log Z(x)$ 项——因为 $Z(x)$ 只依赖于 prompt $x$，不依赖具体的回复 $y$，所以 $y_w$ 和 $y_l$ 对应的 $Z(x)$ 是同一个值，在相减时正好完全抵消：

$$R(x,y_w) - R(x,y_l) = \beta\log\frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\log\frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)}$$

**这一步抵消是 DPO 能够成立的数学关键**：配分函数 $Z(x)$ 本身通常是无法计算的（要对所有可能的 $y$ 求和/积分，序列空间太大），如果它没有被抵消掉，整个方法就无法落地。正因为偏好比较用的是"两个回复的奖励之差"而不是"单个回复的绝对奖励"，才让这个难以计算的项被结构性地消除了。

### 第五步：得到 DPO 损失

把抵消后的差值代回 Bradley-Terry 的 $\sigma(\cdot)$ 里，再把这个概率代入负对数似然损失，就得到 DPO 的最终损失函数（把 $\pi^*$ 换成正在训练的 $\pi_\theta$）：

$$\mathcal{L}^{\text{DPO}}(\theta) = -\mathbb{E}_{(x,y_w,y_l)}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta\log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]$$

### 为什么这意味着"不需要显式训练奖励模型"

把整条链路串起来看：RLHF 原本需要"先训练一个奖励模型，再用强化学习让策略去逼近奖励模型定义的最优解"。但第一步到第四步说明，只要目标函数是带 KL 正则的这种形式，最优策略和奖励函数之间就存在一个可以互相换算的解析关系，而且这个关系里唯一"不可计算"的部分（配分函数）在做偏好对比时会自动消失。于是可以跳过"训练奖励模型"这个中间环节，直接把偏好数据代入一个用策略模型自身表达的损失函数里做监督式优化——训练出来的策略模型，其对数概率比隐式地就是一个奖励模型，只是从未被显式地单独训练过。这就是 DPO 里"隐式奖励模型"（implicit reward model）说法的数学来源。
