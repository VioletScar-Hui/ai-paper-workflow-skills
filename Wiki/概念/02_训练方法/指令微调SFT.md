# 指令微调 SFT

## 一句话定义

监督微调（Supervised Fine-Tuning）是在预训练模型上，使用人工标注的指令-回复配对数据进行有监督训练，将"无目标的下一词预测机器"转化为"能遵循人类指令的对话助手"。

## 寓言学习

### 寓言正文

公司内部知识库常年活跃着一位老工程师，人称"万事通"，什么技术问题丢给他都能答上来，知识面广得吓人。可他写东西全凭兴致：有时候三言两语就把问题绕开去讲别的，有时候一个简单问题能扯出五六个话题，最后也不给个明确结论，看的人常常读到一半就懵了，不知道该往哪找答案。

知识库运营小周想让"万事通"的回答变得规整一些，方便同事直接拿去用。她先把过去三年内部论坛里所有他答过的帖子整理出来，几千条，一股脑打印出来让他参考着写。"万事通"翻了一遍，倒是记住了不少具体问题的答案，可写起新问题来还是老样子——东拉西扯，长短不一，有的直接结束，有的收不住尾，因为那几千条帖子本身水平参差，好的坏的都有，混在一起，没能让他看出一个稳定的写法。

小周后来换了个办法：只从里面精挑出五十条最清楚的回答，每一条都是同样的结构——先给结论，再列两三点理由，最后一句收尾，不多说一个字。她把这五十条整理成一本小册子，请"万事通"照着这个格式重新过一遍。没过多久，同事发现"万事通"回帖变了：不管问题是什么，他都会先给出结论，再补上依据，说完就停，再也不绕弯子。有意思的是，那五十条范例里根本没出现过后来同事问的那些新问题——"万事通"学到的不是背下这五十条答案，而是学会了这套"先结论、后理由、说完就停"的回应方式，套用到任何新问题上都成立。

### 概念解析

**概念名称**：指令微调SFT（Supervised Fine-Tuning），属于大语言模型后训练/对话能力激活问题域。

**学习卡片**
- 核心张力：模型（或人）已经具备大量底层知识，但缺的不是知识本身，而是"该以什么格式、什么角色、在哪里收尾"来回应一个具体请求——知识充足和行为规范是两件独立的事。
- 关键不变量：训练/学习的目标只落在"回应"这一部分该长什么样，不是往里面塞新知识；且范例的质量和一致性比数量更能决定学到的行为模式好不好。
- 触发条件：底层能力/知识已经足够，但当前的输出行为没有固定格式、没有明确的角色边界或结束信号。
- 常见误解/失败模式：以为范例数量越多效果越好，忽视了质量参差的大量范例反而会让学到的格式变得混乱、不一致；把这套训练误当成"灌注新知识"的手段，实际上它更擅长塑造"怎么回应"而不是"知道什么"。
- 非适用边界：如果问题本身超出了原有的知识范围（不是"不知道怎么答"而是"压根不知道答案"），靠调整回答格式的范例解决不了，那属于知识/信息补充的问题，不属于这套机制能处理的范围。

**一句话核心定义**：指令微调是用少量但精心挑选的"问题-规范回答"范例，塑造出一套稳定的回应行为（先说什么、如何组织、在哪收尾），让本来知识充足但行为随意的对象，学会以一致、可预期的方式回应新的、范例里没出现过的问题。

**它试图解决的问题**：当一个知识面已经足够广的对象不知道该以什么格式、什么角色边界来回应具体请求时，如何用少量高质量的示范，让它学会一套能迁移到任意新问题上的稳定回应方式，而不是靠堆砌大量参差不齐的历史记录。

**故事元素映射**：
- "万事通" = 预训练模型，已具备充足底层知识但缺少稳定的回应格式。
- 几千条参差不齐的历史帖子 = 数量庞大但质量不一的训练数据，效果有限。
- 五十条精挑细选、结构统一的范例 = 高质量精选SFT数据（呼应LIMA"少即是多"的发现）。
- "先给结论、再列理由、说完就停"的固定套路 = 训练信号只塑造"回应该怎么组织和收尾"这一行为模式，不涉及知识本身。
- "万事通"套用到范例里没出现过的新问题上依然成立 = 学到的是可泛化的回应模式，而不是死记硬背具体问答对。

**比喻边界**：故事把训练过程简化成了"看一遍范例就学会"，现实中的SFT是通过梯度下降在大量参数上反复调整、且只对"回应"部分计算损失（指令/问题部分不参与梯度回传），这个训练机制远比"翻一遍小册子"复杂；此外真实的数据配方通常还要覆盖不同任务类型的比例分布，故事只呈现了"格式统一"这一个维度，没有涉及任务多样性覆盖的问题。

**非适用例**：如果同事问的是"万事通"过去从没接触过的一个全新技术领域的具体参数配置，给他再多的"回答格式范例"也补不上这个知识空白——这种情况需要的是给他补充相关资料，而不是调整他回答的组织方式，不属于指令微调要解决的问题。

**现实例子**：LIMA（Zhou et al., 2023）的实验发现，用1000条精心挑选的高质量指令-回复数据做微调，效果超过用5万条质量参差的数据训练出的模型；Alpaca则用GPT-3.5生成了52000条数据，仅花费约500美元，就让一个基础模型学会了稳定遵循指令的对话格式。

### 检验问题

1. 理解检验：小周第一次让"万事通"直接看几千条历史帖子效果不好，第二次换成五十条精选范例反而有效，这中间的关键差异是"数量变少了"本身起作用，还是别的原因？
2. 迁移检验：一家公司想让内部一个知识丰富但说话啰嗦的AI助手，学会"先摘要、再展开、附一条行动建议"的固定回复格式。如果只给它十条这种格式的范例，但内容覆盖的话题很单一（比如全是关于报销流程的），你觉得这十条范例能不能让它在完全不相关的话题（比如会议室预定）上也用上这套格式？为什么？

## 核心原理

### 从预训练到对话模型的关键跨越

预训练模型能"续写文本"，但不能"回答问题"——它不知道应该扮演什么角色，也不知道回答应该在哪里结束。SFT 解决的正是这个格式对齐问题：

- **预训练模型的行为**："今天天气很好，我打算..." → 续写任意方向
- **SFT 后的行为**：`User: 今天天气怎么样？\nAssistant: 我没有获取实时天气的能力，建议...`

SFT 数据的标准格式（以 Alpaca 为例）：

```json
{
  "instruction": "将以下句子翻译成法语",
  "input": "The sky is blue.",
  "output": "Le ciel est bleu."
}
```

多轮对话格式则增加 conversation 列表，每轮记录 role（user/assistant）和 content。

### 训练目标

SFT 依然使用交叉熵损失，但**只在 output 部分计算 loss**，instruction 和 input 部分仅作为上下文输入，不参与梯度回传。这保证了模型学到的是"如何回应"而非"如何提问"。

```
损失 = -∑_{t ∈ output} log P(xₜ | x_{<t})
```

### 样本质量 vs 数量

LIMA（Zhou et al., 2023）的关键发现：**1000 条高质量样本的 SFT 效果，可以超越 50000 条低质量样本**。质量维度包括：
- 指令多样性（任务类型覆盖）
- 回复的准确性和完整性
- 格式一致性（避免格式噪声污染模型）
- 无有害内容、无幻觉

### 数据配方

| 数据类型 | 比例建议 | 作用 |
|---------|---------|------|
| 通用对话 | 40-50% | 基础交互能力 |
| 代码生成 | 15-20% | 编程任务 |
| 数学推理 | 10-15% | 逻辑能力 |
| 长文本摘要 | 10% | 长文本理解 |
| 安全拒绝 | 5-10% | 对齐安全需求 |

## PM 决策视角

### SFT 与 RLHF 的分工

SFT 和 RLHF 不是竞争关系，而是序列关系：

```
预训练基座 → SFT → 奖励模型训练 → PPO/DPO 对齐
```

- **SFT 负责**：格式对齐、基本指令遵循、能力激活
- **RLHF 负责**：细粒度偏好对齐、降低有害输出、提升"有帮助性"的主观感受

纯 SFT 模型的典型缺陷：过度冗长、回避边界问题、格式机械化。这些问题需要 RLHF 阶段修正。

### 何时做 SFT vs 何时做 RAG/Prompt Engineering

| 方案 | 适用场景 | 成本 | 时效性 |
|------|---------|------|-------|
| Prompt Engineering | 任务简单，无需深度定制 | 极低 | 实时 |
| RAG | 知识密集，知识频繁更新 | 中等 | 高 |
| SFT | 特定风格/格式，能力激活 | 高 | 低 |
| SFT + RAG | 专业助手（医疗/法律） | 最高 | 中 |

**SFT 适合的场景**：模型基础能力存在但未被激活（如小语种、特定领域风格）、需要固定输出格式（JSON/报告模板）、任务类型固定且样本可收集。

### 合成数据的崛起

Alpaca 开启了用强模型（GPT-4）生成弱模型（7B）训练数据的范式：
- Self-Instruct：模型自己生成指令并过滤
- Evol-Instruct（WizardLM）：自动演化指令复杂度
- 风险：知识上限被教师模型约束，无法超越 GPT-4
