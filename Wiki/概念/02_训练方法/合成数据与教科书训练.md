# 合成数据与教科书训练

> **一句话定义**：不用互联网上爬取的低质量大规模数据，而是用 GPT-4 等强模型合成的高质量、课程化"教科书数据"来训练小模型——phi-1 证明：1.3B 模型 + 7B token 高质量教科书 ≈ 同等能力的 10B 模型 + 1T+ token 粗糙数据。

---

## 寓言学习

### 寓言正文

宠物诊所要培训一批新入职的兽医助理。院长一开始的做法是把过去十年所有的接诊记录、论坛帖子、老员工随手写的病历备注，全部打包甩给新人自己啃——几万份材料里，错的、过时的、讲一半的应有尽有，新人啃了一个月，上手看诊还是磕磕绊绊，常常抓不住重点。

院里最资深的兽医老陈换了个办法：自己动手，只挑了猫狗最常见的二十种病症，每一种都写清楚"典型症状是什么、容易和哪些病混淆、常见的误诊陷阱在哪里"，配上具体病例和标准问诊流程，一共不到诊所旧档案的百分之一那么厚。新人只啃这一份精炼材料，两周后独立接诊的准确率反倒超过了啃了一个月旧档案的那批人。

院长觉得这套教材做法见效快，想批量复制：让实习生照着老陈的教材，自己动手再"扩写"出几十份类似的新教材，用来培训更多新人。可几轮扩写下来，教材里开始悄悄冒出问题——实习生扩写时没有回去核对真实病例，只是照着上一版教材的写法继续往下编，几轮之后，某些病症的"典型症状"描述已经和真实临床表现对不上了，用这批新教材训出来的助理，上手后误诊率反而比啃旧档案的那批还高。院长这才要求，每一版新教材扩写完，都必须挑几个病例回头找真实病历核对一遍，才能拿去用。

### 概念解析

**概念名称**：合成数据与教科书训练（Synthetic Data & Textbook Training），源自 phi-1 的"教科书假设"，属于大模型训练数据构建问题域。

**学习卡片**
- 核心张力：想要模型/新人学得又快又准，直觉上会觉得"给的材料越多越好"，但海量原始材料里掺杂大量重复、错误、过时的内容，反而稀释了真正有效的学习信号；精心设计的少量高质量材料，往往比粗糙的海量材料更有效。
- 关键不变量：真正决定学习效果的不是材料的"数量"，而是"数量 × 平均质量"这个有效量——质量提高一个数量级，需要的数量可以相应减少一个数量级。
- 触发条件：目标任务有相对客观、可核验的正确答案或标准流程（这样"精炼教材"的内容才能保证是对的），且能找到（人或强模型）愿意花成本去设计课程化的高质量材料。
- 常见误解/失败模式：以为一旦有了一份好教材，就可以无限"自我复制"扩写出更多教材来批量培训——如果扩写过程不回头核对真实数据源，只是在自己已生成内容的基础上继续编，错误会一轮轮累积放大，最终训出来的效果反而比用旧的粗糙数据更差。
- 非适用边界：如果任务本身就要求覆盖真实世界的多样性和最新事实（比如需要跟上最新的行业动态、或者需要反映真实人类的多元偏好和创意），精炼合成材料会天然带着"编写者当时知道的那些"的局限，替代不了持续更新的真实数据。

**一句话核心定义**：合成数据与教科书训练是用人工或强模型精心设计的、课程化的高质量材料替代海量粗糙原始数据来训练模型，核心依据是"数据有效量 = 数据量 × 质量"，质量的大幅提升可以换来数据量的大幅减少。

**它试图解决的问题**：互联网/历史档案规模的原始数据里包含大量对学习无益甚至有害的内容，直接堆量训练效率低；用课程化设计的精炼材料，能以远小的数据规模达到甚至超过海量粗糙数据的训练效果。

**故事元素映射**：
- 十年接诊记录、论坛帖子、随手病历备注 = 互联网规模的原始训练数据：量大但质量参差、重复、过时。
- 老陈只挑二十种常见病、写清症状/易混淆点/误诊陷阱 = phi-1 式教科书数据：课程化设计，覆盖精挑细选、附带"为什么"的解释性内容。
- 新人啃精炼教材两周后表现超过啃一个月旧档案的人 = phi-1 证明的核心结论：小数据量 + 高质量 ≈ 甚至优于 大数据量 + 低质量。
- 实习生批量扩写教材、几轮后误诊率反弹 = 合成数据递归自我训练导致的"模型崩溃"（Model Collapse）：每一轮生成都在前一轮的误差基础上继续放大。
- 要求每版新教材回头核对真实病历 = 保留真实数据锚点，防止合成数据分布不断偏离真实世界。

**比喻边界**：故事里"教材"是静态的文本材料，而现实中的合成数据生产往往还包括"合成练习题+标准答案"这类可反复训练用的结构化样本，且合成过程本身依赖精心设计的提示词（决定了合成内容的质量上限）；故事也简化了"扩写导致质量下降"的具体机制——现实中的模型崩溃有更复杂的统计原因（分布尾部信息逐轮丢失），不只是"没有回头核对"这一个因素。

**非适用例**：如果宠物诊所想让新人学会"怎么安抚一只极度焦虑的宠物主人"，这种需要真实情绪反应、没有标准流程可循的沟通技能，靠精炼教材式的合成材料很难覆盖——这类需要真实人类多样性和临场判断的能力，不是"写一份更好的教材"能解决的，合成数据在这里的适用边界很窄。

**现实例子**：phi-1（2023）用 6B token 精心设计的教科书代码 + 1B 合成练习题（总计 7B token），训出的 1.3B 模型在 HumanEval 上达到 50.6% 的准确率，超过用超过 1T token 粗糙数据训练的 13B 参数 CodeLLaMA（36.0%），验证了"数据质量可以大幅替代数据量"。

### 检验问题

1. 理解检验：如果院长一开始就要求老陈把二十种常见病扩展成两百种、但每种病都只用一句话带过（不写误诊陷阱和标准流程），你觉得新人的学习效果会更接近"啃旧档案"还是"啃精炼教材"？为什么材料的"课程化设计程度"比"覆盖的病种数量"更关键？
2. 迁移检验：一家法律科技公司想用 GPT-4 生成的一批"标准合同审查案例"来训练一个小模型做合同风险初筛，之后又打算让这个小模型自己生成更多类似案例来继续训练下一代模型，如此反复几轮、不再引入真实合同数据。你预测几轮之后会出现什么问题？可以对应故事里哪个环节的教训？

## 为什么互联网数据不够好？

```
互联网代码数据的问题（以 phi-1 为例）：
  - 大量 boilerplate、重复、无教育意义的片段
  - 错误示范、过时代码混杂
  - 代码和解释分离（难以学习"为什么这样做"）
  - 测试用例、文档不足
  
传统解法：更多数据
  Codex（12B）：159B code tokens
  StarCoder（15B）：780B tokens
  
phi-1 的质疑：
  "我们需要这么多数据吗？还是只需要更好的数据？"
```

## phi-1 的"教科书假设"

```
核心洞察（论文78）：
  人类学编程不靠爬遍所有 Stack Overflow
  而是靠：
    1. 精心设计的教科书（循序渐进）
    2. 练习题（反复应用）
    3. 解释性示例（"为什么"比"是什么"更重要）
    
实验：
  数据来源：6B token 高质量教科书代码 + 1B 合成练习题
  总计：7B tokens（vs CodeLLaMA 的 1T+）
  
结果：
  phi-1（1.3B）在 HumanEval 上：50.6%
  CodeLLaMA-13B：36.0%
  → 参数少 10x，数据少 100x，但性能更好
```

## 合成教科书的生成方法

```
两类合成数据（phi-1 的实践）：

1. 合成教科书文本（Textbook Content）
   用 GPT-3.5/4 生成高质量解释性代码教材
   提示：
   "以教科书风格写一个关于{主题}的Python教程，
    包括：概念解释、多个例子、递进难度、
    常见错误分析"
   
   质量控制：
   - 多样性：从主题词汇表随机采样，避免重复
   - 人工筛选：过滤低质量输出
   
2. 合成练习题（Exercises）
   针对特定技能生成练习题 + 标准答案
   格式：问题描述 + 规范解法 + 解释
   
核心：提示工程决定了合成质量上限
```

## 数据质量 vs 数量的权衡

```
Scale Law 的修正：

传统理解（Chinchilla 等）：
  性能 ∝ 模型大小 × 数据量（都重要）
  
phi-1 的修正：
  数据质量可以替代数据量
  更精确的公式：
    性能 ∝ 模型大小 × 数据有效量
    数据有效量 = 数据量 × 平均质量
    
  质量 10x → 需要的数量 1/10x
  
实证数据：
  1B token 教科书 ≈ 100B token 网络数据（对代码任务）
  质量放大率 ~100x（任务相关领域内）
```

## 自博弈与数据调味（论文07）

```
更进一步：动态生成训练数据

自博弈（Self-play）思路：
  1. 当前模型生成数据（自我对战/自我评分）
  2. 筛选/优化高质量数据
  3. 用筛选后的数据再训练模型
  4. 循环

"数据调味"（Data Seasoning）：
  不是静态的"合成一次"
  而是根据模型当前弱点动态调整合成数据分布
  → 把更多数据资源放在模型的"痛点"上
  
类比：
  传统：固定食谱，每天吃同样的菜
  数据调味：根据今天的营养缺口，调整明天的菜单
```

## Autodata（论文03）

```
更自动化的合成数据流水线：

自动化步骤：
  1. 主题发现：自动枚举训练任务/技能
  2. 数据生成：针对每个技能自动生成样本
  3. 质量过滤：自动评分 + 去重
  4. 课程编排：按难度排序

优势：减少人工介入，可规模化
局限：自动生成的数据难以避免"模型幻觉污染"
      → 合成数据的质量上限 = 生成模型的能力上限
```

## 合成数据的应用边界

```
适合合成数据的任务：
  ✅ 有客观正确答案的任务（代码、数学）
  ✅ 有可验证的输出（单元测试）
  ✅ 风格/格式统一（教科书格式）
  ✅ 数据稀缺的领域（专业领域）

不适合合成数据的任务：
  ❌ 创意写作（合成内容缺乏多样性）
  ❌ 事实准确性要求高（合成数据可能引入错误）
  ❌ 需要真实人类偏好（RLHF 的人类评分无法合成）
  ❌ 世界知识覆盖（需要真实事件数据）

危险：合成数据训练合成数据的模型 → 模型崩溃（Model Collapse）
  每轮训练都在放大前一轮的错误
  需要保留真实数据锚点（锚住合成分布）
```

## PM 决策框架：什么时候用合成数据？

| 场景 | 推荐 | 原因 |
|------|------|------|
| **代码生成微调** | ✅ 强推荐 | phi-1 已证明高效 |
| **数学推理训练** | ✅ 强推荐 | 有验证器，质量可控 |
| **特定格式输出**（JSON/SQL）| ✅ 推荐 | 规则明确，合成简单 |
| **专业领域知识**（医疗/法律）| ⚠️ 谨慎 | 合成知识可能不准确 |
| **对话/角色扮演** | ⚠️ 部分适用 | 需要真实人类偏好校准 |
| **新闻/事实问答** | ❌ 不推荐 | 合成事实可能出错 |
