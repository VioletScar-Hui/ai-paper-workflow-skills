# 过程奖励模型 PRM

## 一句话定义

过程奖励模型（PRM）对推理链的每个中间步骤单独给出正确性评分，而非仅对最终答案打分，从而能够在多步推理任务中识别出第一个出错的步骤，提供比结果奖励模型（ORM）更精准的训练信号。

## 寓言学习

### 寓言正文

一家做定制柜子的家具厂，过去检验方式很简单：柜子做完，最后在产线尽头设一道验收——开箱看外观有没有磕碰，拿尺子量整体尺寸对不对，合格就装车。工人只要保证"最后交出来的柜子过得了这一关"，中间打孔、拼板、装五金的具体做法，验收员基本不过问。

后来厂里改了规矩：打孔这道工序做完，当场有人拿模具比对孔位；拼板拼完，当场检查缝隙是否对齐；五金装完，当场试拉抽屉和柜门。每道工序做完就在这道工序上打钩或者打叉，不用等到最后成品出来才知道问题出在哪。

改规矩前有一单柜子，最后验收时外观工整、尺寸分毫不差，顺利出了货。客户自己组装内部隔板时才发现，几个打孔的位置其实是错的——只是错位的量刚好被外层面板挡住看不出来，插销靠着一点点富余的空隙硬是能塞进去，最后拼出来的柜子晃是晃，但没到验收员一眼能看穿的程度。要是当初打孔那道工序当场就比对模具，这个问题在流水线中段就会被挑出来，不用等客户自己组装时才发现。

### 概念解析

**概念名称**：过程奖励模型 PRM（Process Reward Model），属于大语言模型强化学习训练的奖励信号设计问题域。

**学习卡片**
- 核心张力：只在最后一步核验结果对不对（成本低，但看不出错在哪一步、也拦不住"蒙混过关"的错误）vs 每个中间步骤都单独核验（能精确定位错误，但需要对每一步都有核验能力和成本）。
- 关键不变量：一步是否"正确"，是在这一步刚完成时就被判定的，而不是等最终结果出来后倒推；即使最终结果侥幸合格，中间某步的错误也应该被记录下来。
- 触发条件：任务是多步骤过程，且中间某一步的错误可能被后续步骤掩盖、或恰好被"凑合"过去而不影响最终表面结果时，逐步核验才显出价值。
- 常见误解/失败模式：以为"最终结果合格"等于"每一步都做对了"——实际上最终结果合格也可能是错误被后面步骤意外掩盖或侥幸兼容的结果。
- 非适用边界：如果任务本身没有明确的中间步骤、或每一步无法被单独判断对错（比如整体是一次性生成、没有可拆分的工序），就没法逐步核验，只能靠最终结果判断。

**一句话核心定义**：过程奖励模型是在多步骤任务的每个中间步骤（而不只是最终结果）上单独给出对错评分的评估方式，用来精确定位第一个出错的步骤，而不是仅凭最终结果是否合格来判断整个过程好坏。

**它试图解决的问题**：如何避免"结果侥幸合格、但过程其实有错"被漏检，在错误发生的那一步就把它揪出来，而不是等到成品甚至交付后才发现。

**故事元素映射**：
- 产线尽头一次性验收成品 = 结果奖励模型（ORM），只判断最终答案对不对。
- 每道工序做完当场核验 = 过程奖励模型（PRM），对推理链的每个中间步骤单独评分。
- 打孔位置错但被面板挡住、插销侥幸能用 = "答案侥幸正确，但推理过程其实有错"的失败模式，ORM 无法识别，PRM 能在打孔工序当场发现。
- 每道工序打钩打叉的记录 = PRM 输出的逐步正确性概率，可用于第一时间定位错误发生的具体步骤。

**比喻边界**：故事把核验简化成"对/错"两种结果，真实的 PRM 输出的是每一步"正确"的概率分数，且可以用于 Best-of-N/束搜索这类推理时决策，也可以作为强化学习训练中的密集奖励信号——这两种用途故事里都没有展开；此外真实场景中逐步人工标注成本很高，工业界常用蒙特卡洛采样（比如 Math-Shepherd）自动估计每步价值，而不是像故事里那样每步都配一个人当场核验。

**非适用例**：如果这家厂做的是纯手工雕花摆件，每件的雕刻手法、造型都不一样，没有"标准工序清单"可以对照，那就没法在中间设固定的核验点——这种没有明确可拆分步骤、也没有客观对错标准的任务，不适合套用逐步核验这套机制，只能靠最后整体判断做得好不好。

**现实例子**：Lightman 等人 2023 年的 "Let's Verify Step by Step" 在 MATH 数学数据集上验证，用 PRM 对候选解题步骤逐步打分再挑选最优路径（Best-of-N），能把 GPT-4 的解题正确率从约 69% 提升到约 78%，明显优于只看最终答案对错的 ORM。

### 检验问题

1. 理解检验：故事里那单出问题的柜子，最终验收时"外观工整、尺寸达标"，为什么还是不合格？这说明"最终结果合格"和"每一步都做对了"之间是什么关系？
2. 迁移检验：如果一家客服团队想用类似的逐步核验思路评估"AI 客服处理一次多轮投诉"的质量，你觉得该在哪些"工序节点"设检查点？

## 核心原理

### ORM vs PRM 的根本区别

**结果奖励模型（ORM）**
- 输入：问题 + 完整推理链
- 输出：一个标量，表示最终答案是否正确
- 问题：不知道错在哪一步；正确答案也可能由错误推理得到（"正确但侥幸"）

**过程奖励模型（PRM）**
- 输入：问题 + 推理链的前 k 步
- 输出：第 k 步是否正确的概率
- 优势：精确定位错误步骤；可用于 step-level beam search；能区分"答案对但过程错"

```
ORM: [问题, 步骤1, 步骤2, ..., 步骤N, 答案] → 正确/错误

PRM: [问题, 步骤1]                    → p(步骤1正确)
     [问题, 步骤1, 步骤2]              → p(步骤2正确|步骤1)
     [问题, 步骤1, ..., 步骤k]         → p(步骤k正确|步骤1,...,步骤k-1)
```

### "Let's Verify Step by Step" 的核心发现

Lightman et al. (2023) 的开创性工作（OpenAI）在 MATH 数据集上系统比较了 ORM 和 PRM：

1. **PRM 显著优于 ORM**：在 Best-of-N 采样中，PRM 用最优步骤选择能将 GPT-4 的数学题正确率从 ~69% 提升至 ~78%
2. **逐步监督比结果监督数据效率更高**：相同标注预算下，PRM 标注的步骤级数据比 ORM 的结果级数据更有价值
3. **人工标注必要性**：自动标注（如答案正确则所有步骤都标正确）会引入噪声，人工逐步标注质量明显更优

### 数学推理中 PRM 的优势

在数学推理场景中，单步错误会导致后续所有步骤无效，但最终答案可能"碰巧"正确（运气）或看起来合理（幻觉）。PRM 能够：

1. **早停错误路径**：在 Tree of Thought / MCTS 搜索中，PRM 分数低的分支可提前剪枝
2. **提供密集奖励**：避免稀疏奖励问题（只有最后一步才知道对错）
3. **步骤级 Best-of-N**：比较同一位置不同续写路径，选最优的继续

### Monte Carlo 估计步骤价值

当人工标注成本过高时，可用 Monte Carlo 方法自动估计每步的价值：

```
V(问题, 前k步) = P(从前k步出发，最终得到正确答案)
             ≈ (从前k步采样N条完整路径中正确的比例)
```

通过对每个中间状态采样大量完整推理路径，用"后续能否得到正确答案"来反推"当前步骤是否正确"。这种方法被 Math-Shepherd、OmegaPRM 等工作采用，大幅降低了 PRM 训练的标注成本。

### PRM 与 RLHF 的结合

PRM 可作为 PPO 训练中的逐步奖励信号替代原来的稀疏结果奖励：

```python
# 稀疏奖励（传统 RLHF）
reward = [0, 0, 0, ..., 0, final_reward]  # 只有最后一步有奖励

# 密集奖励（PRM-based）
reward = [prm_score_1, prm_score_2, ..., prm_score_N]  # 每步都有反馈
```

密集奖励显著加速强化学习收敛，尤其在长推理链场景中效果突出。

## PM 决策视角

### PRM 的适用场景

| 场景 | ORM | PRM |
|------|-----|-----|
| 数学竞赛题 | 弱（步骤多，错误累积） | 强 |
| 代码生成（单函数） | 可接受 | 轻微优势 |
| 开放式写作 | 唯一选项（无标准步骤） | 不适用 |
| 逻辑推理/证明 | 弱 | 强 |
| 工具调用链 | 弱（中间调用难评估） | 强（每次调用可验证） |

### 标注成本的权衡

- 人工逐步标注：质量最高，成本 ~10× ORM 标注
- MC 自动估计：成本低，但准确率受采样策略影响（噪声较大）
- 规则验证（代码执行）：适合代码/数学，成本极低，可替代人工
- 混合策略：前几步人工，后续步骤 MC 估计

### 推理时使用 vs 训练时使用

PRM 有两种使用方式，往往同时采用：
- **训练时**：作为 RLHF 的密集奖励信号，改善策略学习
- **推理时**：Best-of-N / Beam Search 中对候选步骤打分，不改变模型参数

对于预算有限的团队，推理时使用 PRM 做 Best-of-N 是性价比极高的提升方案，无需重新训练基础模型。
