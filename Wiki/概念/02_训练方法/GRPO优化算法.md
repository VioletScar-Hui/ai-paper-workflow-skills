# GRPO（Group Relative Policy Optimization）

> **一句话定义**：GRPO 是 PPO 的轻量替代，通过对同一问题采样一组答案并用组内相对奖励估计优势值，完全省去了 Critic 网络——让推理模型训练更稳定、更节省显存，已成为推理模型后训练的主流算法。

---


## 寓言学习

### 寓言正文

培训班要评估一道应用题的哪种解法更值得推广。以前的做法是请一位阅卷专家，专门给每份答案打一个绝对分数，比如"这份解法算 78 分"。专家要提前培训、状态还容易起伏——今天心情好打分松一点，今天累了打分严一点，专家本身就是一笔额外的开销。

后来培训班换了个办法：让同一个学生，针对同一道题，一口气写出 8 种不同的解法。不需要专家单独给每份打绝对分，只要有一份标准答案核对表，能判断每份解法最后算没算对。8 份答案里，算对的记 1 分，算错的记 0 分，取这 8 份的平均分作为这道题当次的基准线：得分超过平均线的解法，多鼓励学生以后多用这类思路；低于平均线的，少鼓励。省去了专门请阅卷专家这一步，只靠一份对错核对表就能运转。

有一天出的题目太简单，学生轻车熟路，写出来的 8 种解法几乎大同小异，最后全部算对，8 份得分都一样。基准线和每份的得分完全重合，超过平均线和低于平均线的差别消失了，这次没法从中挑出"哪种解法更值得推广"，训练当次没起到效果。

### 概念解析

**概念名称**：GRPO（Group Relative Policy Optimization），属于大语言模型强化学习后训练算法问题域。

**学习卡片**
- 核心张力：额外训练一个独立的"打分员"来评估答案好坏（成本高，打分员本身也可能训练不稳）vs 让同一批候选答案互相比较，用组内相对名次代替独立打分员。
- 关键不变量：一个答案"值不值得多学"是通过它在同一组候选里排名高低算出来的，而不是靠外部单独打分员给出的绝对分数；同一批候选之间必须有质量差异，否则无法比较出高低。
- 触发条件：任务有清晰、可验证的最终结果（对错/通过与否），且希望避免额外训练一个成本高、不稳定的独立打分模型。
- 常见误解/失败模式：忽视"组内比较"依赖候选之间要有区分度——如果同一批候选质量趋同，组内比较会完全失去效果，学习停滞。
- 非适用边界：没有客观可验证结果、只能靠主观偏好判断优劣的任务（比如文采好坏），组内相对排名机制不好用，因为"同一批里谁更好"本身就没有唯一客观答案。

**一句话核心定义**：GRPO 是对同一问题采样一组候选答案，用组内答案的相对奖励（而非外部打分员给出的绝对价值）来估计每个答案的优势，从而完全省去独立打分网络的强化学习训练方法。

**它试图解决的问题**：如何在不额外训练一个独立、昂贵且可能不稳定的打分模型（Critic）的前提下，依然能判断一批候选答案里哪些值得多学、哪些该少学。

**故事元素映射**：
- 请阅卷专家单独打绝对分 = PPO 中的 Critic 网络，需要额外训练、状态可能不稳定。
- 同一个学生写出 8 种解法 = 对同一问题采样 G 个候选答案。
- 标准答案核对表判断对错 = 可验证的结果奖励（Reward）。
- 用 8 份得分的平均线当基准、超过平均线多鼓励 = 组内归一化优势估计，用组内均值代替 Critic 的价值估计功能。
- 题目太简单导致 8 种解法趋同、无法区分好坏 = GRPO 的失败模式：组内候选质量趋同时，方差消失，训练信号失效。

**比喻边界**：故事把"优势"简化成"超过/低于平均分"，但真实的 GRPO 用的是组内奖励的均值和标准差做归一化（Â = (r-mean)/std），并结合 PPO 式的 clip 机制和 KL 惩罚防止更新过大，这些数学细节故事里没有体现；此外 GRPO 依赖"结果可验证"这个前提，故事里的核对表对应的正是这一前提。

**非适用例**：如果培训班要评的是一篇作文"写得好不好"，没有标准答案核对表可以判断对错，8 篇作文互相比较也得不出唯一客观的高低——这种主观评价任务不适合套用组内相对排名这套机制，仍需要一个专门训练的偏好评判模型。

**现实例子**：DeepSeek-R1（2025）用 GRPO 训练推理模型：对同一道数学题采样 8~16 个候选解答，用能否得出正确答案作为结果奖励，组内归一化后指导策略更新，省去了 PPO 里需要的 Critic 网络，训练更稳定、显存需求更低，已成为推理模型后训练的主流算法之一。

## 从 PPO 到 GRPO

```
PPO（Proximal Policy Optimization，标准 RLHF 算法）：
  需要 4 个模型：Policy + Critic + Reference + Reward Model
  Critic：估计每个状态的价值 V(s)，参数量与 Policy 相当
  优势估计：A = R - V(s)  (需要 Critic 网络做 Baseline)
  
  问题：
    ① Critic 网络本身需要大量显存（又一个大模型）
    ② Critic 训练不稳定，影响 Policy 更新质量
    ③ 长序列推理（长 CoT）下，时序信用归因极困难

GRPO（DeepSeek-R1，2025）：
  省去 Critic 网络！只需 Policy + Reference + Reward Model（共3个）
  
  核心思路：对同一问题 q，采样 G 个答案 {o₁, o₂, ..., o_G}
  各答案获得奖励 {r₁, r₂, ..., r_G}
  
  组内归一化优势：
    Â_i = (r_i - mean({r_j})) / std({r_j})
    
  直觉：组内均值作为 Baseline（类似 Critic 的功能），
        用相对排名而非绝对价值评估每个答案
```

## GRPO 的优化目标

```
GRPO 的损失函数（简化版）：

L_GRPO = -E_{q,{o_i}} [ Σ_i [ min(
    (π_θ(o_i|q) / π_old(o_i|q)) · Â_i,
    clip(π_θ(o_i|q) / π_old(o_i|q), 1-ε, 1+ε) · Â_i
  ) ] ]
  - β · KL(π_θ || π_ref)

其中：
  第一项：PPO 的 clipped 目标（防止更新过大）
  第二项：KL 惩罚（防止偏离参考策略太远）
  Â_i：组内相对优势
```

## 奖励设计（以 R1 为例）

```
DeepSeek-R1 的奖励：

1. 正确性奖励（主要信号）：
   数学题：答案正确 = +1，错误 = 0
   代码题：测试用例通过率
   
2. 格式奖励（辅助信号）：
   要求模型用 <think>...</think> 包裹推理过程
   不满足格式 = -1
   
3. 长度惩罚（进阶版）：
   过长推理链 → 惩罚，防止"padding 攻略"
   
不需要：
   ❌ 人工标注的推理步骤
   ❌ 过程奖励（只用结果奖励）
   ❌ 示范答案（只需问题+答案验证器）
```

## GRPO vs PPO 的量化对比

| 维度 | PPO | GRPO |
|------|-----|------|
| 模型数量 | 4（Policy+Critic+Ref+RM）| 3（省去 Critic）|
| 显存需求 | ~3x Policy 显存 | ~2x Policy 显存 |
| 实现复杂度 | 高（Critic 训练、GAE 等）| 中（只需批采样+归一化）|
| 长序列稳定性 | 差（时序依赖的 Baseline）| 好（组内统计不受序列长度影响）|
| 数学上的严格性 | 有理论保证 | 工程上有效，理论稍弱 |

## 实践中的 GRPO 超参数

| 超参 | 含义 | 典型值 |
|------|------|--------|
| G（组大小）| 同一问题采样几个答案 | 8-16 |
| ε（clip 范围）| PPO clip 系数 | 0.1-0.2 |
| β（KL 系数）| 防偏离程度 | 0.01-0.1 |
| max_new_tokens | 生成最大长度 | 8K-32K |

## 最弱假设与边界

1. **同质问题假设**：同一批问题的 G 个答案质量差异要足够大，否则组内归一化无法区分
2. **可验证奖励限制**：GRPO 依赖结果级奖励（数学/代码可验证），主观任务（写作、创意）奖励设计困难
3. **奖励稀疏性**：只有最终答案有奖励，中间推理步骤信号稀疏（PRM 可辅助）
4. **探索坍塌风险**：G 个答案可能趋同 → 组内方差消失 → 学习停滞

## 补充:更严谨的机制与公式(源自 Alisa's Book of LLMs)

### 组内相对优势的完整公式

GRPO 的核心操作是：不再用一个独立的 Critic 网络去估计"这个状态本来预期能拿多少奖励"，而是对同一个问题 $q$ 采样一组 $G$ 个回复 $\{o^{(i)}\}_{i=1}^G$，各自算出奖励 $\mathbf{r} = \{r^{(i)}\}_{i=1}^G$，然后用组内的均值和标准差把每个回复的奖励归一化成一个相对优势：

$$A^{(i)} = \frac{r^{(i)} - \text{mean}(\mathbf{r})}{\text{std}(\mathbf{r})}$$

注意这里 $A^{(i)}$ 是针对整条回复算出来的一个标量，回复里的每一个 token 共享同一个 $A^{(i)}$ 值——这也是后面 Dr. GRPO 要修正的问题之一的来源。GRPO 严格来说不完全是"选一个 baseline 来做差"这么简单，因为它不仅做了减去均值的操作，还额外除以了标准差做归一化，这一步同时决定了后面要讲的一个偏差。

### GRPO-CLIP 目标函数完整形式

$$\mathcal{J}^{\text{GRPO-CLIP}}(\theta) = \frac{1}{G}\sum_{i=1}^{G}\frac{1}{T}\sum_{t=1}^{T}\min\Big(r_t A^{(i)},\ \text{clip}(r_t, 1-\epsilon, 1+\epsilon)\, A^{(i)}\Big)$$

其中 $r_t = \dfrac{\pi_\theta(o_t \mid s_t)}{\pi_{\theta_{\text{old}}}(o_t \mid s_t)}$ 是逐 token 的概率比值（沿用 PPO 的记号，这里用 $o_t$ 代替 $a_t$ 表示生成的 token）。

### GRPO 融合了三个思路

把 GRPO 拆开看，其实是三种已有机制的组合，不是凭空出现的新算法：

1. **off-policy 策略梯度**：用 $\pi_{\theta_{\text{old}}}$ 采样轨迹、$\pi_\theta$ 做更新的重要性采样形式 $\mathcal{J}^{\text{surrogate}}(\theta) = \mathbb{E}_{\tau\sim\pi_{\theta_{\text{old}}}}\left[\sum_t r_t R(\tau)\right]$，这样采样和更新可以分开进行，不需要每一步都用最新策略重新采样。
2. **PPO 的裁剪机制**：把上面的目标裁剪成 $\mathcal{J}^{\text{CLIP}}(\theta) = \mathbb{E}_{\tau\sim\pi_{\theta_{\text{old}}}}\left[\sum_t \min(r_t R(\tau),\ \text{clip}(r_t,1-\epsilon,1+\epsilon)R(\tau))\right]$，防止单次更新幅度过大导致训练不稳定。
3. **组内归一化的优势估计（DeepSeek R1 引入）**：把上面公式里的 $R(\tau)$ 换成组内归一化后的 $A^{(i)}$，这样就不再需要 Critic 网络单独估计"预期奖励"，而是直接用同一批采样结果互相做参照。

三者叠加起来，就得到了前面写的 GRPO-CLIP 目标函数。

### GRPO 训练算法伪代码

```
初始化策略模型 π_θ ← π_θ_init

for each step in n_grpo_steps:
    从数据集 D 中采样一个批次 D_b
    更新旧策略：π_θ_old ← π_θ
    for each question q in D_b:
        采样 G 个输出 {o^(i)}_{i=1}^G ~ π_θ_old(·|q)
        用 R(q, o^(i)) 计算每个输出的奖励 {r^(i)}_{i=1}^G
        通过组内相对优势估计计算 A^(i)

    for each train step in n_train_steps_per_rollout_batch:
        用 GRPO 目标函数更新策略模型 π_θ（最大化 J^GRPO-CLIP）

    （可选）通过持续训练 + replay 机制更新奖励模型 r_φ
```

本质上，GRPO 是用"采样一批、直接测量"代替"训练一个模型去预测"——不学习预测期望奖励，而是靠实际采样去测出来。代价是需要更多计算（每个 prompt 要采样 $G$ 个完整回复），换来的好处是不用再维护和训练一个和策略模型体量相当的 Critic 网络，显存占用更低。

### Dr. GRPO 修正的两个偏差

Dr. GRPO 指出 GRPO 的归一化方式里藏着两个系统性偏差，都会让模型学到"投机取巧"的策略，而不是真正把问题做对：

**偏差一：除以 $\text{std}(\mathbf{r})$ 放大了"太简单或太难"问题组的梯度权重。** 当一组问题过于简单（G 个回复几乎都对）或过于困难（G 个回复几乎都错）时，组内奖励的方差本来就很小，$\text{std}(\mathbf{r})$ 是个很小的数。除以一个很小的数，会把这一组的优势值 $A^{(i)}$ 相对放大，导致模型在优化时"更重视"这些本来区分度就不高、信号质量存疑的题目组，而不是均匀地对待所有难度的题目。

**偏差二：除以回复长度 $|o_i|$ 导致长度和梯度大小反向绑定。** 在对答对/答错的回复做梯度更新时，如果用回复长度去归一化，会产生一个反直觉的效果：在**正确答案**里，越短的回复归一化后梯度越大（被更强烈地强化）；在**错误答案**里，越长的回复归一化后梯度越小（受到的惩罚被稀释）。这两条叠加起来，模型学到的实际策略会是——**答不对的时候，就把回复写得很长，以此减小自己受到的惩罚**。这不是模型在真正学习推理，而是在钻长度归一化的空子。

这个失败模式对判断一个推理模型的训练是否走偏很关键：如果观察到模型在验证集上"答错的题目回复明显变长、但正确率没有相应提升"，很可能就是这种长度归一化偏差在起作用，而不是模型在做更充分的思考。
