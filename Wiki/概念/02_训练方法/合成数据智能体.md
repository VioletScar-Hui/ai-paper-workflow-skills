# 合成数据智能体（Agentic Data Scientist / Autodata）

> **一句话定义**：用 AI Agent 扮演"数据科学家"角色——自动迭代生成训练数据、评估质量、分析反馈、改进生成策略，替代人工标注。

## 寓言学习

### 寓言正文

银行反欺诈部要建一个"可疑交易案例库"，用来培训新分析师。以前的做法是资深调查员老魏亲自设计案例，一个案例要花他大半天，产量太低，跟不上团队扩招的速度。

部门主管小何搭了一套自动生成系统来接手这件事：系统按照当前设定的"出题策略"，批量生成一批模拟可疑交易案例，每一批案例先丢给一个刚入职的新分析师试判断，再丢给老魏复核、确认这笔交易到底是不是真欺诈。小何比对两边的结果定规矩：新分析师和老魏都一眼判断对的案例，扔掉——太简单，练了也没用；两边都判断不出、连老魏都拿不准的案例，也扔掉——这种案例本身可能压根有问题，不该拿来当范本；只有"老魏能确认答案、新分析师普遍判断错"的那批，才留下来当正式培训案例。

系统跑了几个月，小何发现一个更有意思的事：把每一轮"哪批案例被留下、哪批被扔掉"的记录喂回给系统本身，让系统据此调整自己的出题策略，慢慢地，系统一开始生成的案例，命中"留下来"这个标准的比例越来越高，不再需要一开始那样批量生成、批量扔了。

代价也摆在那儿：每个案例平均要在新分析师、老魏、系统之间来回折腾好几轮才能定案，算下来一个案例的成本并不比老魏亲自设计便宜多少，只是不再卡在老魏一个人的产能上。而且小何后来发现，团队新来的分析师如果背景经验和最初那批"新分析师标杆"差别很大，用老标准筛出来的案例，未必真的踩中他们的能力短板——弱-强差距这把尺子，量的是特定那组人的差距，换一批人未必准。

### 概念解析

**概念名称**：合成数据智能体（Agentic Data Scientist / Autodata），属于自动化训练数据生成、AI Agent 系统设计问题域。

**学习卡片**
- 核心张力：想要持续产出"刚好有训练价值"的数据（新手学不会、但答案确实存在且正确），但人工设计这种恰到好处难度的样本，产能永远跟不上模型迭代和团队扩张的速度；让 AI 系统自动生成、自动筛选，才能规模化，但自动系统本身的筛选标准也需要不断被校准。
- 关键不变量：一条样本有没有训练价值，取决于"弱者（目标要提升的一方）做不到、强者（能确认正确答案的一方）能做到"这个差距是否存在且足够大——差距接近零（不管是两边都会还是两边都不会）就说明这条样本该被扔掉。
- 触发条件：目标能力缺乏现成的高质量标注数据，但存在一个明显能力更强、可以充当"验证者"的角色（人或强模型），且生成、验证、筛选的过程可以自动化循环。
- 常见误解/失败模式：以为只要让系统一直生成、一直筛选就会越来越好，忽视了筛选标准本身依赖于当前这组"弱者/强者"的具体能力水平——如果后续要培训的对象和最初校准筛选标准时用的那批人能力结构差别很大，筛出来的"好数据"未必真的对新对象有效。
- 非适用边界：如果任务本身没有一个能可靠"确认正确答案"的强验证者（比如高度主观、没有共识标准的判断），或者场景对实时性要求极高、等不起生成-验证-筛选这套多轮循环的时间和算力成本，这套机制就用不上。

**一句话核心定义**：合成数据智能体是用 AI Agent 自动扮演"出题—弱者试做—强者验证—评判筛选"的完整流程，持续产出"弱者做不到但强者能确认答案"的黄金难度训练数据，并让系统根据历次筛选结果反过来优化自己的出题策略。

**它试图解决的问题**：训练数据的难度校准原本依赖人工反复试错、成本高、产能低；这套机制把"生成-验证-筛选"自动化成一个可迭代的闭环，同时用"元优化"让生成系统自己越用越准，减少对人工设计的依赖。

**故事元素映射**：
- 老魏亲自设计案例、产能跟不上 = 人工标注/设计训练数据的产能瓶颈。
- 小何搭的自动生成系统 = 主编排器 Agent。
- 系统批量生成模拟案例 = Challenger 组件。
- 新分析师试判断 = 弱求解器（目标要训练提升的模型）。
- 老魏复核确认 = 强求解器（用于验证案例是否有明确正确答案）。
- 小何定的"两边都对/都错就扔，只留老魏对新人错"的规则 = Judge 组件，对应"强求解器高通过率 + 弱求解器低通过率"的验收标准。
- 把筛选记录喂回系统调整出题策略 = 元优化：用内循环的质量反馈训练/优化生成系统本身。
- 每案例来回折腾好几轮、成本不低 = 落地代价：每个样本平均要经过多轮 Agent 循环，算力和时间开销不小。
- 新分析师背景差异大导致筛选标准不准 = 局限：弱-强差距的校准依赖具体的弱/强角色配置，换一批对象未必可迁移。

**比喻边界**：故事里"新分析师"和"老魏"是两个固定的人，而现实系统里弱求解器往往就是正在被训练的目标模型本身、强求解器是另一个更强的模型，两者的角色关系比故事里的"新人 vs 资深员工"更动态——弱求解器会随着训练不断变强，理论上需要持续用新一版的弱求解器结果重新校准，这一点故事没有展开；此外故事把"元优化"简化成了"把筛选记录喂回去"，现实中这一步是对生成 Agent 本身做强化学习训练，比单纯参考历史记录复杂得多。

**非适用例**：如果反欺诈部想做的是"评估客户对新推出的理财产品是否满意"，这种没有客观对错、只有主观偏好的判断，没有一个天然的"强求解器"能给出唯一正确答案来验证，弱-强差距这套机制在这里无从谈起——这类主观评价类任务不适合套用这套自动化数据生成流程。

**现实例子**：Autodata（Agentic Self-Instruct，2026）用"Challenger 生成样本 + 弱/强求解器验证 + Judge 评估差距 + 元优化"的完整闭环自动生成训练数据，验收标准设定为强求解器通过率 ≥75% 且弱求解器通过率 ≤25%；论文同时报告，每个样本平均需要 6.59 轮 Agent 循环才能定案，算力成本不低，但换来了不依赖人工标注、可规模化扩展的数据生产能力。

### 检验问题

1. 理解检验：如果小何把筛选规则改成"只要老魏和新分析师判断不一样就留下"，不区分"新人错、老魏对"还是"新人对、老魏错"这两种不一致，你觉得筛出来的案例库质量会出现什么问题？这对应弱-强差距机制里被忽略的哪个环节？
2. 迁移检验：一家教育公司想用同样的思路——自动生成数学题，用"入门学生"和"竞赛教练"两个角色的答题结果筛出黄金难度题目——来构建一个高中数学题库，半年后又想直接把这套筛好的题库不做调整地用于培训初中生。你预测会出现什么问题？可以对应故事里哪个局限？

## 解锁了什么产品能力

- **无人工标注的数据飞轮**：AI 系统可以自我生成训练数据，持续迭代提升自身能力
- **难度精准校准**：生成"弱模型做不到、强模型能做到"的黄金难度数据
- **评测集自动构建**：在没有现成 benchmark 的垂直领域自动生成高质量评测题

## 核心架构（Agentic Self-Instruct）

```
                 ┌─────────────────────────────────┐
                 │     主编排器 Agent（LLM）           │
                 │  分析反馈 → 更新生成策略             │
                 └────────┬──────────────────────────┘
                          │ 指令
           ┌──────────────▼──────────────────┐
           │           Challenger              │
           │   按照策略生成训练样本（问题+答案）  │
           └──────┬────────────┬──────────────┘
                  │            │
          ┌───────▼───┐  ┌─────▼────────┐
          │ 弱求解器   │  │  强求解器     │
          │(目标训练   │  │(验证数据是否  │
          │ 模型)      │  │ 有正确答案)   │
          └───────┬───┘  └─────┬────────┘
                  └──────┬─────┘
                  ┌──────▼──────┐
                  │   Judge      │
                  │ 评估差距是否  │
                  │ 达到要求     │
                  └──────┬──────┘
                          │ 反馈
                 回到主编排器 → 下一轮迭代
```

**验收标准**：强求解器 ≥75% 通过率 AND 弱求解器 ≤25% 通过率 = 优质训练样本

## 弱-强差距（Weak-Strong Gap）

这是评估合成数据质量的核心指标：

| 状态 | Gap | 含义 |
|------|-----|------|
| 数据太简单 | ≈0（都高分） | 浪费：弱模型已经会了，没有训练价值 |
| 数据太难 | ≈0（都低分） | 浪费：强模型也不会，可能是错题 |
| ✅ 好数据 | Gap 大（强高弱低） | 强模型能验证正确性，弱模型有学习空间 |

## 元优化（Meta-Optimization）

除了内循环（生成数据），还有外循环：
- **内循环**：Agent 生成数据 → 评估质量 → 更新生成 prompt
- **外循环**：用内循环的质量指标，对 Agent 本身进行 RL 训练，使其成为更好的"数据科学家"

效果：元优化后的 Agent 生成的数据让弱模型的 RL 训练收益显著增大。

## 落地代价

| 维度 | 评估 |
|------|------|
| 💰 算力 | 高：每个样本平均需要 6.59 轮 Agent 循环；强/弱模型各多次推理 |
| 📊 数据 | 需要少量种子数据（论文/文档）作为 Grounding；不需要人工标注 |
| ⏱️ 延迟 | 不影响推理（仅用于训练时数据生成，离线可接受） |
| 🔧 工程 | 需要搭建多 Agent Pipeline + 评测框架；有一定工程门槛 |

## 适用场景（PM 选型）

| 场景 | 是否适用 |
|------|---------|
| 垂直领域模型微调，缺乏标注数据 | ✅ 强烈适合 |
| 构建垂直 benchmark（法律、医疗、金融） | ✅ 适合 |
| 通用对话质量优化 | ⚠️ 成本较高 |
| 实时推理增强 | ❌ 不适用（这是训练数据方案） |

## 局限与生产风险

- 每个样本生成成本高（多次 Agent 调用），大规模数据集代价昂贵
- 质量依赖弱/强模型的配置，不同模型对的结果不可直接比较
- "弱强差距"可能被错误校准：题目太偏、不具备迁移性
