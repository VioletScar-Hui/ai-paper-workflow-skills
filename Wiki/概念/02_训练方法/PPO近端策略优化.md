# PPO 近端策略优化（Proximal Policy Optimization）

> **一句话定义**：PPO 是策略梯度算法家族里加了"安全带"的一个版本——它在朴素策略梯度（REINFORCE）的基础上引入 baseline 降方差、引入重要性采样支持离线更新，再用一个非对称的裁剪（clipping）机制限制每一步更新的幅度，防止模型在一个批次的 rollout 上走得太远。

---

## 寓言学习

### 寓言正文

电话销售组的主管让组员小段试用一版新话术。每天打完一批电话后，主管不看小段这批电话本身成交了多少单，而是拿这批的成交率和全组当天的平均成交率作对比——高于平均，说明这批话术里用的说法值得多用；低于平均，就该少用。为了不用每次都重新拉一批新客户去验证效果，主管让小段把同一批通话录音反复回听，在这批录音的基础上反复打磨措辞，不用每周都重新打一整批电话。主管还定了条规矩：每周话术调整的幅度不能超过原话术的一定比例，防止小段图快把整套话术改得面目全非。

那批录音里有一句开场白"我们家产品全网最低价"，效果很好，成交率明显高于全组平均，小段已经把它加进了几乎每通电话——按幅度上限，这句已经调到头，主管让他先别再加码，继续推下去也没有意义。

同一批录音里还有一句"这个优惠只剩最后一天"，效果其实很差，成交率比平均低不少，但小段图省事没细听录音，这句话本周用得反而比上周更多了。主管发现后，没有因为"这周调整幅度已经用满了"就放过这句——这句话本身方向就是错的，哪怕已经超出这周原定的调整上限，也必须立刻把它的使用频率降下来。

### 概念解析

**概念名称**：PPO 近端策略优化（策略梯度 + baseline 降方差 + 重要性采样复用数据 + 非对称裁剪限幅），属于强化学习 / 大语言模型后训练算法问题域。

**学习卡片**
- 核心张力：想要根据每次实际尝试的结果反馈，快速调整决策方式（好的多用、差的少用）vs 一次性调整幅度太大，容易把原本还不错的决策方式带偏，或者反复用同一批旧数据训练太多轮导致失真。
- 关键不变量：(1) 判断某种做法好不好，要看它相对于一个参照基准（平均水平）的相对表现，而不是看绝对结果；(2) 每一步调整幅度要被限制在安全区间内，一旦某个方向已经调整到位（有利动作的重要性权重已升到区间上限），该方向就该停止继续推；(3) 但如果发现某个方向的调整本身就错了（不利动作的重要性权重却在上升），不能因为已经超出安全区间就放弃纠正，必须继续往回拉——限幅只管"别把已经调对的地方调过头"，不管"往回纠正一个跑偏的错误"。
- 触发条件：需要用实际尝试反复迭代改进一套决策方式（策略），且希望复用同一批实际尝试数据做多轮更新以节省成本。
- 常见误解/失败模式：不设参照基准，导致所有反馈都很嘈杂，无法判断真正谁好谁坏；或者不设限幅，一次性根据反馈调整过猛，把原本还不错的话术/策略带崩；或者把"限幅"误解成对称的硬上限，忽视了纠正错误方向时应该不受限幅约束。
- 非适用边界：如果每次决策的效果反馈极其稳定、不需要反复复用同一批数据做多轮迭代验证的场景（比如一次性决策，没有"策略"需要持续打磨），不需要这套"参照基准+限幅+数据复用"的机制。

**一句话核心定义**：PPO 是在朴素策略梯度基础上，用参照基准降低反馈噪声、用重要性采样复用旧数据做多轮更新、再用非对称裁剪限制每一步调整幅度（只限制"已经调对的地方别调过头"，不限制"纠正跑偏的错误"）的强化学习优化方法。

**它试图解决的问题**：如何在不产生失控更新的前提下，让一套决策方式（策略）根据实际尝试的结果反馈快速、稳定地迭代改进，同时尽量复用已有的尝试数据以降低成本。

**故事元素映射**：
- 全组当天平均成交率 = baseline（学习的价值函数 $V_\psi(s_t)$），用来把绝对结果换算成相对优势（advantage）。
- 反复回听同一批录音打磨措辞、不用每周重新打新电话 = 重要性采样支持的 off-policy 更新，复用旧策略采样的数据在新策略上做多次梯度更新。
- 每周调整幅度不能超过一定比例 = 裁剪机制，把重要性权重 $r_t$ 限制在 $[1-\epsilon, 1+\epsilon]$ 区间内。
- "全网最低价"已经调到头、主管让小段别再加码 = advantage 为正、重要性权重已超出上限的情况，裁剪生效，梯度为 0，停止继续推。
- "只剩最后一天"效果差却用得更多、主管坚持纠正即使超出本周幅度上限 = advantage 为负但重要性权重却在上升的"跑偏"情况，裁剪不生效，必须继续往回压。

**比喻边界**：故事把"重要性权重"简化成"这周用得比上周多/少"的直观感受，真实的 PPO 里 $r_t = \pi_\theta(a_t\mid s_t)/\pi_{\theta_\text{old}}(a_t\mid s_t)$ 是一个精确计算的概率比值，且裁剪判断是逐 token 进行的；故事也没有展现价值函数 $V_\psi$ 本身是如何被训练出来的，以及 KL 惩罚等其他稳定性机制。

**非适用例**：如果小段每次话术调整之后，立刻就能重新拉一整批全新客户去验证效果，且不介意每次都重新打电话的成本——这种"每次更新都用全新数据、不复用旧数据"的场景，就更接近朴素的策略梯度（REINFORCE），不需要 PPO 里"复用旧数据+限幅"这套机制来保证多轮更新的稳定性。

**现实例子**：RLHF 训练大语言模型时，PPO 在同一批 rollout（模型生成的一批回复）上做多次梯度更新，用裁剪机制（典型 $\epsilon=0.1\sim0.2$）防止某次更新让模型偏离旧策略太远导致训练崩溃、奖励震荡——这正是笔记里提到的"和工程师对齐训练不稳定原因"时最常被追问的超参数之一。

### 检验问题

1. 理解检验：故事里主管为什么没有因为"这周调整幅度已经用满了"就放过"只剩最后一天"这句效果很差的话术？这体现了 PPO 裁剪机制的哪个非对称特性？
2. 迁移检验：如果一套决策调整机制里，"参照基准"本身就是从这批数据里现算出来的、每次都会跟着数据变化，这和故事里"全组平均成交率"作为基准有什么潜在的风险？

## 核心机制

### 1. 策略梯度的记号

把 LLM 生成一段回复看成一个决策序列：

- **action** $a_t$：第 $t$ 步生成的下一个 token
- **state** $s_t$：到第 $t$ 步为止的文本前缀（prompt + 已生成的 token）
- **policy** $\pi_\theta$：LLM 本身，$a_t \sim \pi_\theta(\cdot \mid s_t)$
- **trajectory** $\tau$（也叫 rollout / episode）：从 prompt $s_0$ 开始生成到结束的完整序列
- **reward** $R(\tau)$：这条完整轨迹（一整段回复）获得的奖励，比如奖励模型打分

训练目标是最大化期望奖励：

$$J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}[R(\tau)]$$

用梯度上升更新参数：$\theta_{k+1} = \theta_k + \alpha \nabla_\theta J(\theta_k)$。

### 2. REINFORCE（vanilla policy gradient）

策略梯度可以写成：

$$\nabla_\theta J(\theta) = \mathbb{E}_{\tau \sim \pi_\theta}\left[\sum_t \nabla_\theta \log \pi_\theta(a_t \mid s_t) \, R(\tau)\right]$$

直觉上这个更新和 SFT 几乎一样——都是在最大化 $\log \pi_\theta(a_t \mid s_t)$——唯一的区别是：数据 $\tau$ 不是人工标注的，而是从策略自己采样出来的；并且每个 token 的梯度要按 $R(\tau)$ 加权。

- 如果 $R(\tau) > 0$，就朝着"提高这条轨迹里每个 token 概率"的方向走
- 如果 $R(\tau) < 0$，就朝反方向走
- $R(\tau)$ 的绝对值越大，这一步走得越大

**推导要点（log derivative trick）**：直接对 $J(\theta) = \sum_\tau P(\tau \mid \theta) R(\tau)$ 求梯度，会遇到"如何对一个采样分布求梯度"的问题。技巧是利用恒等式 $\nabla P = P \nabla \log P$，把 $\nabla_\theta P(\tau\mid\theta)$ 换成 $P(\tau\mid\theta)\nabla_\theta \log P(\tau\mid\theta)$，这样就能把梯度重新写成一个期望——也就是可以用采样来估计。再利用轨迹概率是各步骤条件概率之积，$\log P(\tau\mid\theta)$ 展开成对每个 token 的 $\log \pi_\theta(a_t\mid s_t)$ 求和，就得到了上面的策略梯度公式。

实践中用一个批次里 $N$ 条 rollout 做蒙特卡洛估计：

$$\hat{g} = \frac1N \sum_{i=1}^N \sum_{t=1}^T \nabla_\theta \log \pi_\theta(a_t^{(i)} \mid s_t^{(i)}) \, R(\tau^{(i)})$$

工程上这对应一个"policy gradient loss"标量，`pg_loss.backward()` 产生的梯度恰好等于 $\hat{g}$。但要注意：这个 loss 不是传统意义上"越小越好"的损失函数，它不代表策略有多好，只是一个用来产生正确梯度的构造物——而且它没有固定的目标值，因为数据本身是由当前策略采样出来的，训练过程中不断变化。

### 3. 为什么需要 baseline：降方差

REINFORCE 的问题是方差非常高。设想一个简单 prompt，所有采样出来的回复奖励都是正的——没有 baseline 的话，这批回复里所有 token 都会被强化，**包括这批里相对较差的那些**。平均下来训练依然会收敛，但每一步更新噪声很大、很不稳定。

解决办法：从 $R(\tau)$ 里减去一个只依赖状态的 baseline 函数 $b(s_t)$：

$$\nabla_\theta J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}\left[\sum_t \nabla_\theta \log \pi_\theta(a_t\mid s_t)\,(R(\tau) - b(s_t))\right]$$

如果 $b(s_t)$ 和 $R(\tau)$ 是相关的（比如用平均奖励做 baseline），那么"低于平均水平"的回复就不会再被强化，$R(\tau) - b(s_t)$ 本身的数值也更小、更集中，梯度噪声随之下降。**这不改变优化目标，只改变梯度估计的方式**。

### 4. baseline 为什么不引入偏差

关键结论：只要 $b(s_t)$ 只依赖状态 $s_t$、不依赖动作 $a_t$，减去它就不会给梯度估计引入偏差。证明的核心逻辑：

把 baseline 项单独拎出来记作 $B = \mathbb{E}_{\tau\sim\pi_\theta}\left[\sum_t \nabla_\theta\log\pi_\theta(a_t\mid s_t)\,b(s_t)\right]$，只要证明 $B=0$ 即可。

- 先把求和和期望的顺序交换：对每个时间步 $t$，先对采样的轨迹求期望，再把各步骤的期望加总（而不是先对每条轨迹求和再对轨迹取平均）。这一步能做是因为 $X_t = \nabla_\theta\log\pi_\theta(a_t\mid s_t)\,b(s_t)$ 本身只依赖 $(s_t, a_t)$，跟轨迹里其余部分无关。
- 再把 $(s_t, a_t)$ 上的联合期望拆成"先对 $s_t$ 取期望，内层再对给定 $s_t$ 下的 $a_t$ 取期望"。
- 关键一步在内层：因为 $b(s_t)$ 不依赖 $a_t$，可以把它从对 $a_t$ 的期望里提出来，剩下 $\mathbb{E}_{a_t\mid s_t}\nabla_\theta\log\pi_\theta(a_t\mid s_t)$。再用一次 log derivative trick 把它换回 $\sum_{a_t}\nabla_\theta \pi_\theta(a_t\mid s_t) = \nabla_\theta \sum_{a_t}\pi_\theta(a_t\mid s_t)$。
- 而"策略在给定状态下对所有动作的概率求和"恒等于 1（这是一个和 $\theta$ 无关的常数），所以它的梯度恒为 0。

一路把 0 传回去，$B$ 的每一项内层期望都是 0，整体自然也是 0。**这个证明依赖的唯一条件就是 $b(s_t)$ 不能依赖 $a_t$**——如果 baseline 里掺进了动作信息，这一步"提出来"就不成立，偏差就会出现。

### 5. advantage：Q 减 V

- $R(\tau)$ 是 Q 函数 $Q^\pi(s_t,a_t)$（在状态 $s_t$ 采取动作 $a_t$ 后、按策略 $\pi$ 继续走下去的期望奖励）的一次单样本估计
- 学出来的 baseline $V_\psi(s_t)$ 是价值函数 $V^\pi(s_t)$（只依赖状态、不依赖具体动作的期望奖励，$V^\pi(s)=\sum_{a\sim\pi(\cdot\mid s)} Q^\pi(s,a)$）的估计
- 所以 $R(\tau) - V_\psi(s_t)$ 正是优势函数（advantage）$A^\pi(s,a) = Q^\pi(s,a) - V^\pi(s)$ 的蒙特卡洛估计——衡量"这个动作比这个状态下的平均水平好多少"

对每个 token 而言，advantage 回答的问题是：**这条轨迹的最终奖励，是超出还是低于生成到这一步时"看起来大概率会拿到的奖励"？** 一个把原本看起来很差（$V_\psi(s_t)$ 低）的回复扭转成好结果（$R(\tau)$ 高）的 token，会获得更大的信用（credit）。

### 6. 几种 baseline 的实现方式

所有 baseline 本质上都在估计 $V^\pi(s_t)$：

- **学习的价值函数** $V_\psi(s_t)$：PPO 的默认做法，单独训练一个价值网络
- **RLOO**：每个 prompt 采样 $G$ 条回复，某条回复的 baseline 是其余 $G-1$ 条回复奖励的均值（和 GRPO 很像，区别在于逐样本索引以及是否用标准差归一化）
- **REINFORCE++（批量估计）**：直接用整个 batch 的平均奖励做 baseline，最简单粗暴但也有效

### 7. off-policy 策略梯度与重要性采样

朴素策略梯度是 on-policy 的：每做一次梯度更新，就要重新用当前策略采样一批 rollout，成本很高——尤其考虑到一次梯度步通常不会让策略变化很大。

**off-policy 的思路**：用一个旧版本策略 $\pi_{\theta_{\text{old}}}$ 采样 rollout，去优化当前策略 $\pi_\theta$。这需要重要性采样（importance sampling）做修正：如果只有从分布 $q$ 采的样本，但想估计在分布 $p$ 下的期望，可以改写为

$$\mathbb{E}_{x\sim p}f(x) = \mathbb{E}_{x\sim q}\left[\frac{p(x)}{q(x)}f(x)\right]$$

直觉：如果某个样本在 $p$ 下比在 $q$ 下更可能出现，这个样本的权重就应该被放大，反之缩小。

把这个思路套到策略梯度上，得到重要性权重 $r_t = \pi_\theta(a_t\mid s_t) / \pi_{\theta_{\text{old}}}(a_t\mid s_t)$，以及一个替代目标（surrogate objective）：

$$\mathcal{J}^{\text{surrogate}}(\theta) = \mathbb{E}_{\tau\sim\pi_{\theta_{\text{old}}}}\left[\sum_t r_t\, R(\tau)\right]$$

注意：真正严格的 off-policy 重写需要用**整条轨迹**的概率比（各步骤比值的连乘积），但连乘会导致方差极大；surrogate 目标用"逐步的重要性权重之和"近似替代了这个连乘，代价是不再是无偏的，但换来了可用的方差。

### 8. PPO 的裁剪机制（clipping）

PPO 在这个 surrogate 目标基础上，把重要性权重 $r_t$ 裁剪（clip）到区间 $[1-\epsilon, 1+\epsilon]$ 内，并取裁剪前后两者中较小的一个：

$$\mathcal{J}^{\text{CLIP}}(\theta) = \mathbb{E}_{\tau\sim\pi_{\theta_{\text{old}}}}\left[\sum_t \min\big(r_t A_t,\ \text{clip}(r_t, 1-\epsilon, 1+\epsilon)\, A_t\big)\right]$$

（这里 $A_t = R(\tau) - V_\psi(s_t)$，即用学习的价值函数做 baseline 后的 advantage。）

裁剪的作用是在同一批 rollout 上做多次梯度更新时维持稳定——只要没有偏离 $\pi_{\theta_{\text{old}}}$ 太远，这个裁剪后的目标仍是原目标的一个合理近似。代价是放弃了无偏性，换取更稳定的更新。

**四种情况的直觉**（$r_t$ 是否越界、$A_t$ 正负各有两种，共四种组合）：

1. **$r_t > 1+\epsilon$ 且 $A_t > 0$**：用裁剪值 $(1+\epsilon)A_t$，梯度为 0。含义：这是个好动作（advantage 为正），而且已经把它的概率相对旧策略提得足够高了——**停止继续推它**。
2. **$r_t < 1-\epsilon$ 且 $A_t < 0$**：用裁剪值 $(1-\epsilon)A_t$，梯度也为 0。含义：这是个差动作，而且已经把它的概率压得足够低了——**停止继续压它**。
3. **$r_t > 1+\epsilon$ 且 $A_t < 0$**：不裁剪，用原始的 $r_t A_t$，梯度不为 0。含义：这是个差动作（advantage 为负），但它的概率相对旧策略反而升高了——这是训练过程中出现的"跑偏"，必须继续往下压，所以裁剪区间在这里不生效，允许 $r_t$ 继续超出 $[1-\epsilon,1+\epsilon]$。
4. **$r_t < 1-\epsilon$ 且 $A_t > 0$**：不裁剪，用原始的 $r_t A_t$。含义：这是个好动作，但它的概率被压低了——同样是需要纠正的"跑偏"，必须继续把它拉回来。

**这就是裁剪非对称性的直觉**：裁剪只在"已经朝 advantage 鼓励的方向推得足够多"时刹车（情况 1、2），但从不阻止"往回纠正一个已经跑偏的错误"（情况 3、4）。换句话说，裁剪管的是"别把已经调对的地方调过头"，而不是"限制所有大幅度更新"。

PPO 的完整流程：从当前策略采集一批 rollout（trajectories），然后用裁剪后的 surrogate 目标在这批数据上做多次梯度步——这也是它比纯 on-policy REINFORCE 更"数据高效"的原因。

## 为什么 AI PM 要懂这个

- **理解 RLHF/GRPO/DPO 为什么长这样**：这三个后训练算法都是在"策略梯度 + baseline + 稳定性约束"这个共同框架上做取舍——GRPO 用组内均值代替学习的价值函数省掉一个网络，DPO 干脆绕开显式奖励模型和在线采样。看懂 PPO 才能看懂它们各自省了什么、换了什么代价。
- **和工程师对齐"为什么这次 RL 训练不稳定"**：训练崩溃、奖励震荡，很多时候能追溯到裁剪范围 $\epsilon$、batch 内多次更新步数这类超参——PM 不需要会调，但要听得懂工程师说"这批 rollout 上多走了几步导致越界"是什么意思。
- **成本估算**：on-policy 策略梯度每一步梯度更新都要重新采样 rollout（推理成本），这是 RL 后训练比 SFT 贵得多的直接原因；理解 off-policy/重要性采样，才能理解为什么团队会选择"多步复用同一批 rollout"来摊薄推理成本。
