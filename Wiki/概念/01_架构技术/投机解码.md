# 投机解码

## 一句话定义
> 投机解码（Speculative Decoding）使用一个小型草稿模型（Draft Model）快速生成多个候选 token，再让大型目标模型并行验证并按接受率选择性采纳，在保持输出分布与原始大模型完全一致的前提下实现 2-4× 推理加速。

## 寓言学习

### 寓言正文

报社夜班时，头版每一句话最终都要总编亲自过一遍才能签发——总编经验老到、判断准，但一句一句从头写太慢，眼看要错过印刷时间。有天值班的年轻记者提议：由他先按总编平时的风格，一口气往下写好几句草稿，总编不用自己写，只需要一眼看过这几句，符合自己心里预期的就直接签字放行；一旦看到某一句不是他自己会写的写法，就在那一句停下来，自己动笔改掉那句，后面记者写的草稿全部作废，从改过的这句开始，记者再重新往下写几句让总编审。

这样一来，只要记者写的和总编设想的差不多，总编一次能连着签好几句，比自己逐句写快得多；最终见报的每一个字，还是总编亲自认可或亲自改过的，标准没有一点放松。

有一天赶上一篇需要大量个人风格化措辞的专栏稿，记者写的草稿几乎每句都和总编设想的不一样，总编几乎每句都要停下来自己改——那天连着审了半宿，速度比总编从头自己写还慢，因为记者写的草稿虽然快，但总编还得先看一遍再判断要不要，白白多了一道工序。

### 概念解析

**概念名称**：投机解码（Speculative Decoding），属于大模型推理加速问题域。

**学习卡片**
- 核心张力：完全由权威判断者逐句亲自生成（质量有保证，但每一句都要等他，速度慢）vs. 先由一个更快的角色批量起草、权威判断者一次性审阅一批（能大幅提速，但最终是否采纳仍完全由权威判断者说了算）。
- 关键不变量：不管草稿被采纳了多少句，最终见报的每一个字，都必须是权威判断者本人认可或亲自改过的——最终结果的标准和质量与"权威判断者独自逐句生成"完全一致，不打折扣。
- 触发条件：权威判断者本身处理单步的成本很高（比如每次都要"调用"一次），而批量审阅一批候选的成本远低于逐个单独生成时，用起草+批量审阅能带来明显提速。
- 常见误解/失败模式：以为多了一道"先起草再审"的环节，最终质量会打折——实际上只要坚持"不符合就打回重写"的规则，最终质量和权威判断者独自生成完全一样；容易被忽视的是提速幅度完全取决于起草者的命中率，命中率低时收益会很小甚至变负。
- 非适用边界：如果起草者写出来的内容和权威判断者设想的几乎每次都不一样（比如高度个性化、不可预测的创作型内容），批量审阅这道额外工序反而增加了总耗时，比权威判断者直接自己写还慢。

**一句话核心定义**：投机解码用一个小而快的草稿模型先生成多个候选 Token，再让大模型一次性并行验证并按接受规则选择性采纳，在保证最终输出分布与大模型独自生成完全一致的前提下，实现推理加速。

**它试图解决的问题**：大模型逐 Token 生成时，每一步都要完整调用一次大模型，主要瓶颈在于每步都要读取/调用大模型本身，而不是计算量；如何在不改变最终输出质量的前提下，减少大模型被单独调用的次数。

**故事元素映射**：
- 总编 = 大模型（目标模型），拥有最终判断权，决定最终输出。
- 年轻记者 = 草稿模型，快速生成候选内容。
- 记者一口气写好几句、总编一次审阅一批 = 草稿模型生成 γ 个候选 Token，目标模型一次并行验证。
- 遇到不符合预期的句子就停下改掉、后面全部作废 = 拒绝采样机制：接受概率由两个模型的概率比决定，一旦拒绝就从该处重新生成，之后的草稿全部丢弃。
- 见报内容始终是总编认可或改过的 = 输出分布与大模型独自生成完全一致，是无损加速，不是近似。
- 风格化专栏稿命中率低、审阅比自己写还慢 = 草稿命中率（接受率）低的内容（如高度创意写作），投机解码的加速比会大幅下降甚至为负。

**比喻边界**：故事把"是否符合预期"简化成了总编的主观判断，真实的接受规则是基于两个模型在该位置输出概率的比值做拒绝采样，是严格的数学过程，且被拒绝时不是简单地"改成正确答案"，而是从一个修正后的概率分布重新采样；此外真实系统中草稿模型的选择方式也不止"一个人快速写"这一种，还包括无独立模型的 N-gram 匹配、自我投机（层跳过）等变体。

**非适用例**：如果总编本来就打算让记者独立完成一整篇稿子、由记者自己署名发表，不需要总编逐句把关认可，那这就不是投机解码要解决的场景——投机解码的前提是"最终标准必须完全等同于权威判断者独自把关"，如果不需要这个约束，直接让更快的角色独立产出即可，不需要这套验证机制。

**现实例子**：用 Llama-3-8B 作为草稿模型为 Llama-3-70B 做投机解码，在接受率约 0.8、草稿长度 5 的情况下，能带来约 3 倍的推理加速，且最终输出与 70B 模型独自逐 Token 生成的结果在概率分布上完全一致；DeepSeek 的 DSpark 系统还会根据当前生成内容的置信度动态调整草稿长度，容易预测的内容多起草几句，不确定的内容少起草甚至直接用大模型。

### 检验问题

1. 理解检验：记者起草的内容被总编大量采纳后，最终见报的文字质量和总编独自逐句写相比，有没有变化？为什么？
2. 迁移检验：如果有人说"我们想给一个专门写高度个性化诗歌的模型也上投机解码来提速"，结合这个故事，你会提醒他可能遇到什么问题？

## 核心原理

**自回归解码的效率瓶颈：**

标准自回归解码每步只生成 1 个 token，且每步都需要加载完整的大模型权重。对于 70B 参数的模型，每生成一个 token 需要约 140GB 的权重读取（float16），完全受内存带宽限制，GPU 计算单元大量空闲。

**投机解码流程：**

```
Step 1: Draft Model 生成 γ 个候选 token
  小模型: [x₁, x₂, ..., xₜ] → [x̂ₜ₊₁, x̂ₜ₊₂, ..., x̂ₜ₊γ]
                                    (快速，串行)

Step 2: 目标模型并行验证
  大模型: [x₁...xₜ, x̂ₜ₊₁...x̂ₜ₊γ] → [p(xₜ₊₁), p(xₜ₊₂), ..., p(xₜ₊γ), p(xₜ₊γ₊₁)]
                                              (一次前向，并行计算所有位置)

Step 3: 拒绝采样（Token-by-Token 验证）
  对每个位置 i (i=1,...,γ)：
    - 接受概率 α_i = min(1, p_target(x̂ₜ₊ᵢ) / p_draft(x̂ₜ₊ᵢ))
    - 以概率 α_i 接受 x̂ₜ₊ᵢ，否则从修正分布采样并停止
  如果所有 γ 个 token 都被接受，额外采样第 γ+1 个 token

Step 4: 更新状态，回到 Step 1
```

**接受率与加速比的关系：**

```
设平均接受率为 α，草稿长度为 γ
期望接受 token 数 = (1 - α^{γ+1}) / (1 - α)

加速比 ≈ (期望接受 token 数) / (1 + γ · c)
其中 c = 小模型运行成本 / 大模型运行成本

实际加速：
α=0.8, γ=5 → 期望约 3.6 token/大模型调用 → ~3× 加速
α=0.5, γ=5 → 期望约 1.9 token/大模型调用 → ~1.5× 加速
```

**关键性质：无损加速：**

拒绝采样保证了最终输出分布与仅使用大模型自回归采样的分布完全相同（可数学证明）。这是投机解码相比蒸馏/量化的核心优势——精度零损失。

**草稿模型的选择：**

| 草稿模型类型 | 接受率 | 额外成本 | 例子 |
|------------|-------|---------|------|
| 同系列小模型 | 高（0.7-0.9） | 显存增加 | Llama-3-8B drafts Llama-3-70B |
| 自回归推测（MEDUSA） | 中（0.5-0.7） | 少量额外层 | 在目标模型上加投机头 |
| N-gram 匹配（无模型） | 低但零成本 | 无 | 匹配历史 KV Cache 片段 |
| 自我投机（层跳过） | 中 | 无额外模型 | LayerSkip |

**DSpark 置信度调度变体：**

DSpark（DeepSeek 推理系统）引入了基于置信度的动态草稿长度调整：
- 当前 token 生成置信度高（softmax 概率峰值 > 阈值）→ 增加草稿长度 γ
- 置信度低（不确定区域）→ 减少 γ 或直接使用大模型
- 动态调整使平均接受率保持在高位，系统吞吐量稳定

```
置信度高（容易 token）:  γ↑ → 草稿更多 → 接受率高 → 效率高
置信度低（难 token）:    γ↓ → 避免浪费 → 快速回退到大模型
```

**半自回归生成（Semi-Autoregressive Draft，DSpark，论文142深化）：**

DSpark 的 draft 架构本身是投机解码"草稿模型选择"维度上的第三条路线，介于纯并行和纯自回归之间：

```
纯并行 drafter（Medusa / DFlash）：
  单次前向生成所有候选 token，无 token 间依赖
  → 后缀衰变 / 多模态碰撞（如同时采样出不兼容的 "of" 和 "problem" 组合）
  → draft 延迟低，但长块尾部接受率暴跌

纯自回归 drafter（EAGLE3）：
  逐 token 顺序生成，draft 延迟随块长线性增长
  → 接受质量高，但块越长 draft 越慢

半自回归 drafter（DSpark）：
  Parallel Backbone（单次前向，低延迟）
      ↓
  Sequential Head（Markov 头或 RNN 头，逐位置注入局部 token 间依赖）
      ↓
  draft tokens：在几乎不增加延迟的前提下缓解后缀衰变
```

- **效果**：在 Qwen3-14B 上，accepted length 比纯自回归的 EAGLE3 提升 30.0%，比纯并行的 DFlash 提升 18.3%
- **失效边界**：序列头本身仍然是顺序采样，当块长极大（>32）时序列头延迟占比上升，半自回归相对纯并行的优势被侵蚀
- **定位**：半自回归不是"发明新范式"，而是在 draft 阶段对"延迟 vs 质量"做了更细粒度的可调权衡——用轻量序列头换取远高于纯并行的接受长度，同时避免纯自回归的延迟线性增长

**为什么自回归推理天然适合这个优化？**

大模型在验证阶段可以并行处理所有 γ 个位置（等同于一次 prefill），而 GPU 的利用率在 prefill 时远高于单 token 解码。本质上是把"多次低效率解码"变成"一次高效率 prefill 验证"。

## PM 决策视角

**何时使用投机解码：**
- 推理延迟（TTFT 和 TPOT）是关键指标
- 有足够显存同时运行草稿和目标模型
- 输出文本有一定规律性（代码、格式化文本接受率更高）
- 目标模型明显受内存带宽限制（参数量 >30B）

**何时谨慎使用：**
- 显存极度受限，无法加载额外草稿模型
- 高度随机创意写作（接受率低，加速比接近 1×）
- 批大小很大时（大 batch 的大模型本身 GPU 利用率已高）

| 场景 | 推荐策略 | 预期加速 |
|------|---------|---------|
| 单用户交互式聊天 | 同系列小模型草稿 | 2.5-4× |
| 代码生成 | 任意草稿模型 | 3-5×（代码规律性强） |
| 大 batch 服务 | 谨慎评估 | 可能无显著收益 |
| 边缘设备部署 | MEDUSA/LayerSkip | 1.5-2×（无额外模型） |

## 补充:更严谨的机制与公式(源自 Alisa's Book of LLMs)

本页"关键性质：无损加速"部分只给出了结论（"可数学证明"），这里补充完整推导，说明为什么投机解码得到的输出分布严格等于直接用目标模型采样的分布。

设草稿模型在某个位置给出分布 q(x)，目标模型给出分布 p(x)。生成 token x 有且仅有两条互斥路径。

**路径一：draft 采样出 x，且被接受**

草稿模型以概率 q(x) 采样出 x，再以接受概率 min(1, p(x)/q(x)) 被接受，两者相乘：

```
q(x) · min(1, p(x)/q(x)) = min(q(x), p(x))
```

（p(x)≥q(x) 时 min(1,p/q)=1，结果为 q(x)=min(q,p)；p(x)<q(x) 时结果为 q(x)·p(x)/q(x)=p(x)=min(q,p)，两种情况都化简为 min(q(x),p(x))。）

**路径二：draft 采样出某个 x'，被拒绝，再从修正分布重新采样出 x**

草稿采样出 x' 并被拒绝的概率（仅当 p(x')<q(x') 时才会被拒绝）：

```
q(x') · (1 - p(x')/q(x')) = q(x') - p(x')
```

总拒绝概率：

```
P(拒绝) = Σ_x' max(0, q(x') - p(x'))
        = Σ_x' max(0, p(x') - q(x'))   （因 p、q 都归一化到 1，两个求和式相等）
```

一旦拒绝，按归一化分布 `max(0,p(x)-q(x)) / Σ_x' max(0,p(x')-q(x'))` 重新采样。所以"拒绝后恰好采到 x"的总概率：

```
P(拒绝) × [max(0,p(x)-q(x)) / Σ_x'max(0,p(x')-q(x'))] = max(0, p(x) - q(x))
```

**两条路径相加**

```
P(输出 x) = min(q(x), p(x)) + max(0, p(x) - q(x)) = p(x)
```

（p(x)≥q(x) 时：min=q(x)，max=p(x)-q(x)，相加=p(x)；p(x)<q(x) 时：min=p(x)，max=0，相加=p(x)，两种情况都精确等于 p(x)。）

这证明了：不管草稿 token 被接受还是被拒绝重采样，最终输出 token x 的概率严格等于目标模型独立采样的概率 p(x)——这是投机解码"无损"的数学本质，而非近似或经验性说法。
