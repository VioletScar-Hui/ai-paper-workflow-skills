# 自注意力机制

## 一句话定义
> 自注意力机制是一种让序列中每个位置都能直接关注序列中所有其他位置的计算方法，通过 Query、Key、Value 三个线性投影实现加权信息聚合。

## 寓言学习

### 寓言正文

工地上以前的规矩是这样的：谁想知道混凝土浇筑进度，得先问旁边的人，旁边的人再传给下一个，一个一个往下问，问到管浇筑的班组长为止，回话再一路传回来。人一多，消息传到手里往往已经过时了。

新来的项目经理换了套办法：给每个岗位配一个对讲机，每个人手里都握着同一份花名册，标好谁在负责什么。想知道浇筑进度，直接在频道里喊出"浇筑组，进度到哪了"，浇筑组直接答复，不用一个个转达。谁都能直接呼叫工地上的任何一个人，不管他站在哪个角落。

工地开了三个频道：进度频道专门问"到哪一步了"，安全频道专门问"有没有隐患"，物料频道专门问"东西够不够"。同一个人，进度上可能没什么可汇报的，安全上却正好要提醒别人绕开一处沟槽——三个频道各自忙各自的，互不耽误。

工地规模从五十人扩到五百人后，问题来了：理论上任何人都能直接呼叫任何人，可对讲频道里同时冒出几百组呼叫，噪音大到没法用。项目经理不得不把工地拆成几个片区，片区内部还是随便互相喊，片区之间只留几个人专门负责跨片区传话。

### 概念解析

**概念名称**：自注意力机制（Self-Attention），属于 Transformer 架构 / 序列建模问题域。

**学习卡片**
- 核心张力：想让序列里任何一个位置都能利用到其他任意位置的信息（不管距离多远），但信息传递路径越直接，需要维护的"两两联系"就越多，计算和通信开销随规模增长得极快。
- 关键不变量：每个位置都通过同一套查询/匹配/取值规则（Query 找、Key 被找、Value 被取）直接和所有其他位置建立一次联系，联系强度由查询和被查询双方的匹配程度决定，不需要经过中间位置转发。
- 触发条件：任务需要建模任意两个位置之间的依赖关系（不管距离远近），且硬件/算力允许并行计算所有位置对之间的联系。
- 常见误解/失败模式：以为"直接联系"没有代价，忽略了位置数一多，两两联系的总数是位置数的平方，通信/计算/显存开销会迅速失控。
- 非适用边界：如果序列极长（远超硬件能负担两两联系的规模），或者部署环境根本没有余量支撑并行的"两两通话"，直接套用完整的自注意力反而不可行，需要退回稀疏/分片/线性近似的方案。

**一句话核心定义**：自注意力机制是让序列中每个位置都能通过统一的匹配规则，直接向所有其他位置查询相关信息并加权聚合，而不需要像链式传递那样一步步转达。

**它试图解决的问题**：RNN 一类的顺序模型必须把信息一站一站往下传，距离越远的位置之间"传话失真"越严重，也没法并行计算；自注意力让任意两个位置之间的联系变成一步直达，既保留长距离依赖，又能并行处理整个序列。

**故事元素映射**：
- 老办法"一个个传口信" = RNN/LSTM 顺序传播信息，路径长、无法并行。
- 换成人手一台对讲机、想问谁直接喊谁 = 自注意力：任何位置直接查询任何位置，不经过中转。
- 三个独立频道（进度/安全/物料）各自忙各自的 = 多头注意力（Multi-Head Attention），不同头在不同的表示子空间里捕捉不同类型的关系。
- 人数从五十涨到五百后频道拥堵，被迫拆片区 = 自注意力的 O(n²) 瓶颈：两两联系的总量随序列长度平方增长，长序列下必须靠分片/稀疏化（如 Flash Attention、滑动窗口）来控制开销。

**比喻边界**：故事里"喊一声就能问到"简化了实际计算——真正的自注意力里，每次查询都会和所有位置的 Key 做匹配打分（Q·K^T），再按打分做 softmax 加权，取的是所有位置 Value 的加权平均，而不是精确地"问到就有答案"；此外，故事没有展示自回归生成场景里的因果掩码（模型在生成第 n 个词时不能看到第 n+1 个词之后的信息），这是自注意力在语言生成任务里的额外约束，故事里的施工现场直播没有这层限制。

**非适用例**：如果工地信息本来就是严格按时间顺序发生、后一步永远依赖前一步的结果才能开始（比如"必须等地基验收通过才能开始砌墙"），那这种强顺序依赖的场景本身更适合按步骤逐一处理，而不是所有人一股脑互相直接喊话——这提示当任务的依赖关系本身就是链式而非任意两点关联时，硬套自注意力的"人人互联"未必是最优结构。

**现实例子**：Transformer（Vaswani et al., 2017）用自注意力替代 RNN 成为主流架构后，GPT 系列用因果掩码限定"只能看过去"，BERT 用双向注意力允许"看完整句子"；序列长度到 32K 时，完整的注意力矩阵在 float32 下就需要约 4GB 显存，这正是后续 Flash Attention、GQA 等工程优化要解决的问题。

### 检验问题

1. 理解检验：如果工地一开始就统一用一个频道（不分进度/安全/物料），所有呼叫混在一起播报，你觉得会出现什么问题？这对应自注意力里哪个设计想要避免的情况？
2. 迁移检验：一个客服系统要处理一段 10 万字的历史工单记录，如果直接让每一句话都和其余所有句子两两建立联系来做完整的自注意力计算，你预测会遇到什么问题？该怎么参考故事里"工地拆片区"的思路来调整？

## 核心原理

自注意力（Self-Attention）的本质是一种软寻址机制。给定输入序列 X ∈ R^{n×d}，通过三个可学习矩阵 W_Q、W_K、W_V 分别投影得到：

```
Q = X·W_Q    K = X·W_K    V = X·W_V
```

注意力分数计算：

```
Attention(Q, K, V) = softmax(Q·K^T / √d_k) · V
```

除以 √d_k 是为了防止点积在高维时数值过大导致 softmax 梯度消失。

**与 RNN 的根本区别：**

| 维度 | RNN/LSTM | 自注意力 |
|------|----------|---------|
| 信息传播路径 | 顺序（O(n)步） | 直接（1步） |
| 并行度 | 无法并行 | 完全并行 |
| 长距离依赖 | 梯度消失问题 | 直接建模 |
| 时间复杂度 | O(n·d²) | O(n²·d) |
| 空间复杂度 | O(d) | O(n²) |

**Multi-Head Attention（多头注意力）：**

单头注意力只能在一个表示子空间中学习关注模式，Multi-Head 通过 h 个并行注意力头在不同子空间中捕捉不同类型的依赖关系（如句法关系、语义关系、指代关系等）：

```
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) · W_O
head_i = Attention(Q·W_Qi, K·W_Ki, V·W_Vi)
```

每个头的维度为 d_k = d_model / h，总计算量与单头相当。

**O(n²) 问题：**
注意力矩阵 A ∈ R^{n×n} 的计算和存储都是 O(n²)，这是长序列处理的核心瓶颈。例如序列长度 n=32k 时，注意力矩阵需要约 4GB 显存（float32）。Flash Attention 通过分块计算解决了这一问题。

**因果掩码（Causal Mask）：**
自回归语言模型使用下三角掩码，确保位置 i 只能看到位置 0~i 的信息，避免"未来信息泄漏"。

## 演进时间线

- **2017** — Attention Is All You Need (Vaswani et al.)，提出 Transformer，自注意力首次成为主架构
- **2018** — BERT 双向注意力预训练，GPT 因果注意力预训练，两条路线分叉
- **2019** — Sparse Attention（OpenAI）、Longformer，针对 O(n²) 的首批优化
- **2020** — Linformer、Performer，线性近似注意力
- **2021** — Flash Attention v1，IO 感知的精确注意力
- **2022** — Multi-Query Attention (MQA)，KV 共享减少显存
- **2023** — Grouped Query Attention (GQA)，MHA 和 MQA 的折中
- **2024** — Flash Attention 3，针对 Hopper GPU 优化；Sliding Window Attention 成为主流

## PM 决策视角

**何时选择基于自注意力的架构：**
- 需要建模任意位置间的长距离依赖
- 训练数据充足，能发挥 Transformer 的扩展性
- 对推理延迟有一定容忍，但对吞吐量要求高
- 下游任务多样，需要通用表征

**何时考虑替代方案：**
- 序列极长（>100k token），O(n²) 代价难以接受 → 考虑 SSM/Mamba 或稀疏注意力
- 边缘设备部署，显存严重受限 → 考虑 RNN 类模型（RWKV 等）
- 在线流式推理场景，不能等待完整序列 → 考虑因果掩码变体

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| 标准 LLM（<128k ctx） | Multi-head / GQA | 成熟，生态完整 |
| 超长文档（>128k） | Sliding Window + Global | 兼顾效率和全局信息 |
| 实时流式推理 | 线性注意力变体 | 递推计算友好 |
| 资源受限设备 | MQA / GQA | 降低 KV Cache 压力 |

## 补充:更严谨的机制与公式(源自 Alisa's Book of LLMs)

### Causal Mask 的精确施加方式

本页已提到自回归模型使用"下三角掩码"，这里给出精确的逐元素施加规则。对注意力分数矩阵 A（元素 A_ij 表示位置 i 对位置 j 的分数）：

```
A_ij ← A_ij       若 j ≤ i (只能看见自己和之前的位置)
A_ij ← -∞         若 j > i (未来位置直接置为负无穷)
```

经过 softmax 后，-∞ 对应的位置权重变为 0，从而实现"看不到未来"。

### 为什么要除以 √H

本页已提到"除以 √d_k 防止梯度消失"，这里补充更完整的因果链条：点积 Q·K^T 的数值大小会随向量维度 H 增长而增长（因为是 H 个分量乘积之和），如果不做缩放，进入 softmax 的数值会随维度变大而变得很极端，导致 softmax 输出的分布过于尖锐（近似 one-hot），一方面梯度会变得很小、难以更新，另一方面模型对输入的微小变化会过度敏感。除以 √H 相当于把点积的数值范围重新拉回到与维度无关的固定尺度。

### QK-Norm(本页尚未提及的可选技巧)

一些较新的模型架构会在计算 Q·K^T 之前，先对 Q、K 向量分别做一次 RMSNorm，用来控制进入点积运算的向量幅度，进一步稳定训练、减少数值溢出风险。这是缩放点积之外的一个额外的、可选的稳定性技巧。

### GQA 场景下 K/V 的 reshape 与 expand

本页在"与 RNN 的根本区别"里没有展开 GQA 的具体张量操作，这里补充实现层面的形状变化：设 batch=B、序列长度=S/T、总维度=D、注意力头数=N、KV 头数=K、每头维度=H（D=N×H）。Q/K/V 投影后先 reshape 暴露出头维度：

```
Q: (B, T, D)     → (B, N, T, H)
K: (B, S, K·H)   → (B, K, S, H)
V: (B, S, K·H)   → (B, K, S, H)
```

注意 K、V 用的是 K 个头（K ≤ N），因为 GQA/MQA 下 K、V 头数少于 Q 头数。在真正做注意力计算之前，需要把 K、V 沿头维度 expand（重复）到与 Q 相同的头数：

```
K: (B, K, S, H) → (B, N, S, H)
V: (B, K, S, H) → (B, N, S, H)
```

这个 expand 操作不引入新参数，只是把同一组 K/V 复制给同一组内的多个 Q 头共享，是 GQA 节省 KV cache 的具体实现方式（详见 [[Wiki/概念/05_记忆与检索/上下文压缩与KV缓存]]）。

### 滑动窗口与稀疏注意力如何把复杂度从 O(n²) 降到 O(nW)

本页"O(n²) 问题"部分只讲了标准注意力的复杂度瓶颈，这里补充两种降低复杂度的具体方案：

- **滑动窗口注意力（Sliding Window Attention）**：每个 token 只关注最近 W 个 token，而不是全部历史。n 个 token 每个只做 O(W) 的工作，总复杂度从 O(n²) 降为 O(nW)。
- **稀疏注意力（交替局部+全局）**：让大部分层用滑动窗口局部注意力，少数层（或每层的少量 token）保留全局注意力，交替堆叠，在几乎不损失长程建模能力的前提下把整体复杂度维持在接近 O(nW) 的量级。
