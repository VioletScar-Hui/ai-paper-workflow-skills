# 量化技术（Quantization）

> **一句话定义**：将模型权重/激活值从高精度浮点（FP16/BF16）压缩为低位整数（INT8/INT4/FP4），在损失极小精度的前提下，大幅降低显存占用和推理计算量。

---

## 寓言学习

### 寓言正文

老照片档案馆里，扫描员小陶负责把顾客送来的老照片数字化存档。一开始，每张照片都按最高精度扫描留档——每个像素的色彩用两百多级色阶记录，色彩过渡细腻，但一箱底片扫下来，硬盘很快就堆满了。

馆长要求省地方，小陶把存档标准降到十六级色阶。大部分照片降完几乎看不出差别，毕竟大多数照片里的色彩本来就集中在中间那几档灰阶和肤色附近，两百级里很多档位平时根本用不上。可有一批老照片是舞台演出照，追光灯打出的极亮高光和背景的死黑同时出现在画面里，降到十六级后，高光边缘一圈一圈的色带看得清清楚楚，效果差到没法交付。

小陶后来想了个办法：先扫一遍找出照片里色彩特别极端的那一小块区域（追光灯、逆光轮廓这些），这部分单独保留原来的高精度色阶，其余大面积的普通区域照样压到十六级。这样存档，硬盘占用还是省了大半，舞台照的色带问题也没了。

顾客里有个搞司法鉴定的常客，送来的照片要求逐像素比对原始底片的色值差异，用来做证据。小陶告诉他这批必须原样留最高精度，压缩存档不适用——差一级色阶都可能被对方律师挑出毛病。

### 概念解析

**概念名称**：量化技术（Quantization），属于大模型推理优化 / 模型压缩问题域。

**学习卡片**
- 核心张力：想要更少的存储和计算开销，就要降低每个数值记录的精度；但精度降得越粗，某些对结果影响特别大的数值（离群值/关键区域）损失就越明显，压缩比和质量在互相拉扯。
- 关键不变量：压缩后仍要能反推回一个可用的近似值（量化再反量化），整体存储/计算量随每个数值占用的位数近似线性下降，但下降的位数不能是"一刀切"到不顾数据分布特征。
- 触发条件：显存/算力/存储成本是瓶颈，而数据里绝大多数数值本身就集中在有限的取值范围内，允许用更粗的刻度记录也不太影响整体可用性。
- 常见误解/失败模式：以为把所有数值统一压到同一个粗糙精度就万事大吉，忽视了数据里少数"离群值"（异常大/异常关键的数值）一旦被同等粗糙对待，会导致局部质量断崖式下跌，甚至传导污染其余部分。
- 非适用边界：如果场景要求逐个数值精确复原、任何微小误差都不可接受（比如需要和原始数据逐一比对核验的场合），量化压缩本身就与需求冲突，不适用。

**一句话核心定义**：量化是把模型权重/激活值从高精度浮点表示压缩为低位整数或低位浮点表示，用可接受的精度损失换取显存占用和计算量的大幅下降，同时对分布中的异常值/关键区域做特殊处理以避免局部质量崩塌。

**它试图解决的问题**：大模型每个参数如果都用 16 位浮点存储，显存和算力成本高到很多场景部署不起；量化让每个参数占用的位数变少，在保留可用精度的前提下，大幅降低部署门槛。

**故事元素映射**：
- 最高精度两百多级色阶存档 = FP16/BF16 全精度权重。
- 降到十六级色阶节省空间 = INT4/INT8 量化，用更少的位数记录每个数值。
- 舞台照追光灯高光和死黑同时压到十六级后出现色带崩坏 = 直接对全部数值做粗粒度量化时，分布中的"离群值"维度误差被放大，导致大模型（>6.7B）直接 INT8 量化会出现性能崩塌的现象。
- 单独把极端区域留高精度、其余照常压缩 = LLM.int8() 的混合精度分解思路：检测离群值维度，用 FP16 单独计算，其余维度用 INT8，两路结果相加。
- 司法鉴定客户要求原样留档、不能压缩 = 量化的非适用边界，逐像素精确复原的需求与压缩本身冲突。

**比喻边界**：故事里"十六级色阶"是均匀切分的简化说法，而 NF4（QLoRA 用的四比特方案）并不是均匀切分——它依据大模型权重近似服从正态分布这一特点，在数值密集的中心区间切得更细、稀疏的尾部区间切得更粗，是针对这种分布形状专门设计的最优编码，这一点故事里的"整体统一降级"没有体现；此外真实量化还有反量化（推理时把压缩值还原成近似原值再参与计算）这一步，以及"连量化用的刻度参数本身也再压缩一次"（双重量化）等工程细节，故事没有展开。

**非适用例**：如果只是想让模型变得"更小"（参数数量减少），而不是让每个参数占用的位数变少，那不是量化要解决的问题——那属于知识蒸馏或剪枝的范畴，量化压缩的是精度而不是参数量本身。

**现实例子**：LLM.int8()（2022）用向量级量化加离群值分离，让 175B 参数的模型做 INT8 推理时几乎没有性能损失，显存降低约 50%；QLoRA（2023）设计的 NF4 格式让 65B 模型可以在单张消费级显卡上完成微调，是量化和参数高效微调结合的代表案例。

### 检验问题

1. 理解检验：如果小陶一开始就统一把所有照片（包括舞台照）都压到十六级，且不做"单独找出极端区域"这一步，你预测最先出问题的会是哪一类照片？这对应量化技术里的哪个已知风险？
2. 迁移检验：一家公司想把一个 70B 的对话模型部署到延迟敏感的实时客服场景，同时又想尽量保证专业术语（比如药品名称、法律条款）不出错。如果直接对整个模型做统一的 INT4 量化，你觉得可能会在哪类内容上出问题？可以参考故事里哪种做法来规避？

## 核心原理

```
标准精度（FP16）：
  每个参数 = 16 bits = 2 bytes
  70B 模型 ≈ 140GB 显存（纯权重）

INT8 量化：
  每个参数 = 8 bits = 1 byte
  70B 模型 ≈ 70GB 显存（节省 50%）

INT4/NF4 量化：
  每个参数 = 4 bits = 0.5 byte
  70B 模型 ≈ 35GB 显存（节省 75%）
  
量化过程（对称量化为例）：
  scale = max(|W|) / 127
  W_int8 = round(W / scale)
  W_dequant = W_int8 × scale  （推理时反量化）
```

## 量化方案演进

| 方案 | 量化对象 | 精度 | 核心创新 | 性能损失 |
|------|---------|------|---------|---------|
| **LLM.int8()** (2022) | 权重 INT8 | 很低 | 向量级量化 + 离群值分离 | <1% |
| **GPTQ** (2022) | 权重 INT4 | 低 | 逐层量化，最优量化误差 | <2% |
| **NF4（QLoRA）** (2023) | 权重 NF4 | 极低 | 为正态分布设计的最优4-bit | <1% |
| **AWQ** (2023) | 权重 INT4 | 低 | 激活感知权重量化 | <2% |
| **FP4（DeepSeek-V4）** (2025) | 权重 FP4 | 低 | 浮点4-bit（适合未来硬件）| <3% |

## LLM.int8() 的关键洞察（📅 2022）

```
核心问题：直接 INT8 量化在 >6.7B 模型上性能崩塌
根本原因：激活值中存在"离群值"（某些维度异常大），导致量化误差传播

解决方案：混合精度分解
  1. 检测离群值维度
  2. 离群值维度：FP16 高精度计算
  3. 其余维度：INT8 量化计算
  → 两路结果相加 = 最终输出
  
结果：INT8 量化在 175B 模型上无显著性能损失
      显存降低约 50%
```

## NF4 的设计原理（QLoRA，📅 2023）

```
洞察：LLM 权重近似服从正态分布
问题：标准 INT4 均匀划分量化区间，但正态分布中心密集、尾部稀疏
       → 中心量化精度浪费，尾部量化精度不足

NF4（NormalFloat4）设计：
  基于正态分布的理想分位点划分量化区间
  → 中心区间更密集（高密度区域），尾部区间更稀疏
  → 对正态分布权重是信息论最优的 4-bit 编码

双重量化（Double Quantization）：
  量化常数本身也量化一次
  每个参数额外节省 ~0.37 bits
```

## 量化 vs 蒸馏的对比

| | 量化 | 知识蒸馏 |
|--|------|---------|
| **原理** | 压缩同一模型精度 | 小模型学大模型行为 |
| **模型大小** | 不变（只改精度）| 显著减小 |
| **速度** | 提升（计算量减少）| 大幅提升 |
| **质量** | 接近原模型 | 取决于蒸馏效果 |
| **工程难度** | 低（通常即插即用）| 高（需要训练）|

## 推理成本影响

```
量化对实际推理成本的影响：

显存节省（影响可部署的 GPU 规格）：
  A100 80GB 能放多少？
  FP16 70B：≈2张（不够用）
  INT8 70B：≈1张（勉强）
  INT4 70B：≈1张（宽裕，可以有 batch）

吞吐量（影响 QPS）：
  INT8 vs FP16：通常 1.2-1.5x 吞吐提升
  INT4 vs FP16：通常 2-3x 吞吐提升
  （取决于硬件对低位运算的优化程度）

质量-成本权衡：
  INT8：通常无损，推荐用于生产
  INT4：轻微质量损失（1-3%），性价比高
  INT4 + 混合精度（关键层 FP16）：最佳平衡
```

## PM 决策框架

| 需求 | 方案 |
|------|------|
| 生产推理，保证质量 | INT8（LLM.int8() 或 SmoothQuant）|
| 极限压缩，接受小损失 | INT4（GPTQ 或 AWQ）|
| 微调大模型，资源有限 | QLoRA（NF4 + LoRA）|
| 对话产品（延迟敏感）| INT4 + 混合精度关键层 FP16 |
| 边缘部署 | INT4 甚至 INT2（需要仔细评估）|
