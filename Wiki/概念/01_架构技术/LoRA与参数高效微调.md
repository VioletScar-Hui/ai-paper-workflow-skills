# LoRA 与参数高效微调（PEFT）

> **一句话定义**：LoRA（Low-Rank Adaptation）冻结预训练模型权重，只训练低秩分解矩阵（A·B）来模拟权重更新 ΔW，使微调参数量减少 10000 倍，同时保持全量微调的性能。

---

## 寓言学习

### 寓言正文

老张是模具车间的换模工程师。工厂的主力模具用了很多年，能稳定做出标准椅子的所有部件——但客户常点"小改款"：这次要把扶手加宽两公分，下次要把靠背弧度调一调。以前遇到这种订单，老张的做法是重新开一整套模具：画图、开钢料、精铣、试模，一套下来要花大半个月，成本堪比再造一台机器，而这些改款订单往往就做几百件，根本摊不平。

后来他想了个办法：不动主力模具本身，只在扶手对应的那个位置加一块可以拆卸的小插片，插片很薄，形状经过精确计算，装上去正好把扶手轮廓顶出想要的两公分弧度。开一块插片只要两三天，装卸也就几分钟，主力模具原封不动，改完款式还能随时换回标准插片。

有一次客户要的不是扶手加宽，而是整个椅子的力学结构都要按新标准重新设计——座位受力路径、四条腿的连接方式全变。老张试着在关键部位加插片，怎么调整插片的厚度和形状都做不出那种整体结构的变化，插片再怎么加大，最后也只是把主力模具的大部分轮廓又重新做了一遍，还不如直接开一套新模具。

另有一次订单量特别大、跑了几十万件，老张干脆把插片和主力模具永久焊接、打磨成一体，机器上线生产时完全感觉不出这里曾经加过一块插片——不需要额外的装卸步骤，速度和用标准模具一模一样。

### 概念解析

**概念名称**：LoRA（低秩适配），属于大模型参数高效微调（PEFT）问题域。

**学习卡片**
- 核心张力：为了适配一个新需求，把整套底座权重都重新训练一遍（能覆盖任何程度的改动，但成本极高）vs. 冻结底座、只在需要改动的地方加一个很小的低秩"补丁"来模拟权重更新（成本极低，但能表达的改动幅度有上限）。
- 关键不变量：补丁能否生效，取决于"这次需要的权重改动本身是不是低秩的"——即改动能不能被一个远小于原始维度的小矩阵组合近似出来；这个假设不成立时，补丁再怎么调整都补不出想要的效果。
- 触发条件：新任务与底座已有能力足够接近，只需要局部、方向性的调整，而不是从底层结构推倒重来。
- 常见误解/失败模式：以为补丁越大（秩越高）就总能更接近全量微调的效果，忽视了如果任务本身需要的是结构性改动，加大补丁也补不出来；或者反过来，为了省成本把补丁做得过小，实际改动幅度不够，训练完仍然欠拟合。
- 非适用边界：当需要的改动是底座结构性的、全局性的（不是局部方向调整），低秩补丁无法模拟这种改动，只能重新做全量训练。

**一句话核心定义**：LoRA 冻结预训练权重，只训练一对低秩矩阵来模拟权重更新量 ΔW，用远小于原始权重规模的参数量逼近微调效果，且可以在部署时合并回原权重，不增加额外推理成本。

**它试图解决的问题**：全量微调需要为每个新任务保存一整套和原模型一样大的权重，训练和存储成本都极高——如何用远小的参数量，在假设"权重改动是低秩的"前提下，达到接近全量微调的效果。

**故事元素映射**：
- 主力模具 = 冻结的预训练权重 W，保持不动。
- 扶手位置的小插片 = 低秩适配矩阵（A、B 组合），只在需要改动的方向上叠加一个小更新。
- 插片开发只要两三天、装卸几分钟 = LoRA 训练参数量极小、训练速度快。
- 整体力学结构要重做、插片做不出来 = 当任务所需的改动不是低秩的（比如需要底层结构性变化），LoRA 的低秩假设失效，只能全量微调。
- 插片焊死进主力模具、生产时无感知 = 训练完成后把 B·A 合并回原权重 W，推理时零额外成本。

**比喻边界**：故事把补丁简化成"一块插片"，但真实的 LoRA 更新是两个矩阵 A、B 相乘（先降维再升维）的组合，秩 r 的大小、作用在哪些层（只在注意力还是也覆盖 FFN）都会显著影响效果，并非"一块插片多大"这么单一的变量；此外插片焊死这一步在真实场景中通常是训练结束后的一次性权重合并操作，不涉及物理意义上的"打磨"。

**非适用例**：如果客户要的椅子和以前的产品线在结构上完全不同（比如从塑料椅换成需要焊接钢架的椅子），这已经不是"在已有底座上做局部调整"，而是需要一套全新的生产体系，硬套插片思路解决不了——这对应任务与底座差异过大、低秩假设不成立的情况。

**现实例子**：QLoRA 用 4-bit 量化底座 + LoRA 低秩适配，把 65B 参数模型的微调显存需求从约 780GB 压缩到 48GB，单张 A40 显卡就能完成微调，而合并 LoRA 权重后的模型推理成本与全量微调模型完全相同。

### 检验问题

1. 理解检验：老张给整体力学结构做插片失败了，这说明插片这个思路本身有问题吗？故事想让你区分的是哪两种不同的失败原因？
2. 迁移检验：如果有人说"我们的低秩微调效果一直不如全量微调，是不是应该把秩 r 调大一点试试"，结合这个故事，你会提醒他先排查什么？

## 核心原理

```
全量微调（Full Fine-tuning）：
  W_new = W_pre + ΔW    (ΔW 维度与 W 相同，参数量极大)

LoRA 关键假设：
  ΔW 是低秩的（rank << min(d_in, d_out)）

LoRA 数学形式：
  h = W_pre·x + ΔW·x
    = W_pre·x + (B·A)·x
    
  其中：
    A ∈ R^{r×d_in}  （随机高斯初始化）
    B ∈ R^{d_out×r} （零初始化 → 训练开始时 ΔW=0）
    r ≪ min(d_in, d_out)  （通常 r=4, 8, 16, 32, 64）
    
  参数量：原来 d_in×d_out → r×(d_in+d_out)
  当 r=8, d=4096: 从 16.7M → 65.5K（减少 255x）
```

## LoRA → QLoRA 的进化

```
LoRA 的限制：
  还需要加载全精度（FP16/BF16）基础模型 → 仍需大量 GPU 显存
  
QLoRA（Dettmers et al. 2023）三大创新：

1. NF4（NormalFloat4）量化：
   假设权重正态分布 → 设计信息论最优 4-bit 数据类型
   基础模型从 FP16（2B/param）→ NF4（0.5B/param）
   
2. 双重量化（Double Quantization）：
   对 NF4 的量化常数再次量化 → 进一步节省显存
   
3. 分页优化器（Paged Optimizer）：
   处理长序列时 GPU OOM → 自动 offload 到 CPU RAM
   
结果：65B 模型从 ~780GB → 48GB，单张 A40 可微调
```

## 关键参数对显存/性能的影响

| 参数 | 典型值 | 对显存 | 对性能 |
|------|--------|--------|--------|
| **rank r** | 4-64 | 小→省显存 | 小→欠拟合 |
| **alpha（缩放）**| 通常 = r 或 2r | 无影响 | 控制更新幅度 |
| **目标模块** | q,k,v,o + FFN | 多→多参数 | 多→更接近全量 |
| **量化位数** | 4-bit vs 8-bit | 4-bit 省 2x | 基本无损 |

## 与其他 PEFT 方法对比

| 方法 | 思路 | 推理额外成本 | 性能 |
|------|------|------------|------|
| **LoRA** | 低秩矩阵分解权重更新 | **无**（可合并到 W） | ≈全量 |
| **Adapter** | 在层间插入小 MLP | 有（增加推理层数） | 略低 |
| **Prefix Tuning** | 在输入前加可学习 token | 有（增加序列长度）| 较低 |
| **P-Tuning** | 连续提示优化 | 有 | 任务相关 |

**LoRA 的关键优势**：推理时可以将 B·A 合并回 W，零额外推理成本。

## LoRA 变体

| 变体 | 创新点 |
|------|--------|
| **DoRA** | 将权重分解为幅度+方向，分别用 LoRA 更新 |
| **LoftQ** | 量化+LoRA 联合初始化，减少量化误差 |
| **LoRA+** | A/B 用不同学习率，收敛更快 |
| **Flora** | 随机投影，支持任意 rank |
| **LoRA-FA** | 固定 A 矩阵，只更新 B，节省内存 |

## 什么任务适合 LoRA？

| 场景 | 推荐 |
|------|------|
| **领域适配**（法律/医疗/金融）| LoRA r=8-16 于 q,k,v,o |
| **指令跟随微调** | LoRA r=16-64，覆盖全部注意力+FFN |
| **低资源微调**（<8GB 显存）| QLoRA 4-bit |
| **高性能生产模型** | 全量微调（如有资源）|
| **多任务切换** | LoRA Hub（多个 LoRA 权重，按需加载）|

## 最弱假设与批评

1. **低秩假设未必成立**：特定任务的 ΔW 可能不是低秩的，尤其是领域跨度大时
2. **与 SFT 的差距**：在困难任务（代码生成、推理）上，LoRA 通常比全量微调差 1-5%
3. **超参数敏感**：rank、alpha、目标模块的选择影响显著，缺乏通用最优设置
4. **灾难性遗忘**：LoRA 仍可能遗忘未训练的能力，尤其当 r 较大时
