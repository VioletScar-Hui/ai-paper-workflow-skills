# 多模态离散 Token 化

> **一句话定义**：将图像、音频、视频等连续信号离散化为 Token 序列，使多模态内容可以与文本 Token 统一处理——是实现"统一自回归多模态模型"的关键前置技术。

---

## 寓言学习

### 寓言正文

印花工坊接单时，客户经常带来一小块想要复刻的布料样品——颜色、光泽、纹理都是独一无二的。工坊如果只是把这块布料原样收好、留着以后拿出来对色，色彩确实最准，谁都能一眼看出跟原样一不一样；但这样没法把这块布料"写"成一份配方交给印花机去打样新的花色，也没法让另一个师傅照着做出一个"相似但略有变化"的新款——布料样品本身不是一份能拿去执行的说明书。

后来工坊建了一套标准色号本，几千种颜色、上百种纹理，每种都编了号。收到新样品，师傅会把它上面的颜色、纹理拆解成一串最接近的色号纹理号组合，写成一张配方单。有了这张配方单，印花机可以照着打出新样，另一个师傅也能在配方单基础上改几个编号、组合出一款"相似但更亮一点"的新花色——原来做不到的"照着写、改着做"，现在都能做了。

代价是，编号终究是"最接近"而不是分毫不差：客户送来的原始布料带着一种很细微的哑光质感，色号本里最接近的那个号码是偏亮的，配方单打出来的新样和原样放在一起比，能看出轻微的光泽差异——但只要不拿真样品并排细比，单看打出来的成品，几乎没人挑得出来。

### 概念解析

**概念名称**：多模态离散 Token 化，属于统一自回归多模态建模的前置表示问题域。

**学习卡片**
- 核心张力：保留原始信号本身（连续、保真度最高，但没法被"写成"一份可执行的指令去生成新内容）vs. 把原始信号拆解成一套标准编号词汇的组合（有轻微失真，但可以像文字一样被"写"出来、组合、修改，从而支持生成新内容）。
- 关键不变量：不管编号本再大再细，编号始终是对原始连续信号的"最接近"近似，不是分毫不差的还原——这是离散化换取"可写、可生成"这个能力必须付出的代价。
- 触发条件：需要用一个统一的、类似文字词汇表的方式去描述和生成非文本内容（图像、音频、视频），使其能被同一套自回归生成机制处理时，需要先做离散化。
- 常见误解/失败模式：以为离散化后的编号组合可以完全等价于原始信号，忽视了量化损失的存在；或者反过来，只满足于保留原始信号的高保真度，却忽略了这种形式根本没法被写成"配方"去生成新内容。
- 非适用边界：如果任务只需要"看懂、理解"原始信号，并不需要生成新内容（不需要"写配方"这个能力），保留连续的原始表示（不做离散化）反而保真度更高，用不上离散化这一步。

**一句话核心定义**：多模态离散 Token 化把图像、音频、视频等连续信号量化成一串离散的编号（Token），使其能像文字一样被统一的自回归模型处理和生成，代价是引入了量化损失。

**它试图解决的问题**：自回归语言模型的生成能力建立在"词汇表里离散的词"这个基础上，而图像、音频、视频天然是连续信号，无法直接被同一套基于分类（Softmax）的生成机制处理；如何把连续信号也变成一套"词汇"，让文本和其他模态可以被同一个模型统一生成。

**故事元素映射**：
- 客户送来的原始布料样品 = 连续信号本身（如图像的原始像素）。
- 只留样品对色、没法写成配方 = 连续嵌入（如 CLIP 特征）保真度高，但无法被自回归采样/生成新内容。
- 标准色号本、把样品拆解成编号组合写成配方单 = VQ-VAE 等方法把连续信号量化成离散 Token 序列（Codebook）。
- 照着配方单打样、改几个编号组合出新花色 = 离散 Token 序列可以被自回归模型生成、采样、组合出新内容。
- 色号本里最接近的号码和原样有轻微光泽差异 = 量化损失：离散化后的 Token 是最接近的近似，不是无损还原。

**比喻边界**：故事把"编号本"简化成了人工翻查色卡，真实的 VQ-VAE 类方法是用编码器把信号压缩成特征向量，再在一个可学习的 Codebook 里找最近的向量、取其编号，整个过程是自动学出来的，且不同技术路线（如 LongCat-Next 的 DiNA）会把离散化和生成过程联合训练，而不是先固定一套编号本再单独使用。

**非适用例**：如果印花工坊的任务只是"帮客户核对送来的样品和库存里哪块布料颜色最接近"，并不需要打样生成新花色，那留着原始样品直接对比色彩，比拆解成编号组合更准确、更没必要——这对应只需要理解/比对、不需要生成新内容的场景，连续表示比离散化更合适。

**现实例子**：DALL-E 1、VQ-VAE-2 等图像生成模型把 256×256 的图像压缩量化成 256 个左右的离散 Token，再用自回归方式逐个生成这些 Token 来产生新图像；而 LLaVA 这类只做图像理解、不做图像生成的模型则直接使用连续的 CLIP 视觉特征，不需要做这一步离散化。

### 检验问题

1. 理解检验：工坊建了标准色号本之后，为什么打出来的新样和原始样品之间会有轻微的光泽差异？这个差异对应的是什么代价？
2. 迁移检验：如果有人说"我们的多模态模型只需要看懂图片、回答关于图片的问题，不需要生成图片，那也应该把图像先离散化成 Token 会更好"，结合这个故事，你会怎么回应？

## 为什么要离散化？

```
核心动机：自回归语言模型的成功建立在离散 Token 的基础上

文本天然离散：word/subword tokenization → 词汇表大小 ~32K-128K

图像/音频/视频是连续信号：
  → 直接建模：需要回归连续值（MSE 损失）
  → 但语言模型是分类器（Softmax）
  
解决方案：把连续信号也"离散化"成 Token
  → 所有模态都变成"词汇"
  → 统一 Transformer 处理
  → 可以 cross-modal 联合训练
```

## 离散化的主流技术路线

### 1. VQ-VAE（向量量化变分自编码器）

```
流程：
  连续信号（图像/音频）
  → Encoder（下采样 + 特征提取）
  → 向量量化层：每个特征向量 → 最近的 Codebook 向量 → Token ID
  → Token 序列
  → Decoder（从 Token 序列重建原始信号）

关键参数：
  Codebook 大小：通常 1024-16384（词汇量）
  压缩比：图像 256×256 → 16×16 = 256 tokens（典型值）
  
应用：图像生成（DALL-E 1, VQ-VAE-2），音频生成（EnCodec）
```

### 2. LongCat-Next 的 DiNA（Discrete Native Autoregressive）

```
创新点（论文99）：
  传统方法：先训练 tokenizer，再训练生成模型（两阶段独立）
  DiNA：将 tokenization 和 generation 统一在单一框架中
  
具体做法：
  不用预训练的独立 VQ-VAE
  而是把模态词汇化（Modal Vocabularization）内嵌到自回归训练中
  → 模型在学生成时，也在学"如何离散化"

优势：
  端到端优化，tokenizer 和 generator 联合调优
  避免两阶段训练的次优性（tokenizer 的质量限制 generator 上限）
```

### 3. 连续嵌入 vs 离散 Token

```
对比：

方案A：连续嵌入（如 LLaVA 的 CLIP 视觉特征）
  图像 → CLIP Encoder → 连续向量序列 → 拼接文本 Token
  优势：视觉信息保真度高
  劣势：无法自回归生成图像（无法 sample）

方案B：离散 Token（如 DALL-E 1, LongCat-Next）
  图像 → VQ tokenizer → 离散 Token ID → 与文本 Token 统一
  优势：可以生成（自回归采样），统一架构
  劣势：量化损失，特征保真度略低

方案C：混合（如 Chameleon, GLM-5V）
  理解任务用连续嵌入，生成任务用离散 Token
  → 结合两者优势，但架构更复杂
```

## 音频离散 Token 化

```
主流工具：EnCodec / SoundStream
  波形 → 多码本残差向量量化（RVQ）
  每帧多个 codebook，每个 codebook 一个 Token
  Typical：24kHz 音频 → 75 frames/s × 8 codebook = 600 tokens/s

LongCat-AudioDiT（论文98）的创新：
  不用 EnCodec 的 token-level 自回归
  而是在连续的"波形潜在空间"用扩散模型生成
  → 绕过离散化，直接扩散连续特征
  → 保真度更高（音质更好），但不能和文本统一建模
```

## 视频 Token 化的挑战

```
问题规模：
  视频 = 时序图像 + 音频
  1分钟视频（24fps，480p）≈ 1440 帧
  每帧 256 tokens → 总计 369,664 tokens（超过大多数 context window）

解决思路：
  1. 时空压缩：3D 卷积 + 时间降采样（4x 时间压缩）
  2. 关键帧选取：只 tokenize 关键帧
  3. 稀疏 Token：用稀疏注意力处理长视频 Token 序列
  
LongCat-Video-Avatar-1.5（论文97）：
  聚焦音频驱动的人像视频生成
  绕过全帧 tokenization，专注运动参数的离散化
```

## 离散 vs 连续的模态统一之路

```
2022-2024 年的范式演变：

2022 Flamingo/LLaVA：
  视觉 → 连续 CLIP 特征 → 拼接文本
  只能理解，不能生成图像
  
2023 DALL-E 3 / Stable Diffusion + LLM：
  文本 → 指令 → 扩散模型生成图像
  两个独立模型，非端到端
  
2024 Chameleon / LongCat-Next：
  图像 → VQ Token → 与文本统一序列
  同一个 Transformer 做理解 + 生成
  真正的"原生多模态"

未来方向：
  更高压缩比的 tokenizer（256 tokens/image → 64 tokens/image）
  更低量化损失（高频细节保留）
  视频的实时 tokenization
```

## PM 决策框架

| 场景 | 推荐方案 |
|------|---------|
| **只做图像理解**（分类/VQA）| 连续 CLIP 嵌入（信息保真度高）|
| **图像理解 + 生成**（统一模型）| 离散 VQ Token（统一自回归）|
| **高质量图像生成**（创意场景）| 扩散模型（非 autoregressive）|
| **TTS/音频生成**（高保真）| 扩散模型（如 AudioDiT）|
| **多模态 Agent**（理解+生成+推理）| 混合方案（理解用连续，生成用离散）|
