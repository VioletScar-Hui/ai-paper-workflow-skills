# Flash Attention

## 一句话定义
> Flash Attention 是一种 IO 感知的精确注意力算法，通过将 Q/K/V 矩阵分块（tiling）在 SRAM 中完成计算，避免将 O(n²) 的注意力矩阵写入 HBM，从而将内存占用从 O(n²) 降至 O(n)，并大幅提升训练速度。

## 寓言学习

### 寓言正文

她是审核台的核对员，专门判断新歌和曲库里的老歌像不像。曲库存在楼道尽头的档案室里，每次判断一首新歌，都要跟库里几万首老歌一对一对地比：搬来两首、听、打分、把这一对的分数写在纸条上塞进档案柜、再搬下一对。一天下来，大半时间花在来回搬碟子和归档纸条上，真正听、真正判断"像不像"的时间反而被挤到最后，常常听到一半就要收工。

后来审核台边上加了一辆小推车，每次只从档案室拉一小批老歌过来，放在手边。她一边听一边在心里记住"目前听过的这些里，最像的是哪首、多像"，听完这一小批，直接把这批换成下一批，不再给每一对单独写纸条归档——只在心里滚动更新那个最高分。同样判断一首新歌，她几乎不用再来回跑档案室，速度快了好几倍。

主管有点不放心，让她拿同一首新歌，分别用老办法和新办法各判一次。两种办法给出的最终"最像哪首、有多像"完全一样，新办法只是省掉了来回搬运和逐条归档，没有漏判，也没有把判断标准放宽。

不过有一次，只来了两三首候选曲子要比对，她还是习惯性地去推小车、在心里滚动计算，主管提醒她——这么点数量，直接搬去档案室对一下，可能比推车折腾一趟还快。

### 概念解析

**概念名称**：Flash Attention，属于 Transformer 系统效率优化 / GPU 计算与存储协同设计问题域。

**学习卡片**
- 核心张力：把每一次两两比对的中间结果都搬到远处慢速存储里读写归档（信息完整但极耗时间）vs. 只在手边的快速小空间里分批处理、边算边滚动更新一个汇总结果，不落盘中间过程（几乎不占用慢速通道，但依赖精心设计的滚动统计量）。
- 关键不变量：无论怎么分批、怎么滚动计算，最终得到的相似度/注意力输出必须和"存下所有中间结果再统一计算"完全一致——这是精确算法的重排，不是近似算法。
- 触发条件：计算规模是两两全量比对（n×n 量级），且中间结果的读写（慢速存储）远比真正的计算本身更耗时间的时候。
- 常见误解/失败模式：以为提速一定是靠"放宽标准、近似计算"换来的；实际提速来自减少了对慢速存储的读写次数，精度完全没变；反过来，把这套分块技巧套用到规模很小的比对任务上，调度和分批本身的开销可能比直接算还大。
- 非适用边界：比对/计算规模很小、不构成 n×n 级别瓶颈时，分块和滚动计算的调度开销可能抵消收益；这套技巧只解决"怎么算得快、存得省"，不改变"该不该判定像"这个判断标准本身。

**一句话核心定义**：Flash Attention 通过分块在快速片上存储中完成计算、用滚动统计量代替存储完整的中间比对矩阵，把注意力计算从"读写慢速大存储主导"变成"计算主导"，在结果完全不变的前提下大幅提速、省显存。

**它试图解决的问题**：标准注意力需要把 n×n 的中间比对矩阵整个写入慢速显存再读出来做归一化，这个读写过程才是真正的瓶颈，而不是浮点计算量本身——如何在不改变最终结果的前提下，避免这次巨大的读写开销。

**故事元素映射**：
- 核对员 = GPU 的计算单元（Tensor Core），真正做比对/计算的角色。
- 曲库存在楼道尽头的档案室、每对都要写纸条归档 = 标准注意力把 n×n 矩阵整个写入/读出慢速 HBM 显存。
- 小推车、分批搬运、边听边心里滚动更新最高分 = 分块（Tiling）+ 在线 softmax：只在片上快速 SRAM 里处理当前小块，用滚动统计量代替存储完整矩阵。
- 主管让她新老办法各判一次、结果完全一致 = Flash Attention 是精确算法，不是近似，最终注意力输出与标准实现数学等价。
- 两三首歌还去推车反而更慢 = 序列很短、计算规模不构成显存 IO 瓶颈时，分块调度的开销可能盖过收益。

**比喻边界**：故事把"滚动更新最高分"简化成了一个数，真实的在线 softmax 需要同时维护当前最大值和归一化因子两组滚动统计量，且分块顺序、warp 调度等工程细节会显著影响实际加速比，并非只靠"记住一个数"就能实现；此外故事没有体现反向传播时的重计算（Recomputation）机制。

**非适用例**：如果只是要给两首歌打一个总体相似度分数、完全不涉及跟历史曲库做大规模两两比对，那就没有 n×n 级别的存储读写瓶颈，直接算就行，用不上分块和滚动统计这套设计。

**现实例子**：在 A100 80GB GPU 上训练序列长度 2048 的 GPT-2 规模模型，标准注意力的 GPU 利用率约 35%，改用 Flash Attention 2 后利用率提升到约 72%，训练速度提升 2-4 倍，序列越长，读写慢速显存省下的开销占比越大，提速越明显。

### 检验问题

1. 理解检验：核对员新老两种办法给出的"最终判断"完全一样，这说明新办法提速的代价，牺牲的是精度还是别的什么？
2. 迁移检验：如果有人说"我们的模型上下文很短，才 200 个 token，要不要也上 Flash Attention 优化一下"，结合这个故事，你会提醒他先确认什么？

## 核心原理

**传统注意力的 IO 瓶颈：**

GPU 内存层次结构：
```
SRAM (片上缓存)  ~20 MB   带宽 ~19 TB/s
HBM  (高带宽内存) ~80 GB  带宽 ~3.35 TB/s

计算单元 (CUDA Cores / Tensor Cores)
    ↕ 极快读取
  SRAM (~20 MB)
    ↕ 慢 5-6×
  HBM (GPU 主存)
```

标准注意力需要将 n×n 的注意力矩阵 S = Q·K^T/√d_k 写入 HBM，再读回来做 softmax，再写入，再读回来乘以 V。对于序列长度 n=8192，这意味着约 256MB 的 HBM 读写，而实际计算量（FLOP）并不多。**瓶颈在 IO，不在计算。**

**Flash Attention 的核心技巧：**

1. **分块（Tiling）**：将 Q 分成行块，K/V 分成列块，每次只加载一小块到 SRAM
2. **在线 softmax（Online Softmax）**：用滚动方式维护当前最大值和归一化因子，无需存储完整 n×n 矩阵
3. **重计算（Recomputation）**：反向传播时不存储注意力矩阵，而是重新计算（牺牲少量计算换取内存）

**Online Softmax 公式：**

```
对于第 i 个 Q 块，遍历所有 K/V 块 j：
  m_new = max(m_old, max(S_ij))           # 更新当前最大值
  l_new = e^{m_old - m_new}·l_old + Σe^{S_ij - m_new}  # 更新归一化因子
  O_new = (e^{m_old - m_new}·l_old·O_old + e^{S_ij - m_new}·V_j) / l_new
```

**内存复杂度对比：**

| 实现 | 注意力矩阵存储 | 内存复杂度 |
|------|--------------|----------|
| 标准注意力 | 需要存储 n×n | O(n²) |
| Flash Attention 1/2/3 | 不存储，分块计算 | O(n) |

**Flash Attention 版本演进：**

```
FA1 (2022)                FA2 (2023)              FA3 (2024)
  ┌─────────┐             ┌─────────┐             ┌─────────┐
  │ 基础分块  │    ──→     │ 更少串行  │    ──→     │ Hopper  │
  │ Online   │            │ Q块并行  │            │ 专项优化 │
  │ Softmax  │            │ 工作分区  │            │ FP8支持  │
  └─────────┘             └─────────┘             └─────────┘
  2-4× 加速 vs 标准       FA1基础上2×              FA2基础上1.5-2×
  内存 O(n²)→O(n)        causal mask优化          异步流水线
```

**Flash Attention 2 的关键改进：**
- 减少非矩阵乘法操作（主要瓶颈）的比例
- 将 Q 的迭代并行化（FA1 串行遍历 Q 块）
- 更好的 warp 工作分配，减少 shared memory 同步

**Flash Attention 3（针对 H100）：**
- 利用 H100 Tensor Core 的异步特性实现 GEMM 和 softmax 的流水线
- 支持 FP8 精度（相比 FP16 吞吐翻倍）
- Intra-warp pingpong 调度消除同步等待

**对 LLM 训练的实际影响：**

在 A100 80GB GPU 上，序列长度 2048 训练 GPT-2 规模模型：
- 标准注意力：约 35% GPU 利用率
- Flash Attention 2：约 72% GPU 利用率
- 训练速度提升约 2-4×，具体取决于序列长度（序列越长提升越大）

**支持的注意力变体：**
- 因果掩码（自回归 LLM 默认）
- Sliding Window Attention（Mistral、Phi）
- Multi-Query / Grouped-Query Attention
- Document packing（多文档拼接，带 mask）

## PM 决策视角

**何时启用 Flash Attention：**
- 几乎所有基于 Transformer 的模型训练和推理场景
- 序列长度 >512 时收益显著，序列越长收益越大
- 显存受限时（FA 使显存从 O(n²) 降至 O(n)，可以训练更长序列）

**潜在限制：**
- 需要 CUDA GPU（CPU 无法使用）
- 自定义注意力变体需要自行实现 CUDA kernel（有一定工程门槛）
- 某些极端小 batch size + 短序列场景，kernel 启动开销可能抵消收益

| 场景 | 建议 | 说明 |
|------|------|------|
| 预训练长序列（>4k） | FA2/FA3 必开 | 没有 FA 基本无法训练 |
| 推理（生成阶段） | FlashDecoding | 解码特化版本更优 |
| 推理（prefill 阶段） | FA2/FA3 | 与训练相同场景 |
| CPU 推理 | 标准注意力 | FA 仅支持 CUDA |

## 补充:更严谨的机制与公式(源自 Alisa's Book of LLMs)

### 显存数字的精确复核

标准 attention 的 `attn_weights` 张量形状为 `(batch, num_heads, seq_len, seq_len)`。以 seq_len=8192、32 个注意力头、FP16（2 字节）为例：

```
8192² × 32 × 2 bytes ≈ 4 GB
```

这是"一个 batch"的 attention 权重矩阵本身占用的显存，还不包括 Q/K/V 和其他激活值。

> 注：本页"核心原理"部分现有示例写的是"序列长度 n=8192，约 256MB 的 HBM 读写"，与源笔记按 32 heads、FP16 精确计算出的约 4GB 存在数量级差异（可能是遗漏了 num_heads 或换算方式不同），建议核对后统一，此处不擅自改动原文。

### 为什么标准 attention 是"内存带宽瓶颈"而非"计算瓶颈"

标准实现里，N×N 的注意力分数矩阵要经历四次与 HBM 之间的搬运：
1. 计算完 Q·K^T 后，写入 HBM
2. 从 HBM 读回，计算 softmax
3. softmax 结果写回 HBM
4. 再次从 HBM 读出，与 V 相乘得到输出

真正的浮点计算量并不大，但这四次读写发生在带宽远低于片上 SRAM 的 HBM 上，所以瓶颈是数据搬运而不是算力——这也是本页"核心原理"中 SRAM/HBM 带宽对比表想说明的问题的更精确表述。

### FlashAttention 是精确算法，不是近似算法

需要明确强调：FlashAttention 通过分块和在线 softmax 重新组织了计算顺序，但输出在数学上与标准 attention 完全一致，不存在任何近似或精度损失——这一点独立于"分块能省多少显存"，是它区别于线性注意力、稀疏近似等有损方法的关键定性。

### batch × heads 的天然并行直觉

由于每一个 (batch, head) 组合的 attention 计算相互独立，FlashAttention 可以把 `batch × num_heads` 作为并行维度，每个并行 worker 独立处理一个 `m × head_dim` 的 Q/K/V 分块（m 为分块大小），这是 GPU kernel 能高效利用大量并行计算单元的直觉来源。

### PyTorch 中如何启用

除了本页已提到的 `attn_implementation="flash_attention_2"`，更底层、更通用的方式是直接调用：

```python
import torch.nn.functional as F
output = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

PyTorch 会根据硬件和输入形状自动在 FlashAttention、内存高效实现（memory-efficient attention）、朴素数学实现（math）之间选择后端；`is_causal=True` 标志会被融合进 kernel 内部高效实现，而不是显式构造一个 mask 矩阵。
