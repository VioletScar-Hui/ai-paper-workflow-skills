# MTP 多 Token 预测（Multi-Token Prediction）

> **一句话定义**：标准语言模型每步只预测下一个 Token（Next-Token Prediction），而 MTP 让模型同时预测未来多个 Token——这个改变本身不让推理更快，但能提供更丰富的训练信号，显著提升训练效率和模型能力。

---

## 寓言学习

### 寓言正文

工地新人的培训分两批场地。第一批场地里，教练只要求学员报告"接下来这一步打算怎么做"，说完就去做，做完再报下一步，一轮轮很快就能过完一遍浇筑流程，练习次数看起来最多。第二批场地换了个要求：每到一个动作点，学员要一次性报出接下来连续三步的打算，教练把三步都记下来打分，哪怕后两步这轮压根轮不到做——练习节奏明显变慢，同样时间里能过的轮次少了一大截。

一个学员先在第一批场地练完，被派去带一个复杂工序（管线和模板要同时处理），没提前想过后面几步会互相影响，白拆了一次模板返工。后来他被调去第二批场地重新练了一轮，习惯了每一步之前先把后面两步在脑子里过一遍，再上工地独立带班时，虽然还是一步一步动手做，没有人要求他继续报三步，但走位和材料准备明显更从容，返工率降了下来。

有意思的是，他后来带教一个新人，直接把"每步都要提前想三步"这个要求原封不动地搬到工地现场实操里，要求新人干活时也要一步步嘴上先报三步——结果新人干得更慢了，同一段工序花的时间反而比不报三步的时候更长。

### 概念解析

**概念名称**：MTP 多 Token 预测（Multi-Token Prediction），属于大模型预训练效率问题域。

**学习卡片**
- 核心张力：训练时只要求"预测紧接着的下一步"（信号单薄，但每轮练习快）vs. 训练时要求"同时预测未来好几步"（每轮更慢，但每次练习给出的反馈信号更丰富，逼出更长远的规划能力）。
- 关键不变量：这种"多步预测"的价值发生在训练阶段、用来塑造能力，实际执行（部署/推理）阶段该做的事情不会变——还是一步一步来，只是每一步背后的判断变得更周全了。
- 触发条件：处于训练/预训练阶段，且任务存在需要"计划性"的长程结构（比如后续步骤会互相影响）时，多步预测能提供比单步预测更丰富的梯度信号。
- 常见误解/失败模式：把训练时用来塑造规划能力的方法，直接原样搬到实际执行/推理阶段去用，误以为这样能让实际执行也变快——实际上这是训练技巧，不是推理加速技巧，搬到执行阶段反而增加了不必要的开销。
- 非适用边界：如果不打算重新训练/重新塑造能力（比如模型已经训练好，只是要部署上线），MTP 这套思路没有意义；想要加速的是"已训练好模型的实际生成速度"，需要用投机解码这类推理时技术，而不是 MTP。

**一句话核心定义**：MTP 让模型在训练时同时预测未来多个 Token 而不只是紧邻的下一个，用更丰富的训练信号提升训练效率和模型的长程规划能力，但本身不加速实际推理生成速度。

**它试图解决的问题**：标准的"只预测下一个词"每一步只给模型一个训练目标，信号比较单薄；如何在不改变模型实际生成方式（仍是一步步生成）的前提下，让训练阶段给出更丰富、更有"前瞻性"的反馈信号，从而学到更强的规划能力。

**故事元素映射**：
- 学员 = 正在训练的模型。
- 第一批场地只报一步 = 标准的下一词预测（NTP），每步只有一个训练目标。
- 第二批场地报三步、教练三步都打分 = MTP，每个位置同时对未来 k 个 Token 都给出训练信号。
- 报三步训练完后，独立带班时走位更从容、返工率降低 = MTP 训练出的模型在需要规划的任务（代码生成、数学推理）上表现提升。
- 独立带班时不需要继续嘴上报三步，还是一步步做 = 推理阶段模型依然是逐 Token 生成，MTP head 通常在推理时关闭，能力已经内化进权重本身。
- 把"报三步"直接搬进现场实操反而更慢 = 把训练技巧误用成推理时技巧，实际执行速度不升反降。

**比喻边界**：故事把"多步预测"简化成了教练打分这种外部监督，真实的 MTP 是模型自身额外增加几个预测头，用辅助损失和主任务一起训练，训练效率的提升幅度也并非固定的"3倍"，实测通常在 1.3-2 倍之间，且不同任务受益程度不同；此外故事没有体现 MTP head 在某些场景（如投机解码）中被直接复用为草稿模型的情况。

**非适用例**：如果一个模型已经训练完成、现在要做的只是"部署上线、让它生成得更快"，这时候该考虑的是投机解码等推理时加速技术，而不是回头给它加 MTP 训练目标——MTP 解决的是训练阶段"学得好不好"，不是推理阶段"跑得快不快"。

**现实例子**：DeepSeek-V3 在 14.8T token 的预训练中使用 MTP 作为辅助训练目标，让模型收敛更稳定、更快，推理时关闭 MTP head 使用正常主干；其 MTP head 后续还被直接复用为投机解码的草稿模型，一举两得。

### 检验问题

1. 理解检验：学员在独立带班时不再被要求嘴上报三步，但表现依然比只练过报一步的人更好，这说明报三步训练起到的作用是什么？
2. 迁移检验：如果有人说"给一个已经上线跑得好好的模型，实时推理时也让它同时预测未来三个词，这样应该能让生成更快"，结合这个故事，你觉得这个想法哪里站不住脚？

## 核心思路

```
标准 NTP（Next-Token Prediction）：
  输入：[x₁, x₂, x₃, x₄]
  预测：[x₂, x₃, x₄, x₅]
  每个位置只有 1 个训练目标

MTP（Multi-Token Prediction，预测未来 k 个 Token）：
  输入：[x₁, x₂, x₃, x₄]
  位置 1 预测：[x₂, x₃, x₄]（同时预测 3 个）
  位置 2 预测：[x₃, x₄, x₅]
  ...
  每个位置有 k 个训练目标

结果：
  同样的数据量 → k 倍的梯度信号
  或：达到同等质量只需 1/k 的数据
```

## 两种不同的 MTP 实现

### 1. DeepSeek-V3 的 MTP（辅助训练目标）

```
DeepSeek-V3（论文85）的做法：
  主干模型：正常 NTP
  辅助头：额外的 MTP head 预测后续 D 个 Token
  训练时：主损失 + MTP 辅助损失
  推理时：关闭 MTP head，使用正常主干
  
目的：提升训练效率（更好的梯度信号）
    → 模型对未来 D 步都有"计划"
    
效果：训练更稳定，收敛更快
应用：V3 训练 14.8T tokens 时的辅助策略之一
```

### 2. 推测解码（Speculative Decoding）中的 MTP

```
另一个应用方向：加速推理（不是训练）

标准推理：
  主模型（大）每步生成 1 个 Token → 慢
  
推测解码：
  草稿模型（小）快速生成候选序列（多个 Token）
  → 主模型一次性验证/修正
  → 接受则免费得到多个 Token
  
MTP 可以作为内置"草稿模型"：
  主模型有 MTP head → 直接预测后续 k 个 Token
  主模型下一步验证这 k 个 Token
  → 不需要独立的草稿模型
  → 延迟降低（batch verify 比 sequential generate 快）
  
但注意：MTP 的输出质量 < 等参数量的独立草稿模型
```

## TST：Token 叠加训练（Token Stacking Transformer）

```
论文141 的 TST 是另一种 MTP 变体：

核心区别：
  标准 MTP：独立预测头，每个头对应一个未来位置
  TST：将未来 k 个 Token"叠加"为一个宏 Token
    → 单个预测头，但输出代表多个 Token
    
优势：
  计算更高效（减少 forward pass 次数）
  更紧凑的表示

类比：
  标准 MTP = 一个人同时回答 3 道题（3 套答案）
  TST = 一个人给出一个包含 3 道题答案的"套餐回答"
```

## 训练效率的量化

```
理论分析：
  NTP：每个 Token 贡献 1 个梯度信号
  MTP（k=4）：每个 Token 贡献 4 个梯度信号
  → 理论上训练效率提升 4x
  
实际效果（经验数据）：
  并非简单的 4x（后续 Token 的梯度信号相关性更高）
  实际提升通常在 1.3-2x 之间
  不同任务受益程度不同：长程依赖任务提升更大

代价：
  每步多 k-1 个预测头的计算
  显存需求略增（k 个 loss head）
  通常 k=2-4 是甜点区间（再多收益递减）
```

## 为什么 MTP 能提升能力？

```
直觉解释：
  NTP："预测下一步" → 局部视野
  MTP："同时预测未来 k 步" → 需要规划

例子（代码生成）：
  NTP：选择当前最合理的 Token
  MTP：需要考虑"写这个 Token 后，接下来 k 步能写出什么？"
  → 更长远的规划能力

研究发现（Meta 2024）：
  MTP 训练的模型在需要"计划"的任务上提升更显著：
  - 算法任务（需要步骤规划）
  - 代码生成（需要考虑后续语法结构）
  - 数学推理（需要预设推理路径）
```

## PM 视角：什么时候用 MTP？

| 场景 | 建议 |
|------|------|
| **预训练阶段**（自己训模型）| 强烈推荐，训练效率提升显著 |
| **SFT 微调**（少量数据）| 谨慎，数据量少时 MTP 信号可能过强 |
| **推理加速**（生产部署）| 考虑推测解码而非 MTP |
| **已有模型，不重训**| MTP 没有意义（是训练技巧，不是推理技巧）|

## 与推测解码的协同

```
两者都旨在提升"每单位计算生成的 Token 数"，但：

MTP（训练时）：
  提升模型的"规划能力"和训练效率
  产物：更强的模型权重

推测解码（推理时）：
  加速生成速度
  产物：相同质量下更低的延迟

组合：
  用 MTP 训练得到的模型，其 MTP head 可以直接当草稿模型用
  → DeepSeek-V3 就是这样：MTP head 在推理时可作为投机解码的草稿
```
