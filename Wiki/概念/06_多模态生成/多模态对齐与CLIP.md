# 多模态对齐与 CLIP

## 一句话定义

多模态对齐是指把图像（或其他非文本模态）编码成向量后，让这些视觉向量能被语言模型当作"和文本 token 同一空间里的信息"来处理；CLIP 是实现这种对齐最常用的视觉编码器，它通过对比学习让匹配的图文对在向量空间里相似度最大化，从而学到一个和语言语义对齐的视觉表征。

## 寓言学习

### 寓言正文

电商平台要上线一套图文一致性审核系统，用来判断卖家上传的商品实拍图，和卖家自己填写的商品标题描述，说的是不是同一件东西。运营团队没有让系统去死记"这张图对应哪些词"，而是喂给它海量的训练素材：大批"商品图+对应正确标题"的配对，同时也喂了大量"商品图+随便拿别的商品乱配的错误标题"当反例。训练目标很简单——系统给"正确配对"打出的相似分要尽量高，给"随便乱配对"打出的相似分要尽量低，至于图片里具体哪个像素是什么颜色、标题用了什么措辞，系统完全不关心。

训练完之后，系统面对一张全新上传的图片，能直接给出一个和文字标题"放在同一把尺子上"的表示，不需要先把图片翻译成一段文字描述再去比对关键词，两种完全不同格式的东西可以直接拿来算相似度。

有个卖家上传了一张构图精致、色调高级的图，配的标题却写着"厨房抹布三条装"——系统给这组图文打出的相似分很低，判定图文不符，标记了警示。运营复核时一开始也犯嘀咕：这张图明明拍得很讲究，构图和色调都挑不出毛病，怎么会被判不符？细看之后才发现，图里拍的分明是一份精致摆盘的甜品，压根不是抹布——系统的判断其实是对的，它比对的从来不是"这张图拍得好不好看"，而是"这张图内容和这句话说的是不是一回事"。

### 概念解析

**概念名称**：多模态对齐与 CLIP（用对比学习让图文向量在同一语义空间里可比较），属于多模态表征学习问题域。

**学习卡片**
- 核心张力：想让图像信息能被"当文字一样处理"、直接送进同一套后续系统 vs 图像的原始形式（像素）和文字的原始形式（词）完全是两套不兼容的表示，无法直接放在一起比较。
- 关键不变量：转换后的表示，必须保证"内容匹配的图文对"相似度足够高、"内容不匹配的图文对"相似度足够低——这个相对关系才是让图像表示"读懂语义"的关键，不是转换本身还原图像细节的精细程度。
- 触发条件：需要让一个原本只训练过文字的系统也能处理图像等其他模态输入，且不想先把图像转成文字描述再处理（那样会丢信息、也绕远路）。
- 常见误解/失败模式：以为图文相似度分数和"这张图本身拍得好不好、精不精致"有关，实际上系统只关心图像内容和文字描述是不是指向同一件事，和图像的美观程度、拍摄质量无关。
- 非适用边界：如果任务根本不需要图像和文字互相比较或联合处理（比如纯粹的图像压缩、图像去噪，只关心图像内部保真度而不涉及和文字的语义比对），不需要这种"对齐到同一语义空间"的机制。

**一句话核心定义**：多模态对齐是把图像编码成向量，通过对比学习（让匹配的图文对相似度最大化、不匹配的图文对相似度最小化）训练出一个和文字语义对齐的表示空间，使图像信息能被当作和文字 token 同一空间里的信息直接处理；CLIP 是实现这种对齐最常用的视觉编码器。

**它试图解决的问题**：如何让一个只认识文字的系统也能"读懂"图像，并且图像和文字这两种完全不同格式的信息可以放在同一个体系里直接比较、直接一起处理，而不需要先把图像转成文字描述再绕一道弯。

**故事元素映射**：
- 喂给系统大批"商品图+正确标题"配对和"商品图+随便乱配标题"反例 = CLIP 用大量真实图文对做正例、随机/错误图文对做负例的对比学习训练方式。
- 系统只关心相似分高低、不关心具体像素或措辞 = 对比学习的优化目标只关注匹配对和不匹配对之间的相对相似度，不是逐像素还原或逐词复刻。
- 系统给出一个和文字标题"同一把尺子上"的表示 = CLIP 编码出的视觉向量和文本向量处于同一个语义对齐的空间，可以直接算相似度、直接送入 LLM 一起处理。
- 图拍得精致但内容是甜品、标题却写抹布，系统判不符 = CLIP 判断的是图像内容和文字语义是否一致，而不是图像的美观程度，纠正了"图拍得好=分数该高"的直觉误判。

**比喻边界**：故事把"相似分"简化成一个笼统的分数，现实中 CLIP 分别用一个图像编码器（如 ViT，把图像切成 patch 序列送入 Transformer）和一个文本编码器各自产出向量，再计算向量间的余弦相似度；故事也没有展现视觉向量如何被进一步投影到 LLM 的隐藏维度、和文本 embedding 拼接送入 LLM（如 LLaVA 架构里的跨模态投影步骤），这部分是对齐之后"怎么被下游系统使用"的延伸机制，不属于 CLIP 训练本身。

**非适用例**：如果任务是"把一张模糊的老照片修复得更清晰"，这只涉及图像内部的像素级还原，不需要判断这张图和某段文字是否说的是一回事，用不上对比学习这套"匹配对拉近、不匹配对推远"的对齐机制。

**现实例子**：LLaVA 架构里，CLIP 编码出的图像特征经过一个投影矩阵映射到和 LLM 相同的隐藏维度后，直接和文本 embedding 拼接送入 LLM 一起做自回归处理——图像并没有被先转换成文字描述再喂给 LLM，而是作为一段和文本等价的"视觉 token 序列"参与计算，这正是当前主流图文理解模型的通用范式。

### 检验问题

1. 理解检验：故事里的审核系统为什么会把"拍得很精致的图"判定为和"厨房抹布三条装"这个标题不符？它判断相符与否依据的到底是什么？
2. 迁移检验：如果要用类似 CLIP 的思路，训练一个系统去判断"一段配音"和"一段字幕文本"是不是同一句话的两种表达，你觉得训练数据该怎么构造正例和反例？

## 核心机制

### Vision Transformer（ViT）：把图像变成一串向量

ViT 的思路很直接：把一张图像切成一系列小块（patch），每个 patch 展平后当作一个"视觉 token"，送进一个标准的 Transformer encoder 里处理——这样图像就被转换成了和文本序列结构一致的向量序列，可以复用 Transformer 的注意力机制去建模 patch 之间的关系。

### LLaVA 架构：完整数据流

LLaVA 是把 ViT/CLIP 编码器和 LLM 拼接起来做图文理解的代表架构，数据流可以拆成以下步骤（以 LLaVA 论文的设定为例，LLM 隐藏维度 $D=4096$，CLIP 隐藏维度是 1024）：

1. **输入图像**：$[224, 224, 3]$ 的原始图像。
2. **patchify（切块）**：把图像切成固定大小的 patch 网格，得到 patch 序列，例如 $[256, 588]$（256 个 patch，每个 patch 展平成 588 维的原始像素向量）。
3. **linear projection（独立线性投影）**：对每个 patch 独立做一次线性映射，得到 patch embedding，例如 $[256, 1024]$。
4. **拼接 CLS token、加位置编码**：在序列前加一个 CLS token，并加上位置信息，得到 $[257, 1024]$ 的序列。
5. **CLIP encoder（24 层 Transformer encoder）**：这个序列送进 CLIP 的视觉编码器（24 层 Transformer），输出 CLIP 视觉特征，例如 $[256, 1024]$（通常去掉了 CLS token，只保留 patch 特征）。
6. **跨模态投影（projection）**：用一个投影矩阵 $W$，对每个 token 独立地把 CLIP 空间的 1024 维特征映射到 LLM 的 4096 维空间，得到视觉 embedding $[256, 4096]$——这一步是"对齐"发生的地方：视觉向量被投影到和文本 embedding 同一个维度空间。
7. **与文本 embedding 拼接**：视觉 embedding 和文本 embedding（$[N, 4096]$）拼接成一个完整序列 $[256+N, 4096]$。
8. **送入 LLM**：整个拼接后的序列作为输入，送进 LLM 的 Transformer 继续处理，LLM 因此可以在同一个注意力机制里同时"看到"图像 patch 和文本 token。

可以看到，图像并没有被转换成文字描述再喂给 LLM，而是作为一段和文本等价的"视觉 token 序列"直接参与 LLM 的计算——这是当前主流图文理解模型的通用范式。

### LLaVA-NeXT：动态分辨率

原始 LLaVA 受限于 CLIP 编码器固定的输入尺寸（比如固定切成 256 个 patch），无法很好处理高分辨率或宽高比特殊的图像。LLaVA-NeXT 的做法是：把一张高分辨率图像切成多个规则的裁切块（crop），每个 crop 分别单独送入 CLIP 编码器编码，再把各个 crop 的编码结果拼接在一起，作为最终的视觉 token 序列——本质上是用"多份固定尺寸编码"的组合去逼近对任意分辨率图像的编码能力，而不是让编码器本身支持可变输入尺寸。

### Qwen2-VL：用 2D-RoPE 替代固定位置编码

更早的方案（包括原始 LLaVA）用的是**可学习的绝对位置编码**：为固定数量的 patch（比如 256 个）各自学一个位置向量，形状是 $[256, D]$。这种做法的根本限制在于——位置编码的数量是在训练时就固定死的，所以模型也被限制只能处理与训练时 patch 数量一致的固定尺寸图像，换一个分辨率或宽高比就无法直接套用。

Qwen2-VL 的做法是**用 2D-RoPE 替代可学习的绝对位置编码**：patch 的切分大小仍然固定，但每个 patch 的位置不再靠查一张固定长度的位置编码表来获得，而是用它在图像里的行、列坐标 $(row, col)$，通过 RoPE 的旋转编码方式**动态生成**位置信息。因为 RoPE 是实时计算出来的、不依赖一张预先训练好的固定长度位置表，所以模型可以泛化到训练时没见过的任意分辨率和任意宽高比的图像，不再受"patch 数量必须和训练时一致"的束缚。（关于 RoPE 本身如何用旋转编码相对位置，见 [[Wiki/概念/01_架构技术/RoPE旋转位置编码]]——Qwen2-VL 的 2D-RoPE 正是把这套一维序列上的旋转位置编码机制，扩展到了图像的二维行列坐标上。）

### 当前范式总结

- **理解任务**（图像描述、视觉问答等）：用 ViT 类编码器（如 CLIP）提取图像特征，作为视觉 token 输入 LLM，走的是"编码-拼接-自回归"的路线。
- **生成任务**（文生图、图像编辑等）：目前主流用的是在像素空间（或其潜空间）运行的扩散模型，走的是完全不同的生成机制。

也就是说，"理解"和"生成"两类多模态任务，当前并不共享同一套底层技术路线——这也是为什么很多模型要么侧重理解、要么侧重生成，真正统一两者仍是活跃的研究方向（可参考 [[Wiki/概念/01_架构技术/多模态离散Token化]] 里"统一自回归多模态模型"这条尝试同时覆盖理解与生成的路线）。

### CLIP：对比学习是怎么训练出对齐表征的

CLIP 的训练方式是**对比学习**：给定大量图文对，模型分别用一个图像编码器和一个文本编码器把图片和文字都编码成向量，训练目标是让**匹配的图文对**（同一张图和它对应的正确文字描述）在向量空间里的相似度尽可能高，同时让**不匹配的图文对**（图片和一批随机/错误的文字描述）相似度尽可能低。这样训练出来的图像编码器，其输出向量天然和文本语义空间对齐——这正是它能被 LLaVA 这类架构拿来做视觉特征提取器的原因：CLIP 的视觉表征本身已经具备和语言对齐的语义结构，不是纯粹的像素统计特征。

## 为什么 AI PM 要懂这个

- **理解多模态模型能力边界从哪来**：一个模型能不能处理任意分辨率图片、能不能看清图片里的细节文字，往往不是"训练数据够不够"的问题，而是取决于用的是哪一代位置编码方案（固定绝对位置 vs 2D-RoPE）和分辨率处理策略（固定尺寸 vs 动态 crop）——这决定了产品能否支持用户上传任意尺寸/长图的场景。
- **判断"理解"和"生成"能力是否该用同一个模型**：目前理解走 ViT encoder、生成走扩散模型是两条不同的技术路线，如果产品需求同时要"看懂图"和"画出图"，要清楚这在当前主流架构下往往意味着两套不同的模型/模块，而不是一个模型天然就能双向打通。
- **评估视觉编码器选型**：CLIP 是否好用、是否需要换成更新的视觉编码器，核心要看它的对比学习训练数据和训练规模是否覆盖了产品要处理的图像分布——CLIP 的语义对齐质量直接决定了下游 LLM"看图"的理解上限。
