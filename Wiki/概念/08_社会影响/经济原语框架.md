# 经济原语框架（Economic Primitives Framework）

## 一句话定义

AI使用质量的5个基础测量维度——任务复杂度、技能水平、使用场景、AI自主度、任务成功率——可组合成更丰富的经济影响分析信号，比单纯的"AI做了什么任务"更有洞察力。

---

## 寓言学习

### 寓言正文

翻译公司运营负责人手上有一笔有限的自动化改造预算，要决定优先投给哪个环节。候选环节有两个：一个是"标准合同和产品说明书翻译"，听起来单一枯燥，但公司每天有大量人工工时耗在这上面，而且这类文本句式固定、术语统一，工具几乎每一单都能翻对；另一个是"文学和营销文案翻译"，听起来更有技术含量、能覆盖的文体也更广，但目前工具在这类任务上翻对的比例并不高，交出来的稿子大多还得译员从头改一遍。

负责人一开始被"文学营销翻译覆盖面更广"这个说法打动，差点把预算优先投给它。财务同事提醒他换个算法：把"这类任务本来占用多少人工工时"和"工具翻对的比例"这两个数字乘起来看，再比较到底能省下多少实际工时。

一算下来，标准合同说明书翻译虽然单一，但因为占用工时多、翻对比例又高，乘出来能省下的工时反而比"文学营销翻译"那边多得多——后者覆盖面广，但翻对比例低，乘出来的净收益远没有听上去那么大。

负责人最后把预算优先投给了标准合同说明书翻译，把文学营销翻译放到了第二期，等工具在这类任务上的准确率提升之后再重新评估。

### 概念解析

**概念名称**：经济原语框架（Economic Primitives Framework），属于AI经济影响测量问题域。

**学习卡片**
- 核心张力：判断一件事值不值得优先自动化，不能只看"能覆盖多少种任务类型"这个表面指标，要看"这些任务原来最耗时的部分，自动化之后真正能稳定做对的比例有多少"——覆盖广不等于真正省下的时间多。
- 关键不变量：真正的收益等于成功率乘以占用的时间比例（或加速倍数），两个因子缺一个都算不出真实收益；只看单一维度会系统性高估或低估价值。
- 触发条件：要在多个候选自动化场景之间做优先级排序，或者要给一个自动化项目算真实投入产出比时。
- 常见误解/失败模式：被"覆盖面广"这种听起来很厉害的指标误导，选中了看似能做很多事、但真正能稳定做对的比例很低、或者本来就不怎么耗时的任务去优先投入。
- 非适用边界：如果候选任务之间成功率和耗时占比都差不多，没有明显的"广而浅"vs"窄而深"的对比结构，这套有效覆盖率排序方法就用不上，直接按覆盖面排序也没问题。

**一句话核心定义**：经济原语框架用任务复杂度、技能水平、使用场景、AI自主度、任务成功率5个基础维度组合出"有效AI覆盖率=成功率×时间占比"这样的信号，比单纯看"AI能做多少类任务"更能反映真实的经济价值。

**它试图解决的问题**：避免被"覆盖面广"这类表面指标误导，找到自动化投入真正能兑现最大实际收益的场景。

**故事元素映射**：
- 标准合同说明书翻译占用工时多、翻对比例高 = 有效AI覆盖率高的场景（类比原文中的数据录入：低任务复杂度、高成功率、高时间占比）。
- 文学营销翻译覆盖文体广但翻对比例低 = 覆盖率看起来高但有效AI覆盖率低的场景（类比原文中的微生物实验室：任务覆盖广但成功率低）。
- 财务同事提醒把两个数字乘起来看 = 有效AI覆盖率=成功率×时间占比的计算方法。
- 负责人改变预算优先级，把文学营销翻译放到第二期 = 用有效覆盖率而非表面覆盖率做优先级排序的决策应用。

**比喻边界**：故事把5个经济原语简化成了"耗时占比"和"成功率"两个维度，真实框架还包括任务复杂度、人机技能匹配度、AI自主度这三个维度，且这些维度是通过让AI对匿名对话做结构化自分类得到的，并非人工估算；此外故事没有涉及原始加速倍数需要扣除返工成本才能得到实际生产率增益（如1.8pp/年理论上限修正为1.0pp/年实际估算）这一层。

**非适用例**：如果两个候选场景的成功率和耗时占比其实差不多，没有明显的"广而浅"和"窄而深"之分，直接按覆盖的任务类型多少来排优先级也不会有太大偏差，不需要专门套用这套有效覆盖率计算。

**现实例子**：Anthropic经济指数V3报告发现，原始加速倍数需要扣除约35%的返工成本，才能得到真实的生产率增益（理论上限1.8pp/年修正为实际估算1.0pp/年）——这和故事里"文学营销翻译覆盖面看着广，但因为翻对比例低、还要大量返工修改，实际净收益没有看上去那么大"是同一个道理。

### 检验问题

1. 理解检验：负责人一开始为什么差点把预算投给了文学营销翻译？故事想让你看清"覆盖面广"和"真正省下的工时多"之间差的是哪一步计算。
2. 迁移检验：如果一家公司要在"客服常见问题自动回复"（覆盖问题类型少，但每天占用客服大量重复工时，工具回答准确率很高）和"个性化投诉处理建议"（覆盖场景更广，但工具建议经常需要人工大改）之间选一个优先自动化，结合这个故事，你会怎么排序，还需要补充确认什么数据？

## 5个原语（维度）

| 原语 | 测量问题 | 经济意义 |
|------|---------|---------|
| 任务复杂度 | 人工完成需要多少时间？ | 更复杂任务 → 更高加速效益但更低成功率 |
| 人/AI技能 | 理解对话需要的受教育年数 | 技能匹配程度 → 决定对哪类工人的影响 |
| 使用场景 | 工作 / 学业 / 个人 | 劳动市场影响主要来自工作场景 |
| AI自主度 | 给AI多少决策权 | 自主度↑ → 自动化程度↑ → 对劳动需求冲击更大 |
| 任务成功率 | Claude 是否成功完成任务 | 修正理论生产率估算（1.8pp→1.0pp/年） |

## 核心机制

```
为什么叫"原语"：
  - Simple：每个维度只测一件事
  - Foundational：可以叠加组合（如 有效AI覆盖率 = 成功率 × 时间占比）
  - Privacy-safe：通过让Claude分类匿名对话实现，不看原始文本
  
Claude自分类法：
  Anthropic 把匿名对话 transcript 喂给 Claude，
  让 Claude 回答结构化问题 → 生成5个维度的标签
  → 样本：每次报告分析100万条Claude.ai + 100万条API对话
```

## PM 决策指南

**选择AI切入场景时**：
1. 不要只看"任务覆盖率"（AI能做多少类任务）
2. 要看"有效AI覆盖率" = 成功率 × 时间占比（AI能成功做哪些最耗时的任务）
3. 数据录入（低覆盖率，高有效覆盖率）比微生物实验室（高覆盖率，低有效覆盖率）商业价值更高

**量化ROI时**：
- 原始加速倍数 × 任务成功率 = 实际生产率增益
- 1.8pp/年 理论上限 → 1.0pp/年 实际估算（扣除35%返工成本）
- 对话式产品（多轮反馈）的实际任务上限远高于纯API自动化

---

## 局限性

- 分类精度：Claude自分类，非精确测量，只能"方向性准确"
- 选择偏差：用户只带"觉得Claude能做好"的任务来 → 高估成功率
- 任务互补弹性难以测量：不知道人类是否会转移到AI无法做的任务上
