# AI 工作委托（AI Work Delegation）

> **一句话定义**：用户与 AI 的关系从"咨询"（问问题、获取建议）演进为"委托"（把整项工作交给 AI 自主完成）——这是 Agentic AI 时代最核心的范式转变。

## 寓言学习

### 寓言正文

区域主管以前带各家门店店长，方式是"店长遇到问题来问，我出主意"——怎么摆货、怎么定价，主意是主管给的，决定和动手都是店长自己的事。后来主管招了个新助理，这次不一样：助理不只是给建议，而是可以直接接手"整理一批门店的月度补货清单"这种完整任务，主管审核通过就直接下发执行，不用主管自己再动手排一遍。

刚开始，主管把助理交上来的每一张清单都从头核对一遍，谈不上省多少事。后来他发现，门店里那些走固定公式算的常规品补货量，助理算得又快又准，可以少抽查、批量放行；真正该盯着的，是那些没有固定公式、需要临场判断的门店——比如刚开的新店，或者周边突然施工影响了客流的门店。主管的工作重心，从"自己算清单"变成了"设计一套抽查规则：多快抽查一次、重点抽查哪几家"。

促销季那波，助理一口气接手了平时三倍量的门店清单。主管图省事，沿用了平时的抽查比例，没有跟着任务量一起放大自己的核验精力。结果这批清单里混进去的错误没能及时被挡住，好几家门店因为补货量算错，要么断货要么积压。

复盘的时候主管才想明白：助理这次算得并不比平时差，问题出在自己这边——任务量翻了三倍，他核验的强度却还停在原来的水平。是他没跟着放大核验，不是助理没做好。

### 概念解析

**概念名称**：AI工作委托（AI Work Delegation），属于Agentic AI/组织协作问题域。

**学习卡片**
- 核心张力：把"给建议"换成"直接把整件事交出去做"，效率能大幅提升，但风险的性质也跟着变了——从"自己做错了自己担"，变成"要不要相信别人交回来的东西就直接用"；真正卡住上限的，不再是"对方能不能干"，而是"我核对不核对得过来"。
- 关键不变量：交出去的工作规模越大，配套的核验能力必须同步放大，否则规模放大暴露出来的错误量也会跟着放大——委托带来的收益和监督负担是同步增长的，不会只放大收益那一边。
- 触发条件：任务重复性高、有明确对错标准、可以被快速核验时，适合整体交出去自主完成；任务需要临场判断、审美取舍或涉及敏感人际决策时，不适合。
- 常见误解/失败模式：只盯着"交出去省了多少自己动手的时间"，没有同步建起"怎么快速判断对方交回来的东西靠不靠谱"的能力和规则，结果是量上去了，错误也跟着批量产生。
- 非适用边界：如果一件事本身没有明确的"做得对不对"的判断标准（比如纯审美偏好、需要临场社交分寸的沟通），交出去之后没法核验，这套委托框架就不适用。

**一句话核心定义**：AI工作委托是用户与AI的关系从"咨询建议"演进为"把整项工作交给AI自主完成、人工只负责监督"的范式转变，其价值等于委托任务规模乘以执行质量再乘以人工监督效率，三者缺一不可。

**它试图解决的问题**：当AI能力已经不再是瓶颈时，如何设计一套匹配委托规模的监督/核验机制，避免"委托得多、错得也多"的量增质降局面。

**故事元素映射**：
- 从"店长来问、主管出主意"到"助理直接接手整批清单" = 从咨询关系向委托关系的转变。
- 固定公式的常规品补货量可以少抽查、批量放行 = 高重复性、可验证性强的任务适合高比例委托。
- 新店/施工影响客流这类门店需要重点抽查 = 需要临场判断、缺乏固定标准的任务不适合直接批量委托。
- 促销季任务量翻三倍但抽查比例没跟着放大导致批量出错 = 委托规模放大后人工监督效率没有同步跟上，成为真正的瓶颈。

**比喻边界**：故事把"人工监督效率"简化成了"抽查比例"这一个可调参数，真实场景中监督效率还涉及任务状态追踪、并发任务管理、验证工具设计、人工干预点设置等更系统的产品能力，不是简单调高抽查频率就能解决。

**非适用例**：如果主管要助理决定"这家门店的装修风格该走什么调性"，这类涉及审美判断、没有统一对错标准的任务，即使助理执行得再快再省事，也很难通过"抽查核验"来判断好坏，这不属于适合整体委托的任务类型。

**现实例子**：Codex 2026上半年的实证数据显示，OpenAI内部研究员的月产出通过委托提升了50倍，法务提升了13倍，但同时10%以上的用户需要每周同时管理3个以上的并发Agent任务——这说明委托规模扩大的同时，监督和任务管理能力也必须同步跟上，否则收益无法兑现。

### 检验问题

1. 理解检验：促销季那批清单出错，是因为助理这次做得比平时差吗？故事想让你看清真正出问题的环节是哪一个？
2. 迁移检验：如果一家公司决定把"客户合同的条款梳理"全部交给AI自动完成，只在合同金额超过某个阈值时才安排人工复核，结合这个故事，你觉得这套规则设计合理吗，还需要补充考虑什么？

## 咨询 vs. 委托

| 维度 | 对话 AI（咨询） | Agentic AI（委托） |
|------|--------------|-----------------|
| **用户行为** | "这个问题怎么解？" | "帮我完成这个任务" |
| **AI 角色** | 顾问 | 执行者 |
| **人工参与** | 用户做决定和执行 | AI 做决定和执行，人工监督 |
| **任务单位** | 单次对话轮次 | 完整工作流/项目 |
| **时间维度** | 实时对话 | 异步任务（分钟-小时） |
| **输出** | 建议、信息、草稿 | 完成的代码、文档、决策 |
| **代表工具** | ChatGPT、Claude Chat | Codex、Devin、Claude Agents |

## 实证数据（来自 Codex 2026 H1）

```
工作委托深化指标：
  ✓ 活跃用户 6 个月 5x 增长
  ✓ 10%+ 用户每周同时管理 3+ 并发 Agent
  ✓ 26.6% 使用可复用工作流（Skills）
  ✓ "8+ 小时人工任务"委托比例增长 10x

产出结果：
  ✓ OpenAI 研究员：月产出 50x（Nov 2025 → Jun 2026）
  ✓ OpenAI 法务：月产出 13x
  ✓ OpenAI 内部：Codex 占 AI token 总量 99.8%
```

## 委托经济学

### 价值创造新公式

```
AI 价值 = 委托任务规模 × 执行质量 × 人工监督效率
```

旧范式下，瓶颈是"AI 能力"。
新范式下，AI 能力已不是瓶颈，**人工监督效率**成了新瓶颈。

### 委托收益曲线

```
产出增长倍数
  50x ┤           ✦ 研究员（大量重复性研究任务）
      │
  13x ┤      ✦ 法务（合同审查/条款梳理可高度委托）
      │
   5x ┤ ✦ 工程师（代码生成+调试已高度委托）
      │
   2x ┤ 一般知识工作者
      │
   1x ┤ 未采用 Agentic AI 的用户
      └─────────────────────────────→
        委托比例 × 工作流可重复性
```

**规律**：可重复性高 + 可验证性强的工作，委托收益越大。

## 价值最大化的工作类型

| 适合委托（高收益） | 不适合委托（收益低） |
|-----------------|------------------|
| 重复性研究整理 | 创意判断（品味/美感） |
| 代码实现（有规格） | 策略制定（需要情境感知） |
| 合同条款梳理 | 人际关系管理 |
| 数据分析（有结构） | 突破性创新思维 |
| 文档规范化 | 政治敏感决策 |

## 对 PM 产品设计的影响

### 功能优先级重排

```
对话 AI 产品的功能重点：
  1. 回答质量
  2. 对话流畅性
  3. 知识覆盖

委托 AI 产品的功能重点：
  1. 任务状态追踪（进行中？完成？失败？）
  2. 并发任务管理（同时管理多个 Agent）
  3. 验证工具（快速判断输出是否可用）
  4. 工作流模板（可复用的 Skills）
  5. 人工干预点（暂停、修改、恢复）
```

### 用户旅程重设计

```
对话 AI：
  用户输入 → AI 回复 → 用户阅读 → 结束

委托 AI：
  用户定义任务 → 委托给 AI → AI 执行（可能数小时）
       ↓                              ↓
  用户处理其他工作        中间可能需要确认/干预
                                     ↓
                          人工审查结果 → 接受/修改/拒绝
```

## 组织适应要求

委托模式要求组织具备：
1. **任务拆解能力**：把大工作拆成 AI 可执行的子任务
2. **AI 监管能力**：快速验证 AI 输出的领域专业知识
3. **并发协调能力**：同时管理多个 AI Agent 的工作
4. **流程再设计**：哪些工作交给 AI，哪些人保留决策权

**核心风险**：没有"AI 监管能力"的组织，委托 AI 会生产更多未经验证的错误输出——量增质降。
