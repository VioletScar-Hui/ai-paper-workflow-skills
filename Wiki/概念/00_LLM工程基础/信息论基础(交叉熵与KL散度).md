# 信息论基础(交叉熵与KL散度)

## 一句话定义
> 交叉熵衡量"用分布 q 去编码/预测真实分布 p 需要付出的期望代价"，它等于 p 自身的不可约不确定性（熵）加上 q 与 p 之间的差距（KL 散度）——语言模型训练时最小化的交叉熵损失，本质就是最大化模型给真实下一个 token 打出的对数似然。

## 寓言学习

### 寓言正文

眼镜店的库存柜台前，店长老符正在核对这个月的配镜等待时间报表。

店里镜片分现货和定制两类：常见度数，比如两百度、三百度的近视片，柜子里常年备着现货，顾客量完度数几分钟就能装好；冷门度数——高度近视、罕见散光组合——柜子里不备，得现场送去磨房现磨，快则一小时，慢则大半天。备货比例是老符按"全国近视人群的度数大致分布"估的：常见度数备得多，冷门度数备得少。

这套备货比例用了两年，等待时间一直过得去。这学期店门口新开了一所重点中学，附近学生扎堆过来配镜，老符发现现磨的比例突然飙升——尤其是八百度以上这一档，以前一个月来不了几个人，柜子里压根没备，现在几乎天天有人来，柜台前排队等现磨的队伍越拖越长。翻记录一算，原本只占预计比例百分之一的八百度以上顾客，这学期实际占了两成，这批人每次都要多等上小半天，等待时间涨得完全不成比例——不是多等一点点，是等其他常见度数的顾客好几倍。

老符原来那份"全国大致分布"的备货比例，跟这家店周围真实的顾客度数分布，压根对不上号。他把过去半年这家店真实卖出的度数记录重新统计了一遍，把备货比例整个换成"这家店自己的顾客实际都配什么度数"，八百度以上也备出几副现货。调整完，平均等待时间明显缩短了。

不过缩短是有底的——磨房现磨这道工序本身有个最短工时，哪怕店长把每种度数的备货比例调整到跟真实需求分毫不差，总有一小撮特别罕见的定制组合还是得现磨，这部分等待时间怎么调备货比例都省不掉，是这门生意本身摆脱不了的下限。

### 概念解析

**概念名称**：交叉熵（Cross Entropy）与 KL 散度（KL Divergence），属于信息论 / 机器学习损失函数设计问题域。

**学习卡片**
- 核心张力：真实需求（顾客实际的度数分布）本身带着一部分怎么都消除不掉的不确定性；而"用来做决策的预估分布"（备货比例）如果和真实分布不匹配，会额外多付出一份可以消除、也应该消除的代价——这两部分代价性质不同，却混在一起体现在同一个"总等待时间"里。
- 关键不变量：总代价 = 真实分布自身的不可约不确定性（熵）+ 预估分布偏离真实分布多付出的额外代价（KL 散度）；真实分布本身的不确定性是个不随预估调整而变的常数，能压的只有 KL 散度这一部分。
- 触发条件：需要提前按一个"预估的可能性分布"分配有限资源（库存、时长、算力），而资源分配后的代价取决于"实际发生的情况"和"预估时给这种情况分配了多少"之间的落差，且这个落差对"被严重低估的小概率情况"格外不成比例地惩罚。
- 常见误解/失败模式：以为只要预估分布"总体上看着差不多"就够了，忽略了对小概率但真实存在的情况分配得太少，代价会不成比例地暴涨（对应 $-\log q(x)$ 在 $q(x)$ 很小时急剧变大）；或者误以为总代价可以无限压低到 0，忽略了真实分布自身固有的不确定性下限。
- 非适用边界：如果要比较的不是两个"概率分布"，而是两个具体确定的数值（比如两次测量出的具体温度差多少），直接算误差/差值就够了，不需要引入这套"分布不匹配代价"的框架。

**一句话核心定义**：交叉熵衡量"按预估分布 q 提前分配资源，实际按真实分布 p 结算"时的期望代价，它恒等于真实分布自身无法再压缩的不确定性（熵 H(p)）加上预估分布偏离真实分布多付出的那部分代价（KL 散度）；因为熵是常数，想压低总代价，唯一能做的事就是让预估分布尽量贴近真实分布，也就是最小化 KL 散度。

**它试图解决的问题**：当需要提前按一个估计出来的概率分布去分配有限资源，而资源分配的合理性只能在"真实情况发生后"才能验证时，如何量化"估计得不准"到底要付出多大代价，以及这份代价里哪部分是可以通过改进估计消除的、哪部分无论如何都消除不了。

**故事元素映射**：
- 顾客实际配镜的度数分布 = 真实分布 $p$。
- 老符按"全国大致分布"定的备货比例 = 预估分布 $q$。
- 磨房现磨这道工序本身有的最短工时（哪怕备货比例完全准确也省不掉的等待） = 熵 $H(p)$，真实分布自身不可约的不确定性下限。
- 八百度以上顾客被严重低估比例后，等待时间不成比例暴涨 = $-\log q(x)$ 在 $q(x)$ 很小时急剧增大的直觉体现，这正是交叉熵/KL 散度对"小概率事件被低估"格外敏感的原因。
- 老符把备货比例换成"这家店真实卖出记录"后等待时间明显缩短，但没法降到 0 = 最小化交叉熵等价于最小化 KL 散度（把 $q$ 调得更贴近 $p$），但压不掉熵这部分固有下限。

**比喻边界**：故事里"等待时间"只是一个直觉化的代价载体，真实的交叉熵公式是对每种情况按 $-\log q(x)$ 精确计算、再按真实概率 $p(x)$ 加权求和，不是笼统地"感觉等久了"；另外，KL 散度是不对称的（$KL(p\|q)\neq KL(q\|p)$），故事没有专门体现这层不对称性——如果反过来问"按顾客实际分布去猜店长原来设想的分布，代价一样吗"，答案并不相同。

**非适用例**：如果老符要核对的是"某一天具体来了多少个顾客"这种确定性的计数问题（不是"顾客度数会怎么分布"这种概率问题），直接数数字、对总数就够了，不需要引入交叉熵/KL 散度这套框架——这类问题里没有"预估分布 vs 真实分布"这个结构。

**现实例子**：训练语言模型时，`F.cross_entropy(logits, targets)` 本质就是在算模型预测的下一个 token 概率分布 $q$ 与真实分布（one-hot，即"下一个 token 就是那一个"）之间的交叉熵；因为真实分布是 one-hot，交叉熵退化为负对数似然（NLL），训练 loss 能下降到多低，本质上也受限于训练数据本身固有的不确定性（比如同一段上文后面接哪个词本身就有好几种合理可能），不是越低越好、也不该指望降到 0。

### 检验问题

1. 理解检验：故事里如果老符从一开始就按"这家店真实历史记录"备货，而不是按"全国大致分布"备货，等待时间还会不会有下限？这个下限对应交叉熵公式里的哪一部分？
2. 迁移检验：一个短视频平台要提前按"预估的内容类型偏好分布"给推荐池分配各类视频的库存配额，如果某个小众但真实存在的内容类型被严重低估了配额，用户刷到这类内容时体验会怎样？这和"交叉熵对小概率事件被低估格外敏感"这个机制是不是同一回事？

## 核心机制

### 三个基本量的定义

**熵（Entropy）**：分布 $p$ 自身的不确定性，也是用最优编码 $p$ 编码 $p$ 自己时的期望比特数（或 nat 数，取决于 log 的底）。

$$
H(p) = -\sum_{x \in \mathcal{X}} p(x) \log p(x)
$$

含义：$-\log p(x)$ 是"看到 $x$ 有多意外"（$p(x)$ 越小越意外），$H(p)$ 就是这个意外程度按 $p$ 本身的概率加权平均。它是分布 $p$ 内在的、无法再压缩的不确定性下限。

**交叉熵（Cross Entropy）**：用分布 $q$（比如模型预测）去描述真实分布 $p$ 时的期望代价。

$$
CE(p, q) = -\mathbb{E}_{p}[\log q] = -\sum_{x \in \mathcal{X}} p(x) \log q(x)
$$

含义：期望是按真实分布 $p$ 取的（数据真实按 $p$ 出现），但代价 $-\log q(x)$ 用的是模型给出的概率 $q(x)$。如果 $q$ 和 $p$ 差得越远，$q$ 会给真实发生的事件分配偏低的概率，$-\log q(x)$ 就会偏大，交叉熵就偏高。

**KL 散度（KL Divergence）**：$q$ 相对 $p$ 多付出的"额外代价"，衡量两个分布的差异。

$$
KL(p \,||\, q) = \sum_{x \in \mathcal{X}} p(x) \left(\log p(x) - \log q(x)\right)
$$

含义：每个 $x$ 上，"用 $q$ 编码"比"用 $p$ 编码"多花的代价是 $\log p(x) - \log q(x)$，再按真实概率 $p(x)$ 加权求和。KL 散度不对称（$KL(p||q) \neq KL(q||p)$），且恒非负，当且仅当 $p=q$ 时为 0。

### 核心关系：交叉熵 = KL 散度 + 熵

$$
CE(p, q) = KL(p \,||\, q) + H(p)
$$

直觉：交叉熵里包含两部分代价——一部分是 $p$ 自身本来就无法消除的不确定性（熵，跟 $q$ 选得好不好无关），另一部分是因为用了 $q$ 而不是最优的 $p$ 而多付出的代价（KL 散度）。当 $q = p$ 时，KL 散度归零，交叉熵退化为熵本身——这是交叉熵能达到的下限。

证明（把 KL 散度的求和拆开）：

$$
\begin{aligned}
KL(p \,||\, q) &= \sum_{x} p(x)\left(\log p(x) - \log q(x)\right) \\
&= \sum_{x} p(x)\log p(x) - \sum_{x} p(x)\log q(x) \\
&= -H(p) + CE(p, q)
\end{aligned}
$$

移项即得 $CE(p,q) = KL(p||q) + H(p)$。

这个关系解释了为什么"最小化交叉熵"和"最小化 KL 散度"在训练模型时是等价的目标：$H(p)$（真实数据分布的熵）是常数，不随模型参数 $q$ 变化，所以对 $q$ 求最小化时，两者的梯度完全一致，只是差一个常数偏移。

### 交叉熵损失就是负对数似然

当真实分布 $p$ 是 one-hot（分类任务/语言模型里，"下一个 token 是什么"这个真实标签是确定的），交叉熵损失退化为负对数似然（NLL）：

$$
\mathcal{L}(x) = -\sum_{t=1}^{T} \log p(x_t \mid x_{<t})
$$

这里每个位置只有真实 token 对应的那一项 $p(x)=1$ 存活，其余项因 $p(x)=0$ 被消去，所以交叉熵就退化成"把模型对正确答案打的对数概率加负号求和"。这也是"交叉熵损失"和"负对数似然（NLL）"在实践中几乎总是同一件事的原因，也等价于最小化模型分布与真实（one-hot）分布之间的 KL 散度。

### 用 F.cross_entropy 实现语言模型损失时的位移（shift）对齐

语言模型是自回归的：位置 $t$ 的 logits 是用来预测位置 $t+1$ 的 token，而不是预测它自己。所以在算损失前，需要把 logits 和 labels 错开一位对齐：

```python
loss = F.cross_entropy(
    logits.view(-1, vocab_size),
    targets.view(-1),
    ignore_index=pad_idx
)
```

如果手动实现（而不直接依赖 `F.cross_entropy` 内部的位移逻辑），需要显式地把 logits 往前切掉最后一位、labels 往后切掉第一位：

```python
shift_logits = logits[:, :-1, :]      # 去掉最后一个位置（它没有下一个 token 可预测）
shift_labels = input_ids[:, 1:]       # 去掉第一个位置（它不是任何位置的预测目标）
logprobs = F.log_softmax(shift_logits, dim=-1)
token_logprobs = logprobs.gather(index=shift_labels.unsqueeze(-1), dim=-1).squeeze(-1)
# 构建 loss mask（比如把 padding 位置盖掉）
masked_logprobs = -token_logprobs * mask.float()
loss = masked_logprobs.sum() / mask.sum()
```

关键点：`shift_logits[i]`（第 $i$ 个位置的预测）要对应 `shift_labels[i]`（也就是原始序列里第 $i+1$ 个 token）。位移方向弄反是实现语言模型损失时最容易犯的低级错误之一。

## 为什么 AI PM 要懂这个

- 面试高频考点："交叉熵损失和 KL 散度什么关系""为什么语言模型训练用交叉熵而不是别的" —— 这是 LLM 训练最基础的数学语言，答不上来会直接暴露技术深度不足。
- 理解 loss 曲线的含义：训练 loss（交叉熵）下降到多少算合理，本质上和数据分布本身的熵（不可约下限）有关，不是越低越好、也不该指望降到 0。
- 理解模型对齐/蒸馏类工作的目标函数：很多任务（知识蒸馏、DPO 的隐式目标等）本质是在最小化某种 KL 散度，理解这个关系有助于看懂论文里"为什么这样设计 loss"。
- 排查训练 bug 的基础：logits/labels 位移错位是语言模型训练里最常见也最隐蔽的实现 bug 之一，知道这个机制有助于在评审技术方案或排查异常 loss 曲线时问对问题。
