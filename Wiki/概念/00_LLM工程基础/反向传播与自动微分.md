# 反向传播与自动微分

## 一句话定义
> 反向传播是链式法则在计算图上的系统化应用——把复杂的整体梯度分解成"每个节点的局部梯度 × 上游传来的梯度"，从输出往输入逐层传播；softmax + 交叉熵损失的梯度最终化简为一个极简结果 $\mathbf{p} - \text{one\_hot}(t)$，是这套机制最漂亮的例证。

## 寓言学习

### 寓言正文

镶嵌工坊的流水线上，一枚戒指要经过铸坯、镶钻、抛光三道工序才能送到质检员小艾手里。

以前的规矩是这样的：小艾试戴、掂重、对着灯看成色，心里有个大致印象"感觉还行"，就让三道工序的老师傅们"自己回去想想该往哪调"。结果谁都说不清具体该调多少——铸坯老师傅以为是自己模具的问题，抛光老周以为是自己力度的问题，各自猜着调整，这一批反而比上一批更参差。

小艾后来改了规矩：每次质检必须先给出一个具体的总分（比如这批"成色偏差 3 分"），而不是一句模糊的"感觉还行"。有了这个唯一确定的总分，才能顺着生产链条往回拆解——先看抛光这道工序对总分的敏感度有多大（抛光力度变化一点，总分会跟着变多少），把"总分该往哪调、调多大"乘上这个敏感度，就是该反馈给抛光老周的具体调整信号；老周拿到这个信号后，再往前一道，乘上铸坯环节对抛光输入的敏感度，继续往上一级传。

抛光这道工序还有个特殊的地方：老周抛完的半成品，同时会被送去两条独立的检验线——一条测外观光泽，一条测成品重量是否达标。两条检验线各自会根据自己那条线的结果，给老周发一条"你这道工序该往哪调"的意见。头一次这样运行时，小艾只把外观线的意见转给了老周，忘了把重量线的意见也算进去，结果老周按外观线的意见调整后，重量又超了标——两条线的意见都得加总起来，才是老周真正该收到的完整反馈，只听一条线的意见是不完整的。

调整信号一路往回传，传到铸坯环节的模具设置时就"到头了"——这个调整量会被记下来，用来决定下次开模具时具体调多少，但不会再继续往上游传给供应原料的矿场，因为矿石本身的成色不是这条生产链能调的"旋钮"。

### 概念解析

**概念名称**：反向传播（Backpropagation）与自动微分（Automatic Differentiation），属于神经网络训练 / 梯度计算问题域。

**学习卡片**
- 核心张力：最终的"好坏评价"只在生产链条的最后一环才能给出，但真正需要调整的是链条前面每一道工序各自的参数——如何把最后一个总评价，精确拆解成"每道工序各自该调多少"，且拆解的力度要考虑每道工序自己对下一环的敏感程度。
- 关键不变量：往回传给某一环的调整信号 = 从下一环传回来的调整信号 × 这一环自身"输出对输入有多敏感"（局部梯度）；如果一环的产出同时被多个下游环节使用，往回传的调整信号要把各下游环节的意见加总，而不是只取其中一个。
- 触发条件：一个多阶段的计算/生产过程有一个（且只能有一个）最终的标量总评价，需要沿着这个过程往回，把"总评价该怎么调"分解成每个中间阶段各自的调整量。
- 常见误解/失败模式：以为可以直接凭"大致印象"往回反馈，而不落到一个具体、单一的总分上——反向传播必须从一个标量开始，多个并列的评价没法直接同时往回拆解；另外容易漏掉"一环产出被多处使用时要把多路意见加总"这一步，只听其中一条线的反馈会导致调整不完整、甚至互相矛盾。
- 非适用边界：如果某个环节的产出后续根本没有被继续加工、评价（比如原料本身不是这条链上可调的参数），就不需要（也没法）把调整信号继续往它那里传——它是这条链的"起点"而不是可调节点。

**一句话核心定义**：反向传播是把最终的一个标量总评价，沿着计算/生产链条从后往前逐环拆解——每一环拿到的调整信号，等于下一环传回来的调整信号乘以自己"输出对输入的敏感度"，如果一环的产出被多个下游同时使用，则要把多路传回的信号加总。

**它试图解决的问题**：当一个复杂系统由很多相互串联、甚至有分叉复用的中间环节组成，而系统好坏只能在最后统一评价一次时，如何精确、系统地算出"每个中间环节各自该往哪个方向调、调多大"，而不是靠每个环节各自模糊猜测。

**故事元素映射**：
- 铸坯→镶钻→抛光的加工链条 = 神经网络的计算图，每道工序是一个节点/门。
- 质检员给出的具体总分 = 反向传播开始时的标量 loss。
- "总分该往哪调"乘以"抛光对总分的敏感度"传给老周 = 链式法则：下游梯度 = 上游梯度 × 局部梯度。
- 抛光产出被外观线和重量线两条检验线分别使用，两条线的意见要加总 = 分支/fan-out 节点的梯度求和：$\partial f/\partial y=\partial f/\partial a \cdot \partial a/\partial y+\partial f/\partial b \cdot \partial b/\partial y$。
- 调整信号传到模具设置就"到头了"、不再传给矿场 = 参数梯度（用于更新，是计算图的叶子节点）与激活值梯度（继续向前传播）的区别。
- 一开始只给"感觉还行"、无法精确拆解 = 反向传播必须从一个明确的标量开始。

**比喻边界**：故事里"敏感度"是一个直觉化的说法，真实的局部梯度是精确计算出来的偏导数（比如线性变换的局部梯度就是权重矩阵本身），不是模糊的经验判断；此外，真实计算图里节点数量可能有几十上百层，且"局部梯度怎么算"是由框架/程序员针对每种运算类型事先写好的规则（自动微分），不是每次都要人工重新推导，这一层"自动化"在故事里没有直接体现。

**非适用例**：如果生产链条上某一环出了问题（比如某台设备干脆坏了、完全不工作），需要的是直接维修或更换这台设备，而不是"沿着链条往回算调整信号"——反向传播解决的是"这些环节都在正常工作、但参数需要精细调整"的问题，不是排查硬件故障。

**现实例子**：训练语言模型时，softmax + 交叉熵损失的梯度最终化简成一个极简结果 $\mathbf{p}-\text{one\_hot}(t)$——也就是"模型预测的概率分布"减去"正确答案的 one-hot 分布"，这个差值正是最后一层往回传的第一个调整信号，之后再逐层乘以每一层各自的局部梯度（比如线性层的局部梯度就是权重矩阵 $W$ 本身），一路传回最前面的参数。

### 检验问题

1. 理解检验：如果老周抛光后的半成品只被一条检验线使用（不存在"外观线+重量线"两路分叉），往回传给他的调整信号计算方式会有什么不同？
2. 迁移检验：一个多环节的客服质检流程——话术环节、情绪安抚环节、问题解决环节依次进行，最后由客户打一个满意度总分。如果满意度总分要拆解成"每个环节各自该改进多少"，这个思路和反向传播像在哪里？如果某个环节（比如"话术环节"给出的措辞）同时影响了后面两个环节的表现，该怎么处理？

## 核心机制

### 导数、梯度、Jacobian、Hessian 的定义层级

- **导数**：$df/dx$ 衡量"改变 $x$ 一点点，$f$ 会变化多少"的敏感度。如果 $\partial f/\partial x = 3$，那么 $x$ 变化一个很小的 $h$，$f(x)$ 大约变化 $3h$。
- **梯度** $\nabla f$：多变量标量函数对所有输入的偏导数组成的向量。
- **Jacobian**：函数有 $m$ 个输出、$n$ 个输入时，是一个 $m \times n$ 的偏导数矩阵，第 $(i,j)$ 项是 $\partial f_i/\partial x_j$。
- **Hessian**：函数有 $n$ 个输入、标量输出时，是一个 $n \times n$ 的二阶偏导数矩阵 $H_{ij} = \partial^2 f/\partial x_i \partial x_j$，用来描述损失函数曲面的**曲率**。

### 链式法则

单变量复合函数：直接把导数相乘。例如 $x=3y, y=x^2$ 时：

$$\frac{dz}{dx} = \frac{dz}{dy}\frac{dy}{dx} = 3 \cdot 2x = 6x$$

多变量函数：把导数换成 Jacobian 矩阵相乘。神经网络里典型的链条：

$$\mathbf{x} \to \mathbf{z}=W\mathbf{x}+\mathbf{b} \to \mathbf{h}=f(\mathbf{z}) \to s=\mathbf{u}^\top\mathbf{h}$$

逐层求出每一步的 Jacobian 再依次相乘，就能算出任意两层之间的梯度关系，例如 $\partial \mathbf{h}/\partial \mathbf{x} = (\partial \mathbf{h}/\partial \mathbf{z})(\partial \mathbf{z}/\partial \mathbf{x})$。

### 几个常用的 Jacobian

- 逐元素激活函数 $\mathbf{h}=f(\mathbf{z})$ 的 Jacobian 是**对角矩阵** $\text{diag}(f'(\mathbf{z}))$——因为 $h_i$ 只依赖 $z_i$，不依赖其他 $z_j$，所以非对角项全为 0
- $\partial (W\mathbf{x}+\mathbf{b}) / \partial \mathbf{x} = W$
- $\partial (W\mathbf{x}+\mathbf{b}) / \partial \mathbf{b} = I$（单位矩阵）
- $\partial (\mathbf{u}^\top\mathbf{h}) / \partial \mathbf{u} = \mathbf{h}^\top$

### softmax + 交叉熵损失梯度的完整推导

设 logits 为 $\mathbf{z} \in \mathbb{R}^{\mathcal{V}}$，softmax 后的概率为 $p_i = e^{z_i}/\sum_j e^{z_j}$，交叉熵损失 $L=-\log p_t$（$t$ 是正确类别）。

**第一步**，$\partial L/\partial \mathbf{p}$：只有第 $t$ 个分量非零

$$\frac{\partial L}{\partial p_i} = \begin{cases} -1/p_t & i=t \\ 0 & \text{otherwise} \end{cases}$$

**第二步**，softmax 自身的 Jacobian $\partial p_j/\partial z_i$：

$$\frac{\partial p_j}{\partial z_i} = \begin{cases} p_j(1-p_j) & i=j \\ -p_j p_i & i \ne j \end{cases}$$

**第三步**，链式法则合并。因为 $\partial L/\partial p_j$ 只在 $j=t$ 时非零，求和式里大部分项直接消失：

$$\frac{\partial L}{\partial z_i} = \sum_j \frac{\partial L}{\partial p_j}\frac{\partial p_j}{\partial z_i} = -\frac{1}{p_t}\frac{\partial p_t}{\partial z_i}$$

对真实类别（$i=t$）：

$$\frac{\partial L}{\partial z_t} = -\frac{1}{p_t}\cdot p_t(1-p_t) = p_t - 1$$

对其他类别（$i \ne t$）：

$$\frac{\partial L}{\partial z_i} = -\frac{1}{p_t}\cdot(-p_t p_i) = p_i$$

合并成向量形式，得到一个**极简洁的结果**：

$$\frac{\partial L}{\partial \mathbf{z}} = \mathbf{p} - \text{one\_hot}(t)$$

也就是说，每个 logit 该往哪个方向调整、调整多大，就是"模型预测的概率分布"减去"正确答案的 one-hot 分布"——这也是为什么这个推导值得完整展示：它把一大串求和、链式法则最终压缩成一行几乎可以口算的公式。

### 计算图与"gate 通信"的直觉

把神经网络的计算过程画成计算图，每个节点看作一个"门"（gate）。门的划分本身是人为、图方便的——通常把局部梯度容易计算的部分划成一个门。

反向传播可以理解为：**各个门通过梯度信号互相"喊话"**，告诉彼此想让自己的输出增大还是减小、以及有多强烈（为了让最终 loss 下降）。核心规则：

$$\text{下游梯度} = \text{上游梯度} \times \text{局部梯度}$$

每个节点从后继节点收到"上游梯度"，结合自己的"局部梯度"（输出对输入的梯度），算出要往前传的"下游梯度"。

**分支节点的梯度求和**：如果 $y$ 同时被用于计算 $a$ 和 $b$，那么：

$$\frac{\partial f}{\partial y} = \frac{\partial f}{\partial a}\frac{\partial a}{\partial y} + \frac{\partial f}{\partial b}\frac{\partial b}{\partial y}$$

即两条路径对 $y$ 的贡献要相加，而不是取其一。

**常见运算节点的直觉**：
- `+` 门：把上游梯度原样分发给每一个加数
- `max` 门：把上游梯度"路由"给贡献了最大值的那个输入分支，其余分支拿到 0
- `×` 门：在下游梯度里把两个输入的系数互换

### 反向传播算法流程

1. 初始化输出梯度为 1（标量 loss 对自身的梯度）
2. 按**逆拓扑序**遍历计算图的节点：用后继节点已经算出的梯度，计算当前节点的梯度
3. 只要实现正确，前向传播和反向传播的大 $O$ 复杂度是同一量级

### 自动微分（autodiff）

梯度计算可以从前向传播的符号表达式**自动推导**出来，不需要人工手推整个表达式的导数：

- 每种节点类型（每个算子）需要知道两件事：怎么计算自己的输出；给定输出的梯度，怎么反推输入的梯度
- 局部梯度的计算规则是由框架/程序员**事先写好**的（例如 PyTorch 每个 `Function` 都要定义 forward 和 backward）

### 手工梯度检验（gradient checking）

对每个参数 $x$，用有限差分近似验证反向传播实现是否正确：

$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$

### 反向传播为什么必须从标量开始

`.backward()` 要对每个参数 $\theta$ 算出 $\partial L/\partial \theta$，这对每个参数而言只是"一个数"，这只有在 $L$ 是标量时才有意义。对标量调用 `.backward()` 时，PyTorch 会隐式地把反向传播的种子设为 $\partial L/\partial L = 1$。

### mean loss 的梯度 = 逐样本梯度的均值

若有逐 token 的损失 $\ell_1,\dots,\ell_N$，定义平均损失 $L = \frac{1}{N}\sum_i \ell_i$（mean reduction）。由导数的线性性质：

$$\frac{\partial L}{\partial \theta} = \frac{1}{N}\sum_{i=1}^{N} \frac{\partial \ell_i}{\partial \theta}$$

也就是说，对 mean loss 反传得到的梯度，**精确等于**对每个 $\ell_i$ 单独反传后取平均——这保证了"batch 越大梯度估计越稳定"这个直觉背后有严格的数学一致性。

### 激活值梯度 vs 参数梯度

上游梯度传递的对象始终是**激活值**；参数梯度是用来更新参数的，算出来之后就"到头了"，不再继续往前传，因为参数是计算图的叶子节点：

```
loss
 │ ∂L/∂y2 (激活值梯度)
 ▼
Layer 2 ──→ ∂L/∂W2 (参数梯度，存起来用于更新)
 │ ∂L/∂y1 (激活值梯度)
 ▼
Layer 1 ──→ ∂L/∂W1 (参数梯度，存起来用于更新)
 │ ∂L/∂x (激活值梯度 — 通常直接丢弃，因为输入不是需要更新的参数)
 ▼
input
```

### activation / gradient checkpointing 的内存-计算权衡

反向传播需要用到前向传播的中间激活值，标准做法是前向时把所有中间激活值都存下来，代价是内存随层数线性增长。

Checkpointing 用"只存一部分（checkpoint）+ 需要时重新算一遍"的思路，拿计算换内存：如果需要的激活值没有被存下来，就从最近的 checkpoint 开始做一次局部的前向重算。

对一个有 $N$ 层、切成 $K$ 段 checkpoint 的模型：

- 内存：从 $O(N)$ 降到 $O(K+N/K)$
- 反向计算量：从 $O(N)$ 升到 $O(N + N(K-1)/K)$

最优选择是 $K=\sqrt{N}$：内存降到 $O(\sqrt{N})$，反向计算量约为 $O(2N)$——也就是大约多花一倍的反向计算，换来内存需求降到平方根量级。

## 为什么 AI PM 要懂这个

- softmax + CE 梯度化简为 $\mathbf{p}-\text{one\_hot}(t)$，是理解"训练到底在优化什么"最直观的一幅数学画面，面试被问"梯度下降具体在调整什么"时可以直接用这个例子说清楚。
- activation/gradient checkpointing 的 $K=\sqrt{N}$ 权衡，直接对应训练大模型时"要不要开 checkpoint、怎么配置"这类真实工程决策，影响显存预算和训练速度，是评审训练方案时能问出的具体问题。
- mean loss 梯度等于逐样本梯度均值，是理解 batch size 如何影响梯度噪声、进而影响学习率设置的基础知识。
- 面试常问反向传播复杂度、为什么必须从标量开始等基础问题，答不上来容易被判定为"不懂底层"。
- 计算图 / gate 通信的直觉是理解框架（如 PyTorch autograd）、排查训练不收敛问题时的通用心智模型，本身不直接对应某个产品决策，是理解上层机制的必要基础。
