# 多层感知机与线性层

## 一句话定义
> 多层感知机（MLP）是至少含一个隐藏层的全连接前馈网络，其核心运算是"线性变换（矩阵乘法）+ 偏置 + 激活函数"；理解它在批处理（batch）下的形状规则、以及 PyTorch 里权重矩阵的存储惯例和反向传播推导，是理解一切神经网络工程实现的地基。

## 寓言学习

### 寓言正文

小型印刷工坊里，三台老式印刷机同时开工，印的是同一批定制请柬。

三台机器共用同一套调色配方——多少份红、多少份金、加多少份白，这份配方表挂在墙上，谁都照着这张表兑颜料。每台机器各自喂进自己那卷纸浆，兑出来的颜料印在纸上，再过一道显影处理：颜色浓度超过某个门槛的地方，才会被压出清晰的图案边缘，浓度不够的地方直接被冲淡成空白，不是简单的深浅渐变。

有一天负责验收的老板娘发现，三台机器印出来的请柬颜色都偏黄，得调整配方。这时候一个问题冒出来：配方是三台机器**共用**的同一张表，随便改一台机器自己那份颜料没用，必须综合三台机器各自反馈的"偏黄程度"，把三份反馈加在一起，才能算出这张公共配方表整体该往哪个方向改、改多少——三台机器各自用的原始纸浆消耗量、边角料这些各机器专属的记录，倒不用合并，各记各的账就行。

后来仓库管理员整理配方登记表时，把记录顺序从教科书式的"原料编号 × 输出颜色编号"，改成了"输出颜色编号 × 原料编号"。这么一改，日常调整配方时算出来的"建议改动量"表格，跟登记表本身的行列顺序天然对得上，不用每次都先把算出来的调整量倒个顺序才能填进去。这个顺序上的调换本身没花什么功夫——原始配方数据一点没动，只是换了个方向去读这张表。

### 概念解析

**概念名称**：多层感知机（MLP）与线性层的批处理机制，属于神经网络基础结构 / 工程实现问题域。

**学习卡片**
- 核心张力：一层网络的核心运算是"共享的权重"作用在"各自独立的输入样本"上——权重被所有样本共同使用，输入样本却彼此互不干扰，这两类角色在反向传播时该如何区别对待，是理解 batch 维度处理规则的关键。
- 关键不变量：对"所有样本共享"的对象（权重 $W$），batch 维度在梯度计算里要被求和/收缩（因为每个样本都在用同一份权重，任何样本的反馈都要计入对它的调整）；对"每个样本各自独立"的对象（输入 $X$），batch 维度要被保留、各自堆叠（因为一个样本的梯度不该影响另一个样本）。
- 触发条件：一次处理多个样本（batch），且这批样本共用同一套参数做同样的变换。
- 常见误解/失败模式：把"权重矩阵的存储顺序"当成数学本质的一部分，忽略了它只是一个工程实现上的记账习惯（比如为了让梯度形状和权重本身形状自然对齐），转置这类操作本身几乎不花代价，不涉及真正搬动底层数据。
- 非适用边界：如果每次处理只涉及一个样本、不存在"多个样本共用同一套参数"这个场景（没有 batch 维度），也就不存在"哪些维度该求和、哪些该堆叠"这个问题，直接按单样本的矩阵乘法处理即可。

**一句话核心定义**：MLP 的一层核心运算是"权重矩阵乘法 + 偏置 + 激活函数"；引入 batch 之后，反向传播时权重（所有样本共享）对应的梯度要把所有样本的贡献求和/收缩，而输入（每个样本各自独立）对应的梯度要按样本堆叠保留，权重矩阵在具体框架里的存储顺序则是一个不影响数学结果、但影响实现是否顺手的工程选择。

**它试图解决的问题**：如何把"单个神经元的加权求和"这个基本运算，系统性地扩展到"一层里有很多神经元、一次要处理很多样本"的批处理场景，并且在反向传播时正确区分"共享参数"和"独立样本"这两类角色各自该怎么处理 batch 维度。

**故事元素映射**：
- 墙上挂着的调色配方表 = 权重矩阵 $W$，被所有样本（机器）共享。
- 每台机器各自的纸浆 = 输入 $X$，每个样本各自独立。
- 显影处理（浓度不够的地方被冲淡成空白，超过门槛才显现图案） = 激活函数 $f$ 的非线性作用。
- 三台机器的偏黄反馈要合并起来才能改公共配方表 = 权重梯度需要把 batch 维度上所有样本的贡献求和/收缩。
- 各机器专属的纸浆消耗记录各记各的账 = 输入梯度按 batch 维度堆叠、各样本互不影响。
- 配方登记表顺序调换、数据本身没动、只是换个方向读 = PyTorch 里权重矩阵存成 $(n_{out}, n_{in})$ 而非教科书顺序，转置几乎免费（只改变读取方式，不拷贝数据）。

**比喻边界**：故事里"配方偏黄程度"是一个笼统的直觉说法，真实的权重梯度是通过精确的矩阵乘法 $X^\top(\partial L/\partial Z)$ 算出来的，不是简单地把三条反馈"加在一起"这么粗糙；此外，故事没有体现偏置项的梯度处理（同一个偏置被加到每个样本上，梯度也需要对 batch 维度求和，和权重的处理逻辑是一致的）。

**非适用例**：如果三台印刷机压根不共用同一套配方、各自用各自独立配好的颜料（没有共享参数这回事），那就不存在"合并反馈去调整一张公共配方表"这个问题，各台机器的调整完全独立处理即可——这种情况不属于 MLP 批处理这套机制要解决的场景。

**现实例子**：PyTorch 里 `nn.Linear(in_features, out_features)` 内部把权重存成 `(out_features, in_features)` 的形状，前向计算做的是 `X @ W.T`；训练时一个 batch 里 $m$ 个样本同时前向、反向，权重矩阵的梯度形状始终是 $(out\_features, in\_features)$（batch 维已经被求和掉），而输入的梯度形状是 $(m, in\_features)$（batch 维被保留），这是判断"某段自定义反向传播代码有没有写对形状"的最基础检查点。

### 检验问题

1. 理解检验：如果三台印刷机的配方表其实并不共用，各印各的、互不影响，那"三份偏黄反馈要合并起来"这一步在故事里还成立吗？为什么？
2. 迁移检验：一个促销活动里，客服团队所有坐席都在用同一套"话术模板"（相当于共享参数），但每个客户的具体聊天记录各不相同（相当于各自独立的输入）。如果要根据这次活动所有客户的反馈调整话术模板，"合并所有客户反馈"和"保留每个客户各自的聊天记录"这两件事，分别对应 MLP 批处理里的哪个规则？

## 核心机制

### 从单个神经元到矩阵乘法

单个神经元的计算：对输入做加权求和、加偏置、过激活函数

$$y = f(\mathbf{w}^\top \mathbf{x} + b)$$

其中 $\mathbf{x} \in \mathbb{R}^n$ 是输入向量（上一层的激活值），$\mathbf{w} \in \mathbb{R}^n$ 是这个神经元的权重（每条输入边的权重），$b$ 是偏置，$f$ 是激活函数。

一层有 $n_{out}$ 个神经元、接收 $n_{in}$ 个输入时，可以把所有神经元的权重向量堆叠成一个权重矩阵 $W \in \mathbb{R}^{n_{out} \times n_{in}}$（每一行是一个神经元的权重），偏置堆叠成 $\mathbf{b} \in \mathbb{R}^{n_{out}}$，于是整层的计算变成一次矩阵乘法：

$$\mathbf{h} = f(W\mathbf{x} + \mathbf{b})$$

### 引入 batch 维度

实践中我们总是一次处理 $m$ 个样本，而不是逐个算。这时把 $m$ 个输入排成矩阵的行，$X \in \mathbb{R}^{m \times n_{in}}$。按数学惯例，这时把 $W$ 换成 $\mathbb{R}^{n_{in} \times n_{out}}$（每一列是一个神经元的权重），整层变成：

$$H = f(XW + \mathbf{b})$$

其中 $\mathbf{b}$ 被广播（broadcast）成 $m \times n_{out}$ 的形状，加到每一行上。

### PyTorch 里 W 为什么存成 (n_out, n_in)，且做 X @ W.T

数学记号里线性层是 $XW+b$（$W$ 形状 $n_{in} \times n_{out}$），但 PyTorch 实际把权重矩阵存成 $n_{out} \times n_{in}$，前向计算时转置后再乘：

```
X @ W.T   # (m, n_in) × (n_in, n_out) = (m, n_out)
```

这个转置在 PyTorch 里几乎是免费的——转置只改变张量的 stride（读取步长），不需要拷贝底层数据。之所以这样存，是为了让 $W$ 的梯度自然算出来就是 $n_{out} \times n_{in}$，与 $W$ 本身的形状一致，不需要额外再转置对齐。

### 反向传播的形状推导

以数学记号 $Z = XW + b$（$W$ 是 $n_{in} \times n_{out}$）为例：

$$\frac{\partial L}{\partial X} = \frac{\partial L}{\partial Z} W^\top \quad (m,n_{out}) \times (n_{out},n_{in}) = (m,n_{in})$$
$$\frac{\partial L}{\partial W} = X^\top \frac{\partial L}{\partial Z} \quad (n_{in},m) \times (m,n_{out}) = (n_{in},n_{out})$$

偏置的梯度：因为同一个 $\mathbf{b}$ 被加到每一个样本上，所以每个样本都会给 $\mathbf{b}$ 贡献一份梯度，这些梯度需要累加起来：

$$\frac{\partial L}{\partial b_j} = \sum_{i=1}^{m} \frac{\partial L}{\partial z_{ij}} \cdot 1 = \sum_{i=1}^{m} \frac{\partial L}{\partial z_{ij}}$$

对应 PyTorch 实际实现（$Z=XW^\top$，$W$ 是 $n_{out} \times n_{in}$）的形状则是：

$$\frac{\partial L}{\partial X} = \frac{\partial L}{\partial Z} W, \qquad \frac{\partial L}{\partial W} = \left(\frac{\partial L}{\partial Z}\right)^\top X$$

### "共享张量走 contract，非共享张量走 stack" 的直觉

推导 batch 场景下的梯度，最省心的办法是：**先推导单个样本（无 batch 维）的 Jacobian**——这是干净的二维矩阵，然后再考虑 batch 维怎么处理。

- 单个样本时，$\partial L/\partial X$（这里 $X$ 是单个样本）就是 $\partial L/\partial Z \cdot W^\top$，形状是 $(n_{in})$
- 加入 batch 维后，我们知道输出形状应该是 $(m, n_{in})$
- 关键观察：$Z$ 的第 $i$ 行只依赖 $X$ 的第 $i$ 行（batch 内的样本互不干扰），所以直接把每个样本的梯度按行堆叠（stack）起来即可

由此得到一条通用规律：
- 如果某个张量是**所有样本共享**的（比如 $W$，同一份权重被每个样本使用），batch 维度在矩阵乘法里被**求和 / 收缩掉**（"contract"，即 matmul 把 batch 维当作参与乘法的内维）
- 如果某个张量对**每个样本各自独立**（比如 $X$，每行激活值只属于自己那个样本），batch 维度被**保留**，本质上是把每个样本各自的梯度矩阵乘法**堆叠**在一起（"stack"，matmul 把 batch 维放在最外层）

## 为什么 AI PM 要懂这个

- 面试高频考点："手推一个线性层的反向传播形状"，是筛选"真的懂底层"还是"只会调包"的门槛题。
- 理解 PyTorch 权重存储惯例（(n_out, n_in) 而不是数学教科书的 (n_in, n_out)），有助于读懂开源模型代码、判断算法同学的实现是否符合惯例。
- 权重矩阵形状直接决定参数量——这是估算模型参数规模、显存占用、训练/推理成本的最基础计算单元。
- 本身不直接对应某个产品决策，更多是理解 Transformer 结构、后续优化器机制的必要地基。
