# 任务视野（Task Horizon）

## 一句话定义

AI在某一任务时长处成功率恰好下降到50%——这个临界时长即"任务视野"，是衡量AI自主处理能力上限的核心指标，且随模型迭代持续扩展。

---

## 寓言学习

### 寓言正文

工坊里,学徒要独立完成一套带抽屉的书架——立柱、隔板、抽屉滑轨,一共二十几道工序。开工那天没人在旁边搭话,他自己量尺寸、画线、下料、打孔、装配,一步紧接一步往下走。

第一个小时,量的尺寸、打的孔位都对得上,拼起来严丝合缝。第二个小时,有一块隔板的开槽深了半毫米,他没停下来复核,照旧往下装——反正外观上看不出来。第三个小时,这半毫米被硬吃进了下一道工序:抽屉滑轨对齐时,轨道跟着歪了一丝,他又照旧拧上螺丝,继续装下一层。等整套书架快收尾时,最上层的抽屉推拉起来发卡,拆开一查,问题追根溯源全在第二小时那道深了半毫米的槽——可这时候立柱已经上胶,拆装的代价比重做还大。

工坊后来把交货记录摊开来看：只要学徒一个人闷头装到三个小时往后,拆出来返工的比例就过了一半;三个小时以内的活,基本都能一次交对。

后来老师傅换了个做法,不再全程守着,只是隔一阵子踱过来,看一眼手上的活,顺口问一句这一步打算怎么接下一步。学徒但凡哪个尺寸量岔了、哪道槽开深了,这一问的当口就露了馅,趁胶还没上、木料还没锁死,当场改过来,不会被拖到下一道工序里去。同样是学徒自己下料自己装,只是多了这几次顺路搭话,工坊记录里,他能扛住的独立组装时长从三个小时出头,一路撑到了将近一整个白天。

这几年工坊换过三茬学徒,一茬比一茬能扛的独立组装时间长——不是老师傅盯得比以前勤,是这批人手上的活本身就比上一茬更稳。

### 概念解析

**概念名称**：任务视野（Task Horizon），属于 AI 能力评估/Agent 自主执行问题域。

**学习卡片**
- 核心张力：纯自主独立执行（不需要人力持续投入，但误差会在长任务中不断累积、难以被中途纠正）vs 人在回路的中途确认（需要人参与、打断自动化的连续性，但能把偏差随时拉回，从而撑住更长的独立执行窗口）。
- 关键不变量：无论换到哪个场景，衡量的都是"某个时长点上，完成任务的比例恰好跌到一半"这一个临界值，而不是"能不能做"或"平均做得好不好"。
- 触发条件：任务本身足够复杂、需要连续多步骤操作，且步骤之间存在前后依赖（前面的小误差会传导进后面的工序），这个临界值才有意义；单步、无依赖的短任务不构成这个概念要考察的对象。
- 常见误解/失败模式：把"人在回路能撑到更久"误当成"模型本身变强了"——实际上是外部的中途纠错机制在起作用；或者把某一种协作模式（比如多轮对话）测出来的临界时长，直接套用到另一种模式（比如纯 API 自动化）上，忽视了两者纠错节奏完全不同。
- 非适用边界：如果任务各步骤互相独立、前面出错不会传导污染后面（比如每次都是从头开始的独立小任务批量处理），没有"误差累积"这个机制，就不存在一个随时长下降的临界点，这个概念不适用。

**一句话核心定义**：AI 在某一任务时长处成功的比例恰好下降到一半——这个临界时长即任务视野，是衡量 AI 自主处理能力上限的核心指标，且随模型迭代持续扩展。

**它试图解决的问题**：如何用一个具体、可比较的数字，衡量"这个 AI 能被放心地丢开手、独立处理多久的任务"，而不是笼统地说"它能不能做这类任务"。

**故事元素映射**：
- 学徒独立埋头组装、没人搭话 = 纯自动化单轮模式下，模型独自完成任务，没有中途反馈介入。
- 第二小时开槽深了半毫米没被发现、被后续工序继续吃进去 = 误差在长任务执行过程中累积，且越往后越难被发现和纠正。
- 三小时这个返工比例过半的分界点 = 该模式下的任务视野临界时长（对应纯 API 单轮模式下几小时量级）。
- 老师傅偶尔踱过来看一眼、顺口一问 = 人在回路的中途反馈/检查点，不是全程盯着，而是间歇性介入。
- 独立组装时长从三小时撑到接近一整个白天 = 引入中途反馈后，任务视野被大幅拉长（对应多轮协作模式下十几小时量级）。
- 几批学徒一批比一批扛得住更长时间，且是手上功夫本身更扎实而非盯得更紧 = 任务视野随模型自身能力迭代持续扩展，这个扩展独立于人在回路机制之外。

**比喻边界**：故事把误差累积具体化成一道尺寸误差被逐道工序放大，这是为了让机制可感知；但真实系统里，模型的误差来源更复杂（推理偏差、工具调用出错、上下文信息丢失等都可能是源头），不是单一一个可以量出来的尺寸问题，也不总是线性、单向传导的。此外，老师傅"偶尔问一句"在故事里显得很轻松，但现实中人在回路的介入本身也有成本和延迟，不是免费的纠错。

**非适用例**：如果工坊接的是一批一模一样的单个抽屉，每个抽屉独立下料、独立组装、互不依赖，某一个抽屉做废了不会影响下一个——这种情况下不管一个人闷头做多久，都不存在"越往后误差累积越容易翻车"的机制，谈不上有一条随时长下降的及格线，这就不是任务视野要衡量的情境。

**现实例子**：Anthropic Opus 4.5 在纯 API 自动化单轮模式下的任务视野约为 5 小时（METR 基准），而在 Claude.ai 的多轮对话辅助模式下，由于用户会提供中间反馈纠正小错误，任务视野被扩展到约 19 小时。

### 检验问题

1. 理解检验：故事里，同样是学徒一个人动手，为什么"老师傅偶尔看一眼问一句"能让他扛住的独立组装时长从三小时左右一路撑到接近一整个白天？这背后起作用的具体是什么机制？
2. 迁移检验：如果一家公司想用 AI 处理一批客户合同审核，每份合同的审核都是独立开始、独立结束、互不依赖，你觉得"任务视野"这个概念在评估这类工作时还适用吗？为什么？

## 核心数据（2025 下半年）

```
API 纯自动化模式（单轮）：
  Anthropic Sonnet 4.5: 任务视野 ≈ 3.5 小时
  Anthropic Opus 4.5:   任务视野 ≈ 5 小时（METR基准）

Claude.ai 对话辅助模式（多轮）：
  任务视野 ≈ 19 小时（用户参与使上限大幅扩展）

对比历史：
  2023年初期模型：几分钟
  2024：约30分钟
  2025下半年：3-5小时（API）/ 19小时（对话）
```

## 核心机制

```
为什么多轮对话远高于单轮 API？

单轮API：
  模型独自完成复杂任务 → 误差累积 → 3.5小时处跌破50%

多轮 Claude.ai：
  用户提供中间反馈 → 纠正小错误 → 防止累积偏差
  本质上是把"19小时复杂任务"拆成若干"1小时可控片段"
  
→ 人在回路（Human-in-the-loop）实质上是能力放大器
```

## PM 决策指南

**评估AI能否自动化某业务流程时**：
1. 估算该流程中最长的单次无人监督片段是多少小时
2. 若 < 2h：API 自动化基本可行（Sonnet 4.5+）
3. 若 2-5h：需要 Opus 4.5 级别 or 引入检查点
4. 若 > 5h：必须设计人工审核节点，或用对话模式替代纯自动化

**产品设计原则**：
- 不要把19小时的 Claude.ai 上限类推到 API 产品——两者模式完全不同
- 任务视野会随每代模型提升——产品规划中留有升级空间

---

## 局限性

- 选择偏差：用户带来的任务≠全部可能任务，成功率偏乐观
- 非因果：任务视野提高不一定意味着"模型变更聪明"，也可能是训练数据覆盖更广
- 行业特异性：同为"3小时任务"，法律/医疗/代码任务的成功率差异极大

## GLM-5.2 的分层任务分解（HLD）机制（论文143深化）

HLD（Hierarchical Layered Decomposition，分层任务分解）是 GLM-5.2 处理长视野 Agent 任务的核心机制：不依赖模型在单一上下文里隐式"记住"整个长目标，而是显式把目标拆解为可独立执行、可复用工具链的子任务序列。

```
decompose_task(goal) → 生成子任务树（如：读取仓库结构 → 理解代码逻辑
              → 规划实现方案 → 编写代码 → 编写测试 → 运行测试 → 审查提交）
    ↓
execute_plan：逐个子任务执行
    ↓
每个子任务 → 固定/规划出的工具调用序列（read_file / search_code / write_file / run_tests / git_commit …）
    ↓
子任务失败 → re-plan（最多重试2次）→ 仍失败则标记failed，影响上级计划
    ↓
trajectory：记录每个子任务的状态与工具调用历史
```

**HLD 与任务视野的关系**：
- HLD 把一个可能超过任务视野临界时长的长目标，拆解为若干各自处于视野内的短子任务，用"分解+纠错"降低误差累积速度——这与"任务视野"概念里"人在回路能大幅扩展可处理时长"的机制同源：HLD 用模型自身的分层规划代替人工中间反馈，是一种"自动化的人在回路"。
- **对训练侧的连锁影响**：HLD 产生的轨迹长度差异极大（子任务粒度不同），因此 GLM-5.2 放弃了要求组内同 prompt 比较的 GRPO，改用 Critic-based PPO + compaction（把超长轨迹切分为子轨迹训练）——分层分解不仅是推理时的执行策略，也决定了强化训练算法的选型。
- **局限**：分解质量依赖模型自身的规划能力，若遗漏子任务间的依赖关系（如先写测试后才发现需要先重构接口），会导致下游返工；HLD 本身不保证子任务粒度的最优性，粒度过细增加调度开销，过粗则退化为无分解的长上下文依赖。
