# Agentic 与 Agentive 的区分

> **一句话定义**：Agentic（代理性）系统通过外部工程化流程（脚手架、工具、工作流）完成任务；Agentive（自主性）系统的能力从自身内部涌现——当前所有 AI "Agent" 产品都是 Agentic，尚无真正 Agentive 系统。

## 寓言学习

### 寓言正文

无人便利店的补货机器人,只在收到总部系统下发的补货工单时才会动:货架传感器检测到某个货道库存低于阈值,生成一条工单,机器人接到工单,去后仓取货、上架、工单标记完成。它不会自己判断"最近降温了,雨伞可能要多备一点",如果总部系统这次忘了生成雨伞的补货工单,货架空了它也不会主动补——它没有一个持续存在、不依赖每次指令的"想法"。

店长后来做了个实验:把上个月的销售数据、天气数据都喂给机器人,让它自己"预判"接下来几天该多备什么。机器人确实能在数据里发现"降温后雨伞销量涨"这种相关性,并生成一条临时的备货建议——但这个判断只存在于这一次运行里,店长如果不把这份数据重新喂给它,第二天它照样只会老老实实等工单,不会自己记得"昨天算出来的降温规律"这回事,更不会在没被要求的情况下主动去查明天的天气预报。

真正让店长意外的是隔壁那家店的一件事:那家店的机器人在没有任何人下达指令、也没人喂给它当天数据的情况下,自己观察到连续三天雨伞销量异常,主动调整了自己此后每次判断库存阈值的标准,并且这个调整不需要重新训练或重新配置就一直保留了下去——这才是店长真正想要、却始终没在自己店里实现的那种机器人。

### 概念解析

**概念名称**：Agentic 与 Agentive 的区分,属于 AI Agent 理论/系统设计问题域。

**学习卡片**
- 核心张力：能力和目标由外部每次注入、系统只是被动响应(Agentic) vs 能力和目标从系统内部持续自发存在、能自我调节(Agentive)——当前所有产品都停在前者。
- 关键不变量：判断标准不是"系统看起来聪不聪明",而是目标和判断标准是否在没有外部重新指令/重新训练的情况下持续存在并能自我更新——这是两者之间不会因场景变化而改变的分界线。
- 触发条件：只要系统的每一次行动都依赖外部下发的具体指令或重新提供的数据,不管这次行动看起来多"智能",都仍属于 Agentic;只有当系统的目标和判断标准能持久存在并自我调节时,才谈得上 Agentive。
- 常见误解/失败模式：把"这次运行表现得很智能、能发现规律"误当成"这个系统有自己的持久目标";厂商用一次性展示的智能表现来包装成系统具备自主意愿。
- 非适用边界：所有当前可以购买、部署、上线使用的商业 AI Agent 产品,不管宣传语多么强调"自主决策",都还没有真正跨过 Agentive 的门槛。

**一句话核心定义**：Agentic 系统的能力来自外部工程化的脚手架和每次注入的指令,行为随指令结束而结束;Agentive 系统的能力和目标从内部持续存在并能自我调节,不依赖每次重新下发指令——目前所有 AI Agent 产品都属于前者。

**它试图解决的问题**：市面上很多产品把"能自动执行多步任务"包装成"自主决策",这个区分帮助辨别系统的能力究竟来自外部工程设计,还是真正来自系统内部持久的自我驱动,避免把工程能力误判成自主意愿。

**故事元素映射**：
- 补货机器人只在收到工单后才行动,总部忘了下工单它就不会补货 = Agentic 系统:目标由外部每次注入,没有持久的内在目标。
- 喂数据后机器人能算出临时备货建议,但第二天不喂数据就不记得 = 即便一次性表现出"预判"能力,只要判断不能持续存在并自我更新,依然是 Agentic。
- 隔壁店机器人主动观察、自主调整库存阈值判断标准,且调整持续保留 = Agentive 的核心特征:持久的内在判断/目标,能自我调节,不依赖外部重新配置。

**比喻边界**：故事把"持久目标"简化成了"记住一个调整后的阈值",但现实中 Agentive 系统被期望具备的远不止"记住一个数字"——论文提出的 GIC 架构要求系统有独立的世界模型做前瞻规划、有能自我更新的身份认知、能自主判断何时用快思考何时用慢思考,这是一整套目前尚无实现的理论框架。

**非适用例**：如果某个补货机器人被设置成"每天固定时间自动重新读取一遍最新销售数据并更新阈值",这看起来"不需要人天天下指令",但本质上仍然是外部预设的固定流程在驱动,判断标准的更新逻辑还是工程师写死的规则,不是系统自己发现、自己决定要不要调整——这依然属于 Agentic,不能仅凭"不用人天天操心"就归为 Agentive。

**现实例子**：当前的 Claude Code、Cursor 这类编程 Agent 依靠工具调用、提示词工程和固定的计划-执行流程完成任务,一旦超出预设的任务范围就会失效,属于典型的 Agentic 系统;论文提出的 Goal-Identity-Configurator(GIC)架构则是面向 Agentive 系统的理论设计方向,目前仍停留在研究阶段,没有落地产品。

### 检验问题

1. 理解检验：故事里机器人"喂数据后能算出降温备货建议"这件事,为什么不足以证明它是 Agentive 系统?判断的关键点应该看哪一个环节?
2. 迁移检验：某个产品宣传"我们的 AI 客服会根据每天的对话记录自动优化自己的话术,越用越聪明",你会问哪些问题来判断这究竟是 Agentic 的外部工程优化,还是接近 Agentive 的内部自我调节?

## 两者的核心区别

| 维度 | Agentic（当前 AI Agent） | Agentive（真正自主体） |
|------|----------------------|---------------------|
| **能力来源** | 外部工程化脚手架、工作流 | 内部自发产生 |
| **目标** | 每次由用户/提示词注入 | 持久的内在长期目标 |
| **身份** | 无自我认知，无角色演化 | 稳定的、自我更新的身份 |
| **决策** | 固定的计划-执行流程 | 自主调节何时思考、如何思考 |
| **学习** | 外部调度的离线重训 | 在运行中自我发现并主动学习 |
| **代表系统** | GPT-4o + tools、Claude Code、Cursor | 无（理论目标）|

## 五维度评估框架（PM 用于评估 AI Agent 产品）

```
       外部工程化 ←────────────────────────→ 内部自主生成
            
目标   [外部提示词注入] ─────────────── [持久的内在目标体系]
身份   [无自我模型]   ─────────────── [稳定的、演化的自我认知]
决策   [固定 CoT/流程] ────────────── [自调节的 System I/II/III]
自我   [无自我反思]   ─────────────── [持续的自我调节机制]
学习   [外部重训] ────────────────── [运行时自我导向学习]

当前所有商业产品在五个维度上都偏向"左边"
```

## 为什么这个区分对 PM 重要

### 1. 识别营销话术
当厂商说"我们的 Agent 能自主决策"时，问：
- 它的目标是每次注入的还是持久的？
- 它的行为来自内置策略还是外部流程？
- 它能在运行中自我学习还是需要重训？

### 2. 理解当前 Agent 产品的真实局限
- **Claude Code / Cursor**：Agentic（脚手架+工具调用）；出了定义好的任务范围就失效
- **AutoGPT / AgentGPT**：Agentic（固定循环流程）；长时程任务可靠性差
- **真正 Agentive 系统**：2026 年仍是研究方向，无成熟产品

### 3. 产品规划：投入在哪里更有价值？
- **短期 (~2026)**：让 Agentic 系统的脚手架工程更好（更可靠的工具、更好的提示词工程）
- **中期 (~2027-2028)**：关注"目标持久性"和"自我调节"是否开始出现
- **长期**：关注世界模型与 Agent 模型的分离

## GIC 架构（未来方向）

论文提出的 Goal-Identity-Configurator 架构：
1. **层级目标分解**：长期目标 → 子目标链，持久不依赖提示词
2. **演化身份**：不通过重训就能更新自我认知
3. **模拟规划**（System II）：有独立的世界模型做前瞻推理，与动作模型分离
4. **自我调节**（System III）：学会何时用快思考（System I）/慢思考（System II）
5. **自导向学习**：从真实 + 模拟经验中主动发现并填补自身弱点

## 局限与生产风险

- 这是理论框架，尚无实现；GIC 架构的每一层都需要突破性技术进展
- "世界模型"需要独立训练，与当前 LLM 统一训练范式冲突
- "持久目标"在商业产品中带来对齐安全风险（Agent 可能发展出与人类不一致的目标）
