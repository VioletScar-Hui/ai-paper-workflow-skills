# 幻觉与接地

## 一句话定义

幻觉（Hallucination）是LLM生成看似合理但与事实不符内容的系统性现象；接地（Grounding）是通过外部知识源约束生成的技术手段，两者共同定义了AI系统在事实性维度上的可信度边界。

---

## 寓言学习

### 寓言正文

高管的助理经常要临场回答各种问题。有一次高管随口问："上次跟我们谈合作的那家公司，联系人叫什么名字来着？"助理其实已经记不清了，但觉得愣在那儿显得不够靠谱，就脱口而出一个听起来很像的名字。后来高管照着这个名字联系过去，对方一脸茫然，压根不是这个人。

另一次，团队开会做话术演练，高管说："你随便编一个虚构客户案例，我们练一下应对话术。"助理这次编了一个完全不存在的客户和场景，讲得绘声绘色、细节丰富。高管听完很满意，说这次编得很好，正是他们需要的。

事后复盘那次联系人搞错的事故，高管没有说助理"记性不好"，而是说了另一句话："下次你要是记不清，就说'我查一下再回复你'，别现编一个听起来对的名字糊弄过去。"

助理这才意识到，问题不在于自己"编不出来"或者"编得不够真"——她编虚构客户案例时讲得头头是道，没人觉得有问题。真正的区别在于，那次问的是一个应该有确切答案的真实的人，而这次演练本来就是要编。同一种"自信地把话说圆"的本事，用在被期待要说真事的场合，就成了误导；用在被期待要编故事的场合，反而正是需要的。

### 概念解析

**概念名称**：幻觉与接地（Hallucination & Grounding），属于大语言模型事实性/可信度问题域。

**学习卡片**
- 核心张力：把话说得流畅自信，和内容是不是真的，本来是两件事，但说话人（或模型）倾向于用"说得自信"来掩盖"其实没把握"，听者也容易把两者混为一谈。
- 关键不变量：判断一段编造的内容是不是"幻觉"，要看当下场合的预期是什么——预期要事实时的编造是幻觉，预期要虚构时的编造是创作，区分点在场合而不在内容本身像不像真的。
- 触发条件：被问到自己没有确切依据、记不清或从未接触过的具体信息时，仍然选择直接给出一个听起来确定的回答，而不是承认不确定。
- 常见误解/失败模式：把"回答得很流畅自信"当成"内容属实"的证据；或者不区分场合，把事实性场合的错误编造和创作场合的合理编造一律苛责或一律纵容。
- 非适用边界：如果讲述者本来就明确说了"我不确定"或双方都清楚这是虚构创作场合，那种"编"不属于这里要处理的失败模式。

**一句话核心定义**：幻觉是模型（或人）在被期待给出事实的场合生成看似合理却与事实不符的内容，接地是通过外部核实（检索、工具调用、引用来源）约束生成、降低这种错误的技术手段。

**它试图解决的问题**：当被问到自己并不确定的信息时，如何避免"自信地编一个听起来对的答案"，转而先去核实或坦诚承认不知道。

**故事元素映射**：
- 助理凭印象脱口而出一个错误联系人名字 = 事实性幻觉（Factual Hallucination），在事实场合自信编造。
- 助理在话术演练中编造虚构客户案例 = 创作场合的合理生成，不属于幻觉。
- 高管建议"记不清就说我查一下再回复" = 接地/优雅拒绝回答策略，先核实或坦诚不确定，而非直接编造。
- 高管区分两次"编"的场合而非一律评判助理的编造能力 = 幻觉与创造力的边界判断，取决于任务类型预期而非内容本身。

**比喻边界**：故事把幻觉简化成"记错一个名字"这种事实错误型，真实的幻觉还包括同一对话中前后自相矛盾（如角色设定漂移）、以及无中生有编造完全不存在的实体（如虚构论文、法律条款）这两种更复杂的类型；故事也没有涉及RAG、引用生成、自一致性等具体接地技术的实现细节。

**非适用例**：如果助理面对一个她真的很熟、天天打交道的同事随口问的日常小事（比如"茶水间的纸巾在哪"），凭记忆直接回答且大概率不会错，这种日常确定性回忆不属于需要接地核实的高风险场景。

**现实例子**：SelfCheckGPT通过多次采样同一问题、检查回答之间是否一致来判断幻觉风险；FactScore则把生成内容拆成一条条原子事实，逐条用可信资料库核实——这两种检测方法本质上都是在做"这次回答到底是有据可查，还是在自信地编"的核实工作，和故事里高管教助理"记不清就说我查一下"是同一个道理。

### 检验问题

1. 理解检验：助理在话术演练里编的虚构客户案例，为什么高管不认为那是幻觉？故事想让你看清判断幻觉的关键是什么，而不是内容本身编得像不像真的。
2. 迁移检验：如果一个AI写作助手在帮用户"续写一篇科幻小说"时，编造了一个完全不存在的星球和文明，这算不算幻觉？结合这个故事，你会怎么判断，还需要补充了解什么信息？

## 核心原理

### 幻觉的三种类型

**类型一：事实错误（Factual Hallucination）**

模型生成的信息在客观世界中是错误的，但语言表达流畅自信：
- 错误的时间/日期：「爱因斯坦于1921年获得诺贝尔物理学奖」（正确，但模型有时给出错误年份）
- 错误的数字：引用错误的统计数据、论文引用数、人口数字
- 人物混淆：将A的言论归到B名下
- 根本原因：预训练数据中存在噪声，模型学会了「自信地填空」而非「检索事实」

**类型二：自相矛盾（Intra-context Contradiction）**

模型在同一对话或文档中生成前后不一致的内容：
- 先说「X公司成立于2010年」，后文又说「X公司是2015年成立的初创企业」
- 多轮对话中角色设定的漂移（对话开始说是医生，后来说是工程师）
- 根本原因：Transformer的注意力机制在长上下文中对早期Token的关注度下降，缺乏显式一致性约束

**类型三：无中生有（Fabrication / Confabulation）**

模型生成完全不存在的实体或事件：
- 编造不存在的论文（标题、作者、期刊均看似真实但不存在）
- 编造不存在的法律条款、历史事件、公司产品
- 编造真实人物未说过的话（深度伪造文字版）
- 根本原因：语言模型的目标是「下一个Token的概率分布最大化」，而非「生成真实世界存在的内容」

### 幻觉的深层机制

**参数化知识 vs 上下文知识**

LLM存储知识的方式是将信息压缩到权重参数中，这导致：
- 知识的时效性问题（训练截止日期后的信息缺失）
- 长尾知识的覆盖问题（热门信息准确，冷门信息易幻觉）
- 知识冲突问题（训练数据中对同一事实有矛盾记录时，模型的输出不可预测）

**置信度与校准问题**

RLHF训练可能加剧幻觉：强化反馈倾向于奖励「听起来有用」的答案，而不区分其真实性，导致模型在不确定时也倾向于给出确定性答案。

## 接地技术

### RAG（检索增强生成）

最主流的接地方案，在生成前检索外部知识库：

```
用户问题 → 检索器（向量/BM25） → 相关文档 → LLM（生成时参考文档） → 答案（可附引用）
```

- 优势：知识可实时更新，可提供信息来源，大幅降低事实幻觉
- 局限：检索质量决定生成质量（Garbage in, garbage out）；多跳推理场景效果有限
- 关键指标：召回率（是否找到正确文档）+ 精度（答案是否忠于检索内容）

详见：[[RAG与检索增强]]

### 工具调用（Tool Use / Function Calling）

对于需要实时数据或精确计算的场景，让LLM调用外部工具：
- 数据库查询：精确获取结构化数据
- 计算器：避免数学幻觉（LLM算术能力弱）
- 搜索引擎：获取实时信息
- 代码执行：验证代码逻辑而非依赖模型想象

### 引用生成（Citation Generation）

生成内容的同时输出信息来源：
- 显式引用：「根据[文档A，第3段]...」
- 后验归因：生成后自动找到支撑句子的来源段落（Attributable to Identified Sources, AIS）
- 评估标准：AIS Score、Citation Recall/Precision

### 自一致性（Self-Consistency）

多次采样同一问题，取多数答案作为最终输出：
- 减少随机采样导致的一次性错误
- 对于有确定答案的问题效果显著（数学推理、事实问答）
- 成本是普通推理的N倍（通常N=5-20）

## 检测方法

### 基于模型的自我评估

**SelfCheckGPT（Manakul et al., 2023）**

- 多次采样同一问题，检查不同输出间的一致性
- 高一致性 → 低幻觉风险；高变异性 → 高幻觉风险
- 实现简单，无需外部知识库，但成本高

### NLI验证（自然语言推理）

- 使用NLI模型判断生成内容与参考文档的蕴含关系
- 分类：蕴含（Entailment）/ 中性（Neutral）/ 矛盾（Contradiction）
- 工具：MiniCheck、AlignScore

### 基于检索的验证

- FactScore（Min et al., 2023）：将生成文本分解为原子事实，逐条用维基百科验证
- RAGAS：评估RAG系统的忠实性（Faithfulness）和答案相关性

### 置信度评估

- 模型输出的对数概率（log probability）作为置信度代理
- 但模型在错误上也可能输出高置信度（置信度校准问题）

## 幻觉 vs 创造力的边界

幻觉和创造力的表象相同（都是生成「不存在的内容」），但本质不同：

| 维度 | 幻觉 | 创造力 |
|-----|------|-------|
| 预期 | 用户期望事实 | 用户期望虚构 |
| 危害 | 误导用户决策 | 丰富用户体验 |
| 上下文 | 事实性任务（QA、摘要） | 创作任务（故事、诗歌） |
| 应对 | 接地、引用、拒绝回答 | 鼓励、强化 |

**关键原则**：系统应明确声明任务类型。当用户问「X公司的CEO是谁」时，生成一个逻辑上连贯但错误的人名是幻觉；当用户说「写一个关于X公司的故事」时，虚构CEO是创作。

## PM 处理幻觉风险的策略

### 产品设计层面

1. **限定问答范围**：明确告知用户系统知识边界，设计优雅的「我不知道」响应（而非编造答案）
2. **强制引用**：所有事实性输出必须附带信息来源，无法引用则拒绝回答
3. **置信度分级显示**：高置信答案直接显示，低置信答案添加「可能不准确，请验证」提示
4. **人工复核工作流**：对高风险决策（医疗、法律、财务）设置专业人工审核关卡
5. **用户反馈机制**：「这个答案是否有帮助/准确」的反馈按钮，积累校正数据

### 技术栈层面

| 风险等级 | 推荐方案 | 成本 |
|---------|---------|-----|
| 低风险 | 裸LLM + 明确disclaimer | 低 |
| 中风险 | RAG + 引用生成 | 中 |
| 高风险 | RAG + NLI验证 + 人工复核 | 高 |
| 极高风险 | 专用知识库 + 规则引擎兜底 | 极高 |

### 衡量指标

- **幻觉率**：在已知答案的测试集上，模型错误率
- **引用精度**：生成的引用与实际来源的匹配率
- **用户信任度**：NPS/CSAT中对「信息可靠性」的专项评分
- **拒绝率**：模型在不确定时拒绝回答的比例（过低=幻觉风险高，过高=用户体验差）

## 演进时间线

| 年份 | 事件 |
|-----|-----|
| 2021 | 「幻觉」作为LLM核心问题被系统性研究（NLP社区） |
| 2022 | InstructGPT，RLHF引入，幻觉部分缓解但未根治 |
| 2022 | FactScore、SelfCheckGPT等评估框架发布 |
| 2023 | ChatGPT编造论文引用事件引发公众关注 |
| 2023 | RAG成为企业AI部署标配接地方案 |
| 2024 | 长上下文模型（128K+）减少因截断导致的矛盾幻觉 |
| 2024 | DeepSeek-R1等推理模型通过Chain-of-Thought降低数学幻觉 |
| 2025 | 幻觉检测市场出现（Vectara、Galileo等） |
