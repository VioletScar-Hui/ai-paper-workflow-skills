# 差分隐私（Differential Privacy）

> **一句话定义**：差分隐私（DP）是一种数学可证明的隐私保证——对于任意一条训练记录，无论攻击者拥有多少背景知识，都无法通过观察模型输出来确定该记录是否存在于训练集中。形式化为 (ε, δ)-DP：ε 越小隐私越强，δ 是允许以极低概率例外失败的概率。

---

## 寓言学习

### 寓言正文

部门茶水间摆着一个匿名建议箱，统计员每个月要整理一次，对外公布"这个月吐槽薪酬相关的意见占比"。她心里清楚，哪怕有人事后拿着全部门同事名单一个个去猜，也不该有办法从这份公布的数字里，反推出"某个具体同事到底有没有投过那张纸条"。

她的做法有两步：第一，不让任何一张纸条对总占比的影响超过一个很小的上限——哪怕某张纸条写得格外激烈，也不能让整体比例因为这一张就明显跳动；第二，公布之前她会往真实计数上额外掺一点点随机浮动，不是原始的精确数字。这样，哪怕上个月和这个月之间真的只多了一张吐槽纸条，公布出来的两次比例前后也几乎看不出差别。

有一次，上级临时要求"先看一眼原始建议箱里每一条的具体内容，做个初步归类，方便后续统计"，统计员照办了，把每张纸条按主题归了类，归类底稿留在了内部系统里，之后才按老办法生成对外公布的比例。

事后一位同事无意中翻到了那份归类底稿，一眼就认出了其中几条字迹和内容对应的是谁。统计员这才意识到：她后面那道"公布前掺扰动"的手续，保护的只是"对外公布的最终数字"，跟那份留在内部、没做任何处理的原始归类底稿完全是两回事——只要原始内容在哪个环节被直接翻看过又没加保护，事后不管在最终结果上补多精细的手续，都堵不住这个漏洞。她把流程改成了从收到纸条那一刻起，连内部初步归类都要走同一套加扰动、限权重的处理，不再直接接触原始内容。

### 概念解析

**概念名称**：差分隐私（Differential Privacy, DP），属于隐私保护/合规AI问题域。

**学习卡片**
- 核心张力：要让最终结果"看不出某一条具体记录是否参与过"，就必须故意在每一步都掺入不确定性（限权重+加噪声），但掺得越多，结果离真实情况就越远——隐私强度和结果可用性彼此拉扯。
- 关键不变量：只要某个环节直接接触过原始记录且没加保护，这个环节留下的痕迹事后无法靠"在别的环节补一道保护手续"抹去；保护必须覆盖数据被处理的每一个环节，不能只做最后一步。
- 触发条件：需要公开或使用一份统计结果，且这份结果不能被用来反推出"某一条具体记录是否存在于原始数据中"时。
- 常见误解/失败模式：以为只在对外公布这最后一步加了扰动就等于全程受保护，忽视了中间某个环节（比如内部初步整理）已经直接暴露过原始内容、留下了可被复原的痕迹。
- 非适用边界：如果统计的数据本身不涉及"某一条记录是否存在"这类需要保护个体归属的信息（比如完全公开、无个体关联的统计口径），就不需要这套刻意注入噪声的机制。

**一句话核心定义**：差分隐私是一种数学可证明的隐私保证——通过限制单条记录对结果的最大影响并注入校准噪声，使得无论攻击者掌握多少背景知识，都无法通过观察输出判断某条特定记录是否参与了统计或训练。

**它试图解决的问题**：在需要公开统计结果或用敏感数据训练模型时，如何保证这份结果本身不会成为反推"某个具体个体信息是否在其中"的线索。

**故事元素映射**：
- 不让单张纸条把占比拉得太明显 = 梯度裁剪（Gradient Clipping），限制单条样本对结果的最大影响力。
- 公布前额外掺一点随机浮动 = 添加校准高斯噪声，噪声幅度由隐私预算 ε 决定。
- 内部初步归类底稿没加保护直接留存 = 预训练阶段未做DP保护，模型已"记住"敏感模式。
- 事后只在最后一步补扰动堵不住内部底稿的漏洞 = "只在微调阶段加DP不够"，必须全程（预训练+微调）都受保护，才是唯一可验证的合规路径。

**比喻边界**：故事把"隐私预算累积"简化成了"每次统计都单独处理"，真实的DP-SGD中，隐私预算会随训练轮数（epoch）累积消耗，需要专门的隐私会计（Privacy Accounting）来追踪总消耗，并非每次都是独立的一次性处理；此外故事没有涉及量化与DP噪声叠加的工程问题。

**非适用例**：如果建议箱统计的是"这个月一共收到多少张纸条"这种不涉及任何个体归属的总数，谁投过、投了什么内容都不影响这个总数是否安全公开，就不需要这套刻意限权重加噪声的保护机制。

**现实例子**：VaultGemma是首个全程DP预训练的开源大模型（ε≤2.0），可检测记忆率降到0，但代价是能力水平退回到约5年前（相当于GPT-2水准）；这印证了故事里的权衡——扰动加得足以彻底保护隐私时，结果的可用性会明显打折。

### 检验问题

1. 理解检验：统计员在对外公布环节明明按规范加了扰动，为什么还是出了隐私泄露的问题？故事想让你看清的是哪个环节的保护被漏掉了？
2. 迁移检验：如果一家公司说"我们只在模型上线前的最后一轮微调阶段加了差分隐私处理，预训练阶段用的是公开抓取的普通数据"，结合这个故事，你会追问它什么问题？

## 核心数学定义

```
(ε, δ)-差分隐私：
  对于任意两个相差仅一条记录的数据集 D 和 D'，
  对于任意输出集合 S，满足：
  
    Pr[M(D) ∈ S] ≤ e^ε · Pr[M(D') ∈ S] + δ

  直觉：攻击者拿到模型，无法区分"数据集含某条记录"
        和"不含该记录"训练出的模型
  
  参数解读：
    ε = 1.0：极强隐私（极少数场景可实现）
    ε ≤ 2.0：强隐私（当前 VaultGemma 的标准）
    ε = 8~10：弱隐私（理论上有保证但实践中几乎无保障）
    δ ≤ 1/N：必须远小于训练集大小的倒数
```

## 核心机制：DP-SGD

```
普通 SGD（无隐私）：
  数据 → 计算批次梯度 → 更新模型参数
  问题：梯度本身会泄露训练数据信息

DP-SGD（差分隐私随机梯度下降）：

  Step 1：Per-sample 梯度计算
    每个样本单独计算梯度（而非批次平均）
    
  Step 2：梯度裁剪（Gradient Clipping）
    对每个样本梯度按范数 C 裁剪：
    g̃_i = g_i / max(1, ||g_i||₂ / C)
    → 限制单条样本对模型的最大影响力
    
  Step 3：添加校准高斯噪声
    g_noisy = (1/B) · (Σ g̃_i + N(0, σ²C²I))
    → 噪声幅度 σ 由隐私预算 ε 和 δ 决定
    
  Step 4：正常更新参数
  
  隐私会计（Privacy Accounting）：
    每一步训练消耗部分隐私预算
    全程累计消耗 = 总 ε 预算
    → 训练 epoch 越多，ε 越大，隐私越弱
```

## 关键发现：为什么"微调时加 DP"不够

```
常见的错误架构：
  预训练（无DP）→ 在私有数据上 DP 微调

  为什么不行：
  ① 预训练时模型已"记住"公开数据中的 PII 模式
  ② DP 微调不能"擦除"预训练时的记忆
  ③ 攻击者拿到开源模型全量权重，可以系统性探测
     预训练记忆（比闭源更危险）

VaultGemma 的正确做法（📅 2025.09）：
  预训练 + 微调 全程 DP
  → 记忆率降至 0（所有非 DP Gemma 版本均有可检测记忆率）
  → 这是唯一可验证的合规路径
```

## 隐私预算解读

| ε 值 | 隐私强度 | 能力损失 | 适用场景 |
|------|---------|---------|---------|
| ε ≤ 1.0 | 极强（理论最佳）| 巨大 | 学术研究 |
| ε ≤ 2.0 | 强隐私（当前标准）| 显著（≈5年前水平）| 医疗/金融合规 |
| ε ≤ 8.0 | 中等 | 较小 | 企业内部数据 |
| ε > 10 | 弱保证 | 极小 | 名义上合规 |

**δ 的设定原则**：δ ≤ 1/N（N=训练集大小），VaultGemma 达到 δ ≤ 1.1×10⁻¹⁰。

## PM 决策框架：合规 AI 选型指南

| 产品场景 | 监管要求 | 建议 |
|---------|---------|------|
| **医疗 AI**（含 PHI 数据）| HIPAA | 必须全程 DP 训练；仅微调阶段 DP 不满足要求 |
| **金融 AI**（含客户数据）| GDPR/金融监管 | ε ≤ 2.0 是当前可引用的强隐私标准 |
| **企业私有数据微调** | 内部合规 | 基础模型未做全程 DP 时，DP 微调仍有预训练记忆风险 |
| **B2B SaaS 合规层** | 客户合规审查 | "记忆率=0"是可量化、监管可接受的合规指标格式 |
| **能力期望管理** | 产品定位 | 告知客户：全程 DP 模型当前能力约为 2020 年水平——这不是 bug，是特性 |

## 量化技术与差分隐私的组合

```
特殊场景：隐私保护 + 量化的双重压缩

朴素方案问题：
  DP 噪声（浮点精度需求高） + INT4 量化（精度压缩）
  → 两重精度损失叠加，误差比单独使用更大

VaultGemma 创新：
  量化感知的 DP 噪声注入
  → 噪声幅度 σ 根据量化误差范围联合设计
  → 隐私保护 + 量化同时实现，总损失 < 叠加损失

应用：医疗/金融场景的隐私推理端侧部署
```

## 差分隐私 vs. 其他隐私技术

| 技术 | 保证类型 | 可验证性 | 计算开销 | LLM 适配 |
|------|---------|---------|---------|---------|
| **差分隐私（DP）** | 数学可证明 | 高（ε,δ 可量化）| 高（需 per-sample 梯度）| DP-SGD |
| 联邦学习 | 分布式训练 | 中（仍有梯度泄露风险）| 很高（通信成本）| 结合 DP 使用 |
| 数据脱敏 | 后处理移除 PII | 低（不完整，可重识别）| 低 | 无训练保证 |
| 同态加密 | 计算层加密 | 高 | 极高（不可实际部署）| 推理阶段 |
