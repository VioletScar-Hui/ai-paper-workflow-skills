# 形式化推理与自动定理证明

> **一句话定义**：形式化推理要求模型不只是"看起来正确"，而是产生机器可验证的逻辑证明——每个推理步骤都能被 Lean/Isabelle 等定理证明器机械地验证。这是从"AI 辅助数学"迈向"AI 自主数学"的关键跨越。

---

## 寓言学习

### 寓言正文

工地夜里刚浇筑完一片承重墙的钢筋笼,包工头老周拿着手电筒绕着焊点走了一圈,拍了拍其中几处:"这几个焊得牢,继续往下干。"

质检员小陈接手后没有直接签字。她把每个焊点编号,一个个接上便携拉力测试仪,给绳索加载,记录下每个焊点在多大拉力下开始变形、多大拉力下断裂。有三个焊点在读数还没到标准值的一半时就悄悄松脱了——从外表看,它们和旁边通过测试的焊点一模一样,连老周都看不出区别。

老周不服气,说自己干了十几年,眼睛比机器准。第二天他索性把自己判断"牢"的焊点也贴上标签,让小陈按标签直接过。小陈没有妥协:每个焊点都要过一遍测试仪,读数达标才盖章,读数不到就返工,不管是谁说"看着牢"。返工那次查出来,是同一批钢筋里有一卷材质本身就有问题,肉眼和手感完全测不出来。

### 概念解析

**概念名称**：形式化推理与自动定理证明(Formal Reasoning & Automated Theorem Proving),属于大语言模型数学推理/AI 评测问题域。

**学习卡片**
- 核心张力：“看起来合理”(自然语言/经验判断) vs “机械可验证”(逻辑证明器的二元判定)——前者依赖信任,后者不需要信任。
- 关键不变量：验证结果必须是机器可执行、无歧义的二元判断(通过/不通过),而不是“大概率对”的主观信心。
- 触发条件：当任务的正确性可以被形式化为一套公理系统内可机械检查的规则时,才能上形式化验证;结论本身模糊或依赖价值判断时不行。
- 常见误解/失败模式：把“经验丰富、看起来专业”等同于“逻辑无懈可击”;或者反过来,用形式化语言的语法技巧“骗过”验证器却没有真正证明目标(奖励黑客)。
- 非适用边界：无法被公理化、依赖主观审美或价值取舍的判断,形式化验证帮不上忙。

**一句话核心定义**：形式化推理要求把“推理过程”转成能被定理证明器机械检查的逻辑链条,通过就是100%正确,不依赖任何人(或模型)的主观信任。

**它试图解决的问题**：自然语言/经验式推理可能“看起来对”但其实跳步、幻觉或想当然,形式化推理用机器可验证的规则替代人的信任,把“正确性”变成客观、无歧义的判定。

**故事元素映射**：
- 老周凭经验拍焊点判断“牢” = 非形式化推理(自然语言/经验判断),别人只能选择信或不信,存在“幻觉正确”的风险。
- 小陈给每个焊点上拉力测试仪、记录读数 = 形式化验证,每一步都能被机器复核,通过或不通过没有中间地带。
- 有三个焊点外表和好焊点一样却测试不达标 = 经验判断无法识破的错误,恰恰是形式化验证存在的意义。
- 老周试图用自己的判断标签替代测试仪读数被拒绝 = 形式化验证不因权威、经验、自信而让步,机器是唯一裁判(oracle)。

**比喻边界**：故事把“形式化”简化成了一台读数仪器,但现实中把数学命题或代码逻辑“翻译”成 Lean/Isabelle 这类形式语言本身极难、耗费大量人工(自动形式化本身就是研究难题),不是简单“接上仪器”就能完成;而且形式化语言和自然语言之间存在语义不唯一的翻译损耗,这一层复杂度故事没有体现。

**非适用例**：如果客户要求“帮我判断这堵墙刷成米白色还是浅灰色更好看”,不管请多少个质检员用多精密的仪器去测,都测不出“正确”答案——这是审美偏好判断,没有可形式化的公理系统可依据,形式化验证机制在这里没有用武之地。

**现实例子**：AlphaProof 在 IMO 2024 数学奥赛题上拿到 3/6 题的形式化证明,每一步都经过 Lean 验证器机械检查,不存在“看起来对但其实跳步”的可能;LongCat-Flash-Prover 则用强化学习直接从 Lean 验证器的通过/报错反馈中训练模型写证明,而不依赖稀缺的人工标注形式化数据。

### 检验问题

1. 理解检验：如果一个焊点被拉力测试仪判定“不达标”,但老周坚持说“我干了十几年,这个焊点绝对牢固”,谁的判断应该被采纳?为什么这不是“经验 vs 直觉”的问题,而是这个概念的核心机制决定的?
2. 迁移检验：某公司想用 AI 自动生成法律合同条款,并声称“AI 生成的条款经过了形式化验证,保证没有逻辑漏洞”。你觉得这个说法可信吗?合同条款是否具备“可以被机械化、无歧义验证”这个前提条件?

## 形式化 vs 非形式化推理

```
非形式化推理（自然语言数学，如 CoT）：
  Q: 证明 √2 是无理数
  A: 假设 √2 = p/q，...（自然语言步骤）
  
  判断正确性：人类读懂，认为逻辑合理
  问题：模型可能跳步、引入无效推理、"幻觉正确"
  
形式化推理（Lean/Isabelle）：
  theorem sqrt2_irrational : Irrational (Real.sqrt 2) := by
    rw [Nat.irrational_sqrt_two]  -- Lean 代码
  
  判断正确性：定理证明器机械验证，通过 = 100% 正确
  优势：不可能有幻觉错误（机器验证是 oracle）
  挑战：形式化语言极难学习，与自然语言差距巨大
```

## 为什么形式化证明重要？

```
1. 数学可靠性：
   形式化证明 = 绝对正确（在公理系统内）
   用于验证关键软件（编译器、操作系统、密码协议）
   
2. AI 评估的黄金标准：
   自然语言数学评测存在歧义性和过拟合问题
   形式化证明：正确/错误 是二元的，无歧义
   → 是评测推理模型的理想 benchmark
   
3. 科学发现的基础：
   未来的 AI 数学家 = 必须能生成可验证的证明
   否则只是"建议"，不是"发现"
```

## 三条技术路线

### 1. 自动形式化（Autoformalization）

```
思路：
  自然语言数学命题 → LLM 翻译 → Lean 语句
  → Lean 验证

流程：
  1. "质数有无穷多" → Lean: theorem infinitely_many_primes : ∀ n, ∃ p, p > n ∧ Nat.Prime p
  2. LLM 生成证明草稿
  3. Lean 验证（可能失败）
  4. LLM 根据报错修改
  
代表：LLM 通过 few-shot 学习形式化语法
局限：自然语言歧义 → 形式化语义不唯一
```

### 2. 证明搜索（Proof Search）

```
思路：
  给定形式化命题，在证明空间中搜索
  
方法：
  树搜索（MCTS）+ 价值函数（预测证明成功率）
  Bundle 搜索：同时搜索多条证明路径
  
代表：AlphaProof（Google, 2024）
  在 IMO 2024 题目上：3/6 题（历史性突破）
  
LEAP（论文33）：LLM-based formal proof agent
  Retrieval + Planning + Execution 三层
  GPT-4 + Lean 联合推理
```

### 3. 强化学习形式化训练（论文100，Flash-Prover）

```
核心创新：
  不依赖人工形式化数据（极度稀缺）
  用 RL 从 Lean 验证器的反馈中直接学习
  
奖励信号：
  - Lean 验证通过 → 正奖励（稀疏但精确）
  - Lean 报错类型 → 细粒度负奖励
  
难点：
  形式化奖励极度稀疏（大多数尝试都失败）
  → 需要强大的探索策略
  
发现：模型学会 9 种常见"奖励黑客"模式（靠语法技巧绕过验证而非真正证明）
  → 需要特殊检测和惩罚
```

## AI 数学家工作台（论文138）

```
更宏大的视野：AI 不只是证明已知定理，而是协助发现新数学

AI 协数学家的能力层次：
  Level 1：验证（验证人类给的证明）
  Level 2：补全（完成人类给的不完整证明）
  Level 3：证明（证明人类给的定理）
  Level 4：猜想（提出新的数学猜想）
  Level 5：发现（发现新的数学领域）
  
论文138 的工作台：
  FrontierMath 数据集：专业级数学题（不在任何训练集中）
  评测结果：AI 协数学家在 Tier 4 从 <20% → 48%（人机协作）
  → Level 3 的门槛已接近突破
```

## 形式化语言生态

```
主要定理证明器：
  Lean 4（最活跃）：Mathlib 4 覆盖大量大学数学
  Isabelle/HOL：机器验证操作系统/协议
  Coq：程序验证
  
LLM 友好程度：
  Lean 4 > Coq > Isabelle（训练数据量）
  Mathlib 是最大的形式化数学库（>100K 定理）
  
当前 LLM 局限：
  Token 预测无法感知"Lean 的执行语义"
  → 需要工具集成：LLM + Lean 解释器 交互
  → 类似代码解释器：生成 → 执行 → 修改
```
