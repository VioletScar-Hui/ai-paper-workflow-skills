# 蒙特卡洛树搜索（MCTS）

## 一句话定义

蒙特卡洛树搜索（Monte Carlo Tree Search, MCTS）是一种基于随机模拟的启发式树搜索算法，通过迭代执行选择（Selection）、扩展（Expansion）、模拟（Simulation）、回溯（Backpropagation）四个步骤，在不穷举所有节点的前提下逐步建立高价值路径的统计估计，已从游戏AI（围棋）扩展至LLM推理时的搜索策略。

---

## 寓言学习

### 寓言正文

指挥部要在天黑前找到迷路的驴友,山里有五条岔路,人手不够把每条路都走到底。

最开始的打法很直接:五条岔路,平均分成五队,每队两人,沿一条路一路走到底,谁先发现线索谁跟进,但规定不许中途折返换路。结果三号队在头二十分钟就走岔到了一条早就废弃的采石道上,一路走到底什么都没有,而失踪者留下的手机信号最早其实是在一号路附近出现的——三号队的人力被彻底浪费,没法抽回来支援一号路。

指挥部后来换了打法:每隔二十分钟,各队用对讲机汇报"沿途有没有新鲜脚印、丢弃物品这类线索的密度"。指挥部根据汇报实时调配——线索密集的方向立刻加派人手深入搜索,线索稀薄的方向只留一人意思意思地继续探,一旦某个方向突然传回强线索(哪怕之前只派了一个人去探过),立刻把其他方向的人抽调过去支援。凌晨两点,靠着最开始只派了一人去探的四号路突然传回强线索,指挥部把原本分散在其他三条路的六个人全部调了过去,四十分钟后找到了人。

### 概念解析

**概念名称**：蒙特卡洛树搜索(Monte Carlo Tree Search, MCTS),属于搜索算法/大语言模型推理时搜索问题域。

**学习卡片**
- 核心张力：相信已经验证过的高价值方向、继续深挖(利用) vs 分一部分资源去探索还没验证过的方向(探索)——两者要动态平衡,而不是一次性分配死。
- 关键不变量：资源分配必须是非均匀且可回溯的——已被证明低价值的方向要及时减少投入,新出现的高价值线索要能立刻把其他方向的资源抽调过来,而不是一开始分好就不再变动。
- 触发条件：搜索空间太大无法穷举,但有办法对“当前路径有多大希望”做出统计估计(比如线索密度、价值函数打分)时才适用。
- 常见误解/失败模式：把资源一次性平均分配后就不再调整(退化成固定宽度搜索),或者只根据“目前看起来最好”的路径反复深挖,完全不留资源探索新方向。
- 非适用边界：如果搜索过程中完全没有中间信号可以参考(走到底才知道对不对),就没法做“选择-扩展-模拟-回溯”这套动态调配,这时候只能靠穷举或固定策略。

**一句话核心定义**：蒙特卡洛树搜索是通过反复“选择-扩展-模拟-回溯”四步循环,根据实时统计信号动态调配搜索资源、允许把资源从低价值方向抽回投入新发现的高价值方向,从而在不穷举全部路径的前提下逐步逼近最优解的搜索方法。

**它试图解决的问题**：当可能的路径太多、无法一一走到底验证时,如何用有限的资源,一边利用已知的好方向、一边留出探索新方向的余地,并且能在过程中根据新线索纠正早期的资源分配错误。

**故事元素映射**：
- 五条岔路对应巨大的搜索空间,人力对应有限的计算/搜索预算。
- 每隔二十分钟汇报线索密度、动态调配人手 = 选择(Selection,靠 UCB1 类信号决定往哪投入)+ 回溯(Backpropagation,新信号更新对各方向的价值估计)。
- 派人去探一条还没走过的方向 = 扩展(Expansion),向未充分探索的节点延伸。
- 靠脚印/遗留物品这类中途线索判断该方向有没有希望 = 模拟/评估(Simulation/Evaluation),不用走到底也能对当前路径打分,对应 LLM 推理里的 PRM 估值。
- 四号路只派一人探却突传回强线索,指挥部立刻把其他方向的人抽调过去 = MCTS 能“回溯纠错”的核心优势——早期投入少不代表放弃,只要信号变强就能重新加码。
- 五队固定分配、不许折返换路的最初打法 = Beam Search 的对照:固定宽度、一旦早期走错无法把资源抽回来。

**比喻边界**：故事把“价值估计”简化成了脚印和遗留物品这类直观线索,但 LLM 推理中的 MCTS 靠的是 UCB1 公式(结合访问次数和平均价值的数学平衡)和过程奖励模型(PRM)的打分,这是一套可以精确计算、反复迭代成千上万次的统计机制,不是人凭经验判断“线索多不多”这么直观,现实搜救中人力抽调也有物理延迟和成本,和模型内部搜索节点之间几乎零成本的资源重分配不完全一样。

**非适用例**：如果山里完全没有信号覆盖、对讲机全部失效,五个队伍彼此毫无联系,指挥部拿不到任何中途反馈,那就没办法做“根据线索动态调配”这件事,只能靠最初的固定分配方案硬走到底——这种没有中间信号可用的场景,MCTS 这套动态调配机制发挥不了作用。

**现实例子**：AlphaGo 用 MCTS 结合策略网络和价值网络击败李世石,策略网络负责决定往哪个方向扩展,价值网络替代了传统 MCTS 里“随机走到底”的模拟步骤;在 LLM 数学推理中,rStar-Math 等工作用过程奖励模型(PRM)代替随机 rollout 给每一步推理打分,让 MCTS 在不用生成完整答案的情况下就能判断某条推理路径是否值得继续深挖。

### 检验问题

1. 理解检验：故事里三号队“不许中途折返换路”的规定,如果换成允许中途根据线索调整,MCTS 里对应的是哪个步骤在起作用?这个规定的存在恰好对照了 MCTS 相对哪种搜索方法的优势?
2. 迁移检验：如果要在一个“代码生成”任务里引入 MCTS 式搜索,你觉得除了要有大量计算预算之外,还必须具备哪个前提条件(对照故事里“线索密度”这个角色)才能让这套机制真正发挥作用?

## 核心原理

### 四步循环详解

MCTS的核心是一个反复执行的四步循环，每次迭代后更新树结构和节点统计信息。

---

**步骤一：选择（Selection）**

从根节点（初始问题状态）开始，沿着树向下遍历，直到到达一个尚未完全扩展的节点或叶节点。

选择策略的核心是**UCB1（Upper Confidence Bound 1）公式**，用于平衡探索（exploration）与利用（exploitation）：

```
UCB1(v) = Q(v)/N(v) + c * sqrt(ln(N(parent)) / N(v))
```

其中：
- `Q(v)/N(v)` — 节点v的平均价值（利用项）：鼓励选择历史上表现好的路径
- `c * sqrt(ln(N(parent)) / N(v))` — 探索项：鼓励选择访问次数少（可能被低估）的路径
- `c` — 探索系数，控制探索与利用的权衡（通常取√2 ≈ 1.414）
- `N(v)` — 节点v的访问次数
- `N(parent)` — 父节点的访问次数

**直觉**：当N(v)很小时，探索项很大，算法倾向于探索未知路径；当N(v)增大，探索项减小，算法更信任已有统计。

在LLM推理中，节点v对应一个中间推理状态（已生成的部分推理链），选择下一步扩展哪个状态由UCB1决定。

---

**步骤二：扩展（Expansion）**

对选中的叶节点，通过语言模型生成一个或多个候选的下一步推理步骤，添加为该节点的子节点。

在LLM推理中：
- 每个"步骤"可以是一行推理、一个句子、或一个完整的推理段落
- 扩展时使用采样（temperature > 0）保证多样性
- 扩展数量（branching factor）是搜索宽度的关键超参数

---

**步骤三：模拟（Simulation）/ 评估（Evaluation）**

从新扩展的节点开始，快速估计其最终价值。原始MCTS使用**随机模拟（rollout）**：从该节点随机走到终态，用最终结果估算价值。

在LLM推理中，有两种主要变体：
1. **Rollout**：从当前节点继续生成完整答案，检查答案是否正确作为奖励（0/1）
2. **PRM估值**：使用**过程奖励模型（Process Reward Model）**直接对当前推理步骤打分，无需走到终态（更高效）

---

**步骤四：回溯（Backpropagation）**

将模拟/评估获得的价值沿着路径反向传播，更新路径上所有节点的统计信息：
- N(v) ← N(v) + 1（访问计数+1）
- Q(v) ← Q(v) + reward（累计价值更新）

多次迭代后，高价值路径的统计估计逐渐精确，算法对"好的推理路径"的识别能力越来越强。

## PRM作为Value Function

在AlphaGo中，价值网络（value network）评估棋盘局面的胜率。在LLM推理中，**过程奖励模型（PRM）**扮演相同角色：

**PRM的输入与输出**：
- 输入：问题 + 已有推理步骤
- 输出：当前推理状态最终能得到正确答案的概率估计（0-1之间的实数）

**PRM作为Value Function的优势**：
- 无需完整rollout到终态，每步都能得到价值估计
- 比最终答案验证（outcome reward）提供更密集的学习信号
- 能识别推理链中的早期错误，引导搜索及时剪枝

**PRM的挑战**：
- 需要大量步骤级标注数据训练（如PRM800K，每步由人工标注正确/错误）
- PRM可能被搜索算法"hacking"：找到PRM打高分但实际上错误的推理路径

## 搜索深度与计算预算

MCTS的计算成本由以下参数决定：

| 参数 | 含义 | 典型值 | 对结果的影响 |
|------|------|-------|------------|
| 迭代次数（N_iter） | MCTS循环执行次数 | 100-1000 | 直接决定计算预算 |
| 分支因子（branching factor） | 每次扩展的候选步数 | 2-5 | 搜索宽度，越大越耗资源 |
| 最大深度（max depth） | 推理链最大步数 | 5-20 | 限制搜索树高度 |
| Rollout长度 | 模拟时生成的额外步数 | 0-5 | 0=纯PRM估值，>0=混合 |

**计算预算与准确率的关系**：近似对数线性，每增加一倍计算预算，准确率提升约2-5%。这正是"推理时计算扩展"定律的来源。

## 与Beam Search的对比

| 维度 | MCTS | Beam Search |
|------|------|-------------|
| 搜索策略 | 自适应（UCB1引导，重点探索高价值路径） | 固定宽度，始终保留top-k候选 |
| 计算分配 | 非均匀（难题多搜索，简单题少搜索） | 均匀（每步固定beam数） |
| 需要价值估计 | 是（PRM或rollout） | 否（或仅需局部评分） |
| 对早期错误的容忍度 | 高（可以回溯，探索其他路径） | 低（错误路径在早期可能挤掉正确路径） |
| 实现复杂度 | 高 | 低 |
| 适用场景 | 复杂多步推理，计算预算充足 | 快速推理，延迟敏感场景 |

**关键优势**：MCTS能够"回溯"（backtrack）——当某条路径被证明无价值时，通过UCB1机制自动减少对该路径的探索，并加大对其他路径的投入。Beam Search一旦在某步骤剪掉了正确路径，无法恢复。

## PM决策视角

**何时在产品中引入MCTS推理**：

1. **前提条件**：需要可靠的步骤级验证器（PRM或可执行代码验证），否则无法正确引导搜索
2. **适用任务**：竞赛数学、复杂代码生成、多步逻辑推理（需要长链推理且错误代价高）
3. **成本权衡**：MCTS的延迟是Greedy解码的10-100倍，仅适合高价值、低实时要求的场景
4. **替代方案评估**：
   - 延迟要求严格 → 自洽性采样（更简单，延迟较低）
   - 计算预算中等 → Best-of-N + PRM打分
   - 计算预算充足 → MCTS（效果最好）
