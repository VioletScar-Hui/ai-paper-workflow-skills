# Agent 长期记忆

> **一句话定义**：Agent 的长期记忆是跨 session、跨任务持续积累的信息存储——不同于上下文窗口内的短期记忆，长期记忆需要主动写入、组织、更新，并在未来任务中检索使用，是 Agent 从"工具"走向"助理"的核心能力。

---


## 寓言学习

### 寓言正文

大厦门口的礼宾员认识楼里大部分常住户。谁家几点通常回来、平时点外卖爱吃辣还是不辣、家里几口人，他心里都有本账。但他不可能把每天见到的所有细节都记下来——今天谁穿了什么颜色的衣服、谁今天心情好不好，这些他扫一眼就过，不往本子上写；只有真正会影响以后怎么接待、怎么联系的信息，他才记下来。

有一天，302 的住户升职换了新职位头衔，还顺带把家里的紧急联系人从父母换成了配偶。礼宾员在本子上划掉旧职位、写上新职位，动作挺利索。但那一页边缘原来记着的旧紧急联系人信息，他忙着写新职位，忘了同步划掉。

半个月后，302 家里出了点急事，物业让礼宾员帮忙联系家属，他翻开本子，看到那页边缘写着的名字，想都没想就报了出去——正是那个早就作废的旧联系人。等对方那头一头雾水地反问"我不是他家人了"，礼宾员才意识到，那条记录压根没跟着职位一起更新，一直安安静静地留在本子边上，看起来没什么问题，其实早就是错的。

### 概念解析

**概念名称**：Agent 长期记忆（Long-term Memory），属于 LLM Agent 记忆系统设计问题域。

**学习卡片**
- 核心张力：记住得越多看起来越贴心，但记录本身会过时、会和新信息冲突，甚至记得太多反而互相打架、拖慢判断。
- 关键不变量：记忆必须经过筛选才写入（不是全量留存），且需要有更新/遗忘机制处理旧记录和新信息之间的冲突，否则旧记录会在无人察觉的情况下悄悄变得不准确。
- 触发条件：一个反复被调用、跨越多次任务/多天持续为同一对象服务的场景，且相关信息会随时间变化。
- 常见误解/失败模式：更新某条信息时只改了"看得见"的部分，没同步检查关联的旧信息，导致细节层面的记录悄悄过时却"表面看起来正常"——直到被真正用到时才暴露问题。
- 非适用边界：一次性、用完即扔的交互不需要长期记忆机制，直接用当次上下文处理就够，引入长期记忆存储反而是浪费。

**一句话核心定义**：Agent 长期记忆是指跨会话、跨任务持续积累的信息存储，需要主动筛选写入、定期更新、处理冲突，并在未来任务中被检索使用，让 Agent 从"每次从零开始的工具"变成"记得住你的助理"。

**它试图解决的问题**：一个需要反复为同一对象服务的 Agent，如何决定"该记住什么、怎么存、什么时候该更新或遗忘"，而不是每次交互都从空白状态开始，也不是把所有信息不加筛选地全部堆积起来。

**故事元素映射**：
- 礼宾员 = Agent 本身，负责判断"什么值得记"。
- 只记会影响后续接待的信息，不记穿什么颜色衣服 = 记忆写入的筛选机制：不是所有信息都值得存，要挑对未来任务有用的。
- 划掉旧职位写新职位，却没同步更新旧紧急联系人 = 记忆的"修订老化"：信息更新时只 patch 了一部分，其余关联记录悄悄过时，且行为表现（本子看起来整洁）无法暴露这种老化。
- 半个月后报出作废的旧联系人才暴露问题 = 修订老化的隐蔽性：问题不在写入的那一刻暴露，而是在未来某次检索使用时才显现出来。

**比喻边界**：故事里礼宾员的记忆是一本纸质本子，更新方式是"划掉重写"，但真实的 Agent 记忆系统涉及向量数据库、结构化存储、检索策略等更复杂的工程实现，且"修订老化"在真实系统里往往涉及多条记录、多个存储层之间的不同步，而不只是同一页纸上的一行没划掉。

**非适用例**：如果礼宾员只是帮一位路过的陌生人指一次路，说完这次对话就结束，不会再有后续交集，那就不需要把这次对话存进本子里——这种一次性交互不需要长期记忆机制。

**现实例子**：AgingBench 研究发现，Agent 记忆系统中存在"修订老化"（Revision Aging）问题——信息更新时只 patch 了部分记录，其余细节精度悄悄下降，且常规行为测试根本发现不了，论文提出用"类型化状态副车"（Typed-State Sidecar）把结构化事实单独存储、独立更新，将这类老化减少 25%~47%。

### 检验问题

1. 理解检验：礼宾员报错联系人那件事，问题出在他"记性不好"，还是记忆系统的哪个具体环节？这类问题为什么在事发之前不容易被发现？
2. 迁移检验：如果你在设计一个记住用户饮食偏好的健康管理 Agent，用户某天说"我现在不吃辣了，医生让我少吃辣"，结合这个故事，你觉得 Agent 除了更新"是否吃辣"这条记录，还应该检查哪些关联信息，以避免类似的问题？


## 记忆层次

```
Agent 的三层记忆（类比人类）：

工作记忆（In-Context Window）：
  当前 prompt 中的所有信息
  容量：4K - 1M tokens
  持久：否（session 结束即消失）
  特点：全部"可见"，但受 context window 限制
  
情节记忆（Episodic Memory）：
  过去任务/对话的压缩记录
  存储：外部向量数据库 + 结构化存储
  检索：按需检索（语义/时间/关键词）
  论文94（TaskMem）核心处理的就是这层
  
语义记忆（Semantic/Parametric）：
  模型权重中编码的世界知识
  更新：需要微调或 RAG 注入
  论文44（睡眠记忆巩固）探索的是这层
```

## 记忆写入的核心难题

```
"什么值得记忆？"——TaskMem（论文94）的核心贡献

直觉：Agent 面临信息爆炸
  每次对话：1000 tokens
  每天 100 次对话：100K tokens
  一年：36M tokens（不可能全记）

传统方法：
  规则过滤（记忆重要事件、用户偏好）
  → 规则设计困难，泛化差
  
  LLM 自动总结
  → 受总结模型能力限制
  → 不知道哪些对"未来任务"有用
  
TaskMem 解决方案：
  Phase 1（预部署）：学会高质量写入（准确、简洁、格式正确）
  Phase 2（部署后）：用实际遇到的任务调整"写什么"
  → 记忆策略随任务分布动态自适应
```

## 记忆老化问题（AgingBench，论文48）

```
4种老化机制：

1. 压缩老化（Compression Aging）
   原始信息被压缩 → 细节丢失
   表象：记忆准确度下降，但表达还是流畅的
   
2. 干扰老化（Interference Aging）
   新记忆覆盖旧记忆（写入冲突）
   表象：模型混淆新旧信息
   
3. 修订老化（Revision Aging）
   信息更新时 patch 了旧记忆
   表象：行为测试看起来正常，但细节精度下降
   关键：行为测试无法发现这种老化！
   
4. 维护老化（Maintenance Aging）
   多次"维护"操作累积误差
   
对抗策略：
  Typed-State Sidecar（类型化状态副车）：
    将结构化数据（事实、日期、数字）存入独立的类型化存储
    不与非结构化记忆混合
    → 修订老化减少 25-47%
```

## 睡眠式记忆巩固（论文44）

```
人类睡眠中发生什么：
  海马体（短期）→ 新皮层（长期）的记忆转移
  不重要的记忆逐渐消退
  相关记忆之间建立连接
  
AI 对应方案（论文44 提出）：
  离线阶段（"睡眠"）：
    对在线学到的 embedding 进行递归回放
    强化重要记忆，弱化次要记忆
    建立跨记忆连接
    
  在线阶段（"清醒"）：
    正常任务执行
    新记忆进入短期缓存
    
  类比：在线学习+定期离线整合
```

## 与 RAG 的关系

```
RAG vs Agent 长期记忆：

RAG（传统）：
  外部文档 → 向量化 → 静态索引 → 检索
  文档不会"学习"或"成长"
  
Agent 长期记忆：
  动态写入（每次交互可能更新记忆）
  个性化（记忆是关于"这个用户/这个Agent"的）
  主动整合（新旧记忆有冲突时需要处理）
  遗忘机制（防止记忆无限增长）
  
工程实现：
  短期（in-context）+ 长期（向量DB + 结构化DB）
  写入策略（何时写、写什么、怎么压缩）
  检索策略（按相关性/时间/任务类型）
  更新策略（如何 patch 已有记忆）
```

## 记忆诅咒：记忆越多协作越差？

```
论文140（记忆诅咒）的逆直觉发现：
  假设：更多记忆 → 更好的多 Agent 协作
  实验：随着记忆规模扩大，多 Agent 协作性能下降

原因分析：
  每个 Agent 的记忆是个体化的（私有的）
  → 记忆越多，Agent 们的"世界观"越分歧
  → 协调成本急剧上升
  → 出现"记忆回音室"（各自强化各自的偏见）

对策：
  共享记忆层：Agent 共享部分记忆（减少分歧）
  记忆对齐协议：定期同步关键事实
  元记忆（Meta-memory）：记录"我不知道什么"和"A 知道什么"
```

## delta-mem：轻量在线记忆

```
论文135（delta-mem）的创新：
  问题：传统记忆系统需要离线训练/更新
  解法：在推理时（在线）实时更新轻量记忆

核心思想：
  不更新主模型权重
  只更新一个极小的"delta 记忆向量"（参数量 << 主模型）
  → 推理时可以持续学习和记忆新信息
  
对比：
  传统 RAG：读-检索-注入（静态）
  delta-mem：读-更新-注入（动态）
  → 适合需要实时个性化的 Agent 场景
```

## MeMo：记忆即模型

```
论文124 提出的激进视角：
  核心论点：记忆不应该是模型的附件，而是模型本身的一部分
  
实现思路：
  把用户的历史交互"蒸馏"进模型权重的局部更新中
  → 记忆永久编码在模型里，不需要外部存储
  
优势：推理时没有检索开销，记忆永远"在线"
劣势：更新频繁时计算成本高，且难以"遗忘"
```
