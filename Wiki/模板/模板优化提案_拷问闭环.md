# 模板优化提案：用 grilling 思路补全"提取验证"闭环

> **一句话结论**：现有的概念挖掘和论文笔记体系是**存储优化**的（怎么把知识写好），grilling 能补上缺失的另一半——**提取验证**（怎么证明你真的懂了）。最大收益不在往模板里加字段，在于补一个"拷问闭环"工作流，模板改动只是为这个闭环准备接口。

---

## 一、第一性原理：这套模板到底在优化什么

你的终局目标有四个：**面试能讲**（经得起面试官追问）、**产品判断能用**、**长期记住**、**体系化**。倒推回来，有五条第一性原理：

| # | 原理 | 依据 |
|---|------|------|
| P1 | **测试效应**：理解和记忆在"被迫提取"时形成，不在"重读"时形成 | 学习科学共识；重读只产生熟悉感（自我满足的来源，即 digest_rule §4.1） |
| P2 | **卡点即缺口**：答不上来的地方才是真没懂的地方，系统必须制造卡住并记录它 | digest_rule §4.6 已有此认知，但**没有机制承接**——卡点从未被记录 |
| P3 | **理解的判据是经得起对抗性追问**，不是"字段填满了" | grilling 的共识门；面试本质就是一场 grilling |
| P4 | **事实与判断分离**：可查证的交给机器核查，需要立场的必须过人的手 | grilling 原文："facts 自己查环境，decisions 必须交给我" |
| P5 | **问题应组织成依赖树，不是平铺清单**：上游不通过，下游没意义 | grilling 原文："walk down each branch of the decision tree, resolving dependencies one-by-one" |

一个隐藏的结构性事实：digest_rule §4.6 说"写的时候理解才发生"——但这套流水线里**写笔记的是 Claude，不是你**。"写"的理解红利归了 AI，你拿到的是精良的参考资料。你的理解从未被系统性验证过。这就是 grilling 要补的位置。

## 二、grilling skill 的六个可迁移机制

grilling 全文只有 6 句话，但每句都是一个机制：

1. **穷追不舍直到共识**（relentless until shared understanding）
2. **决策树逐支下钻**，按依赖顺序逐个解决
3. **一次只问一题**，多题并发让人懵
4. **每题附上推荐答案**——拷问者先做完功课，被拷问者不会被晾着
5. **事实自查、判断上交**：环境里能查到的自己查，立场性决定必须交给人
6. **不确认共识不动手**——完成的判据是双方确认，不是文档写完

## 三、现状审计（对照 P1–P5）

### 做得已经很好的（不要动）

- **对论文的 grilling 已经存在**：骨干模板的"证据审计"（"如果我是审稿人会要求补充___"）和"设计决策解剖"（被放弃的方案/何时失效）就是在拷问论文本身，质量很高
- **概念页的学习卡片五要素**（核心张力/不变量/触发条件/误解/非适用边界）本质是对概念的系统性拷问提纲
- **复习队列基础设施**（Dataview + 复核日期 + 成熟度分级间隔）已经搭好
- **digest_rule 的对照表纪律**（§4.8）是防遗漏的成熟机制

### 五个缺口

| # | 缺口 | 违反 | 证据 |
|---|------|------|------|
| G1 | **自测题没有答案闭环**。concept-fable 的设计是"内部保留判分点，等用户回答后再反馈"——但寓言入库后判分点随会话消失，检验问题成了永远不会被执行的摆设。论文笔记的"自测三层""3天后要回忆的问题"同样只存题不存判分标准 | P1, P3 | [[Wiki/概念/04_Agent框架/Harness设计模式]] 检验问题无答案；[[Wiki/论文笔记/03_Agent系统设计/39_Harness-1状态外化搜索Agent]] 五个回忆问题无判分点 |
| G2 | **复核日期记录"时间"不记录"验证结果"**。复习队列在调度"重读"（P1 说重读无效），没有任何字段记录"哪题答错了""掌握到什么程度" | P1, P2 | [[Wiki/复习队列]] 仅按 复核日期+成熟度 调度 |
| G3 | **判断字段由 Claude 单方面填写，你从未 ratify**。成熟度评级、"何时采用/何时规避"、PM 决策框架——这些按 grilling 属于 decisions，必须过你的手，现在全是 Claude 的立场 | P4 | 所有笔记的 成熟度/PM决策 字段 |
| G4 | **自测题是平铺清单，无依赖结构**。L1/L2/L3 有难度分层但无分支逻辑（L1 复述不过，L3 应用题没有意义） | P5 | 骨干模板"自测三层" |
| G5 | **概念挖掘的判定链是隐式的**。"新建/扩展/合并"由 Claude 静默决定；"每篇至少 2-3 个概念"是数量下限不是质量判据；关联密度校验（§4.5）是事后补救不是入库前检 | P4, P5 | digest skill 第 2 步 |

## 四、优化方案菜单

### 模板层（改文档结构，为闭环准备接口）

**A1 · 自测题折叠答案化——判分点随笔记入库**
- 所有检验问题/自测题改用 Obsidian 折叠 callout：`> [!question]- 题目` 内藏参考答案+判分点（答对必须命中哪几个机制点）
- 自测体验不受损（默认折叠），拷问会话有了现成题库，判分点不再随会话丢失
- 修复：G1。成本：模板改一行规则；存量在被拷问时顺手补（不批量重写）

**A2 · frontmatter 增加 `掌握度` 字段 + 笔记尾部「卡点记录」区**
- `掌握度: 未拷问 / 有卡点 / 一轮通过 / 能教人`（四档）
- 卡点记录格式：`日期 | 哪题卡住 | 错在哪个机制点`——这是 P2 的物理承接
- 修复：G2。成本：frontmatter 一个字段 + 一个可选 section

**A3 · 概念页增加「易混淆拷问」区块**
- 与最近邻 2-3 个概念的一句话区分 + 混用后果（如 Harness vs Scaffold vs Workflow）
- 这是面试被追问频率最高、现有模板最薄的一层；学习卡片管"这个概念是什么"，这个区块管"它不是什么"
- 修复：G4 的概念页侧。成本：新概念页 +3 行；存量按需

### 协议层（改生产过程）

**B1 · 概念挖掘判定链显式化**
每个候选概念走四步显式判定（替代静默决定）：
```
① 一句话定义测试        → 不能一句话定义 = 降级为某页的小节（事实，Claude 判）
② 库内查重（Grep+索引）  → 已有页面？（事实，Claude 查）
③ 新建 / 扩展 / 仅双链   → 明确判定 + 理由；边界案例攒成清单批量上交给你挑，
                          每个附推荐选项（决策，你拍板——grilling 第 5 机制）
④ 关联密度预检           → 能自然链到 ≥3 个已有页？<3 标 ⚠ 存疑（入库前检，不是事后补救）
```
- 修复：G5。成本：digest_rule §二 Step 2 加一小节，消化时多一张判定表

### 工作流层（最大杠杆）

**B2 · `/grill-wiki` 拷问复习会话**——grilling 六机制的完整移植：
1. 取材：从复习队列取一篇（或你指定），开场只问一件事：这轮要 L1 快测还是 L3 深拷
2. **一次一题**，按依赖树走：L1 复述不过 → 给出参考答案、标记卡点、换下一分支，**不进 L2**
3. 每题 Claude 持有判分点（取自 A1 的折叠答案；旧笔记则现场从笔记/PDF 提炼）
4. **事实自查、判断上交**：你质疑某个数字，Claude 查笔记/原文验证；成熟度评级、"何时采用"这类判断请你当场表态，你的口径回写进笔记（顺手修复 G3）
5. **双向归因**：你答错的题，先判断是你没懂还是**笔记本身没写清**——是笔记的锅就当场修笔记。拷问会话同时是笔记质量的回归测试
6. **共识门收尾**：报告"通过 X 题 / 卡点 Y 个"，更新 `掌握度`+`复核日期`，卡点写入卡点记录区
- 修复：G1–G4 全部在此闭环。落地形式：写进 digest_rule 作为 §九 + 建一个 vault 内 skill（或全局 skill）

**B3 · 复习队列按掌握度调度**
- Dataview 增加视图：`掌握度 = 有卡点` 的笔记置顶，其次"未拷问"，再按日期
- 复习优先级从"多久没看"变成"哪里被证明不会"
- 依赖：A2。成本：复习队列加一个查询块

## 五、推荐组合与实施顺序

**最小闭环 = A1 + A2 + B2**（题库有答案 → 有字段记结果 → 有会话跑闭环），其余三项可以后补。

建议第一步不是改模板，而是**先拿一篇现有笔记（比如 [[Wiki/概念/04_Agent框架/Harness设计模式]]）跑一场真实的拷问会话当小样**——立刻能验证：题的颗粒度对不对、判分点好不好用、卡点记录格式顺不顺。小样通过再固化进模板和 digest_rule。

**存量策略：增量迁移，不批量重写。** 174 篇论文笔记 + 99 个概念页不动，新笔记用新模板，旧笔记在被拷问到的那次顺手升级（补折叠答案、补掌握度字段）。批量重写成本高且没有提取价值——被拷问过的笔记才值得升级。

## 六、明确不建议做的

- ❌ 给存量 273 个页面批量补折叠答案——没有拷问会话消费它们，就是又一轮"存储优化"
- ❌ 把骨干模板改成纯 Q&A 制——"设计决策解剖""证据审计"这些表格结构承载对照信息的效率比问答对高，保留
- ❌ 每次消化完强制跑拷问——消化（生产）和拷问（验证）节奏不同，强绑定会拖慢批量消化；拷问由复习队列驱动即可
